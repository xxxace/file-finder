## 01:02 选中环不可见 —— 设计原理 + 留缝解法

- **问题的本质**：封面的颜色是**不可控输入**。环贴在图像边缘时，它是在跟"照片"比对比度；
  碰上蓝调/大面积高亮的封面就瞎了。**加粗不解决对比度问题，只放大噪音**（3px 也救不了）。
- **业界三种解法**：① 留缝（Figma 选择框 / VS Code 焦点 / macOS 焦点环）② 双环互补（白 + 深两圈，
  至少一圈能压住）③ 蚂蚁线（Photoshop，黑白交替）。
- **我们选留缝**：`outline: 2px solid var(--ff-highlight); outline-offset: 2px;`
  环的内侧与外侧**都只面对网格底色**（深 #141414 / 浅 #f1f2f3）⇒ 任何封面下都稳定，且明暗主题一致。
- 同时 **3px → 2px**：对比度靠"站在哪"，不靠"多粗"。
- 几何校验：`2 + 2 = 4px < --ff-grid-ring-room(6px)` ⇒ 最左/最右列不会被 `overflow:hidden` 裁掉；
  标题 `margin-top: 6px`，环下沿占 4px ⇒ 不压标题（剩 2px）。
- typecheck 0；探针 59 持平。

offscreen 窗口的 rAF 会被合并/丢帧，"第几帧"不可信。改成 `await nextTick()` 之后**同步读
getComputedStyle`**：判据是"内容已换、但还没有帧被画出来的那一刻透明度是多少"。稳定得 0。
⚠️ 顺带自我纠错：`fill: 'backwards'` 在这版 Chromium **不是必需的**（动画创建即 current），
原注释说"等于没做"是错的，已改。曲线实测：100ms（半程）已到 0.98（expo-out）。

## 方向键到边界的滚动：单次平滑 / 长按瞬时（原生，不自绘）

先量（`docs/probes/scroll-smooth/`，Chromium 152）：单次 150px（一格）= **210ms**、600px = 415ms；
**长按（每 60ms 一格）用平滑的话每步落后 150→636px，最后一次追加后 600ms 仍在 714/1200 ⇒ 根本没追平**，
光标早被滚出视口。瞬时版每步落后 **0**。

⇒ 判据 = `e.repeat`（和 `MOVE_REPEAT_MIN_MS` 那条节流描述的是同一个事实），
`moveCursor(dir, !e.repeat)` → `focusCursor(key,{smooth})` → `scrollIntoViewIfNeeded(key,smooth)`。
`focusCursor` 的 `smooth` **默认 false** ⇒ 定位/点击/切密度后重定位/onBack 恢复全部保持瞬时。

❌ 不用 CSS `scroll-behavior: smooth`：它对容器**全局生效**，会把 `onBack` 的 `scrollTo(恢复 scrollY)`
和 `enterScreen` 的 `scrollTo(0,0)` 一起变成动画，而它们后面的**回读确认是当帧读 scrollTop** ⇒ 读到中间值。
❌ 不自绘 rAF：① 长按那一帧 `probeLayout` 本来就要读几百个 `offsetTop`，再塞一份滚动写入等于最忙的帧加活；
② `scrollIntoView` 会替我们处理 `scroll-margin-block`（6px 环让位），自算就得重实现；③ 滚轮打断原生自动让位。
⚠️ 首/末行那两句 `scrollTop = 0 / = scrollHeight` 也会**覆盖** scrollIntoView ⇒ 必须一起改成 `scrollTo({top, behavior})`。
⚠️ 原生 smooth **不会**自己尊重 `prefers-reduced-motion`，要自己判。
⚠️ 探针坑（第二次）：对象字面量的键不能以 `①`/`②`/数字开头（`①实现:` `600ms 后位置:`）—— 会直接 SyntaxError 让整个页面白跑。

### 进度效果搬进地址槽（同日第四轮）

主人："先隐藏 `n-loading-bar`（不移除），把效果用到地址栏的盒子中、占满整个盒子"。

- **关**：`App.vue` 的 `container-style` 加 `visibility: 'hidden'`。⚠️ **绝不能用 `display:none`/`height:0`** —— 像素层靠 `rect.width ÷ 容器宽` 算进度比例，display:none 会让 rect 全归零。`visibility` 不改布局 ⇒ 尺寸照读。
- **搬**：`GalaxyLoadingBar` 从 App.vue 根部挪进 `index.vue` 的 `.nav-zone`；几何从"窗口宽 × `--ff-bar-h`"改成"父盒实际尺寸 × 100%"，`width = 比例 × 盒宽`；`draw.ts` 一个常数没动。
- **结构**：地址槽拆两层 —— `.nav-zone`（面：底/圆角/padding/角标槽）+ 内层 `.crumbs`（TransitionGroup，`z-index:1`）。**画布不能当 TransitionGroup 的兄弟**（子节点必须带 key、还会被 FLIP 挪）。**类名仍叫 `.nav-zone`**，10 处 `.nav-zone .fx-*` 靠后代关系继续命中，一处没改。
- 画布尺寸用 ResizeObserver 盯父盒（搜索展开会收窄槽，否则点阵被 CSS 拉伸成糊）；`pad: 0`（盒外会被 `overflow:hidden` 裁）。
- 退路：去掉 `visibility` 即可回到顶部轨道（像素层代码还在，只是不挂在那儿）。

**第四轮补的两件**（主人："底色的紫色渐变色呢？还有阈值不用等 30%"）：
- **底色紫渐变是 naive 的 `colorLoading`（`--ff-bar-base`），bar 一藏就没了** ⇒ `draw.ts` 加 `drawBase()`，坐标系与 naive 一致（0 → 当前进度宽，元素变宽渐变被拉伸）。`--ff-bar-base` 拆成 `-from`/`-to` 两个色标（canvas 的 `createLinearGradient` 只吃颜色、不吃 CSS 渐变串），CSS 那条由它们拼，十六进制不写第二遍。
- **最小阈值删掉**：判据就是 `ratio > 0`。"开头看不出在加载"的死区是**自然的**（底色没人画 + 星点左疏两条叠起来），底色补上就不存在了。
- ⚠️ **未实测风险**：底色是**不随主题变**的深靛，浅色主题下深灰字压上去会看不清（他只看过深色）。补救二选一：底色按主题给透明度，或只铺盒子下半截。
