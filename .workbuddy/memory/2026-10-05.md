### ⭐ scroll 的真根因（探针 `docs/probes/onback-real/` 复现）
我第三版加的判据是：
```ts
if (first && first.dir === path && el && el.dataset.key === keyOf(first)) return true;
                    ^^^^^^^^^^^^^^^^^^ ★ 这个条件在 cover 模式下**永远为 false**
```
**为什么 false**：`cover` 模式下**子目录会收敛成封面条目**，
那些条目的 `dir` 是"**封面图所在的目录**"，与"这一屏的路径"**不一定相同**
（整屏都是收敛出来的目录脸时，`dir` 全都对不上）。
⇒ `waitForGridOf` 走满 20 帧 ⇒ 返回 false ⇒ `onBack` 走"**不恢复**"分支
⇒ **返回到哪都停在上一屏的滚动位置** = 主人说的"A 返回后停在 B 的高度"。

⇒ **完美解释"间歇性"**：`to.scrollY === 0`（没滚过）⇒ **根本不进恢复分支** ⇒ 看起来正常。
⇒ **修法**：删掉 `first.dir === path` —— `await fetchFolder()` 已保证 `dataSource` 换成新屏，
只需等 **DOM 跟上数据**（`el.dataset.key === keyOf(first)`）。

**关键排除**（探针实测）：`history` 里记的值是**对的**（800）⇒ 我前几轮怀疑"记录端错了"是**错的**。

⚠️ 探针本身**未跑通**（`new Function` 的自由变量作用域问题，R0b 手动测成立、函数内 false），

### ② 返回后滚动串屏 —— 根因一行
`onBack` 恢复滚动那段是 `if (to.scrollY) { … }`。而**容器不会自己归零**
（`grep scrollTop` 只有"被记录"/"被恢复"，**没有写 0**），`fetchFolder` 换的是**数据**、容器元素没换
⇒ 目标屏记的是 **0** 时整段被**跳过**，容器把**上一屏的偏移**一直带着。
B 没滚过时容器本就是 0 ⇒ 看起来正常（"没滚动就正常，滚动了就不对"逐条吻合）。
⇒ **无条件恢复（含 0）**；`0` 不需等 DOM，**非 0 必须**等 `waitForGridOf`（否则在旧屏上"成功"滚动、回读也一致）。
