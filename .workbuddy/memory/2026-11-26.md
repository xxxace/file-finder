## 设置页卡片改玻璃材质（`--ff-glass-*`）

- **物理前提**：设置页背后是**纯色画布**（`Shell/index.vue` 只有一层 `--ff-bg`），窗口也没有 mica/vibrancy ⇒ `backdrop-filter` 对静态卡**零变化**。玻璃感只能由「顶亮底暗渐变 + 1px 发丝内描边 + 半透明」给。
- **两个材质，别混用**：`--ff-glass-*`（压画布、不遮内容 ⇒ **不挂 blur**，白付合成成本）；`--ff-glass-cover-*`（遮内容，必须够不透明，否则字从卡里渗出来 ⇒ 才吃 `blur(18px)`）。
- 落点：`GeneralPanel .set-card`（5 张）· `SiteRulesPanel .rule-card`（3 步）· `RuleTestResult .result` · **`.editor-head` 是全页唯一真 blur**（sticky，卡从它下面滚过）。
- ⚠️ 深色卡顶**刻意不抬亮**：卡内 step 徽标/内嵌块吃 `--ff-raised`(#242424)，卡顶一旦比它亮，徽标就溶进卡面。
- **没动选中高亮** `--ff-ctl-on`：他 2026-11-08 定过「工具条按钮和左栏选中必须同色」，那是全局 token，为一个彩蛋改它对整站生效 —— 要做单独提。

### 追加（同日 · 他说"菜单为什么没用上"）—— 三档玻璃定型

- **我上一轮判断错了一处**：把"菜单选中块"归进"全局选中色"没动，结果同一屏两种质感。修法不是把 `--ff-ctl-on` 改透明（**30 处消费**：滑块轨道 `railColor`、右键菜单悬停、工具条、首页盘块…），而是**新增第三档 `--ff-glass-hi-*`**，只给"行/块选中"这一类：alpha 校准到与旧 `#3a3a3a` **同一明度**（深 0.18 白 / 浅 0.05 黑）+ 发丝边。
- **三档 = 同一条光向、同一发丝边，只差密度**：`hi`（0.18，选中行）< `bg`（0.075→0.042 渐变，卡片）< `cover`（0.88 渐变，sticky 编辑头）。cover 抬密度只因**它底下有字要盖**；一开始给 0.82 纯色，与卡片的渐变对不上，改成同端点渐变（压画布 ≈ #212121→#1a1a1a，与卡 32→24 同线）。
- 落点：`Settings/index.vue` 的 `.nav-row.is-active` · `RuleSiteList.vue` 的 `.rule-row.is-active`。
- **判据**：同一个"面"只允许一份材质；差档必须有物理理由（要不要遮内容），不能靠手感调色。

### 危险色两修（"hover 变色" + "hover 好丑"）

- **hover 变色的机制**：naive 的 `.n-button:hover{color:var(--n-text-color-hover)}` 与我们 scoped 的 `.del-btn[data-v]{color:red}` **同为 0,2,0**，平手时**后注入者赢**，naive 在挂载时才注入 ⇒ 悬停红图标被换成默认文字色。
  - 正确修法：**钉 naive 自己的变量**（`--n-text-color{,-hover,-pressed,-focus}` + `!important`，值来自其内联/主题类），四个状态一起红；**不是**再补一条 `&:hover{color:red}`（那只是 specificity 打架）。三处：SiteList / StepList / CoverList 的 `.del-btn`。
- **"清除选中"按钮 hover 丑的根因**：hover 同时染「红描边 + 红字 + 灰底」三色 ⇒ 控件身份跳变。改成：**描边保持中性** + `--ff-danger-weak` 淡危险底 + 红字（新增 token：浅 8% / 深 14%，是"水洗"不是色块）。
- ⚠️ 未根治：`purge` / `purgeStorage` **没有确认框**，点了就真删；红色只在 hover 一瞬间出现，保护不到误点。加确认是行为改动，等他拍板。

### tooltip 描边看不到的真正原因：落点半像素

- `FluidTipHost.place()` 的 `cx - w/2` 常是小数 ⇒ `transform: translate(x,y)` 带小数 ⇒ **整层被重采样**：字形发虚 + 1px ring 被 AA 吃掉一半（实测同一圈 ring：右/下 105、左/上 81）。
- 修：**落点 `Math.round`**（`offsetWidth/offsetHeight` 本身返回整数 ⇒ 四边落到整数栅格）；ring `0.22 → 0.26`。
- 判据记下来：**1px 描边能不能看见，先看几何是不是整数栅格，再看 alpha**。alpha 加到 0.4 也救不了半像素。
- **更硬的一条判据（2026-11-26 对比图定案）**：一条边读不读成"边框"，看它落在 **[填充, 背景] 区间内外** ——
  · 深色：填充 30 / 背景 14 / 白边 57 ⇒ **区间外** ⇒ 读作边框 ✓
  · 浅色：填充 66 / 背景 238 / 白边 115 ⇒ **区间内**，与抗锯齿过渡值同族 ⇒ 大脑判成"边缘糊"，0.14→0.26 全无效 ✗
  ⇒ 浅色只能**往暗里描**（`inset 0 0 0 1px rgba(0,0,0,.42)`，边落到 38）。
  ⇒ 推论：浅色想要"深色那种亮晶晶的边"**物理上不可能**（背景 238 已是最亮）；那条路只能把浅色提示换成**浅磨砂片 + 深字**。
- **第四轮实测（最终判据）**：0.42 黑的内描边**确实在渲染**（左右像素 38 vs 填充 66），但旁边是 238→88 的边沿跳变 —— 172 级的强对比把 28 级的线吃掉了。⇒ **色差不是杠杆，宽度才是**：1px → **2px** 才以"带"的形态独立成型。
  · 深色保持 1px：它背景 14 / 填充 30 只差 16 级，1px 本身就是最强跳变，加宽反而糊。**宽度按对比度定，不按主题对称定。**
- 顺带否掉"浅色改浅磨砂片"这条路：`--ff-tooltip-bg` 被**右键菜单/多顶层菜单**共用（ctx-menu.css），一起变白会分裂成两套浮层语言 —— 项目明确反对（同一界面两套浮层语言）。要做必须给 FluidTip 单开一组 token，代价远大于收益。

### 最终解：浅色提示改「浅片」（第 5 轮，主人："用 UIUX 处理这种颜色问题"）

- **前四轮全错在同一件事**：一直在给"深片"补边。深片在浅色画布上差 **172 级** —— 这个对比既让深片突兀（他两次说"太黑"），又让任何 1px 边都读不出来（白边落在区间内=抗锯齿；暗边被 172 级跳变吃掉；加宽到 2px 又"很厚"）。
- **正解 = 换材质，不是补边**：浅色 ⇒ `rgba(252,252,253,.95)` 白磨砂 + `blur(16px)` + 1px 0.08 黑发丝 + 双层柔影；键帽反成"浅槽"（0.05 黑底 + 0.12 黑下缘）；文字 `--ff-text-1`。**填充与背景只差 ~14 级 ⇒ 那条 1px 深线就是这道边上最强的跳变**，边自然成立。
- **有先例**：右键菜单在浅色下早就是这么做的 —— `ctx-menu.css:45-49`「白面压在白卡片上只靠明度差没有边界」⇒ 补 1px `--ff-line-strong`。我只是把同一条规则用在提示上，不是新发明。
- **深色一个值都没动**（填充 30 / 背景 14 / 亮边 57，他说"暗色就很好"）。
- ⚠️ 连带：`.n-popover:has(.file-list)` 多文件弹层 + naive tooltip 共用这组 token ⇒ 浅色下一并变浅（符合"跟随主题"）。已把 `ctx-menu.css` 那段"反色深片是唯一立得住的材质"改判并写明理由。
- **教训**：视觉改不动时，先问"这个材质在当前明度关系里成立吗"，而不是继续调 alpha / 加宽度。前四轮就是没问这一句。

### 浅色"糊"的光学解释（最终定型）

- **为什么浅色做不到暗色的锐利**（根因，不是调参能解的）：暗色里黑影压在黑底上**不可见** ⇒ 整颗只剩"1px 高光边"一个信号 ⇒ 必然锐利；浅色里白片只能靠影"画"出来 ⇒ **可见的柔影必然包住边缘** ⇒ 天生软。
- 上一版最"糊"的元凶是 `0 12px 28px -10px`：大半径 + 负 spread = 一团灰雾贴着边。**禁止用大半径负 spread 给浮层做影**。
- 定型配方（浅色）：面 `#fff@0.97` → 轮廓 `inset 0 0 0 1px 黑.15`（⇒217）→ **贴身影 `0 1px 2px` @.16（2px 内收干净）** → 短扩散 `0 5px 14px -6px` @.22。明度阶梯 241→255→217→更暗，边界才读得出。
- **上限要讲清**：暗色那种"发亮的边"在浅色里没有可发亮的方向（背景已最亮），浅色的天花板是"干净有形"，不是"发光"。
- 备用下一招（未做）：浅色提示字重 500→560。暗底白字有光渗显得更粗，同字重的浅底黑字更细，这是"糊"的另一半来源。
- 左侧 `RailTip` 也走 `transform`，同样可能发虚（未查，未改）。
