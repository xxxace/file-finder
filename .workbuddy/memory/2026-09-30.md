## 预览图"点图外关闭"—— 调研完、被用户叫停，**产品代码零改动**

用户问：「是否可以点击图片外的范围就关闭预览？现在要点击关闭按钮才能关闭」

### 我做了什么（全部落在 `docs/probes/preview-fill/`）
把根因、四个候选方案、A/B 对照全跑通了（真 Electron offscreen，视口 1903×1063）：

- **根因**：naive-ui 的"点图外关闭"是靠 overlay 接住点击。上一版把预览 img 的元素盒撑满视口后，
  **图内容与盒子之间的留白也归 img 吃点击**（大图左右各 162px、竖图左右各 764px、宽银幕上下各 360px），
  那部分从 overlay 手里被拿走 → 点它不再关闭。
- **`stretchClick`（stretch + 坐标判定）实测通过**：同一探测点，无判定 `closed:false` / 有判定 `closed:true`；
  点图内容正中两种方案都 `closed:false`（不误关）。A/B 对照成立。
- **`fit` / `fit48`（盒子贴合图 + 放大边距）已排除**：对**比视口更宽**的图失效 ——
  `width:auto; height:100%` 只在"高度受限"时保持比例，宽银幕图宽被 `max-width` 钳后**高度不重算**，
  假空白 360px 又回来了（`boxEqualsContent:false`）。

### 结果：用户裁定不采用
原话：「**算了 如果要算这么多东西就不要搞了**」

→ `src/views/FileFinder/index.vue` **一行未动**，保持 09-27 的"打开即撑满"
（`previewedImgProps = { style: { width:'100%', height:'100%', objectFit:'contain' } }`）。
探针里保留 `stretchClick` 的代码与 `out.txt` 只作证据，README 顶部已写明"未采用、勿误读"。

### ⚠️ 教训（本轮最值钱的一条）
**诉求明确、但实现有成本梯度时，先给成本阶梯，再动手。**
这次的诉求其实有两条路：
- **一行版**（`pointer-events:none`）：点任何位置都关（含点图片本身），够用大部分场景
- **约 20 行版**（坐标判定）：精确区分图内/图外

我直接端上了 20 行那版的设计，他只看到"要算这么多东西"就否掉了 —— **而一行版覆盖同一诉求的绝大部分**。
正确做法：**先摆出"一行能拿到什么 / 多花 20 行能多拿到什么"，让他选**，而不是替他把最完整的那版做完再汇报。

补充事实：naive-ui 预览面板**没有任何外部可用的 close API**（只能点它自己的 overlay / ✕ / Esc），
所以"关闭"这条路要么走 overlay 的 DOM click，要么用一行版让事件自己穿透过去 —— 没有第三条。

### v2 打磨（用户四问：用上大小 / 有遗漏吗 / 三神技 / 交叉验证）

#### Q1 结论：**能用上文件大小，数据早就在库里**
- `FileInfo.size` 一直存着；**收敛条目的 size = 该子目录所有文件之和**（`server/index.ts:347-398`，`size += stat.size`）。
- 实测：213 条里 **210 条**能算出量；单层最大 **492.55 GB**；全库 **3.35 TB**；内存聚合一次 **0.07 ms**（零额外磁盘 I/O）。
- **双算证伪（3 轮探针收紧）**：① 有父路径 208/213（只是结构）→ ② 父自身字节>0 有 102 条（必要不充分）→
  ③ 精确判据「父层非 folder 条目名 ∈ 同名子记录名」= **0 条**；反证 208 对配对**全部是 folder 条目（size 0）**。
  - 结构性原因：**收敛要求子目录没有子目录，而被收敛的目录永远不会产生独立记录**（双击封面条目 = 打开里面的视频，不是进目录）。
  - ⚠️ 不是结构性保证：用「选择文件夹」手工选一个已被收敛的子目录 → 就有了独立记录 → 盘级会虚高。
- **裁决**：做**行级「大小」列 + 按大小排序**；**不做**盘级/全库总量（快照 + 有理论双算 → 会误导）。
  文档里落了「库 81.7 MB ↔ 省下 3.35 TB 重读 = **1:43000**」这个"缓存值不值"的答案。
- **发现 `parseSize` 的 TB 截断**：`src/utils/index.ts:3` 是 `gb = bytes/1G % 1024` → 1.83 TB 渲染成 `850.xxGB`，2 TB 渲染成 `0.00GB`。**静默输出错误数字**，一行必修。

**⚠️ 一个 scoped 样式的坑（记下来，以后复用）**
naive-ui DataTable 的 `render()` 回调是在 **DataTable 自己的渲染上下文**里执行的，

解法：`<style>` 不加 scoped，全部规则用外层类名前缀（`.cache-panel xxx`）隔离。**以后凡是要给 render 出来的节点写样式，都走这条。**

|---|---|---|---|---|
| old（我第 1 轮） | `max-height:86vh` + `.table-wrap{overflow:auto}` + `thead{sticky}` | **4235px** | `table-wrap` | **相对表格 −3562 → 滚走** ❌ |

**根因**：`max-height` **只封顶、不给确定高度** ⇒ 容器高度仍是内容高度 ⇒ `flex:1 1 auto` 的表格

**代价**：卡片从"最小 86vh"变"恒定 86vh"（几行数据时下方留白）——列表页这样更合适（翻页不跳）。

⚠️ 教训：**"给它一个 overflow 就行"是偷懒的因果关系**。滚动条要落在哪，前提是"那一层的高度先被真正约束住"；
没约束住时，overflow 只会把滚动条放到最外层。**下次遇到"滚错地方"，先量"谁的高度没被约束"，而不是先加 overflow。**

## 头部区域（根路径 + 面包屑 + 工具条）重设计方案 —— 2026-09-30 晚

### 诊断（全部 `[静态]`，可复算）

靶子是三个**无界内容**：根路径长度、单层名字长度、面包屑层级数。根因一句话：
**头部高度是「用户数据」的函数** —— `.hstack{flex-wrap:wrap}` 把「低频的·无界的根路径」和「高频的·无界的面包屑序列」
塞进同一个换行容器，共享同一份宽度预算；`.toolbar{nowrap}`（子项 `min-width:auto` ⇒ 缩不下去）先占满自己，
剩下的才给 `.hstack` ⇒ 装不下就在**内部换行**。而 `.toolbar{align-self:flex-end}` 让它"看起来和面包屑同一行"——
**那是巧合，不是设计**。窗口一窄或内容一长，头部就从 1 行涨到 2–3 行，把网格挤下去。

关键静态事实（都写进方案 §1 了）：
- `FolderSelector` 把**完整路径原样**塞进 `n-tag`，**无 max-width / 无省略**，且该组件 `<style>` 是**空的**；
- `n-tag` 自带 `white-space:nowrap` ⇒ 长路径**只会把 tag 撑宽**，不会换行；
- 面包屑**一层一个 tag、无上限、无折叠、无分隔符**；所有 tag 都 `cursor:pointer`，但 `handleJump` 对**最后一层直接 return**
  ⇒ **当前层是死交互**（看着能点，点了没反应）。

### 方案要点（三个膨胀源 ↔ 三种有界化，别混）

| 源 | 解 |
|---|---|
| A 换行 → 垂直无界 | 分区：`.header-bar` 补 `nowrap`；导航区 `flex:1 1 auto; min-width:0; overflow:hidden`；`.toolbar` 补 `flex:0 0 auto`。**`min-width:0` 是地基**（flex 子项默认 `min-width:auto`，不加它设了 overflow 也不收窄） |
| B tag 数 = 层级数 | 按**层数**折叠（不按像素）：≤4 全显；>4 ⇒ 首 1 + `…` + 末 3，`…` 用 `n-popover` 列出被折层且**可点跳转**（折叠只牺牲"常显"，不牺牲能力） |
| C 单条长度 | `max-width`+ellipsis+tooltip；根路径用一个**纯函数** `foldPath()`（`盘符 + 末 n 段`，中间折 `…`）。**不用 `direction:rtl` 那类 CSS 反向截断**（会把 `F:/` 的 `/` 排错位） |

三档成本阶梯（用户要求"先摆阶梯别替他选最完整那版"）：① 一行版＝只做分区（**但会把当前层裁掉**，比不修更糟）
② 标准版＝①+单条有界 ③ **完整版＝②+折叠+修死交互+分隔符** ⇒ **推荐 ③**，因为"当前层永远可见"是硬约束、而 ③ 只多了 1 个 computed + 1 个 popover + 3 处条件绑定。

### 外部权威（`[引用]`，用来锚定第一性原理，不是用来抄）

`Cognite Aura 设计系统` / `SSW Rules` / `TYPENORM`（转引 NN/g）四家共识高度一致，正好逐条对上三个膨胀源：
**面包屑绝不换行（truncate instead）**；**超过 4–5 条就把中间折成省略号**；**首段+末段永远可见、当前页永远可见**；
**单条截断 + tooltip 显全名**；**当前项不应可点**；**不要横向滚动**（用户发现不了）。

### 明确不做

可编辑地址栏（浏览≠输入，且和双击/跳转语义打架）· 面包屑横向滚动 · 根路径 chip 合并进面包屑（要重做 `×` 语义 = 动已声明特性）· 按像素动态折叠（引入测量与抖动）· 改动作按钮文案（认知成本已记档）· 好看的样式升级。

### 读盘

**零。** 无新端点、无新请求、**主进程不动** ⇒ 本轮**不需要重启 dev**。改动面 = 渲染层 3 文件（`index.vue` / `FolderSelector` / `utils` 加 `foldPath`）。

  ⇒ Apple 与 Microsoft **两家独立收敛到同一条折叠规则** ⇒ 这是本方案最强的一条证据。

**发现了一条真正的「重构可能」+ 一条「被规范解锁的中间路线」**（路线定义见 §14）：
- **路线 B（路径下沉到窗口底部独立一条，Apple 模型）** —— 备选。
  它的额外价值：路径拿到**独占一整行**后，才**解锁** Explorer 式的「可编辑路径 + Ctrl+L 键盘直达」
  ⇒ 上一轮把「可编辑地址栏」列为"不做"的**理由要更新**：不是"浏览≠输入"，而是**我们没有它的空间**。
- **路线 C（左侧目录树，三家共同答案）** —— **否**。否决理由是本项目特有的、有说服力的：
  **它的核心收益（跳到任意层级）已经被「缓存记录」面板覆盖**（213 目录黄页、可搜、**纯内存零读盘**、已上线）
  ⇒ 边际收益小、成本最大（奥卡姆）。这也是一条可复用的判断法：**新造大件前，先问它的核心收益是不是已有面板已经给了。**

**另有一条「不能照抄规范」的具体证明（已写进 §13.4）**：Fluent 的「单条 >30 字符截断」是**拉丁文语境**，
中文 1 字≈拉丁 2 字宽 ⇒ 30 个中文字≈360px，照抄等于没截断 ⇒ 中文必须用**像素** `max-width`。

### 追加：导航语义升级（同日晚）—— 用户新增一条硬约束

用户反馈：「**由于我们通过缓存打开的页面是不会被识别成栈模式的，返回的体验有些怪**」，同时下了一条新硬约束：
**「不允许手动输入编辑路径」**（已记入 `MEMORY.md` §十第 5 条）。产出 `docs/DESIGN-NAV-2026-09-30.md`。

**根因（比用户的描述更精确，`[静态]` 可复算）**：
`openStack` **一个数组同时承担「祖先链（位置）」和「访问历史」**两个语义。逐层下钻时两者**恰好重合**，
所以一直没暴露；**一旦跳转（从缓存记录打开一行）就必然分叉**，而 `handleDirChange` 对任何入参都
`openStack = []` + 压一层 ⇒ 栈长恒为 1。于是三处症状同源：
① 面包屑只剩 1 段（`handleDirChange` 把跳转目标当成新起点）→ **看不到自己在树的哪里**；
② 「返回」按钮条件 `v-if="dir"`（**曾经选过根**＝快照）而 `onBack` 实际条件 `openStack.length > 1`（**此刻真有上一屏**＝事实）
⇒ 栈长 1 时**看得见、点不动**；③ 历史被销毁 ⇒ **回不到刚才那屏**，只能重开缓存面板再找那一行。

⚠️ **第 ② 条是「判据落在事实还是快照上」的第二次复发**（第一次是 `path.startsWith('#')`）——
说明这条自检问句值得从"项目记忆"升级为**每次改交互条件时的固定动作**。

**设计（升级点）**：
1. **位置不再存状态** —— 由纯函数 `ancestorsOf(path)` 推导；状态里只剩 `history: NavEntry[]`。
   同时把 `openStack` + `searchStack` + 挂在元素上的 `scrollY` **三处靠索引对齐**（不变量 `searchStack.length === openStack.length − 1`）
   合并成"一屏一对象"。**声明：现有实现是对的**（我推演过 `handleJump` 的 `slice` + `pop`，那个 −1 恰好抵消），
   不是修 bug，是拆语义时不能再靠这种隐式不变量。
2. **面包屑改成绝对路径链**（`E: › 祖 › 父 › 当前`）—— 依据是 Apple HIG 路径控件官方模型
   （"includes the root disk, parent folders, and selected item"）。因为它**不需要状态**，跳转后自动正确。
   首段（盘符）**不可点**，理由：点它会打开盘根、通常未缓存 ⇒ **会真读一次盘**；为不引入这条新读盘路径而放弃。
3. **「返回」= 回上一屏，且跳转可撤销**（出现条件改 `history.length > 1`，根层不显示；新增 `Backspace` 键）。
   ⇒ 这才是"妙用"：现在从缓存跳转是**单向门**，改完是一键可撤销 ⇒ 用户敢到处跳。
4. **chip 升级为「回根」入口**（现在只有 `×`，没有点击行为）⇒ 解决"跳转后想回根"，且不新增按钮。
5. **位置先到、内容后到**：面包屑由 path 推导 ⇒ 点下那一行位置立刻到位，不等数据。

**连带决策**：因为"手动输入路径"被禁止，`DESIGN-HEADER` 的**路线 B（路径下沉）降级为不做**
（它的解锁价值正是"可编辑路径 + 键盘直达"，被禁后只剩搬迁成本）；**只做路线 A**。
`DESIGN-HEADER` 的面包屑折叠阈值也随"相对链 → 绝对链"更新为 **首段 + `…` + 父 + 当前（最多 4 段）**。

**读盘**：零新增端点 / 零扫盘 / 主进程不动 ⇒ **不需重启 dev**。唯一被*避免*的新读盘路径＝面包屑首段。
