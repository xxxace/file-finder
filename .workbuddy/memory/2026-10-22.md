## webp 无图 + 视频不抽帧（裂图）· 根因与修复

**根因（一条链，两个症状）**：打包版里 `@ffmpeg-installer` 给的路径在 `app.asar` 内部，
而 `child_process.spawn` **不走 Electron 的 asar 补丁** ⇒ `ENOENT`。于是
**webp 转码兜底**和**视频抽帧**全部静默失败 → 无 `sig` → 前端 `<img src="">` → 裂图。
jpg/png 走 nativeImage、不碰 ffmpeg，所以图片大部分正常。

**证据**（详见 `docs/FIX-WEBP-VIDEO-COVER-2026-10-22.md`）：
- 实测 `release/1.0.0/.../app.asar/.../ffmpeg.exe` → `spawn ENOENT`；同一份 `app.asar.unpacked/...` → `exit 0`。
- 真库（`~/.file-finder/searchCache.db`，解密后）：image 976/993 有 sig，其中 **webp 仅 3/16**；
  video **128/222**，失败集中在用 exe 扫的那几层。
- 探针 `docs/probes/webp-video/`：webp 3 变体（动图/alpha/2400px）+ mp4 5 变体（frag/faststart/0.4s/attached_pic/AV1）全过；
  **修后** 容器 60s / 视频流 0.5s 的样本也能抽到帧（修前 exit 0 但零输出）。

**改动（4 处）**：
1. `electron/utils/thumbnail.ts`：`realBin()` 把 `app.asar` 重写成 `app.asar.unpacked`，ffmpeg/ffprobe 都过它（dev 路径不受影响）。
2. 同文件：`probeDuration` 改成**先查 `stream=duration`（视频流）再退 `format=duration`（容器）** ——
   容器时长 > 视频流时长时，1% 会落到流末尾之外；`extractFrame` **补上"产出文件非空"的判据**。
3. `src/views/FileFinder/index.vue`：`n-image` 的 `v-if` 加 `!!item.thumb`（无图退到类型图标，绝不渲染空 src）；
   类型图标类名 `item.ext.toLowerCase()`（库里有 `.MOV` 大写，`fiv-icon-MOV` 匹配不到）。
4. `electron-builder.json5`：显式 `asarUnpack` 两个 installer（不靠 electron-builder 的自动检测）。

**验证**：typecheck 0；探针全过；重新打包成功（`vite.config.ts:9` 的 `rmSync('dist')` 会被宿主
safe-delete shim 拦，构建前先把 dist 移走即可，**不要改那段代码**）。

**⚠️ 验收要点**：修复后**已缓存的失败条目不会自动重抽**（`findCache` 命中就短路），
必须对没封面的目录按一次 **↻** 才会重扫出图。

## 追加：目录的脸也认 webp

- 原状：`DIR_COVER_FILES` 只有 `avatar.jpg` / `cover.jpg`（写死），`cover.webp` 连 stat 都不发生。
- 改动：抽 `electron/server/dirCover.ts` 作**单一真相源**（`DIR_COVER_FILES` + `isDirCover`），
  `server/index.ts` 与 `assistant/scan.ts` 共用；名单 = `avatar.jpg / cover.jpg / avatar.webp / cover.webp`。
  **jpg 优先** ⇒ 旧行为不变。`makeDirCover` 里写死的 `'jpg'` 改成 `getExt(name)`（不撒谎）。
- 效率实测（本机 SSD 热缓存，300 次）：4×失败 stat **35.8 µs** vs 2× **16.3 µs**（+19.5 µs/目录），
  仍低于 1× readdir **46.5 µs** ⇒ 扩名单比"改成列目录"便宜。
- ⚠️ 两处共用一份的理由：助手侧若漏改，会把"已有 webp 封面"的目录判成没脸并**覆盖写 cover.jpg**。
- 行为对齐：`cover.webp` 不再是独立条目，而是目录的脸（与 cover.jpg 同待遇）。


## 补/换封面：暂停·终止·试跑中断 + 一次全链路审查

**根因（4 条，全部静态可证）**：
1. `jobs.ts` 只有 running/done/cancelled/error，**没有暂停态**；`cancelJob` = abort ⇒ 在飞全断。
2. `grab.ts:278` `if (job.cancelled) return;` 把**已经 await 到手的命中整条丢掉** ⇒ hits=0、写入按钮不出现。
3. `dryrun` 没接 `abortOnClose(res)` 的 signal ⇒ 试跑**无法中断**（最长白等 45s）。
4. 「过验证后重抓」`startGrab(blockedTargets)` 起**新 job** ⇒ 之前命中的行凭空消失（真 bug）。

**改动**：`jobs.ts` 加 `Gate`（暂停闸门）+ `pauseJob/resumeJob/reopenJob`；`grab/apply` worker 在**取下一条之前** `await gate.wait()`；
`finishJob` 认 paused（否则从暂停态终止会永久卡住）；`grab` 用 `allSettled` 收拢再收尾；`runGrab(..., append)` 累加 total；
`POST /assistant/jobs?id=&act=pause|resume`；`startGrab` 支持 `jobId` 追加、冲突由 409 改 200+reused；前端 footer 加暂停/继续/终止/重试失败项，
确认弹窗标「已写入」并默认不勾（`writtenSet` 跨多次写入累积）；`postAction` 支持 signal，试跑按钮变「取消试跑」。

**验证**：typecheck 0；探针 `docs/probes/jobs-pause/verify.mjs` 11/11 PASS（纯逻辑，import jobs.ts，无需 electron）。
**未做（列给主人定）**：认不出番号的手填入口、主界面扫描的暂停、进度 ETA、结果表按状态筛选。

**追加（同日）**：给所有动作按钮加 `acting` loading（pause/resume/stop/grab/apply，同刻只放行一个）+ 动作后
`refreshJob()` 立刻拉快照（不等 1.2s 轮询）；「终止」的转圈靠 `settleActing()` 保持到 `!isLive`；
关面板清 acting。左轨「缓存记录」图标 `FootstepsOutline` → `TimeOutline`（时钟）。

**问答·封面三种写法的支持边界（静态结论，未改代码）**：
`buildExtractScript` 的 `tryCss` 只走 `el.getAttribute(attr)`（`text`/`html` 两个特例），**不看可见性** ⇒
①`<img src>` 即使 `display:none`/`0×0` 也能抓（配 `attr:src`）；②内联 `style="background:url()"` 只能靠
`kind:'regex'` 抓（整页 outerHTML，先匹配到的常是 logo）；③class 里声明的 background **完全抓不到**
（样式在外部 CSS，不在 HTML 里）。⚠️ 陷阱：`attr:'style'` 不是取空而是取到整串
`background: url(...) 0% 0% / cover;`，经 `abs()` 拼成垃圾 URL 且**算命中**，把后面的候选全堵死。
`buildPickerScript` 的 `pick()` 只认 `IMG`/`closest('img')` ⇒ 点背景图 div 无反应。
②③+点选背景图同根（都缺 `getComputedStyle`），补的话约 20 行（`tryCss` 加一个 `bg` 分支 + pick 认背景元素）。

**改·抽取层三处（`docs/FIX-EXTRACT-LAZY-2026-10-22.md`）**：
① `tryCss` 的 `attr` 支持 `|` 回退链（`src|data-src|data-original`），新候选默认就带 —— 根因是
`lazyloaded` 类只在懒加载完成后才加，隐藏窗 1000×720 不滚动 ⇒ 首屏外的图永不加载 ⇒ `.x.lazyloaded` 落空；
② 封面值加 `looksUrl` 校验（挡 `attr:'style'` 返回的整串 CSS，它会算命中并堵死后续候选；`data:` 放行）；
③ 试跑面板接上 `imgCount`/`sampleSrcs`（后端早就算了，前端没显示）+ 被拦红字改成「打开页面看看 → 就地过验证」
（原指向补封面面板，但那里的验证按钮只会在抓完被拦后出现，照做扑空）。
验证：typecheck 0；脚本是字符串 TS 查不到语法，用 esbuild bundle 后跑 3 例（回退链/整串CSS被挡/只剩style返空）全 PASS，脚本未入库。
⚠️ 教训：在 `buildExtractScript` 的模板字符串里写 markdown 反引号会提前闭合字符串（本次踩到，TS 报的是后面几百行的语法错）。

**追加·抽不到的真根因 = 抓取窗从不滚动**（用户问"过掉验证为什么还是取不到 / 用什么技术"）：
技术栈 = **Electron BrowserWindow 真 Chromium 渲染 + 页面内 `querySelector`/`getAttribute` + `executeJavaScript` 取回**，
无 puppeteer/cheerio；`kind:'regex'` 是唯一文本解析分支（在 `documentElement.outerHTML` 上跑）。
⇒ 三个必记差异：①人眼定位 vs `querySelector` 只取**文档里第一个**匹配；②F12 里页面**滚过**，隐藏窗 1000×720
**从不滚** ⇒ 懒加载不执行；③F12 看到的是**加载后最终态**，我们抽的是当下态。
修法：`siteFetch.ts` 加 `LAZY_SCROLL_SCRIPT` + `lazyNudge(win, tries)` —— **只在抽不到时**第 3 轮滚到底、
第 4 轮滚回顶（靠轮询分两拍，否则 IO 回调还没跑就离开）；`runExtract` 与 `runSteps` **两条通道都接**。
`tryCss` 另补 `srcset` 解析（与 `rawSrc` 同一套）。校验：typecheck 0 + 4 例全 PASS（回退链/srcset/整串CSS被挡/相对路径补全）。
