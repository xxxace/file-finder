## 核查：视频预览图能否滚轮缩放（认知型提问，未改代码）

**结论：naive-ui 2.45.3（= npm latest，本地即最新）不支持滚轮缩放；且视频预览连自带「放大」按钮也是死的。**

证据链（均落 `node_modules/naive-ui/es/image/src/ImagePreview.mjs`）：
1. 预览容器绑 `onWheel: this.handleWheel`（:502），而 `handleWheel` 只有 `event.preventDefault()`，不改 `scale`（:387-389）。→ 静态证据。
2. `zoomIn()` 有守卫 `if (scale < maxScale)`（:279-286）；`getMaxScale()` = `max(1, naturalHeight/(innerHeight-40), naturalWidth/(innerWidth-40))`（:252-263），下界恒为 1。
   → 480px 宽的抽帧 / 1880px 视口 ≈ 0.26 → maxScale = 1，初始 scale = 1 → `1 < 1` 假 → 点不动。
   → 双击同理（:218-222，scale 与 originalImageSizeScale 都是 1，交换后不变）。
   → 只有图片走 `/raw` 原图（大于视口）时 maxScale > 1，放大会有反应。**推理（算术推演），未真机实测。**
3. 像素预算：`THUMB_WIDTH = 480`（`electron/utils/thumbnail.ts:24`）；抽帧时 ffmpeg 出的是 `scale='min(960,iw)':-2` 的 PNG（:310），随后被 `scaleToThumb` 压到 480（:32）→ **上游有 960 的料，存盘时丢了**。

**方向判断（待用户裁决，未动手）**：滚轮手势与分辨率是两件独立的事。
- 滚轮 = 只能自研一层预览（库无钩子，无新版可升）→ 违背奥卡姆。
- 提高预览图分辨率 = 只改本地缓存写入，不多读一次移动硬盘，且**官方现成的放大 + 拖动会立刻全活**（maxScale > 1）。
- 建议优先后半件；若做，考虑「点开预览时才按需生成大图」，避免缓存膨胀。

**提问类型**：认知型（「是否可以支持」）→ 只讲机制，结尾不加催办。

## 落地：预览图"打开就撑满视口"（用户诉求：不用手动点放大）

**改动（2 处，纯渲染层，HMR 自动生效）** `src/views/FileFinder/index.vue`：
1. 主列表的 `n-image` 加 `:previewed-img-props="previewedImgProps"`
2. 新增常量 `previewedImgProps = { style: { width:'100%', height:'100%', objectFit:'contain' as const } }`

**为什么是这个入口**：预览 img 的脚手架样式只有 `max-width/height: calc(100vw|100vh - 32px)`、**没有 width/height**
（`naive-ui/es/image/src/styles/index.cssr.mjs` 的 `.n-image-preview`）→ 按自然尺寸显示。
用库公开的 `previewed-img-props`（透传到预览 img）补 100%×100%+contain；库自带 max-* 把盒子钳到
`(100vw-32)×(100vh-32)`，边距与工具条位置**原样保留**（不是我们设的魔法数）。
`objectFit` 必须写 `as const`，否则 vue-tsc 报 `string` 不匹配 `ObjectFit`。

**实测（新探针 `docs/probes/preview-fill/`，真 Electron offscreen 跑真实 Chromium，视口 1903×1063）**：
- 480×270 抽帧（视频）：显示 480×270 → **1833×1031**（撑满，≈3.8 倍插值）——**收益全在这一档**
- 3000×2000 原图（图片走 /raw）：显示 1546.5×1031 → **1546.5×1031**（**视觉零变化**）
  即：图片那档本来就被 max-* 钳到贴边，改动只对"比视口小的图"起作用
- 命中测试：最外圈 16px 仍是 overlay（x=8）、x=40 是 img → **"点空白关闭"仍在，可点区缩到一圈**
- 关闭三路仍在：✕ 常显 / 最外圈空白 / Esc（`ImagePreview.mjs:97`）
- `vue-tsc --noEmit` 通过

**代价（已在代码注释里如实写明）**：3.8 倍插值会糊；要真清晰得让抽帧存更大的图 =
重算缓存 + 重读移动硬盘 → **不做**（第一目标少碰盘）。

### ⚠️ 无头验证 Electron 渲染层的三个坑（下次直接用，别重踩）
1. 本机 shell 注入了 `ELECTRON_RUN_AS_NODE=1` → 直接跑 electron 被当 node（`require('electron')` 拿不到 app）。
   必须 `env -u ELECTRON_RUN_AS_NODE`，**设空字符串无效**。
2. 项目 dev 实例占着默认 userData 的 GPUPersistentCache → GPU 崩 + `ERR_FAILED`。
   探针要独立 `userData`（用 `$TMP/probe-preview-fill`）+ 禁 GPU。
3. **`show:false` 窗口量不准**：不参与合成 → rAF 不推进 → Vue `<Transition>` 的 `enter-from`（scale **0.9**）
   永不移除，盒子整整小 10%（1855×966 量成 1670×870）。`--disable-renderer-backgrounding` /
   `backgroundThrottling:false` **都治不住，必须 `webPreferences.offscreen = true`**。
   两个错误方向（都试过）：等 `getAnimations()` 结束、注入 `transition:none` —— 后者只会让 class 更赖着不走。
