## vite.config.ts 类型报错（配置层，已修）

   **刻意没做 `content-visibility`**：卡片高度是窗口宽度的函数，`contain-intrinsic-size` 估错会让滚动条跳，
   而 `probeLayout` 读的是每张卡的 `offsetTop`。
2. **不做条数上限/熔断**：6 万/10 万不是现役场景。
3. **`usePinYin` 加缓存**（按输入串，上限 2048 满则整表丢）。实测 60k 条：冷 12.6ms → 热 5.8ms；
   ⚠️ 如实：剩余成本主要是 `toUpperCase()+includes()`，不是拼音。
4. **顺序不排序**（业主核实）：按每个目录自身的原序原地展开（in-place DFS），谁在盘上排第几就排第几。
   ⇒ `mergeSubtreeLeafItems` 注释里"按 name 自然序升序"是**文档说谎**，已改正（代码本来就对）。
`docs/RISK-FLAT-PERF-2026-11-10.md` §4 有收口表。

### 平铺"一开就请求 500 张图"的根因（业主 DevTools 数出来的）
**不是 `<img loading="lazy">` 失效，是模糊底**：`coverBackdrop(item)` 把 `--cover-src: url(...)`
写进**每一张** `.card-cover` 的内联样式，CSS `::before` 拿它当 `background-image` ——
**背景图没有 lazy**，样式一解析就发请求 ⇒ 500 条全打。
⇒ 改成 `@load="onCoverLoad"`：图片自己下载完才 `style.setProperty('--cover-src', ...)`（同一字节已在 HTTP 缓存，
零额外请求）；目录的脸走 `n-image` 的 `img-props.onLoad`。走 DOM 直写、不走响应式。
⚠️ 这条**优化前就存在**，只是过去一屏几十张看不出来。教训：**给元素加 lazy 之前，先确认同一个 URL
没有被别的属性/样式（background-image / srcset / preload）提前拉一遍**。
