### 追加：「取消选择文件夹」不该清空已打开内容（用户质疑，已改）

用户问：「选中文件夹、点取消（也就是没选）会清空当前已打开的内容，是否合理？」
⇒ **不合理，已改**。完整分析在 `DESIGN-HEADER` §18.10。

**铁证**：`electron/main/index.ts` 的注释原文写着「取消时仍然发 `undefined`
（渲染层靠 `value ? value[0] : ''` 清空输入框），语义与原来逐字一致」。
当年说的是"**清空输入框**"；后来演进成 `setRoot('')` ⇒ **连 `history`（当年不存在）一起清掉**。
⇒ **典型语义漂移：后果被放大，而注释没跟着更新 —— 注释开始撒谎就是这类 bug 的信号。**（那句注释已改）

**链路**：取消 → `undefined` → `setValue('')` → `setRoot('')` → 清掉 dir + history + dataSource + 搜索词。
**三条理由**：① 取消 = "算了，不改" ② 代价大且**不可逆**（丢当前视图 + 整个导航历史，无确认无撤销）

`if (!value || !value.length) { isFocus.value = false; return; }` ⇒ 取消什么都不做。
**静态验证**：`setValue('')` 现在只剩 `onClear`（×）一个调用点 ⇒ `setRoot('')` 只能由 × 到达。

| 681 | 「共 N 项」**12×96（竖排成一列字）**、分页器 495（被压）、总览按钮偏移 +13 | **52×22**、536、+3 |
| 761 | 「共 N 项」**12×96**、495 | 52×22、536 |
| 821+ | 52×22、536 | 52×22、536（两者一致） |

⇒ **坏区间 = 窗口 ≤ 约 800px**；修复后全区间正常 ✓（复现与修复都有实测）。

### 根因：三处都是同一类 —— **flex 子项被挤压**
| 症状 | 根因 | 修法 |
|---|---|---|
| 「共 N 项」竖排 | 分页器内部 `flex-wrap: nowrap`，一被挤就把前缀压到内容最小宽（≈12px）⇒ 一个字一行 | 分页器 `flex: 0 0 auto`（装不下整块换行）+ 自己改 `flex-wrap: wrap` + 前缀 `nowrap; flex:0 0 auto` |
| 总览与按钮互挤 | 总览行 `space-between` 且**不换行** ⇒ 文本换行后按钮悬在第二行最右 | 行 `flex-wrap: wrap` + `align-items: baseline`；文本 `flex: 1 1 320px`；按钮 `flex: 0 0 auto` |
| 底部批量区与分页器互挤 | 底部行不换行 | 行与批量区都 `flex-wrap: wrap` |

### ⚠️ 撤了一处自己的改动：`:scroll-x="720"`（别再顺手加）
我加它的理由是"最后一列被裁"。**量出来理由不成立**：
目录列实际宽只 **240 → 258**（差 18px），而**可横向滚动的容器数改前改后都是 2** —— 表格本来就能横向滚。
⇒ 已从组件撤回（不为改而改），探针里也同步去掉（否则量的是别的东西）。

### ⚠️ 探针自身的坑：判据要能区分「被裁」和「可滚动」
判断"有没有横向滚动"**不能只看 `scrollWidth > clientWidth`** —— 被父级裁掉的内容 scrollWidth 照样更大。
第一版就这么写，结果"改前"也被判成"可横向滚动"，证据不能用。
**正确判据**：computed `overflow-x` ∈ {auto, scroll} **且** 内容更宽。

### 仍未解决（设计取舍，等用户定）
小窗口下看「上次扫描」需要横向滚。要它不滚就可见，只能动列的固定宽（或小窗口下合并列）——
那是拿信息密度换可见性，**不是 bug**，本轮没动。

## 追加：总览独占一行（用户提的，判断比预想的更准）

用户看完小窗口修复后提：「下拉框和打开文件夹放同一行这样子，汇总信息文本就不会换行了」。

**同一个探针改成验"按钮放在哪一行"**（两个变体共用同一个按钮实例）：

| 窗口 | 按钮在总览行（改前） | 按钮挪到下拉行（改后） |
|---|---|---|
| 681 / 761 | 总览文本高 **40（折两行）** | **20（一行）** |
| **901** | **也是 40（折两行）** | **20（一行）** |

⇒ **改前在 901px 的宽窗口下也在折行** —— 不只是小窗口的问题。
总览是面板里最长的一句，**和任何东西挤一行就会被压到折行**；给它整行就彻底不折。
修法：`.g2-row` 退回成只放总览的普通块；按钮挪进 `.g2-disk`（和盘筛选同行），`margin-left:auto` 靠右
（这样这一行自己换行时按钮仍靠右，且不会回头挤总览）。

**教训**：**"换行"的根因常常不是容器太窄，而是"它得和一个不许缩的东西抢同一行"**。
以后遇到某句长文本莫名折行 → 先看它同行有没有"不许缩"的邻居，而不是先去调文本本身。
