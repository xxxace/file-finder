### 五个判断（用户 5 个问题）
1. 一次性返回全部 + base64 —— **不合理，是万恶之源**。把图片当数据传，丧失并发/缓存/渐进解码，还付 37% 膨胀。
2. 懒加载 —— **形式上写了（`index.vue:47,48` 有 `:lazy="true"`），实质是假懒加载**。base64 已在内存，lazy 只推迟解码。且 `v-for` 全量渲染无虚拟滚动。
3. BUG —— 已列 24 项，P0 五项：URL 未 encode、`item.files![0]` 崩溃、单个文件出错整目录返回空、`postAction` 不检查 code 导致「失败提示成功」、`app.listen` 无 error 处理。
4. 见上，卷序列号。
5. 「服务接口乱」—— 根因是**HTTP 这一层本就不该存在**（同机同进程组，该走 IPC）。次因：地址硬编码 5 处、返回值形状 4 种、错误只在 body 的 `code` 里。

### 用户的三点质疑与我的修正（**重要，别再犯**）
1. **「为什么要砍 HTTP 走 IPC？前后端分离不是更简单？」** → 用户说得对，**我收回**。理由成立：性能瓶颈不在通信层（payload 降到 10KB 后 HTTP 开销无关紧要）；DevTools Network 可逐条看请求是真实价值。**教训：我推 IPC 是过度设计。** 改为保留 HTTP，只修安全面 / 端口崩溃 / URL 编码 + 收敛统一响应体。
2. **「我为了隐私不存明文图片文件」** → 必须尊重。同时要告知他一个事实：**base64 不是加密**，记事本能直接看到 `data:image/jpeg;base64,...`，所以现在的设计**没有技术上的隐私保护**，只提供「不容易被一眼看到」。→ 推荐方案改为**零新增文件**：不落盘、不进 DB，主进程内存 LRU 持有缩放后的 JPEG；独立 `GET /cover?path=...` 接口返回 JPEG 二进制。
3. **「缩略了会影响画质吗？」** → 不影响，反而现在才是浪费。实测 CSS：`--item-width: calc(100%/6)`，1200px 窗口下每格约 180×144 px。800px 封面缩到 480px 仍是显示区 2.7 倍（1920px 窗口 1.5 倍），超过 2 倍 HiDPI 经验值。缩放用 Electron 内置 `nativeImage`（`createFromPath().resize().toJPEG(82)`），**零新依赖**。

### 第二次自我纠错（用户纠正我）—— file-docker 机制

**我错在**：拿 `D:/file-docker` 是空目录就断言「视频封面功能从未生效」。真相：**file-docker 是按「资源所在盘」创建的**，封面在 `H:/file-docker`，而 H 盘当时未挂载 —— **取样错误**。

**用户的 file-docker 设计意图（他自己说明的）**：封面属于哪个盘就在哪个盘建 `file-docker`，所以**他有意允许明文存储**，因为它等价于「跟盘走的缓存」。他自知「这样子一样会泄露」，不确定设计好不好，在向我求证。

**我的结论（已写进报告第四节）**：
- **他的方向是对的，我提议「改成不落盘」是错的**——那会丢掉「缓存跟盘走」这个 DB 放 C 盘做不到的核心收益。
- 第一性原理：**封面是派生物，原文件就明文躺在同一块盘同一目录**。看到封面的人本来就能看到原文件 → **同盘场景下不构成额外泄露**。真正有风险的只有：把封面聚合到某处/上传云端、或只把 file-docker 拷走。
- 真实缺口是「没做完整」而非「泄露」：①图片封面走 base64 进 C 盘 DB（**两套策略并存**，DB 因此 103MB）②视频封面尺寸失控 ③命名用剥扩展名的 `name` 会互相覆盖（P1-8）。
- **正确方向：把图片也纳入 file-docker，统一生成 480px JPEG，而不是替换这个机制。**

### 怎么在沙箱里把 E2E 跑起来的（方法值得复用）

1. **Electron 起不来**：沙箱无可用的 GPU/显示 → `app.ready` 永不触发、Node timer 不被 pump、进程 5s 自退（exit 3），日志 `GPU exited unexpectedly: exit_code=-2147483645`。`--disable-gpu` 能救生命周期，但一碰 `nativeImage` 又卡。**结论：这是环境限制，与服务端逻辑无关。**
   → 解法：写 `_electron_stub.cjs` 替身（`nativeImage.createFromPath` 对不存在的文件返回空图、文件名含 small 返回 300px、`toJPEG` 输出带 `STUB;src=;out=` 标记的假 JPEG 并把缩放目标写进 `_trace.txt`），用 esbuild `--external:electron` 打包后 `sed` 换成替身，纯 Node 跑。
2. **只有一块物理硬盘**（本轮最有价值的手法）：在 `require` 服务端**之前**截住 `fs/promises.stat`，把「盘根」路径（`D:/`）的 `dev` 换成可控值 → 同一块盘上模拟出任意多个「盘身份」。**用户点名的那条需求因此能被真正验证，而不是靠推演。**
   - 关键细节：esbuild 的 `__toESM` 用 getter 复制命名空间，所以补丁前后挂上都能生效。

### E2E 先复现出真 BUG，再证明修复

**`findDriveByLetter()` 直接信内存盘列表** → 盘符被复用（A 盘 H: 拔出、B 盘插进同一个 H:）时会**拿旧序列号去查缓存，插上 B 却看到 A 的封面清单** —— 正是用户担心的「双方数据冲突」。实验输出：

```
FAKE=A → AAAA- size=1234    FAKE=B → BBBB- size=4321    FAKE=A → BBBB- size=4321  ❌
```
修法：解析盘符时用**一次 stat** 复核这个盘符现在是谁，主人换了就整表作废重扫。修完：
```
FAKE=A → AAAA- size=2234    FAKE=B → BBBB- size=5321    FAKE=A → AAAA- size=2234  ✅
数据文件里该盘内路径 2 条并列记录（AAAA1111 / BBBB2222），各自 key 指向自己那块盘的图
```
**这组实验刻意不调 `/getDisks`** —— 内存盘列表始终是上一轮的映射，服务端必须自己发现「盘符换主人了」。

### 顺带修掉的第二个真 BUG

网格 `v-for` 用 `:key="item.name"`，而 cover 模式下条目名取的是**封面图文件名**（沿用原行为），所以同层两个文件夹若都叫 `cover.jpg` → 两个 `key="cover"` → Vue 复用错组件实例 → **封面串格**。改成 `item.dir + '/' + item.name`。

### 旧库回收结果（用户问的「会不会失效」）

真实旧库 103MB / 107 条旧格式记录：**回收后 72 B，耗时 7.5s，自动备份一份，遗留 0 条。**

**nedb 数据文件的两种元数据行（不然后面会误判成脏数据）**：
- `{"$$indexCreated":{...}}` —— `ensureIndex` 的索引声明，**compact 会重新写进去**（压缩后那个 72B 文件装的就是它）
- `{"$$deleted":true,...}` —— `remove` 往尾部追加的删除标记

合起来解释「append-only 为什么只涨不缩」：**删一条不是抹掉，是再追加一行**。所以覆盖写必须 `removeCache → insertCache` + `compact()` 兜底。

### 管线实测

冷扫 9ms / 热读 1–2ms / 响应体 **1595 B**（重构前 674KB 级）/ 响应体里 `data:image` **0 次** / 缩放 800→480、300 保持 300 / 存储态所有 `item.dir` **不含盘符** / `noCache` 重扫不堆积。

### 三个必须记住的教训

1. **`cmd | tail -5` 会掩盖失败**：管道退出码取自 `tail`，我因此拿着**未重新生成的旧产物**跑了一轮测试并白排查了一阵。真实原因是 esbuild 报 `Could not resolve "./lib-cov/fluent-ffmpeg"`（fluent-ffmpeg 里的可选 require），加 `--external:fluent-ffmpeg` 解决。**凡靠退出码判断成败，不要接管道。**

### 关键设计决定

- **P0 先装类型门禁，且必须单独一个 `tsconfig.electron.json`** —— 主进程是 Node/CJS、渲染层是 DOM，塞进同一个 `include` 会被迫共用 `lib`、两边报假错，那就成了「为了装门禁而改代码」。
- **`fileList` 改 `computed`，而不是给调用方加 `await`。** 竞态的根因是「有个地方会异步写 `fileList`」；用 `await` 摆对顺序只是让这一个调用点暂时正确，下一个人再加写入口就复发。改 `computed` 后 `fileList` **没有任何写入口**，bug 在结构上无法存在 —— 同时删掉 `handleFilter` 与它的 5 个调用点。**代码更少，不是更多。**
- **「结构性不可能发生」>「加了道工序让它不发生」** —— 这条写进规划当判据了。
- **`fetchFolder` 不再顺手清 `searchText`** —— 取数的函数不该同时改搜索框（隐藏耦合）；清空/恢复交给导航动作，于是 `onRefresh` 的存/取搜索词也一起消失。
- **`readFolder(…, storeDir)` 必填参数** —— `item.dir` 的存储形态由调用方声明，不再靠 `relOf()` 这层字符串操作隐式决定；编译器强制两个调用点表态。
- **`contextBridge` 桥接必须逐字转发 `value`**（`(_e, value) => cb(value)`），**不能** `(...args) => cb(...args)` —— 后者把数组摊平成多参数，`:59` 的 `value[0]` 会取到第一个**字符**，`H:/x` 变成 `H`，且是静默的。

**③ 更根本**：`openHistory` 按**缓存记录的 mode** 分叉 —— mode 是记录属性，不该决定导航形状。

**"能改"≠"改得对"**：文件没锁 → 操作会成功 → 恰恰因此更危险（用户以为成了）。

## 19:45 用户点头：「至少让我只读也可以啊」→ 做了「离线盘只读浏览」

### 方案（一句话）：只读锚点 `#<serial>/<relPath>` 代替盘符寻址
- 为什么不记住"上次盘符"：盘符不是身份（`driveIdentity.ts` 开头就在讲这个），给离线盘编
  一个 `H:/…` 是**编造身份**；另一块盘插到 H: 时那个地址就指向别人。
- 为什么不加一组接口参数：导航栈/面包屑/下钻/返回**只流动一个字符串**
  （`item.dir + '/' + name`）。让锚点长得像路径 → **导航那一整块一行都不用改**，
  也不会出现两套并行导航。`#` 在 Windows 路径里永远不合法。
- 只读是**结构性**的：锚点这一支只 `findCache` —— 不 readdir、不 `scanAndCache`、不写库、
  忽略 `noCache`；`/raw` 天生拒绝锚点 → **锚点没有任何读到磁盘文件的通道**。

## 20:00–20:20 · 根因：两个「重读这一片」+「取消」点了没用（`n-space` 重复 key）

用户线索（关键）：「为什么会出现两个重读这一片，**是因为我点了补全这一片**，而且取消按钮也没用，
设计和交互多和 pc 的文件管理器学习，你现在的设计我感觉一般有点乱和随便！」

### 根因（推翻白天那个「旧代码渲染」的判断）
- `naive-ui 2.45.3` 的 `Space` **给每个子项硬编码同一个 key**（`createElementBlock("div", { key: 1, … })`，
  `es/lib` 两份产物都有）。最新版就是 2.45.3，没有可升版本。
- `normalizeVNode(() => array)` → `patchFlag=-2` Fragment → Vue 走 `patchKeysChildren`（全量 keyed diff）
  → 两个新 div 的 key 都是 1，后写顶掉前写 → 两个旧节点认领**同一个新槽位** → 残留。
  **每切一次 `scanning` 多留一个节点。** Vue 自己喊 `Duplicate keys found during update: 1  at <Space>`。
- 我们的触发条件：工具条上扫描中把两个入口「就地换成」进度+取消 → `n-space` 子元素个数随状态变。

### 验尸
全新实例只切一次 → `["取消","补全这一片","重读这一片","重读这一片"]`（**与用户截图逐字一致**）。
扫描中「取消」按钮 3 个；30 轮后 30 个。→ "取消没用" = 残留节点还在屏上 + 点击到生效之间零反馈。

### 修法（不是补丁）
3 处**会增减子元素**的容器不再用 `n-space`，换裸 flex `.hstack`（`gap:12px`，与 n-space 默认一致）：
头部左组（面包屑 v-for + 返回 v-if）、头部右组、封面文件 popover（v-for）。
`FolderSelector`/`HistoryTable` 那两处子元素**恒定**，**没动**。
交互（PC 文件管理器）：扫描入口**常驻、忙碌只置灰**；进度+取消挪到网格下方**独立状态条**；
工具条子元素恒定；取消加 `cancelling` → 按钮当场变「正在取消…」+ 置灰 + 一句
「当前这个目录扫完就停」（软取消是刻意保留的特性）。
