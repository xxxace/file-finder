## 补封面：按当前文件夹隔离 + 全选/反选
- **根因（静态，可复算）**：`AssistantCoverModal.vue` 的 `runScan`/`deepRescan` 硬编码
  `relPath: ''` ⇒ 永远整盘。`resolveDriveContext` 早已返回 `relPath`，但 `setShowModal`
  只取 `serial`。后端 `/assistant/scan|rebuild` 本来就收 `relPath`，`scan.ts` 的 `inScope`
  带分隔符边界（`TEMP` 吃不掉 `TEMP2`）⇒ **纯前端接线，后端零改动**。
- **判据（重要，别退化）**：`scope` 是"最后一次成功扫描用的范围"，**只在 `runScan` 成功后
  与 `scan` 同拍提交**（失败两者都停旧值）。分两拍写 ⇒ "标着 TEMP、清单却是整个盘"
  （与 11-10 换屏过滤失效同一形态）。
- **换盘必须清 scope + openScope**：路径属于某块盘，留着会让新盘扫出 0 条 = "这盘封面都齐了"的静默假象。
- **空态必须三段**：`scope 非空 && scannedDocs===0` ⇒ 「这个文件夹还没有缓存记录」（**空 ≠ 齐了**）；
  `scope 非空 && skippedCategory>0` ⇒ 「这里只有分类目录」；否则原文案 + 「扫描整个盘」出口按钮。
- 交互：范围 chip 放 **meta 行**（不动 tools 子元素个数），两态 toggle 不做下拉；`⇄` 只在
  有两态时出现（避免扫描中闪动）。全选/反选复用 `.ffw-meta-link`，按**卡**粒度（分卷不拆）。
- ⚠️ 踩点：给 `runScan` 加可选参数后，模板 `@click="runScan"` 会把 MouseEvent 当 scope 传进去
  ⇒ 全部改成 `runScan()`。
- 未做（等他用完一轮再定）：整盘模式下的「按一级目录分组 + 组头三态」（范围收窄后组数=1 会自隐）。
- 未实测：真机目视（范围 chip、空态三分支、反选计数）。dev 只改渲染层，HMR 即生效。

## 抓取性能重构 + loading 精确化（跨零点，记为 11-14 的工作）
- **老路为什么卡（根因，静态）**：`siteFetch.runExtract` 每条都 new BrowserWindow，
  且 `await win.loadURL()` = 等 `load` 事件 ⇒ 等全站图片/广告到齐；5 并发 = 5 个渲染进程
  同时解码图片跑广告。**卡的根源是单窗成本，不是并发数**。11-13 把 5 降到 2 只是掩盖。
- **改法（四道）**：① 只等 `dom-ready`（三路竞速：domReady / navSettled / 25s 兜底，
  少了 navSettled 会在导航失败时白等 25s）；② 窗口内拦 `image/font/media/ping/cspReport`
  —— 抽取脚本只读 `getAttribute('src'|'data-src'|'data-original'|'srcset')`（rules.ts rawSrc），
  不读渲染结果，所以安全；③ `GRAB_PARALLEL` 2→3；④ `HOST_GAP_MS` 1500→1200（主人裁决）。
- ⚠️ **`MAX_ACTIVE_PER_HOST` 必须 ≥ worker 数**（现 3），否则第 3 个 worker 只是换个地方排队。
- ⚠️ `session.webRequest.onBeforeRequest` **整个 session 只有一个监听器**（后装覆盖先装），
  所有抓取窗共用 `persist:assistant` ⇒ 只能装一次 + `webContentsId` 白名单；人工验证窗不登记（要完整页面）。
- **loading 只认在飞**：`Job.inflight: string[]`（grab 用 push/splice 支持并发，frame 串行用整体赋值），
  `snapshotJob` 下发，前端 `inflightRels` 合并两个 job。删掉旧的"选中且没结果就算 pending"推断
  —— 那会把几十张排队的卡一起点亮。`buildCoverItems` 因此**不再收 `selected`**。
- 批量抽帧不再 `markBusy` 整批（只有单卡「换一帧」才乐观标记）；`finishJob`/`reopenJob` 清 inflight。
- **badCover 每站重置**（`blocked` 不重置，它是累积信号）：否则"第一站图坏 + 第二站没图"报成"封面取不到"。
- `POLL_MS` 1200→800（吞吐提到 ~0.8/s 后 1.2s 轮询明显滞后）。
- ⚠️ 未实测：`image` 拦截对"依赖 onerror 改 src"的懒加载库有风险（rawSrc 有 data-src 兜底）；
  回滚 = 从 `SKIP_RESOURCE_TYPES` 里删掉 `image`。
- 待商量（未动）：`scan.ts` 的 `MAX_DOCS=3000` 在整盘模式会静默截断清单。

## 封面卡状态语汇（2026-11-14 凌晨）
- **诊断**：状态不是缺，是"等待"和"没扫过"长得一样（都是 idle）、失败原因 `message` 有数据但没出口
  （卡面只放得下两个字）。所以补的是**区分度**和**详情出口**，不是新状态机。
- **卡面**：badge 只染**字**不换材质（底仍是实心面板胶囊）——`data-tone` 四档
  `ok/warn/err/mute`，对应 `--ff-status-*` 与 `--ff-text-2`。排队 = mute（最弱，灰）；
  已写入 = ok；未找到/被拦/认不出 = warn；失败 = err + 卡片描边染色（本来就有）。
- **悬停**：走全站唯一的 `v-tip` 富内容（`body: () => h(...)` + `.ffw-ctip` 网格），
  **不新增 tooltip 机制**。内容 = 番号 / 类型 / 站点 / 原因 / 目标。
  ⚠️ 无 note 且无 site 时返回空串（空壳提示比没有更糟）；⚠️ 浮层 Teleport 到 body ⇒
  `.ffw-ctip` 必须放**全局** css（workspace.css 不是 scoped，正好）。
- **数据**：`GrabRowLike.message` / `ApplyRowLike.message` 之前前端类型里根本没有 ⇒ 补上；
  `CoverItem` 加 `note` / `site`。
- **排队只打给选中的卡**（`opts.selected`）——没选中的不在队列里，说"排队"是假话。
  ⚠️ `selected` 仍**不许**用来推 `pending`（那是 inflight 的职责）。
- 底栏 grab detail 末尾加 `· 排队 N`（前端算：`total - processed - inflight`，未加后端字段）。
