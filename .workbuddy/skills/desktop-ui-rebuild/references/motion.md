# 动效 · 六个机制与场景决策

先数**这个界面真正发生了几件事**，一件事最多配一个动效。通常 6 处以内就够。

## 一、六个可迁移机制（按贡献排序）

### 机制 1 · 同节点形变（贡献最大，不是曲线问题）

同一处状态变化（空闲 → 运行 → 完成）**用同一个 DOM 节点改内容与尺寸**，
不要拆成两个节点交叉淡入。

- 反例：底栏「开始」淡出 + 「暂停」淡入 = 两块东西在打架
- 正例：底栏还是那条底栏，只是文字换了、按钮换了，高度不变

**判据**：如果两个状态的"位置"是同一个，就必须是同一个节点。

### 机制 2 · 非对称进出（最便宜的 20%）

进场慢（200ms，可带轻微过冲）、退场快（90ms，不反弹）。

> ⚠️ 用户已经决定走了，让他在原地等动画是最没礼貌的事。

同一个曲线用在进出两个方向 = 退场显得黏，这是自制动效最常见的缺陷。**必须两条曲线。**

### 机制 3 · 速度驱动形变

拖动/长按时，按**速度**做拉伸或倾斜，速度归零即回正。
只在"手指/鼠标正按着"的场景用；松手之后不要继续抖。

### 机制 4 · 延迟阶梯（编排，不是装饰）

列表逐项入场，**18~24ms / 项，必须封顶**（建议 14 项）。
不封顶的后果：500 张卡片按 `i × 18ms` 会拖到 9 秒，最后几张像卡死。

用 `animation-delay` 配 `both` 时，延迟期间元素是**不可见**的 —— 所以封顶值要覆盖一屏。

### 机制 5 · 模糊做转场遮罩

大范围内容替换时：先让内容失焦（`blur 7~8px` + 压暗）→ 完成替换 → 再清晰。
比"直接换"温和，比"交叉淡入"轻。

⚠️ 两个坑：`filter: blur()` 会让整层重新栅格化（大面积会掉帧）；
祖先有 `filter` 时，子元素的 `transform` 合成会出错。

### 机制 6 · 弹簧积分器（只在需要"可打断"时才上）

只有"用户能在动画中途改变主意"的场景才值得上物理弹簧，其余一律用曲线。
上之前先问：这个动画**能不能被第二次点击打断**？不能就别上。

## 二、场景决策表

| 场景 | 用哪招 | 时长 |
|---|---|---|
| 按钮 hover | 只变色（机制 2 的反面：**不许位移**） | 160ms |
| 按钮按下 | 底色再深一档 | 120ms |
| 列表/卡片首次出现 | 机制 4 延迟阶梯 + 位移 8px | 200ms，24ms/项 |
| 同一处状态切换（空闲↔运行↔完成） | 机制 1 同节点形变 | 200ms |
| 内容整体替换（换页/换数据集） | 机制 5 模糊过场 + 交叉位移 | 300ms + 450ms 失焦 |
| 弹层/面板进入 | 位移 8px + 淡入 | 300ms |
| 弹层退出 | 只淡出 | 90ms |
| 进度条推进 | **线性，禁用缓动** | 与真实进度同步 |
| 完成的正反馈 | 一次性光雾/扫过，**只此一瞬** | ≤ 1.4s |
| 宽度/高度生长（如搜索框展开） | **专用尺寸曲线**，见下 | 200ms |

## 三、参数（照抄，改一处要能说清为什么）

```css
/* 时长阶梯：按元素尺寸分档，不按组件分档 */
--dur-tap:   120ms;   /* 按压、图标态 */
--dur-hover: 160ms;   /* 悬停变色 */
--dur-move:  200ms;   /* 一拍：位置迁移 / 重排 / 高度收放 */

/* 退场与淡入是从"一拍"派生的比例，不是独立旋钮 */
--dur-exit:         calc(var(--dur-move) * 0.45);   /* 90ms */
--fade-in:          calc(var(--dur-move) * 0.5);    /* 100ms：后 50% 显形 */
--fade-in-delay:    calc(var(--dur-move) * 0.25);   /* 前 25% 只落位不显形 */

/* 三条曲线，各有分工 */
--ease-enter: cubic-bezier(0.34, 1.28, 0.42, 1);  /* 进入，轻微过冲 */
--ease-exit:  cubic-bezier(0.32, 0.72, 0, 1);     /* 退出，收紧不反弹 */
--ease-move:  cubic-bezier(0.19, 1, 0.22, 1);     /* 位移（expo-out） */

/* ⚠️ 尺寸变化必须另用一条：expo-out 的初始斜率 = 1/0.19 = 5.26，
   给 60px 位移是"利落"，给 192px 的宽度生长就是"啪一下弹开"
   （算过：前 1/3 拍走完 92%，峰值速度是前者的 4.3 倍）。 */
--ease-size:  cubic-bezier(0.25, 0.46, 0.45, 0.94); /* easeOutQuad，斜率 1.84 */
```

**过冲量**：样本值 1.35，生产力工具建议 1.28。密集网格里过冲太大会晃眼。
要更 Q 就单点改这一行，别到处加。

## 四、禁用清单

- ❌ `transition: all`
- ❌ 动画 `width / height / top / left / margin`（除非用 FLIP 量过）
- ❌ `scale(0)` 出现（用 `opacity + translateY(8px)`，或最低 `scale(.96)`）
- ❌ hover 加位移/抬升
- ❌ 永久 `will-change`
- ❌ 键盘触发进入动画（键盘操作要"立刻到位"）
- ❌ 进度条用缓动（缓动会骗人，前快后慢像卡住）
- ❌ 无限循环的装饰性呼吸（除了"正在处理"的加载态）
- ❌ 少 `prefers-reduced-motion` 分支

## 五、两个最容易误判的点

1. **"动效看起来变形了"，先怀疑布局在动。**
   常见链条：某条状态栏挂上 → 用 `grid-template-rows: 1fr→0fr` 从 0 长到 40px
   → 这 40px 是**从内容区扣的** → 里面的遮罩/canvas 被自下而上压扁，
   同时状态栏自己向下展开 = 观感"先上后下"。改缓动曲线是白改。

2. **canvas 是 `width:100%; height:100%` 时，容器一变高矮位图会被压扁**，
   不是重新布局。必须上 `ResizeObserver` 重设 `canvas.width/height`。
   并且绘制要用 `clientWidth/clientHeight`，不是 `canvas.width`（后者是设备像素，
   在 `setTransform(dpr)` 之后再用会多乘一个 dpr）。
