# 设计语言 · 从产品里量出来的规则

来源：对 WorkBuddy 侧栏截图做几何 + 取色测量（原图 446×1230，按字号反推缩放 1.32，
全部换算成逻辑 px；文字取笔画核心像素，不是平均值）。

## 一、七条核心规则（照抄，别发挥）

| # | 规则 | 依据 | 落地 |
|---|---|---|---|
| 1 | **文字只有 2 档色** | 主文 `#e9e9e9`、次要 `#8f8f8f`，全图无第三种文字灰 | 砍掉 text-3。弱化靠**字号降到 11**，不靠第三档灰 |
| 2 | **图标与所在行文字同色** | 导航行图标 = 标签 = `#fff` | 不做"灰图标 + 白文字"，图标继承行色，整行一起亮暗 |
| 3 | **行高 30 / 行距约 32.6** | 实测行距 43 ÷ 1.32 | 列表行 34，数据表行 36 |
| 4 | **分区只靠留白 + 12px 灰标签，零分割线** | 全侧栏没有一条 1px 线 | 删掉分割线；组间距 20，标签到首行 14 |
| 5 | **激活态 = 圆角 8 的 30px 灰底** | 胶囊 317×30，`#313131`，无边框无色条无阴影 | 侧栏/列表统一这个形态 |
| 6 | **图标 16px、统一描边体** | 图标 ink 18 ÷ 1.32 ≈ 14 主体 / 16 外框，与文字间距 6~8 | 不许混实心图标 |
| 7 | **字重只用 400 / 500** | 全图无 700 | 见下面那条前提 |

### ⚠️ 第 7 条有个平台前提（重要，别照搬）

`400 / 500` 只在**西文可变字体**下成立。

- `Segoe UI` → `SegUIVar.ttf` 是可变字体，500 有真实字形
- `Microsoft YaHei` → 只有 300 / 400 / 700 三档

CSS 字重匹配规则（Fonts 4）：请求 500 而字体没有 500 时，**向下取 400**，不跳 700、不合成。
⇒ **中文写 `font-weight: 500` 等于写 400，视觉零变化。**

所以中文的主次只能靠 **字号 + 颜色 + 独占一行** 表达。
想让中文真有 500，只有两条路：自托管可变中文字体（MiSans VF / Noto Sans SC VF，子集化后数 MB），
或者接受"中文只有 400 / 700"。

## 二、"协调感"从哪来（五条机制，不是玄学）

1. 所有可点元素是**同一个形状**（圆角 8 的块），只是底色深浅不同
2. 图标与文字**共用一种颜色**
3. 左右内边距**对称**，没有任何元素贴边
4. 层级**只由字号和留白表达**，颜色只分主 / 次两级
5. **每一组行距相同**，整列有节奏，眼睛能顺着往下滑

## 三、明度分层

| 档 | 深浅关系 | 用在哪 |
|---|---|---|
| `canvas` | 最深（深色）/ 最浅（浅色） | 窗口底、内容区 |
| `panel` | 中间 | 卡片、列表行、顶栏底栏 |
| `raised` | 最亮 | 悬停、弹出层、输入框底 |

- **深色不加投影**：深底上的投影只会变脏。分层靠明度差（约 5~8 级）。
- **浅色要投影 + 一档描边**：浅底明度差不够，只靠明度会糊成一片。
- 发丝线 `rgba(255,255,255,.08)`（浅色 `rgba(0,0,0,.08)`），只在真正需要边界时用。

## 四、字阶 / 圆角 / 间距

| 类别 | 档位 |
|---|---|
| 字号 | 15 标题 / 13 正文 / 12 辅助 / 11 眉标 |
| 圆角 | 卡片 10 / 控件 8 / 小标 6（**同心**：内层 = 外层 − 间距） |
| 间距 | 8 / 12 / 16（4 的倍数，三层递减：组间 16 > 组内 12 > 元素间 8） |
| 行高 | 顶栏 44 / 底栏 52 / 列表行 64 / 表格行 36 |

## 五、控件三态 × 按钮四形态

控件只有三种形态，多一种整屏就散：

- `primary`：反色（深色下白底黑字）。**一屏最多一个**。
- `default`：比面板亮一档。
- `ghost`：透明，悬停才出现底。工具条、行内动作用它。

按钮的状态矩阵（四形态 × 四状态）：

| 状态 | 变化 | 时长 |
|---|---|---|
| hover | **只变色** | 160ms |
| focus-visible | 2px 强调色描边 + 2px offset | 即时 |
| active | 再深一档 | 120ms |
| disabled | `opacity: .4` + `pointer-events: none`（不是灰字，灰字会读成"可点但坏"） | — |

## 六、强调色的三处限制

强调色（蓝/品牌色）**只允许出现在三处**：选中、焦点、悬浮。

主按钮涂成强调色 = 立刻变成第四处，整屏就花了。所以 primary 用**反色**而不是品牌色。

状态色另算：绿 = 成功，黄 = 警告，红 = 失败。
**"未命中"算警告不算错误** —— 它不是系统坏了，是这次没找到。

## 七、Token 分三层（为"以后好改"服务）

```
L0 原始值   --raw-n1 .. n9        只在这里出现色值
L1 语义     --surface / --field / --line / --text-1 / --text-2
L2 场景     --card-bg / --dock-bg / --row-hover
```

规矩：**组件只用 L2**；L1 只给 L2 用；改主题只动 L0。
出现"某个组件直接写 `#313131`"就是分层破了，下次换主题必然漏掉它。

> 例外：动效里的「光」可以有自己的色组（如绿/蓝/紫光带），
> 它不是界面配色，改它不影响任何控件观感 —— 但仍然要放进 token，不许写在组件里。
