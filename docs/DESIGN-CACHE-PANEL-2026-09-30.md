## 2. 问题清单

### P0 —— 结构性问题

**P0-1【v3 改写】主路径不可发现，但解法**不是**加操作列** `[静态]` `HistoryTable:24-46, 110-131`

现状两条毛病：
1. 打开目录的唯一入口是路径文字的 `ondblclick` —— 而它被渲染成 `NButton quaternary`，**看着像单击链接**。
2. 一年用两次的迁移动作（备份/还原/合并）占了整条工具条，与日常入口同级。

**用户裁决 C1：不加操作列。** 我原来的解法（行尾常驻「打开」）作废。
→ 改后的解法（**零新增列、零新增功能**）：
- 把目录名从 `NButton quaternary` 换成**纯文本**（去掉"像链接"的假单暗示），`cursor: pointer`；
- 行 hover 时在目录名右侧出现浅灰小字 **「双击打开」**；
- 保留行 hover 背景高亮。

**为什么这样够**：主界面本身就是"双击格子才打开"（`index.vue:99-101`），
所以"双击"不是新概念，**是从主界面带过来的既有心智**。真正缺的只是"面板里那行文字看起来能单击"。
把这个假暗示去掉 + 给一句悬停提示，就够了。

⚠️ 诚实标注：这比加一个按钮的**可发现性弱**。如果他试完觉得还是不好找，**加一列只是 15 行的事**，可以随时回补。

## 3. Q1 答案：用上视频文件大小（按 C2：只汇总缓存，不读盘）

### 3.1 数据来自哪里 `[静态]`
- `FileInfo.size` 本来就存着。
- **收敛条目的 size 就是"这部片子有多大"**：`handleCover` 里 `size += stat.size` 累加，
  `info.size = size + stat.size`（`server/index.ts:347-398`）。
- folder 条目（分类目录）`size = stat.size`（NTFS 目录项 = 0）→ **不贡献字节**，正好不会把子目录重复算。

### 3.2 双算证伪 `[实测]`（三轮探针收紧）
| 轮次 | 判据 | 结果 |
|---|---|---|
| 1 | 父路径也在缓存里的记录 | 208/213 → 只说明结构 |
| 2 | 父记录自身字节 > 0 | 102 条 → 仍必要不充分 |
| 3 | **精确**：父层"非 folder 条目"名 ∈ 同名子记录名集合 | **0 条** ⇒ 无双算 |
| 3 反证 | "父层条目 ↔ 同名子记录"配对 | **208 对，208 个父层都是 `folder`（size 0）** |

**结构性原因**：收敛要求子目录内没有子目录；而被收敛的目录**永远不会产生独立记录** ——
因为双击父层的封面条目是"**打开里面的视频**"，不是"进入目录"。所以收敛目录必然是叶子。
→ 合计 **3.35 TB 可信**。
⚠️ 不是结构性保证：若用「选择文件夹」手工选一个已被收敛的子目录，它就会有独立记录 → 那时会虚高。

### 3.3 零读盘是怎么保证的 `[静态]`（读 nedb 实现）
- `loadDatabase` 一次把整库读进内存；`getAllData() { return this.indexes._id.getAll() }`
  （`node_modules/@seald-io/nedb/lib/datastore.js:416-418`）→ **文档全在内存索引里**。
- `find()` 走 `_getCandidatesAsync` 从索引取候选 + 内存匹配；`projection` 只是下发前删字段。
- ⇒ 在 `loadMeta()` 里多算一次 `data[].size` 求和，**不新增任何磁盘 I/O**；
  实测这一趟遍历 **0.07 ms**（整库载入 520 ms 是 nedb 启动本来就做的）。
- ⚠️ 证据等级：**静态（读依赖源码）**，不是真机实测。

### 3.4 落地与三条规矩
| 落点 | 做不做 |
|---|---|
| **行级「大小」列** | ✅（0 → 显示 `—`） |
| **总览里的合计** `已读到 3.35 TB` | ✅（措辞是"缓存里记录到的字节之和"，不是"硬盘上有"） |
| **按大小排序** | ✅ |
| 盘条 chip 上放每块盘的大小 | ❌ chip 会太长；行级排序已够 |

1. **只汇总缓存，一次 `stat` 都不做**（C2）。
2. 它是**扫描那一刻**的快照 → 叫「上次读到时的大小」，不叫"当前大小"。
3. `0` 显示 **`—`**（反例实测：`AAAA1111/示例分类目录` 是 `104 个条目 / 0 字节`，全是子目录）。
4. **格式必须支持 TB**（P2-6 的 `%1024` 截断）。

## 5. 关键文案

**删除**：按钮 `删除记录`；确认框
`只删掉这 3 条**记录**，硬盘上的文件一个都不动。删掉后，下次打开这些目录会**重新读一遍硬盘**（要碰移动硬盘）。其中 2 条在那块没插的盘上 —— 删了就看不到了，除非把盘插回来重扫。`

**从文件还原**（语气修正，见 §8 苏格拉底问 1）
`会用选中的文件整体替换当前缓存。替换后，本机独有的 213 个目录 / 1247 个条目要重新读一遍移动硬盘才能回来。还原前会自动留一份快照，还原后立即生效，不用重启。`

**合并缓存**：不弹确认（只增不删），只播报 `新增 27 条、覆盖 3 条、跳过 9 条`。

**空态**（判据先排除 loading/失败）
- `还没读过任何目录` + `在主界面选个文件夹，点「补全这一片」`
- `没有匹配「xxx」的目录`

**count=0 的行**（P1-12）：`空目录，或上次没读到 —— 双击打开它，在主界面按 ↻ 重读一次`

## 8. 三神技过一遍

**⚔️ 苏格拉底问 1：这个面板为什么要有「备份」？**
→ 怕丢。**但缓存丢了会怎样？重扫一遍就回来了。**
→ ∴ 缓存是**可重建的派生物**；「备份」保护的不是"数据"，是**你花在读移动硬盘上的时间**。
→ 全案语气因此改变：不该说"会丢数据"，该说"要重新读一遍移动硬盘"。**v1 在这里错了，已改。**

**⚔️ 问 2：「条目数」是给谁看的？** → 若它回答"丢了要重扫多少"，它就是**代价的度量** → 总览从"信息展示"升格成"风险度量"。

**⚔️ 问 3：如果面板明天消失，损失什么？** → 失去"盘不在时翻旧账" + "找回上次看的目录" → 印证 **P0-1 / P0-6 是第一优先**。

**🔬 第一性原理**：本体是一张 `(盘序列号, 盘内路径) → (条目列表, 扫描时刻)` 的表，**不能自己产生内容**。
→ 三个必然推论：① 每个数字都必须带时刻；② 大小只能是快照量，不能写"当前"；③ 任何"写"都只在改这张表，**永远不碰硬盘文件**。
→ 再剥一条：**这张表的唯一价值 = 省下重读硬盘的时间**（库 81.7 MB ↔ 省下 3.35 TB ≈ **1 : 43000**）。

**🪒 奥卡姆**：
| 候选 | 裁决 | 理由 |
|---|---|---|
| 行尾「打开」操作列 | **砍**（用户 C1） | 双击是既有心智；缺的只是"假链接样式" |
| 「重读这一条」 | **砍**（用户 C3） | 新开读盘入口；指路到既有功能即可 |
| 盘条 chip 上放盘大小 | 砍 | chip 太长，行级排序够用 |
| 拼音搜索 | 砍（本轮） | 卡在架构决策 |
| 总览大小合计 | **保留** | 用户 C2 要的正是"汇总已有缓存" |
| `closable` / 入口 tooltip / 折叠区 | 保留 | 一行级收益 |
