# 修 · 搜索框伸缩"突兀"（2026-11-08）

**一句话**：不是曲线不好看，是**同一条指数减速曲线被派去干 192px 的宽度生长**，
再加上**内容比容器晚 50ms 出现** —— 前 50ms 观众只看得到一块空白猛撑开。

主人口述：「地址栏的动效还是挺 Q 弹的，但是过滤框感觉很突兀」。

---

## 一、先量，不猜

`cubic-bezier(x1,y1,x2,y2)` 的**初始斜率**就是"起步那一瞬间有多冲"，
它决定大距离位移的峰值速度。用牛顿迭代（与浏览器同法）算三条候选：

```
cubic-bezier 进度表（x% = 时间进度，y% = 走完的距离）
  曲线                          10%   20%   33%   50%
  ff-ease-move (0.19,1,0.22,1)  48%   77%   92%   98%   ← 现在用的
  ff-ease-exit (0.32,0.72,0,1)  27%   66%   88%   95%
  easeOutQuad  (0.25,0.46,.45,.94) 19%  37%   58%   77%   ← 改成这个
```

峰值速度 = 初始斜率 × 距离 ÷ 时长：

| 对象 | 距离 | 时长 | 曲线 | 初始斜率 | 峰值 |
|---|---|---|---|---|---|
| 面包屑换层（**他说 Q 弹的**） | ~60px | 200ms | ease-move | 5.26 | **1578 px/s** |
| 搜索框（**他说突兀的**） | 192px | 150ms | ease-move | 5.26 | **6733 px/s** |

**4.3 倍。** 同一条曲线，位移一放大就从"利落"变成"甩"。

复算脚本（40 行，无依赖）：

```js
const sx = (t, a, b, c) => ((a * t + b) * t + c) * t;
// 标准 bezier 求解，x1/y1/x2/y2 = 控制点
// 初始斜率 = y1 / x1；峰值 = 初始斜率 × 距离 / 时长
```
数值直接由控制点得出，不需运行环境。

## 二、第二个缺陷：无内容的那 50ms

旧时序：

| 时间 | 宽度 | 输入框 opacity |
|---|---|---|
| 0 | 28px | 0 |
| **50ms** | **204px（走完 92%）** | **仍然是 0** ← 这里就是"突兀" |
| 100ms | 218px | 约 0.5 |
| 150ms | 220px | 1 |

宽度先"落位"、内容后"显形" —— 这是他从参考件抄来的**拍内分带**，在面包屑上成立：
"落位"的是**有形状的文字块**，块先飞到位再淡入 = 有质量感。

但宽度不是位移。**宽度的"落位"就是一块空白。** 空白撑开 + 内容后到 = 空格子自己弹了一下。

> 原则没错，错在**用错了对象**。位移 → 分带；尺寸 → 不分带。

## 三、改了什么

| 位置 | 改动 | 依据 |
|---|---|---|
| `tokens.css` | 新增 `--ff-ease-size: cubic-bezier(0.25, 0.46, 0.45, 0.94)` | 尺寸专用。独立 token 而不是复用 move，避免下次又错用（判据：同类场景会不会复发） |
| `.search-slot` 基础态 | 曲线 `ease-exit` → `ease-size`；时长/延迟不动（收起仍"先消失后收摊"） | 收起时空白在**变小**，不刺眼，且收窄时不该看到内容被挤 |
| `.search-slot.is-open` | 时长 `0.75 拍 → 1 拍`（150 → 200ms）；曲线 → `ease-size` | 原来那 25% 尾巴是留给"先落位"的，内容已同起跑就不需要 |
| `.search-slot.is-open .n-input` | 去掉 `var(--ff-fade-in-delay)` | 那个延迟正好盖住宽度冲完 92% 的 50ms |

改后峰值：`1.84 × 192 ÷ 200 = 1766 px/s`，与面包屑 1578 同一量级（差 12%）。

## 四、没验的部分（必须说清）

- **观感只能肉眼。** 上面的数是"速度对齐"，不等于"看着舒服"。仍要主人目视。
- **`width` 动画每帧触发 layout**（面包屑用的是 transform，走合成层）。
  本次没动这一点。如果改完仍然"发涩/掉帧"，那问题就不在曲线，而在
  "用 width 做动画"本身 —— 那时才该上探针采帧间隔，方案会大改
  （容器 transform + 内部反向缩放，或直接接受裁切）。
- 探针 `header-width` 的页面还是 10-02 版，**没有搜索框**；本次没为它补场景，
  因为静态证据已经能定位到具体两条缺陷（不满足"静态全对才上探针"的门槛）。
