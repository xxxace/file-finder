# 探针 · 网格 6 列左右对齐

**一句话**：量"首格的左边 = 头部的左边？末格右边 = 头部的右边？"，并复核一行**还是 6 个**。

## 复跑

```bash
bash docs/probes/grid-6col/run.sh      # 会先重建真 CSS，再跑，输出写 out.txt
```

⚠️ 依赖 `../header-width/css-real.generated.css`（同目录的 `build-css.mjs` 生成）。
`run.sh` 已自动先重建一次 —— 因为它用的是**真实编译产物**，改了 `FileFinder` 的
`<style scoped>` 之后不重建，这里量到的就是旧样式。

- **零读盘**：夹具是写死的格子，不碰 `searchCache.db`、不 stat 任何盘。
- 页面直接 `<link>` 那份真 CSS，DOM 是**静态 HTML**（不引 Vue）——
  网格的结构只有 `.image-box > .image-box-item`，没有组件语义，静态复刻失真风险最低。

## 改动是什么

```less
.image-box { margin-left: -5px; margin-right: -5px; }
```

## 判据（`run.cjs` 里自动判定）

| # | 判据 | 为什么 |
|---|---|---|
| 1–3 | **[对照]** 改动前每档都**内缩 5px**（首格相对头部 = 5） | 先证明"问题真的存在"。对照不成立 ⇒ 后面所有结论都没意义 |
| 4–5 | 改动后首格贴边（= 0）、末格贴边（= 0） | 这就是用户要的两件事 |
| 6 | 改动后一行**仍是 6 个** | ⚠️ 负 margin 让容器**变宽了 10px** ⇒ 必须复核列数没被这个变化带跑 |
| 7 | **[对照]** 改动前一行也是 6 个 | 证明"6 列"是改动前就成立的，不是改动带来的 |

`首行格数` 是**按渲染结果数的**（数首行里 top 相同的格子），不是按公式推的 ——
公式推出来的"6"证明不了浏览器真的排了 6 个。

## ⚠️ 已知局限（别把它当全绿）

- **测不到那几个响应式断点**（≤600px 变 5 列、≤400px 3 列…）：它们是
  `@media (max-width:...)`，看的是 **viewport**；而这里改的是 `#stage` 的宽度，
  媒体查询根本不会触发。真要测得 `win.setSize()` + 重新布局等待。
  ⇒ 桌面窗口有 `minWidth: 1024`，那几档**实际触不到**，所以没测。
- **只证明"盒子对齐"**：格子自身有 `padding: 0 2px` + 1px 透明边框 ⇒
  图片（`<img width:100%>`）距容器边仍有 ~3px。那是**另一件事**，本探针不管。
- 观感（间距是否顺眼）只能真机目视。
