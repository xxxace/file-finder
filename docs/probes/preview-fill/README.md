## 背景：为什么会冒出"点图外关不掉"这个问题

naive-ui 的预览面板里，**"点图外关闭"是靠 overlay 接住点击实现的**：
预览 img 的元素盒只贴合图本身（`.n-image-preview` 只有 `max-width/height`，没有 `width/height`），
所以"图以外的地方"落回 overlay（`z-index:-1`）→ 触发关闭。

一旦把 img 的元素盒撑满视口（为了让小图变大），**图内容与盒子之间的留白也归 img 吃点击**，
那部分就从 overlay 手里被拿走了 → 点它不再关闭。

## 实测数据（视口 1903×1063，Electron 44 offscreen，真实 Chromium 布局）

`padX/padY` = 元素盒比图内容宽出来的那半条（**会被 img 吃掉的"假空白"**）。

| 场景 | 元素盒 | 图内容 | 假空白 | 点假空白·无判定 | 点假空白·有判定 | 点图内 |
|---|---|---|---|---|---|---|
| 小图 480×270（视频抽帧） | 1871×1031 | 1833×1031 | 左右各 19px | ❌ 不关闭 | ✅ **关闭** | 不关闭 ✓ |
| 大图 3000×2000（/raw 原图） | 1871×1031 | 1547×1031 | 左右各 162px | ❌ 不关闭 | ✅ **关闭** | 不关闭 ✓ |
| 竖图 600×1800 | 1871×1031 | 344×1031 | 左右各 764px | — | ✅ **关闭** | 不关闭 ✓ |
| 宽银幕 2400×400 | 1871×1031 | 1871×312 | 上下各 360px | — | ✅ 关闭 | 不关闭 ✓ |

**A/B 对照成立**：同一张图、同一个探测点，没有判定时 `closed:false`、有判定时 `closed:true`；
点图内容正中在两种方案下都是 `closed:false`（不会误关）。
所以"关得掉"确实来自那段判定，不是碰巧。

### 顺带记下：`stretch` 对"撑满"这件事的效果（2026-09-27 实测）

| 场景 | 改前 | 改后 |
|---|---|---|
| 480×270 抽帧（视频） | 显示 480×270，居中 | **显示 1833×1031**（撑满，≈3.8 倍插值） |
| 3000×2000 原图（图片） | 显示 1546.5×1031 | 显示 **1546.5×1031**（**完全一致，零变化**） |

即：**收益全部来自"比视口小的图"**；大图本来就被 `max-*` 钳到贴边。

### 为什么排除 `fit` / `fit48`（盒子贴合图 + 放大边距）

`width:auto; height:100%` 让盒子按图片内在比例贴合图 → 图外重新归 overlay，看起来更优雅。
但**约束只在"高度受限"时保持比例**：对**比视口更宽**的图（宽银幕电影、21:9），
height 是显式值、宽度被 `max-width` 钳住后**高度不会重算**，于是盒子又变成 1871×1031、
图内容只有 1871×312 —— 假空白 360px 回来了，`boxEqualsContent: false`。

（`fit48` 把边距放大到每侧 48px 能让常规图那段边好点，但同样治不了宽银幕，且图从 100% 掉到约 91%。）

## 如果以后要重开这件事：成本阶梯

| 方案 | 成本 | 拿到什么 | 代价 |
|---|---|---|---|
| `pointer-events: none`（加在预览 img 上） | **一行** | 点**任何位置**都关闭（含点图片本身） | 点图内也关；旋转后不能拖拽平移 |
| `stretchClick`（本探针里那段判定） | **约 20 行** | 精确区分"图内容内 / 外"：图内不关、图外关 | 要算 contain 后的内容矩形；旋转 90° 时用 `DOMMatrix` 解角度兜住 |

**当时的教训**：直接把 20 行那版端上去，用户只看到"要算这么多东西"就否了 ——
而一行版覆盖了同一个诉求的绝大部分。**下次这类"诉求明确、实现有梯度"的事，先给成本阶梯再动手。**

## 三个环境坑（都踩过，别再踩）

1. **`ELECTRON_RUN_AS_NODE=1` 被注入到本机 shell** —— 直接跑 `electron` 会被当成 node，
   `require('electron')` 拿不到 `app`。必须 `env -u ELECTRON_RUN_AS_NODE` 真删掉，**设成空字符串没用**。
2. **项目 dev 实例占着默认 userData 的 GPUPersistentCache** → GPU 进程反复崩、连带 `ERR_FAILED`。
   探针要换独立 `userData`（本目录用 `$TMP/probe-preview-fill`）并禁用 GPU。
3. **`show: false` 的窗口量不准（最坑的一个）**：Windows 上它不参与合成 → rAF 不推进 →
   Vue `<Transition>` 的 `enter-from` class 永远移不掉，而 `enter-from` 正是 `scale(0.9)`，
   量出的盒子整整小 10%（1871×1031 会量成 1670×870）。
   命令行 `--disable-renderer-backgrounding` / `backgroundThrottling:false` **都治不住**，
   必须 `webPreferences.offscreen = true` 让 Electron 自己驱动帧。
   ——排查时一度以为是"入场动画没跑完"，两个错误方向都试过（等 `getAnimations()`、注入 `transition:none`），
   后者只会让 class 更赖着不走。

## 两种读数口径（别混）

| 读什么 | 含义 | 可信度 |
|---|---|---|
| `getComputedStyle().width/height` | CSS 盒尺寸，**不受 transform 影响** | ✅ 判"占多大"用这个 |
| `getBoundingClientRect()` | 渲染尺寸，**受入场动画 scale 影响** | 需先解决上面第 3 条 |
