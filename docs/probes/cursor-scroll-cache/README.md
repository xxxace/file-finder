# cursor-scroll-cache · 滚动 / 懒加载 / 长按 与行结构探测

```bash
bash docs/probes/cursor-scroll-cache/run.sh
```

**验什么**：业主 2026-10-04 二次报「长按方向键，**到底部几行**就错乱；**刚开始上半部分正常**」。
（第一次报的是"按右不一定动、按上去了右"，根因见 `docs/ANALYSIS-arrow-key-misalign-2026-10-04.md`。）

**15 PASS / 0 FAIL。**

## 三个候选，本探针逐一给出答案

| 候选 | 实测结论 |
|---|---|
| **懒加载** | ❌ **不是**。图片到达前后 `offsetTop` 漂移 **0.000px**、行结构 10→10 不变（行高被 `!important` 钉死）|
| **长按本身** | ❌ **不是**。长按只是让按键变密⇒ 让"滚动 → 缓存失效 → 重新探测"这条路径**必然被踩到** |
| **滚动导致重新探测** | ✅ **是根因**。见下|

## 机制：三拍时间线（这是"上半部分正常"的全部原因）

```
第 1 次按键 → probeLayout()  ← ★此刻 cursorKey 还是空
                ⇒ 屏幕上没有任何 .cursor ⇒ 探测干净 ⇒ 缓存住干净结构
第 2 次按键 → 缓存命中（rowTops 非空）⇒ 用干净结构 ⇒ 走对
   ↓ 落点出视口 ⇒ scrollIntoView ⇒ scroll 事件 ⇒ invalidateRowTops
第 3 次按键 → rowTops 空 ⇒ 重新探测 ← ★此刻焦点格正带着 scale(1.012)
                ⇒ 探测变脏（10 行 → 12 行）⇒ 从此一错到底
```

实测按键序列（前 26 次按 ↓）：
```
对对✗✗✗✗✗✗✗✗✗✗✗✗✗✗✗✗✗✗对对✗对对✗
    ↑ 第 3 次开始全错        ↑
```

⚠️ **变脏比滚动晚一拍**是正常的：`scrollIntoView` 同步改了 `scrollTop`，
但 `scroll` 事件是**异步派发**的 ⇒ 探针在下一步才作废缓存。

## 关键判据：S3「只要重新探测，即使不滚动也已经错了」

这条**反直觉但至关重要**：它排除了"'上半部分正常'是因为那里不滚动"这个解释。
不滚动也会脏 —— 上半部分正常**只可能因为缓存根本没有重新探测**（首探时没有焦点格）。

## S4 · 主人症状的完整对照表

脏行结构 `4/1/1/6/6/6/6/6/6/6/6/6`（正确应为 `6/6/6/6/6/6/6/6/6/6`），
焦点 `k4` 的正确坐标 `{r:0,c:4}` 被误判成 `{r:1,c:0}`：

| 方向 | 正确落点 | 实际落点 | 主人的说法 |
|---|---|---|---|
| `→` | k5 | **k4（原地不动）** | "按右不一定动" |
| `↓` | k10 | **k5（横向跳）** | "和预期不一样" |
| `←` | k3 | **k4（原地不动）** | "要么就不动" |
| `↑` | k4（顶边界） | **k0（横向跳）** | — |

**4/4 个键全错**，且错的形态与主人描述逐条吻合。

## S3b · 治本对照

只把探测量从 `rect.top`换成 `offsetTop`（其它一字不改，含缓存逻辑）：
滚动照常发生（第 2 次按键）、行结构从头到尾 10×6 正确、**26 次按键 0 步走错**、
"末行停住"的正确行为仍保留。

## ⚠️ 我在写这个探针时踩的坑（记下来，别再犯）

**第一版把期望值算成了 `rows[at.r+1][at.c]` —— 用脏结构自己算期望 ⇒ 循环论证**
⇒ 得出"26 步 0 步走错"的假结论，与 S4 的4/4 全错直接矛盾。
**判据的期望值必须来自独立的真值**，绝不能从被测对象推导。
（探针里 `truth` 是硬编码的 6 列 × 10 行，与 DOM 无关。）
