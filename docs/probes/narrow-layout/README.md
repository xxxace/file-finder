# 探针：小窗口下的布局（改前 / 改后）

**用户反馈**（附截图）：小窗口下文本布局错乱 —— 总览那句和右边按钮挤在一起、底部「共 106 项」被压成**竖排**、
表格最后一列看不到。

**复算**

```bash
bash docs/probes/narrow-layout/run.sh     # 窗口宽度扫 680→1100，结果写进 out.txt
```

无头 Electron（真 Chromium）+ **真 naive-ui UMD 包**，渲染与 `HistoryTable` 相同的结构，
在两个变体间切换并量：底部「共 N 项」的盒子尺寸、分页器宽度、总览按钮相对文本的偏移、各列实际渲染宽。
窗口高度固定 700；宽度扫 680 / 760 / 820 / 900 / 1100。

## 实测结论（`out.txt`）

| 窗口宽 | 变体 | 「共 N 项」 | 分页器宽 | 总览按钮偏移 |
|---|---|---|---|---|
| **681** | old | **12×96 ← 竖排（坏）** | 495（被压） | +13（错位） |
| 681 | new | **52×22 ✓** | 536（自然宽） | +3 ✓ |
| **761** | old | **12×96 ← 竖排（坏）** | 495 | +3 |
| 761 | new | **52×22 ✓** | 536 | +3 |
| 821 及以上 | old / new | 52×22 | 536 | +3（两者一致） |

⇒ **坏区间是窗口 ≤ 约 800px**（用户截图的图像宽度 890 是被裁过的，不能当窗口宽度用 ——
单点测量没复现出坏状态，所以改成扫宽度才找到区间）。**修复后全区间正常。**

## 根因与修法

| 症状 | 根因 | 修法 |
|---|---|---|
| 「共 N 项」竖排成一列字 | 分页器内部是 `flex-wrap: nowrap`，**一被挤压**就把前缀压到内容最小宽（≈12px）⇒ 一个字一行 | ① 分页器 `flex: 0 0 auto`（装不下就整块换行，而不是缩小）；② 它自己改成 `flex-wrap: wrap`（极窄时页码换行，而不是溢出被裁）；③ 前缀 `flex: 0 0 auto; white-space: nowrap` |
| 总览那句和「打开存放文件夹」互相挤 | 总览行 `justify-content: space-between` 且**不换行** ⇒ 文本换行后按钮悬在第二行最右边 | 行 `flex-wrap: wrap` + `align-items: baseline`；文本 `flex: 1 1 320px`；按钮 `flex: 0 0 auto; white-space: nowrap` |
| 底部「批量区 + 分页器」互相挤 | 底部行不换行 | `flex-wrap: wrap` + 批量区自身也允许换行 |

## ⚠️ 一个**撤回**的改动（记下来，免得以后又"顺手加"）

我曾给表格加了 `:scroll-x="720"`，理由是"小窗口下最后一列被裁"。
**量出来这个理由不成立**：

| 指标 | 改前 | 加了 scroll-x |
|---|---|---|
| 目录列实际宽（761px 窗口） | 240 | 258（只差 18px） |
| 可横向滚动的容器数 | **2** | 2（一样） |

⇒ 表格**本来就能横向滚动**，"最后一列看不到"其实是"需要往右滚"，不是被裁掉。
所以那个改动已从组件里撤回（**不为改而改**）。探针里也同步去掉了，否则量的是别的东西。

**也顺带说明一个探针自身的坑**：判断"有没有横向滚动"不能只看 `scrollWidth > clientWidth` ——
**被父级裁掉的内容，scrollWidth 照样更大**，第一版就是这么写的，结果"改前"也被判成"可横向滚动"，
证据没法用。判据必须是 *computed `overflow-x` ∈ {auto, scroll} 且内容更宽*。

## 还没解决的一件事（属于设计取舍，等用户定）

小窗口下看「上次扫描」那列需要横向滚动。要让它不用滚就可见，只能动**列的固定宽度**
（例如「大小」96 → 84、「条目」88 → 64、「盘」88 → 64），或把小窗口下的两列合并 ——
那是在"信息密度"和"可见性"之间换，**不是 bug**，所以本轮没动。
