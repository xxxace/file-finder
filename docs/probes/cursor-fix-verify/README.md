## ⚠️ V3b 为什么要手动触发滚动

`scrollIntoView` 在**无头环境**里对 `.image-box` 不生效
（实测落点已走到 `k66`、远超视口能显示的第 4 行，`scrollTop` 仍恒为 **0**）
⇒ 靠自然滚动**测不到**"缓存被作废 → 重新探测"这条路径。

⇒ 改为**手动 `box.scrollTop = scrollHeight` + 派发 `scroll` 事件**
（与 `invalidateRowTops` 的触发条件等价）⇒ 那条路径才真的被走到。

⚠️ **否则那条判据是"没测到"而不是"没问题"** —— 这是本探针最危险的一处。

## 我在这个探针上踩的坑（4 个，都写进了 skill）

1. **composable 必须在 `setup()` 顶层调** —— 我第一版在 setup 外调`useGridCursor`
   ⇒ `onMounted` 不注册 ⇒ **keydown 监听压根没挂** ⇒ 所有按键返回空串。
2. **空落点会被算成"走错"** ⇒ 看起来像"抓到 bug"，其实是探针坏了
   ⇒ 加 **V1b 守卫**：落点为空立即中止，并提示"探针没接上"。
3. **换站必须 `app.unmount()`** —— 否则**上一个用例的 window 监听还在**
   ⇒ 一次按键被多个监听处理 ⇒ 落点跳格。
4. **`position:absolute` 挂载点被挪出视口** ⇒ `scrollIntoView` 认为"已在视口内"⇒ 不滚
   ⇒ 改成**重建主容器**（在文档流里、有真实高度）。
