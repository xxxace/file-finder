# grid-cursor-visual · 焦点环可见性与状态色可区分性

```bash
bash docs/probes/grid-cursor-visual/run.sh
```

**验什么**：业主 2026-10-04 报「选中框样式很丑」的那个改动到底对不对。

**根因不是审美** —— 原来的焦点态**边框色与 `:hover` 完全相同**（都是 `#7a8da9`），
只有阴影形状不同 ⇒ 鼠标划上去和键盘选中看起来一样，等于没有焦点。

## 三条判据的来历（都是被数据纠正过的）

| 判据 | 管什么 | 指标 | 出处 |
|---|---|---|---|
| 焦点环 vs **页面底/图片** | 环**浮不浮得起来** | WCAG 3:1 | Fluent 2 accessibility官方页引 WCAG |
| 焦点 vs hover 等状态色之间 | 两态**分不分得开** | **色相/饱和度差**，不是亮度比 | ⚠️ 见下 |
| 焦点环**不透明度** | 浅色封面上糊不糊 | alpha 扫表 | 本探针实测 |

⚠️ **我一开始把 WCAG 3:1 套错了对象**：拿它比"状态色 vs 状态色"，报了一堆 FAIL
（hover vs focus 只有 1.15:1）。但那不是设计缺陷 —— WCAG 3:1 管的是「控件与**它后面的东西**」，
对「彩色边框 vs 中性底」是错的指标。实测 hover #7a8da9 与 focus #2080f0
**色相 215.7° vs 212.3°、饱和 27.8% vs 86.7%** —— 一个灰蓝、一个亮蓝，一眼能分辨。
同理，中灰底图（#808286）上蓝环只有 1.01:1，但**饱和差 81**，仍然一眼可辨。

⚠️ **内层深线的 alpha 也扫过表**（不是拍的）：
`.45` 合成后与中灰图明度只差 2 ⇒ **在中灰底上等于隐形**；`.75` 是同时满足
"压住亮图"（vs 白图 10.37:1）与"中灰底不隐形"（明度差 28）的最小值。

## 实测数据留档

- 半透明外环 **必然不过 3:1**：alpha .55→1.96:1 · .75→2.58:1 · .85→2.92:1 · **1.0→3.56:1**
  ⇒ **环必须不透明**，而封面图绝大多数是浅色的。这就是"看着糊"的量化本质。
- 内层**亮白**线 vs 白图 = **1.00:1**（等于没有）⇒ 那个方向是错的。

**判据效力已验**：把焦点色退回"与 hover 同色" ⇒ **19 PASS / 7 FAIL**；恢复 ⇒ 24/0。
