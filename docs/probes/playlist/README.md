> 同 `rule-builder/` 的纪律：esbuild 打包**真源码**后断言 —— 探针验的东西和线上是同一份代码，不许手抄。

## 验什么（6 组 · 39 条）

| 组 | 对象 | 为什么必须测 |
|---|---|---|
| ① | `binStore.thumbNameOf` / `sigOfThumbName` | 加入清单时前端只有图片名（`sig` 不在下发白名单）⇒ 服务端必须能逆运算回指纹 |
| ② | `deriveIdentity` | 锚点 `#序列号/盘内路径` 必须拆回原值；空序列号 / UNC 拒收 |
| ③ | `dirOfItem` / `keyOfItem` | 在线给实时路径、离线给锚点；**key 必须与渲染层 `keyOf` 同形（`dir/显示名`，不加扩展名）** —— 加后缀曾让星标/选单 ✓/「从清单移除」全部静默失配（2026-10-21 真机报，已修）；**离线 key 的目录段能 round-trip 回身份** |
| ④ | `wireItem` | 离线条目**不许**带可生成的 `preview`（否则 = 白读一次盘）；无 sig 全空；目录条目带 `files` 快照 |
| ⑤ | `pickCovers` | bin 仓没有的名字不下发（假 sig ⇒ 恒空） |
| ⑥ | `playlistStore` | CRUD + 落盘 + 默认清单不可改名/删 + 损坏回落重新 seeding（**临时目录**，不碰真数据） |

## 零读盘说明

只测纯函数与存储层（临时 `dataDir`），**不触发任何路由** ⇒ 不调 `getDrives()`、不 stat 盘符、不碰移动硬盘。
`binStore` 模块初始化会 `readdir` 一次 `~/.file-finder/bin`（只读、毫秒级、内存集合）。

## 没验的（要真机）

- 「加入 → 货架 → 详情 → 拔盘降级 → 插盘恢复」的完整交互手感（2026-10-21 已用无头实例验过浏览链路：货架点卡片 → 面包屑「清单 / 名称」→ 网格出条目；拔插盘那双分支仍按 `DESIGN-PLAYLIST-2026-10-21.md` 的验收清单目视）
- 星标/✓ 的**视觉**呈现（本探针只验 key 同形这一必要条件）
