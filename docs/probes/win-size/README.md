# 探针 · 主窗口初始尺寸 / 最小尺寸

**一句话**：在**真 Electron** 下量"这台机器上，`main/index.ts` 那两行 `Math.min(...)` 实际取到什么值"。

## 复跑

```bash
bash docs/probes/win-size/run.sh      # 输出写 out.txt
```

⚠️ `run.sh` 里的 `env -u ELECTRON_RUN_AS_NODE` 不能省：本机 shell 注入了这个变量，
不删掉的话 electron 退化成纯 Node，`screen` 拿不到显示器（理由与 `../header-width/run.sh` 同）。

## 为什么要它

初始尺寸那三行（`width/height/minWidth/minHeight`）**看起来是算术，其实要看屏**：

- `workAreaSize` 与 `size` 差一个任务栏 ⇒ 拿 `size` 算会算出"盖住任务栏"的窗口；
- 缩放系数（本机 1.25）会让"物理 2560×1600"变成"逻辑 2048×1280"，
  而 `screen` 给的是**逻辑值** —— 心里按物理分辨率算会全错；
- `minWidth > 可用区宽` 时窗口**连缩到屏内都做不到**，这种错在代码里看不出来。

⇒ 这三件事都不该心算。**实测一次，把数字留在 `out.txt`。**

## 判据（`run.cjs` 里自动判定，6 条）

| # | 判据 | 为什么 |
|---|---|---|
| 1–2 | 实取尺寸 ≤ 可用区 | 否则开局就有部分窗口在屏幕外 |
| 3–4 | 实取尺寸 **>** `minWidth/minHeight` | 相等意味着"开局就顶在下限上"，等于下限设得比初始还大 |
| 5–6 | `minWidth/minHeight` ≤ 可用区 | 否则窗口缩不到屏内 |

## ⚠️ 局限

- 三个常量（`BASE_W/BASE_H/MIN_W/MIN_H`）**是抄的**，抄自 `electron/main/index.ts`。
  改了那边必须同步改这里，否则这份证据就变成在证明另一个东西 —— 这是本探针唯一的失效方式。
- 它只证明"数值落在可用区内"，**不证明"这个尺寸好看/够用"**。后者只能真机目视。
- 多显示器只取 `getPrimaryDisplay()`，与主进程一致（主进程也没做"记住上次在哪块屏"）。

## 实测（2026-10-02）

```
分辨率 2048 × 1280 · 可用区 2048 × 1232 · 缩放 1.25
基准   1280 × 860
实取   1280 × 860（基准值，未触发小屏收窄）
判据   6/6 ✅
```

⇒ 本机屏够大，`Math.min` 没有触发收窄；收窄分支只在 ≤1320 宽的屏上才会走到。
