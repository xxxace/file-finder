# 探针 · 头部行数 / 面包屑折叠 / 单条截断

**一句话**：用真 Chromium 量「头部高度到底是常量还是内容的函数」。

## 复跑

```bash
bash docs/probes/header-width/run.sh          # 先重建真 CSS，再跑，输出写 out.txt
```

（等价于 `node docs/probes/header-width/build-css.mjs` + `env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe docs/probes/header-width/run.cjs`）

- **零读盘**：夹具是写死的假路径，不碰 `searchCache.db`、不 stat 任何盘。
- 页面加载的是 `node_modules` 里**真的** naive-ui UMD + `vue.global`，所以量到的是真组件 + 真 CSS。

## 两个变体的差别（就是本轮的改动）

| | `old`（改造前写法） | `new`（候选实现） |
|---|---|---|
| 样式来源 | **手写复刻**（`index.html` 里的 `.old-header`）· 不带 scoped 属性 | **`css-real.generated.css`** —— 从两个 SFC 的 `<style scoped>` **真实编译**（less + scoped 转换） |
| 左区容器 | `.hstack{flex-wrap:wrap}` | `.nav-zone{nowrap; flex:1 1 auto; min-width:0; max-width:50%; overflow:hidden}` |
| 面包屑 | 全部层级平铺，无 `max-width`、无省略 | 折叠成「首段 + `…` + 父 + 当前」；每段 `max-width:160px` + 省略号 |
| 单项 | 不设 `flex` | `.crumb{flex:0 1 auto; min-width:0}`（可收缩）· `.crumb-current{flex:0 0 auto}`（永不被压掉） |
| 工具条 | `nowrap` + `align-self:flex-end` | `nowrap` + `flex:0 0 auto`（不参与压缩） |

> ⚠️ **为什么 `new` 一定要用真 CSS**：手抄一份"等效 CSS"只能证明"这套写法在普通 CSS 下成立"，
> **证明不了 `:deep()` / `:not()::before` 在 scoped 转换之后还成立**。
> 第一版就是手抄的 —— 那是个真实的验证缺口，`build-css.mjs` 是为此加的。

## 判据（`run.cjs` 里自动判定）

1. **头部高在每一档窗口宽度下完全一致** ← 核心。这就是"高度是常量"的定义
2. 当前段可见（折叠后"我在哪"没被挤出屏幕）
3. 工具条不溢出
4. **角标不得"新增"裁剪** ← 2026-10-02 加（口径是**相对的**：只有"无角标不裁、有角标才裁"才算回归）
5. **角标真的画出来了** ← 直接问 `::after` 的 content（`"none"` = 那条 scoped 规则没命中）

测的窗口宽度见 `index.html` 的 `WIDTHS`：`[640, 800, 1024, 1280, 1920]`。
⚠️ 加 **1024** 是因为那是主窗口 `minWidth`（`electron/main/index.ts`）——判据必须覆盖
"用户真能拖到的每一档"，只测 1280/1920 会正好漏掉最危险的那档。

`old` 变体只作对照打印，不参与判定；`new-无角标` 只作判据④的对照。

## 实测结果（2026-10-01，真 Chromium + 真 scoped CSS，见 `out.txt`）

`old` = 改造前**完整形态**（`flex-wrap` 换行 ＋ 三个平铺按钮）；
`new` = 已落地的形态（nowrap 分区 ＋ 三个动作收进「更多」）。

```
                640      800      1280     1920        工具条是否溢出（640/800/1280/1920）
old 头部高      196      196      116      76          是 / 是 / 否 / 否
new 头部高       37       37       37      37          否 / 否 / 否 / 否     ← 常量 ✓
new 导航区宽    188      341      616     936
new 截断段数    3/3/3/2                                  ← max-width + 省略号确实生效
new ::before   ["›","›","›","›"]                         ← scoped 规则命中（否则必为 none）
```

工具条预算：改造前 **605px** → 改造后 **405~411px**（三个动作收进「更多」，文案一字未缩）。

根 chip 三形态（⚠️ 关键指标是 **导航区宽 − 芯片宽** ＝面包屑真正能用多少）：

| 窗口 | 路径 tag 220px | 文字按钮 124px | 图标按钮 34px |
|---|---|---|---|
| 640 | **−33（面包屑 0）** | 57 | **147** |
| 800 | 121 | 217 | **303** |

（这条收益全部落在「冷启动 → 从缓存记录跳进来」——那时 `dir` 为空、chip 是**按钮**，
而面包屑**同时存在**；常规"已选根"场景里没有按钮，收益为 0。）

⇒ 四件事被同时证明：
1. 「头部高度是用户数据的函数」这个诊断**成立**（`old` 随窗口变 196/196/116/76），且已改成常量（`new` 恒 37px）。
2. `:deep(.n-tag__content)` 与 `:not(.crumb-root)::before` 在**真实 scoped 转换后**确实命中（截断数与 `::before` content 两处独立证据）。
3. 「更多」收纳把工具条 **605 → 405~411**，四档宽度下都不再溢出。
4. 根 chip 图标化在窄窗下把面包屑从 **0** 提到 **147px**。

## 实测结果（2026-10-02：条目数角标从工具条挪进面包屑的**当前段**）

改动本身见 `docs/CHANGES-2026-10-02.md` §三。这里只记证据。

```
                640      800      1024     1280     1920     结论
new 头部高       37       37       37       37       37      ← 恒常量 ✓（5 档全一致）
new 角标 ::after ["35"]  ["35"]   ["35"]   ["35"]   ["35"]   ← 规则真命中，不是 none ✓
new 导航区宽    224      376      488      616      936
new 是否裁内容  裁       裁       不裁     不裁     不裁
对照(关角标)    裁       裁       不裁     不裁     不裁      ← 640/800 是**既有局限**
⇒ 角标没有新增任何一档裁剪 ✓
```

**三条必须记着的口径（本轮各踩过一次）**

1. **判据必须用"对照组"，不能用"绝对值"**。第一版把判据写成"所有档都不裁内容"，
   于是 640/800 的**历史局限**把本次改动报成 ❌ —— 假 ❌ 和假 ✅ 一样有害：
   它会让人去改一个本来没坏的东西。正解是逐档比"有角标 vs 无角标"。
2. **探针必须复刻"已落地形态"**。第一版 `__probeAll` 让 `new` 变体继续用 `more` 工具条
   （= 上一轮的形态，角标**还在工具条里**）⇒ 量出来的是"双角标"形态、导航区**偏窄 38px**。
   截图上一眼能看见两个 35 —— **几何数字看不出的失真，截图能看见**。
   为此新增 `more2` 形态：`more` 保留旧语义，`more2` = 本轮落地形态。
3. **非折叠分支也要打 `crumb-current`**。角标 CSS 是 `.crumb-current[data-count]::after`；
   探针的非折叠分支原来只给 `crumb-root`，于是"短路径"场景下量不到角标——
   **那是探针的漏，不是实现的漏**（实现里两个分支都有那个类）。
   教训同 `old` 的手写复刻：**复刻件少一个属性，量出来的就是另一个东西**。

**顺带的收益**：角标搬走后工具条少 26px + 一格 gap ⇒ 640px 下导航区 **189 → 224px**。

**⚠️ 本条不在本探针范围内**：观感（红胶囊的圆角 / 间距 / 字重）只能看截图或真机，
几何数字说得再清楚也证明不了"好不好看"。

## ⚠️ 已知局限（别把它当全绿）

- **窗口 ≲ 640px 时面包屑仍然很紧**（导航区 188px − 芯片 34px = 154px，约等于"首 + … + 当前"）。
  ⚠️ 更正历史说法：早期版本写的"≲900px 被压成「…」"是**推理**；实测口径是
  **改造前 640/800 下"头部变高 196px 且工具条仍然溢出"，改造后四档都不溢出、头部恒 37px**。
- **列名 `顶边簇数(仅参考)` 不是"行数"**：它把**所有子孙元素**的顶边按 10px 容差聚类，
  tag 内部的 avatar/content 也会各算一次，所以绝对值偏大。它只能看**变化趋势**
  （`old` 变，`new` 不变）。判断"几行"请用 `头部高`。
- **观感（颜色、`›` 的位置、当前层加粗）不在本探针范围内** —— 那只能真机目视。
  本探针只证明"该规则命中了、且没把布局弄坏"。
- `old` 的样式是**手写复刻**、不是从 git 抽出来的旧文件 ⇒ 它是"等效对照"，不是"旧代码原样"。

## 附加：工具条预算（`__measureToolbar` / `__measureToolbarPlans`）

同一个页面还提供两个测量函数，用来回答"**工具条是导航区不够的元凶吗**"：

```
── 工具条预算 ──  总宽 605px = 子元素 533 + gap 72（12px × 6）
  补全这一片 90 · 重读这一片 90 · 补封面 62 · 缓存记录 34 · 角标 26 · 搜索框 200 · 刷新 31

── 形态对比（工具条宽 / 640px 下的导航区宽）──
  now 605/0(溢出)   short 507/85   short2 419/173   more 387/205
```

⚠️ **两个必须记着的坑（都踩过）**

1. **复刻件也要打 scoped 属性**：`n-input` 漏了 `data-v-probe` ⇒ 真实 CSS 里的
   `width: 200px` 不生效 ⇒ 把它量成 175px，**整张预算表偏小 25px**。
2. **"导航区 = 0 且工具条未溢出 = false" 是要读出来的信号**：它说明当前形态在窄窗口下
   **会溢出**，不是"挤一挤还能用"。第一版只看导航区宽，把这一条漏过去了。

## 附加：截图 —— 「观感只能目视」不等于"我看不了"

`run.cjs` 会 `capturePage()` 出三张图（跟着 `out.txt` 一起留档）：

| 文件 | 内容 | 用来看什么 |
|---|---|---|
| `shot-header.png` | 长链 @1280 | 折叠 / 截断 / 分隔符的整体观感 |
| `shot-crumbs.png` | **复刻用户报的那个场景** @820 | 窄窗口 + 图标 chip + `H: › 新建文件夹` |
| `shot-left.png` | 左区**局部放大** | **5px 级的间距问题**（分隔符离边框多远） |

**为什么必须有局部放大那张**：整条头部缩到 1256px 宽时，5px 的溢出和"压到边框"根本看不出来。
第一版只有整条截图 ⇒ 漏了两个真 bug：

1. **根 chip 的路径文本画到盒子外**、盖在后面几个面包屑上 —— 量到 `文本宽 211px vs 外框 150px`；
   根因是 `.n-tag__content` 默认 `min-width: auto`，而 FolderSelector 的样式块漏了这条（面包屑那边写了）。
2. **补上第 1 条后仍不生效** —— 「**打印编译后的选择器**」发现产物是 `[data-v-x] .n-tag__content`，
   **`.fs-tag` 前缀整个丢了**（纯 CSS 块里嵌套 `:deep()` 被 CSS Nesting 搅坏）⇒ 必须写扁平规则。

⇒ 结论：**"打印编译后选择器" + "局部放大截图" + "逐元素量宽度"，三件一起才能抓到这一层的问题。**

## 附加：本轮顺带改掉的两处规则

- **折叠从 `首 + … + 父 + 当前` 改成 `首 + … + 当前`**：截图显示即使 1280px、4 格也正好吃满导航区，
  末段被压到 22px（**连 padding 都被裁**）。Apple HIG 与 Fluent 2 说的都是「首 + 末」，没有"父"这一格。
- **分隔符定位改用 CSS 变量**：原写法 `left: -13px` 是魔数，而 gap 只有 8px ⇒ 往左多插 5px、
  压在**前一个标签的右边框**上（用户截图报的就是这个）。现在空隙宽度只有一个来源，`›` 居中落在空隙里。
