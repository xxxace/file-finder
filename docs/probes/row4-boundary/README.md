# row4-boundary · "前三行正常、第四行开始错"的界限

```bash
bash docs/probes/row4-boundary/run.sh
```

**验什么**：业主 2026-10-04 三次报「**前三行怎么玩都行，到第四行就开始有问题**；
第四行之后只能靠上下键，**左右键灵，但上下键走的不是那一列**」。

**13 PASS / 0 FAIL。**（无头 Electron，窗口按主屏真实尺寸 **2048×1280**）

## 结论：不是虚拟滚动，是**视口的物理边界**

| 候选 | 实测| 结论 |
|---|---|---|
| **虚拟滚动** | DOM 里格子数 = **72/ 72**（视口外 8 行**全在 DOM 里**）| ❌ **不是** |
| **懒加载** | 只管 `<img>`，不管格子；`offsetTop` 漂移 0.000px（见 `cursor-scroll-cache` S2）| ❌ **不是** |
| **视口边界** | 见下 | ✅ **是** |

## 关键数字：为什么偏偏是"第四行"

```
网格可视区高度 = 1145.0px   （1280 窗口 − 头部 40 − 工具条 34 − padding）
格高1.5rem      = 307.2px   （1rem = 2048/10 = 204.8px）
⇒ 1145 / 307.2 = 3.73 行
```

实测每一行的可见性：

| 行 | 完整可见 | 可见比例 |
|---|---|---|
| 1 / 2 / 3 | **是** | 100% |
| **4** | **否** | **60%**（被切掉 40%） |
| 5+ | 否 | 0% |

⇒ **第 1–3 行完整可见（按方向键不触发滚动），
第 4 行是第一个"要滚才看得全"的行** —— 这就是主人观察到的那条线。

R3 逐行实测滚动（`__focusCursor` 与产品 `focusCursor` 同构：设焦点 + `scrollIntoView`）：

```
第 1 行：需要滚动=false · box 0→0    · window 0→0
第 2 行：需要滚动=false · box 0→0    · window 0→0
第 3 行：需要滚动=false · box 0→0    · window 0→0
第 4 行：需要滚动=true  · box 0→124  · window 0→0   ★ 第一次滚动
第 5 行：需要滚动=true  · box 124→441
```

⇒ **第 4 行 = 第一次作废缓存的那一行** ⇒ 也就是"从这一行开始一错到底"的那一行。

## R5 · 为什么"左右键灵、上下键不灵"（扫全部 72 个焦点位置 × 4 方向）

| 方向 | 走错数 | **平均偏差** | 最大偏差 | **原地不动** | 偏差≥1 行 |
|---|---|---|---|---|---|
| `up` | 60/72 | **3.92 格** | 6 | 1 | **55** |
| `down` | 71/72 | **2.39 格** | 5 | 1 | **55** |
| `left` | 60/72 | **1.00 格** | 1 | **72** | 0 |
| `right` | 60/72 | **1.00 格** | 1 | **72** | 0 |

⚠️ **左右键不是"没坏"，是"错得看不出来"**：
偏差**恰好 1 格**，且**72/72 全部原地不动** ⇒ 主观上就是"按了没反应/卡住"。

⚠️ **上下键是"错得很明显"**：平均偏差 2.4–3.9 格、**55/72 直接差了整行**
⇒ 一眼就看出"跳错行了"，也正是主人说的"**不是那一列**"。

## ⚠️ 探针自身踩的坑（第二版修的）

第一版 `__setCursor` **只改 class、不调 `scrollIntoView`** ⇒ 量不到"跨过视口边界"这件事，
R3 显示"全程没滚过"。必须让探针的落焦动作与产品 `focusCursor` **同构**。

另一版判据把"视口装不满 3 整行"写成 `< 3`，而实测是 3.73 ⇒ 判据本身写错了
（应该是"装 3 整行**加一部分**"）。
