## 排序标准（三条同时满足才进 A 级）

1. **填真实缺口** —— 不是"锦上添花"，是当前做不到的事
2. **读盘代价低** —— 主人 2026-10-03 定义：「零读盘」= *读盘有代价，尽可能少读*
3. **复用现成设施** —— 不引新依赖、不新建基础设施

## A 级：建议做（两条，都是零读盘）

### A1 · 全局搜索

| 项 | 内容 |
|---|---|
| **现状** | `filterByName(dataSource, searchText)` —— **只过滤当前层**。1202 条目 / 5 块盘的库上，它等于"在当前这一格里找" |
| **要做** | 跨目录（可跨盘）搜索 + 结构化过滤（类型 / 大小区间 / 年份 / 盘） |
| **读盘代价** | **零**。nedb `loadDatabase()` 启动时全库载入（`nedb.ts:229`），`loadMeta` 已实测中位 0.84 ms |
| **成本** | 中。服务端加一个查询入口（走 `loadMeta` / `findCache` 同一套），前端加一个结果面板 |
| **可行性前提** | ✅ **已核实**：`loadMeta({withBytes:true})` 已在服务端内存里聚合（`server/index.ts:858`/`957`）⇒ 纯内存查询这条路是**已经铺好的**，不是新建 |
| **风险** | ⚠️ 1202 条目规模下**必须防卡顿**：全库 `data[]` 拉进渲染层会冻界面 ⇒ 应该在服务端过滤、只下发命中项 |
| **为什么 A 级** | 唯一同时满足三条标准的项 |

## B 级：值得做，但要你确认值不值

### B1 · 键盘导航 + 排序

| 项 | 内容 |
|---|---|
| **现状** | 只有 4 个单键（S / D / F5 / Backspace）。**无方向键、无排序、无视图切换**，纯网格单视图 |
| **要做** | ↑↓←→ 移动焦点、Enter 打开、Home/End；点标题或右键排序列 |
| **读盘代价** | 零 |
| **成本** | 小。网格是"margin 撑间距 + `width:100%/6−10px` 补偿"的算法（`CHANGES-2026-10-02.md` §五）⇒ **加焦点态不能参与布局**，否则 6 列会算错 |
| **提醒** | 记忆里的坑：`minWidth 1024` 下断点实际触不到；`@media` 看的是 viewport 不是 `#stage.style.width` |

### B2 · 缓存库「刷新年龄」呈现

| 项 | 内容 |
|---|---|
| **现状** | 缓存记录表里有 `create_at`，但**没有"你正在看的数据是什么时候扫的"** |
| **要做** | 面包屑/标题栏显示"本层数据扫描于 X 天前" |
| **读盘代价** | 零 |
| **成本** | 小 |
| **为什么值得** | 移动硬盘的数据可能已经变了。**没有这个信息，用户无法判断"看到的列表是不是真的"** —— 这正是离线优先应用的诚实义务 |

### B3 · 目录"上次扫描耗时 / 抽帧失败率"

| 项 | 内容 |
|---|---|
| **现状** | 扫描有时长但没记录；`ffprobe` 泄漏已实测成立（记忆 §六） |
| **读盘代价** | **零**（复用已有记录）。但要新增计时字段 ⇒ 改动存储结构 |
| **成本** | 中。⚠️ `CACHE_VERSION` 非必要不升（铁律 5）⇒ 要么塞进现有字段，要么升版本，**这条得你定** |

## D 级：唯一保留的"领先"方向（但我建议**不排第 1**）

**在不读盘的前提下，把"盘的状态"讲清楚。**

现在这个应用**不知道**下列事实，而它们全部零读盘可得（`serial` + `relPath` + `size` 全在库里）：

| 它不知道 | 现有设施 |
|---|---|
| 「这部作品只在 E 盘，拔了就永久没了」 | `loadSubtreeBytes` 子树聚合已实测 0.84 ms |
| 「每块盘各存了什么类型 / 体积 / 年份」 | 同上 |
| 「4 块盘里哪块最久没扫」 | `loadMeta` 的 `create_at` |

**为什么排 D 不排 A**：它的价值随盘数增长而增长，**现在 5 块盘还没到临界**。
等盘到 8-10 块、或者你真的发生过"拔盘后永久打不开"这件事，它才值得做。

**它唯一真差异化的地方**：别的文件管理器要么读盘去算，要么压根不管盘。
`driveIdentity.ts` 已经认得每块盘的序列号 —— **身份已经在手，缺的只是"拿身份做统计"**。

## 一句话总结

**能做的都列在这儿了。真正值得做的只有两条：全局搜索（零读盘）+ exe 图标目视（极小）。**
