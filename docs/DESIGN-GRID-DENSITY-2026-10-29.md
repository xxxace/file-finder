# 网格密度三档（宽松 / 标准 / 紧凑）· 设计

日期：2026-10-29 · 状态：待主人批准 · 规模：小改动

## 一、意图

Flat 摊开后一屏动辄上千条，恒定 6 列一屏只看得到十几格 ⇒ 扫片要靠不停滚。
给主人一个**常驻**的密度开关：三档切换列数，摊开时用紧凑档快速扫，回到普通目录用宽松档看细节。

## 二、目标

1. 三档常驻：任何目录都能切（普通 / flat / 只读层 / playlist / 搜索结果），不随视图模式出现或消失。
2. 一次点开即可选到目标档，当前档一眼可见。
3. 记住上次选择，重启 app 仍是那一档。
4. 切换**零读盘、零请求**：纯 CSS 变量重排。

## 三、非目标

- **不做自动响应式断点**。10-21 主人已裁定「删掉 5/3/2/1 断点、恒定列数」；这次是「用户自己选列数」，不是把断点加回来。
- 不做每屏记忆（一个全局偏好即可）。
- 不改缩略图生成尺寸：384px 在 12 列下显示 147px，DPR 1.5 ⇒ 需 220px，够。
- 不做切换时的滚动位置补偿（切换通常意味着"从头扫"，代价大于收益）。

## 四、反目标

- 加列数滑杆 / 无限档位 —— 每次都要重新想，是认知负担。
- 塞进「更多」下拉 —— 那是低频动作的家（换封面、站点规则）；密度属于**视图动作**，和 flat 按钮同类。
- 为三档各写一套卡片 CSS —— 只有「紧凑」需要覆盖，其它两档共用现状值。

## 五、约束（不可违反）

1. **列数只有一个真相源**：`density.ts` 的档位表 → 绑定到 `.image-box` 的 `--ff-grid-cols` → CSS 唯一消费点。
2. **同行等高**：`gridGeometry.groupRows()` 按 `offsetTop` 分行，同排格子高度必须一致 ⇒ 标题区高度只能由**档位**决定，不能由内容撑。
3. `.toolbar { flex-wrap: nowrap }` 与 `.header-bar .n-input { width: 260px }` 两条不许动（历史事故）。
4. 不在 `n-space` 里放**会增减**的子元素 ⇒ 密度控件用 `n-dropdown`，不引入新的 space 容器。
5. 方向键的行结构缓存必须跟着档位失效（见 §七.6）—— 这是**正确性**问题，不是优化。

## 六、方案

### A（弃）：三段常显按钮组
三颗图标按钮常驻工具栏，占宽约 100px，一次点击直达。
弃用理由：主人裁定「空间不够」；工具栏已有 4 个控件，1024 最小窗下导航区还要留折叠余量。

### B（选）：一颗图标按钮 + 下拉
图标（九宫格）+ 下拉箭头，点开菜单选三档，当前档打勾。占宽约 55px。
选它的理由：省 45px；密度不是高频动作（一天数次，不是每分钟）；与「更多」的下拉语言一致。

## 七、已定细节（我做出的决定，可被推翻）

### 1. 档位表

| 档位 | key | 列数 | 格宽 @2048 |
|---|---|---|---|
| 宽松 | `wide` | 6 | 310px |
| 标准 | `normal` | 8 | 229px |
| 紧凑 | `tight` | 12 | 147px |

### 2. 默认档 = `wide`（6 列）
就是今天看到的观感，切换是可选动作，不会一打开就变样。
（"标准"在中间但不做默认：默认该等于现状。）

### 3. 窄窗保护：纯 CSS，一行
`.image-box-item { min-width: 110px }`（新 token `--ff-grid-min-cell`）。
`width` 是百分比首选值，`min-width` 是硬下限 ⇒ 窗口窄到百分比算出的宽度 < 110px 时，格子被抬到 110px，`flex-wrap` 自然少放几个 ⇒ **自动降档**，无需 JS 监听窗口。
1024 窗（容器约 936px）下紧凑档会自己退到 **7 列**（936 ÷ (110+16) = 7.4），不会出现一屏 62px 的糊片。

### 4. 紧凑档的排版收缩
只有 `tight` 覆盖，`wide`/`normal` 共用现状值：

| 量 | 现状（宽/标） | 紧凑 |
|---|---|---|
| 标题高 | 40px | 34px |
| 标题字号 | 14px | 12px |
| 标题行高 | 20px | 17px |
| 角标高 | 18px | 16px |
| 角标字号 | 12px | 11px |
| 卡片内下边距 | 6px | 4px |

实现方式：`.image-box[data-density='tight']` 上覆盖一组 `--item-*` 变量，`.image-box-item` 消费。**不写第二套选择器**去直接改 `.card-title`。

### 5. 持久化
`localStorage['ff.grid.density']`，值为档位 key。读取时**白名单校验**，非法值退回 `wide`（不信任存储里的旧值）。
写法照 `useTheme.ts`（本项目已有的 localStorage 先例）。

### 6. 键盘选择器必须跟着失效（真风险）
`useGridCursor` 的 `layoutCache` 只在 `fileList` 变化与 `window resize` 时失效。
切档只改 CSS 变量 ⇒ **不触发**这两个 ⇒ 缓存里还是旧的 `rows`（6 列的行结构）
⇒ 切到紧凑档后第一次按 →，会按旧列结构跳格 / 撞边界（与 2026-10-04 那次"第 4 行起全错"同族）。

做法：`useGridCursor(deps)` 增加可选 `cols: ComputedRefLike<number>`，内部 `watch(cols, invalidateLayout)`。
**不**在 `index.vue` 的切换回调里手动调失效 —— 新增第 2 个切档入口就会忘；由模块自己订阅，结构上不可能漏。

### 7. 代码落点

| 文件 | 动作 |
|---|---|
| `src/views/FileFinder/density.ts` | 新增：档位类型、档位表、`loadDensity()` / `saveDensity()` |
| `src/views/FileFinder/GridDensityMenu.vue` | 新增：受控 `v-model`，图标按钮 + `n-dropdown` 三项 + 打勾 |
| `src/views/FileFinder/index.vue` | 模板加一个 `<GridDensityMenu v-model="density" />`；`.image-box` 绑定 `:data-density` 与 `--ff-grid-cols`；CSS 改 3 处（`--item-width` 用变量、加 `min-width`、紧凑档覆盖） |
| `src/views/FileFinder/useGridCursor.ts` | 增加 `cols` 依赖 + 一个 `watch` |
| `src/styles/tokens.css` | 新增 `--ff-grid-min-cell: 110px` |

`index.vue` 已 3423 行，所以**新 UI 拆子组件、纯逻辑拆 .ts**（模块化纪律），index.vue 只增 3 行左右。

### 8. 位置
工具栏里，紧挨 flat 按钮**左侧**（视图类动作聚在一起：密度 → 平铺 → 刷新）。

## 八、留给实现者的自由

- 图标具体画法（九宫格线框，14×14）
- 菜单项文案是否带列数（建议带，如「宽松 · 6 列」）
- 是否给快捷键（**不做**，键盘已被方向键/回车/空格/S/D/F5 占满）

## 九、验收

1. `npm run typecheck` 0 error。
2. 三档目视：列数对、标题不溢出、同排等高、右侧贴边。
3. 切档后立刻按方向键（尤其 → 和 ↓）不错位，三档都试。
4. 重启 app 档位保持；手改 localStorage 成乱值不炸。
5. 1024 窗宽下紧凑档自动降到约 8 列（目视）。
6. flat 模式下切档不重新读盘（无请求、无 spinner）。
