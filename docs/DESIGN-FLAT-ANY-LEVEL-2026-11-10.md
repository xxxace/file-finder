# 平铺视图放开到任意层级 —— 2026-11-10

> 业主原话：**"flat 之前只限定盘根可以开启，我觉得很不好用，尝试改成所有层都可以开启，
> 都从自身向下 flat，这样子实现可以兼容任意层级。"**

## 1. 结论

改完了，**只删闸门、没加功能**：服务端那个"从传入路径向下合并"的遍历本来就在，
限制它的是 `isCacheRoot()` 这一道判断。删掉它之后，任意一层都能平铺。

**零读盘**（这是能放开的前提，见 §3）。

## 2. 事实基线（改之前是什么样）

| 位置 | 原来 | 判据 |
|---|---|---|
| `electron/server/index.ts:1113` / `1159` | `if (flat && await isCacheRoot(serial, relPath))` | 请求的路径**必须**是"采集源头"（有子目录、且自身没有更上层记录）才允许 flat |
| `findSubtreeLeafItems(serial, baseRel, mode)` | 已存在 | **本来就是"从 baseRel 向下"**：DFS 收 `doc.data` 里的叶子，再加一条"兜底收集未在父 data 里展开的子孙记录" |
| `src/.../useScreenData.ts` | 每次取数先打一次 `/isCacheRoot` | 拿到 `isRoot=false` 就**自动把 flat 关掉** |
| `canToggleFlat` | `isCurrentCacheRoot && !playlistLevel && !!currentPath` | 只有盘根能开 |
| 平铺按钮 tooltip | "仅在根缓存目录可开启平铺视图" | — |

⇒ 换句话说：**能力早就有，缺的只是一个 `if`**。这也是这次改完 `-0` 行新逻辑的原因。

## 3. 读盘清单（硬约束：必须主动交代）

**零读盘。** 三条依据：
1. `mergeSubtreeLeafItems` 是**纯函数**（只吃 nedb 里的 `rows`，不碰 `fs`），函数注释原文就写着"严格零读盘"；
2. 反而**少了一次往返**：原来每次 `fetchFolder` 都额外请求 `/isCacheRoot`（纯内存判定，但也是一次 HTTP + 一次 nedb 查询）；
3. 平铺结果**不写缓存**（每次按缓存行现算），不新增任何写盘。

## 4. 改动清单

**服务端**
- 两处 flat 闸门 → `if (flat)`（锚点分支那一处也一起放开：只读层同样能任意层平铺）。
- 删 `/isCacheRoot` 端点 + `isCacheRootController`；删 `nedb.ts` 的 `isCacheRoot` / `checkIsCacheRoot`。
  判据同 2026-11-07 删 `flexible.ts`：**前提消失**（唯一消费者就是那道闸门与那个端点），
  不是"看着没人用就删"—— 同查生产者与消费者，两边都归零才动。

**渲染层**
- `useScreenData`：删 `/isCacheRoot` 探针那一整块；`useFlat` 从 `canToggleFlat && isFlatView` 简化为 `isFlatView`
  （`canToggleFlat` 从此只是"界面上按钮能不能点"，不再是取数条件 —— 平铺能不能开不该影响"取数怎么取"）。
- `index.vue`：删 `isCurrentCacheRoot` ref 与它的两处 `= false`；`canToggleFlat = !playlistLevel && !!currentPath`。
- 平铺按钮 tooltip 改口径；空态加一条（见 §5）。

## 5. 语义与边界

- **"从自身向下"** = `baseRel` 这一层自己的文件 + 它下面**已缓存**的整棵子树，逐层 DFS，含"父目录 data 没列出来但记录存在"的兜底支路。
  ⚠️ 不认识"向上"：父级与兄弟目录**永远**不会进来（探针第 2 条就是这个反证）。
- **只摊缓存里已经有的**：深层没扫过 ⇒ 平铺出来可能是空的/稀的。那是缓存态，不是丢东西。
  ⇒ 空态文案专门加了一条："这一层下面还没扫到作品 —— 平铺只摊缓存里已有的，「更新读取」扫一遍再看"。
- 清单屏（`@pl:`）依旧不能开：清单不是目录，没有"向下"这回事。
- 换屏（下钻 / 面包屑 / 缓存跳转）时 `isFlatView` 照旧由 `enterScreen` 复位（只有缓存跳转的 `keepFlat` 会带过去）——
  与"只在盘根能开"时代的观感一致：**平铺是这一屏的视图状态，不是全局模式**。
- 拔盘换锚点时平铺保留（`fetchFolder` 读 `isFlatView`），服务端锚点分支同样支持。

## 6. 验收

- `npm run typecheck` 0 error（含 `tsc -p tsconfig.electron.json`）
- `node docs/probes/flat-subtree/model.mjs` → 6/6（盘根 / 中间层 / 三层 / 兜底支路 / 大小写反斜杠 / 跨盘过滤）
- 真机（**改主进程 ⇒ 必须重启 dev**）：
  1. 进到"盘根 › 某分类"这一层，点平铺 ⇒ 只出现这一层下面的作品，**不含**旁边别的分类
  2. 再进一层点平铺 ⇒ 只剩它自己的
  3. 平铺下点面包屑回上一层 ⇒ 回到普通视图（不是"平铺跟着走"）
  4. 从来没扫过的深层点平铺 ⇒ 出现那句"还没扫到作品"，而不是空白

## 7. 遗留（需业主裁决，本次不做）

| 项 | 为什么不做 |
|---|---|
| 平铺时**顺带扫一遍子树**，让深层平铺"一定有内容" | 那是**真读盘**（一层层 stat + 读目录）。本项目第一优先级是少读盘 ⇒ 必须先经你点头，且要单独给读盘量估算 |
| 平铺状态下继续下钻 | 平铺没有目录条目可点，本来就没有下钻入口；要支持得另设交互 |
