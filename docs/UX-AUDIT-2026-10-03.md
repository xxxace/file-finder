## 一、头部 / 工具条

### 1. 搜索框 placeholder 没说清搜的是什么
| 项 | 内容 |
|---|---|
| 现象 | 主界面写「搜索」（`index.vue:112`），而「缓存记录」面板写的是「搜索目录名」 |
| 问题 | 两处**搜的东西不同**（主界面搜当前层条目名，面板搜目录名），但文案长得一样 ⇒ 用户以为是同一个东西 |
| 建议 | 主界面改成「搜索本层」（**改一个字符串**） |
| 成本 | 极小 · **证据：静态** |

### 2. 悬停/激活配色是硬编码的，与 naive-ui 主题脱钩
| 项 | 内容 |
|---|---|
| 现象 | `.image-box-item:hover` 用 `#7a8da9` / `rgba(110,123,173,.16)`；选中用 `#18a058`（`index.vue:1752-1761` / `:1629`） |
| 问题 | 项目**没有自定义主题**（`App.vue` 无 `themeOverrides`，见 `:1619` 注释）⇒ 这些值是手调出来的，**没有统一色板** |

| 成本 | 小 · **证据：静态** |
| 备注 | 单看每条都不像 bug，但**调整观感时没有一个统一旋钮** —— 属"重构"性质，看主人要不要 |

## 二、网格

### 4. ⭐ 文件名只显示一行，但高度留了 38px（**最有性价比的一条**）
| 项 | 内容 |
|---|---|
| 现象 | `index.vue:1738-1750`：`height: 38px !important` + `line-height: 1em` + `white-space: nowrap` + `text-overflow: ellipsis` |
| 问题 | `line-height:1em`（=16px）⇒ 38px 的高度**够两行**，却因为 `nowrap` **只显示一行**，下面空着约 22px。而这批文件名通常很长（带编号/标题），**一行装不下，被截成省略号** |
| 建议 | 允许**两行**（去掉 `nowrap`、用 `-webkit-line-clamp: 2`）。高度 38px 不用改 |
| 成本 | 小（改 CSS）· **证据：静态** |
| ⚠️ 硬约束 | **不能新增参与布局的属性** —— 6 列宽度是"margin 撑间距 + `width:100%/6−10px` 补偿"算出来的（`:1667-1685`）。本条只改文字内部换行、**高度已固定**，相对安全，但**必须目视确认格子没变形** |

### 5. ⚠️ 网格断点**实际永远不触发**（真问题，不是观感）
| 项 | 内容 |
|---|---|
| 现象 | `--item-width: calc(100%/6)`（`:1702`）；断点写在 `max-width: 1100/600/400/300/200px`（`:1763-1781`） |
| 问题 | `@media (max-width)` 看的是 **viewport**，而窗口 `minWidth: 1024` ⇒ **600/400/300/200 这四个断点永远不会命中**，是**事实上的死代码**。窗口拉到最小 1024 时仍是 6 列 ⇒ 每格约 165px |
| 建议 | 把断点挪到**真实会出现的宽度**（如 1280 / 1440），或引入密度调节 |
| 成本 | 小（改断点值）/ 中（密度调节）· **证据：静态**（断点值 + `minWidth 1024` 都是查过的） |
| 备注 | 与记忆一致：`@media (max-width)` 看 viewport；改 `#stage.style.width` **不会**触发断点，测响应式必须 `win.setSize()` |

### 6. 无排序
| 项 | 内容 |
|---|---|
| 现象 | 条目顺序 = 服务端 `readdir` 的原始顺序（`electron/server/index.ts:220`），前端不排序 |
| 问题 | 用户无法按名称 / 大小 / 时间排。找东西时"顺序不对"会让浏览变慢 |
| 建议 | 工具条加排序下拉（名称 / 大小 / 时间，升降）。⚠️ **纯内存可做**（数据已全在内存），零读盘 |
| 成本 | 中（新增控件 + 排序状态）· **证据：静态** |

### 7. 无多选
| 项 | 内容 |
|---|---|
| 现象 | 唯一的"选择"是「换封面」模式的专用选择（`index.vue:1265`） |
| 问题 | 无法批量操作（如批量复制文件名） |
| 建议 | ⚠️ **建议先不做** —— 批量操作一旦涉及写盘就违背最高优先级；纯"复制文件名"类批量的收益有限 |
| 成本 | 中 · **证据：静态** |

### 8. `transition: all .1s` 过宽
| 项 | 内容 |
|---|---|
| 现象 | `index.vue:1718`：`transition: all .1s ease-in-out` |
| 问题 | `all` 会连带过渡**布局属性**（width/height/margin），在网格里可能引起不必要的重排与抖动 |
| 建议 | 收窄为 `border-color, background-color, box-shadow` |
| 成本 | 极小 · **证据：静态** |

本项目已实测确认：**结构**（渲染出几个节点）可用 happy-dom 验；**布局**（几行、多宽）可用 Playwright + 真 Chrome 验；
**观感**（好不好看）**只能人眼**。以下必须目视：

1. 6 列在 **2048 宽**下每格约 330px —— **是不是过大**（一屏只看到 6 个）

4. hover / active 那组配色（见第 2 条）**是否协调**
5. 只读横幅 / 失败横幅在真实数据下的**视觉分量**
