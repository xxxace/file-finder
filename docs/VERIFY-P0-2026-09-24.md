## 二、3 处改动（逐处）

### 1) `nedb.ts` + `server/index.ts` —— 把"删除"从启动路径上移除

- 删掉整个 `dropLegacyRecords()`（含 `count → 备份 → remove → compact` 那一串）。
- `server/index.ts` 末尾那行 `dropLegacyRecords().catch(...)` 换成一段说明**为什么不能有它**的注释。
- `CACHE_VERSION` 的文档注释同步改写：版本不符**不再等于删**。

> 判据从 `{ v: { $ne: 2 } }` 改成"什么都不做"。原来那个判据的实际含义是
> **"没有 `v` 就删"**（nedb 的 `$ne` 连字段不存在也匹配），
> 于是"格式完全正确、只是没打版本号"的记录会被一起干掉。

### 2) `nedb.ts` 的 `findCache` —— 版本不符即当未命中

```ts
const found = (doc as SearchCache) || null;
resolve(found && found.v === CACHE_VERSION ? found : null);   // ← 新增
```

删都不用删：下次浏览那个目录时 `scanAndCache` 会 `removeCache + insertCache`，
把同一主键**整条**换掉，旧的自然被 remove 带走。

### 3) `server/index.ts` —— 条目按白名单重建

```ts
export type WiredFileInfo = Omit<FileInfo, 'thumbData' | 'avatarThumbData'>;

export function pickFileInfo(raw: FileInfo): WiredFileInfo {
    return {
        dir: raw.dir, name: raw.name, isDirectory: raw.isDirectory,
        ext: raw.ext,
        files: raw.files?.map(f => ({ name: f.name, size: f.size })),   // 嵌套那层也重建
        type: raw.type, size: raw.size, thumb: raw.thumb, avatar: raw.avatar,
    };
}
```

`wire()` 里 `stripThumbData(item)` → `pickFileInfo(item)`。

⚠️ **白名单是 9 个"会下发"的字段，不是 `FileInfo` 的 11 个**：`thumbData` /
`avatarThumbData` 是**只存不发**（base64 由 `wire()` 登记进内存索引，渲染层只拿
`thumb` 这个 key 去 `/thumb` 取）。第一版把它们也放进了白名单 → 实测下发 JSON 里真的
出现了 base64（探针抓到的，见 §六）。

## 三、验收判据的实测结果（A/B 对照）

走**同一套**断言。

| 判据 | `before`（旧代码） | `after`（新代码） |

## 四、探针怎么做的（可复算）

隔离原则：**独立端口 + 独立数据目录 + 独立 fixture**，不碰真实 `~/.file-finder`、
不碰 `E:/` `F:`（用户的实例正占着 3060，探针用 3061/3062）。

```
探针目录（系统临时目录，可留可删）：
  C:\Users\<user>\AppData\Local\Temp\ff-p0-verify-1790239584\
    before-src/   ← git archive HEAD electron（对照组）
    after-src/    ← 工作区 electron 的副本（被测）
    out/{before,after}.cjs   ← esbuild 打成 CJS，external 全部裸模块（与生产 notBundle 契约一致）
    electron_stub.cjs        ← electron 替身（只补 nativeImage 那一点）
    run.cjs                  ← 灌种子 → 起服务 → 跑断言 → 出报告
    fixtures/  *-data/       ← 夹具与隔离库

复算：cd 到探针目录，NODE_PATH=D:/code/file-finder/node_modules node run.cjs after
```

两个探针侧改动（只改副本，源码零污染）：`config.userBasePath` 钉死在探针数据目录、
`app.listen` 端口换成 3061/3062。另：产物里那句 `Local Server: http://127.0.0.1:3060/`
是**没被替换的日志字面量**，与实际监听端口无关（探针靠 HTTP 就绪探测，不靠这行日志）。

## 五、偏离开工件的地方（3 条，都需要你知情）

| # | 偏离 | 为什么 |
|---|---|---|
| 1 | 白名单挂在 **`wire()`**（唯一的下发出口），而不是只挂在"取缓存"那一支 | 开工件写的是"取缓存分支"。但 `wire()` 自己的注释就写着"所有下发路径都必须过这里，且只留这一处" —— 放这里等于把约束放在咽喉点，UNC 那条非缓存路径也一起管住，谁都不用记得清一遍。放分支里就是"每个调用方各加一道守卫" |
| 2 | **删掉了 `stripThumbData`**（第 3 个文件 `thumbStore.ts`） | 白名单接管后它零引用。留着一个**黑名单** helper 就是给同类 bug 留复发入口（用户判据：以后新增同类场景会不会复发）。它的类型含义（`Omit<...>`）被 `pickFileInfo` 的返回类型接管 |
| 3 | 白名单是 **9 个下发字段**，不是开工件写的"10 个" | 开工件那个数字数的是 `FileInfo` 的字段；但其中两个是"只存不发"。照字面实现会把 base64 发回渲染层（第一版真踩了） |

**另**：`compact()` 改完**没有调用方**了（原本只有 `dropLegacyRecords` 用它）。**保留**了，
并在注释里写明"现无调用方"—— 它上面那段是 @seald-io/nedb 4 换库时私 API 失效的取证，
将来做维护入口（`/compact`）还要用。要删你说一声。

## 六、过程中被推翻的两个判断（记下来，别再犯）

| # | 我先前的判断 | 实测 | 教训 |
|---|---|---|---|
| 1 | "对照组里旧代码**没有**删掉那两条记录 → 说明 `dropLegacyRecords` 本来就不生效" | ❌ 是**探针自己的时序问题**：`dropLegacyRecords()` 是 fire-and-forget（`.catch()` 连 `await` 都没有），我在 1 秒内就 `process.exit`，读到了"还没删完"的中间态。给两个变体加同样的 2.5 s 等待后，对照组立刻复现（`已清理 2 条`、记录归零） | **对照组必须给被测的异步行为同样的落地窗口**，否则"通过"和"失败"都是噪声。这正是"自己写的对照组是坏的"那类坑 |

### 8.3 ⚠️ 复算这个探针前**必须**先清数据目录（否则会看到假 FAIL）

`run.cjs` 的 `seed()` **只 `insert`、不清库**，而数据目录是 `path.join(PROBE, variant + '-data')` ——
**在脏目录上重跑会叠加**：上一轮留下的 `v:2` 记录会和这一轮的种子同主键共存，
于是 `findCache` 命中的是那条**遗留的 `v:2`**、压根不会走 `scanAndCache`，
判据 2b 就报"该主键下 2 条"→ **2 条假 FAIL**。

实测：`%TEMP%\ff-p0-verify-1790239584\report-after.txt`（16:51 那份）就是这个脏产物，
结尾写着「after：2 条判据未通过」，**与本文 §三 的结论矛盾** —— 但它不是代码问题，
是探针被重复执行造成的。清空 `<variant>-data` 后重跑即全绿（见 §8.1）。

> **归档的那份才是准的**：`docs/P0-probe-{before,after}.log` 都是 `seeded 记录：3 条` 的**干净跑**。
> 教训一句话：**探针的可复算性 = 脚本 + 前置状态**。只给脚本不给"必须先清库"，复算的人必然被自己骗一次。
