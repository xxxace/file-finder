**移植时改的三处，每条都有理由**
1. **颜色去彩**：本项目无彩纪律（唯一彩色只给选中/焦点）。白 + `globalAlpha`，不拼 `rgba` 字面量（`probes/tokens/no-raw-color.mjs` 会拦）。
2. **范围收窄到 image-box**：动效只覆盖网格可视区，不是整窗 —— 用户的注意力应该留在"这一片"上。
3. **必须能终止**：原式是一段不可打断的 5.2s；这里加「终止」按钮 + `Esc`。

## 二、结构（为什么要包一层）

```
.file-finder (flex column)
└─ .image-box-wrap (position: relative; flex: 1)   ← 2026-11-08 新增，只为给动效一个定位祖先
   ├─ .image-box (overflow: hidden auto)           ← 原样，仍是滚动容器
   └─ ScanGlow (position: absolute; inset: 0)      ← 不随内容滚走
```

`ScanGlow` **不能**放进 `.image-box` 里：那一层自己是滚动容器，遮罩会跟着内容一起滚。
给 `.image-box` 的父级加 `position: relative` 也不行 —— 那个父级还装着横幅与扫描状态条，
`inset: 0` 会连它们一起盖住。所以只加一层不带其它职责的壳。

## 三、时长与阶段：为什么不是固定 5 秒

真实扫描可能几十毫秒（缓存全命中）也可能 30 秒，所以**没有固定进度**：

- `running` 为真时：**每 5.2 秒一轮「抬起 → 扫走 → 再抬起」**（`p` 取 `(elapsed % 5.2s)/5.2s`，
  `rise` / `sweep` / `dust` 全是参考件原式，一个字没改）；文案 2.6s 后换第二段。
  ⚠️ **不要为了"适配不定长"把 rise/sweep 换成缓慢呼吸** —— 2026-11-08 干过一次，
  主人当场否掉：「向上抬起」那一下才是这个动效的重点。遮罩由独立的进出场包络控制，
  所以每轮结尾光扫走时，画面只是光没了，不会闪白。
- `running` 变假：开始 `320ms` 退场，退完 emit `closed`，父组件摘掉。
- **最短 2000ms**：收尾时间点取 `max(任务结束, 进场 + 2s)`。
  否则缓存命中的目录会"闪一下就没"，看着比不做动效更糟。

## 四、接线（已去掉演示开关）

`startScan(rescan)` 是这个动作的**唯一入口**（两处菜单都走它，没有别的调用点），所以动效就挂在那儿：

```ts
scanning.value = true;
glow.value = rescan ? 'rescan' : 'fill';   // 起
glowKey.value += 1;                         // 每次都重建实例（上一次的退场没播完又点了，也不会串）
...finally: scanning.value = false;         // 组件看到 running=false，自己退场并 emit closed
```

「终止」= `onScanCancel()`，与扫描条那个「取消」是同一个函数（软取消，只在目录边界生效）；
`cancelling` 为真时按钮变「正在取消…」并置灰。

## 五、曾经踩的两个坑（第一版为什么"看不到光"）

1. **遮罩压住了光**：`veil` 写在 `canvas` 之后 ⇒ 0.45 的遮罩色把整片光盖黑。
   层次必须是 `veil（压暗内容）→ canvas（发光）→ panel（文字）`。
2. **强度按"白色"调的，换成彩色后同样看不见**：白光的 alpha 0.06~0.14 在暗底上几乎为零；
   现在是 0.22~0.34，颜色本身也带亮度。

### 五·三、遮罩的"方向"（2026-11-08 主人追问后查证）

先给事实：参考件的遮罩是 **`.tg-white-veil{position:absolute;inset:0;background:#fff;opacity:var(--tg-veil)}`
—— 一块平的白色雾，没有任何方向**；自下而上的只有 canvas 那层光。

那我们为什么看起来"遮罩先从上盖下来"？两处都是实现问题，不是容器问题：

| # | 错在哪 | 现象 | 改法 |
|---|---|---|---|
| 1 | 遮罩用独立的 260ms 包络进场，而光要等到 8.5%（≈440ms）才动 | 中间 180ms 只有暗、没有光 ⇒ 眼睛先读到"盖了一层" | 遮罩的升起窗口与光的 `rise` **完全对齐**（8.5%~20%） |
| 2 | 参考件是**白雾往上糊**，我们用**深色压黑** | 深色压暗只会读成"遮罩落下" | 压暗从 0.70 降到 0.62 |

**真正的根因（2026-11-08 19:58，主人定位）**：不是遮罩，也不是光 —— 是**扫描状态条**。

`.scan-bar-slot` 在**文档流里**，挂上时靠 `grid-template-rows: minmax(0,1fr) → 0fr`
在 200ms 内从 0 长到 40px，而这 40px 是**从网格里扣的**：

```
点「补全」→ scanning=true
   ├─ 状态条挂上，向下展开 40px（视觉：向下的动作）
   └─ image-box-wrap 变矮 40px
        └─ 里面的遮罩/canvas 是 inset:0 ⇒ 一起变矮
             └─ canvas 位图被 CSS **压扁**，光带贴着底边被自下而上挤压（视觉：向上的动作）
```

一个向下展开、一个向上压扁，同一 200ms 里同时发生 —— 这就是"先上后下"。

**修法（改布局，不改动效）**
1. **glow 期间不渲染状态条**：`v-if="(!glow && scanning) || picking"`。
   光雾面板本身已经承担了"在做什么 + 终止"，状态条是重复入口。
2. 它的两条信息搬进光雾面板：`已扫 n / 待扫 m`（`scanDone` / `scanPending`）。
3. `ScanGlow` 加 `ResizeObserver`：容器尺寸一变就重排 canvas 位图，
   不再让 CSS 把画面压扁（这是"动效被布局带动"的另一半原因）。
4. 遮罩回退为**纯 opacity**（跟着进场包络，`0.62`），不带任何几何变换。

**判据**
- `grep translateY ScanGlow.vue` 只应命中文案换行那两个 keyframes。
- glow 在跑时，页面上不该同时出现状态条（`已扫 / 待扫` 只在光雾面板里）。

## 六、样式上的一个硬要求

**遮罩层不能带 `border-radius`**。它盖的是直角的网格区，给它圆角会在右下角露出一块"被啃掉"的边
（主人 2026-11-08 指出过一次）。

## 七、已知风险（未实测项）

- **`filter: blur(7px)` 罩在 500 张封面上会有整层重新栅格化的开销**（`STUDY-MOTION` §五 警告过）。
  半径已压到 7px、时长 420ms、只在动效期间存在；真机上若卡顿，退路是「只用遮罩不上模糊」（改两行 CSS）。
- 动效期间滚轮事件会落到外层，通常滚不动；键盘已被让出。**未在真机验证滚动手感**。
