# 预览层：图与工具条的布局（底部通栏）

日期：2026-10-04 ｜ 状态：**已落地**（`typecheck` 0 error · 几何探针 11 条断言全过·两个视口；
剩**真机目视**，见 §六）
需求（主人原话）：
> 预览图和预览图操作栏的布局是否要调整，因为放到最大的预览图的下方会被操作栏遮盖住，
> 无论是哪一方都占不到好处，你分析一下，也可以上网搜索借鉴，给一个好的体验方案！
> grill-me

---

## 一、问题诊断（先量后改）

**这不是审美问题，是几何上的零和。** 两条实测事实：

| 事实 | 证据 |
|---|---|
| 图的元素盒 = `100vw-32 × 100vh-32`（几乎贴满，底部只留 16px） | `docs/probes/preview-fill/`（真 Chromium，视口 1903×1063） |
| 工具条 = `position:absolute; bottom:40px; height:48px; left:50%` | `naive-ui/es/image/src/styles/index.cssr.mjs:20-38` |

⇒工具条**整条落在图里面**，压掉图底 **88px**（`40 + 48`）。
主人说的「哪一方都占不到好处」，正是这两条叠在一起的结果：
图要最大 ⇒ 条压图；条要不被压 ⇒ 图变小。

**业界（Google Photos / PhotoSwipe / Kalium Lightbox 等）的第三条路**：
工具条**闲置自动隐藏**。Google Photos 的说明里写得很直白——
左右箭头"如果你不动鼠标，几秒后会消失，以免遮住照片"。

## 二、方案空间与裁定

| 方案 | 图 | 条 | 判定 |
|---|---|---|---|
| A. 自动隐藏（鼠标一动回来） | 最大 | 找得到 | ❌ **主人否决**：「自动隐藏没什么意思」——而且条上有名称/计数/9颗按钮，藏起来等于让这些功能"找不到"，反而更差 |
| B. 图让出底部，条放下方 | 小40px | 永远可见、绝不遮挡 | ✅ **采纳**（主人裁定：「让点空间出来吧，在下方，下方的空间尽可能的利用，别浪费」） |
| C. 条移到右侧竖排 | 少一条宽 | 可见 | ❌ 竖排按钮不顺手，且 2048 宽下横向完全够用 |
| D. 只做半透明 | 最大 | 还是挡在那儿 | ❌ 没解决零和 |

**「下方的空间尽可能利用，别浪费」这句是本轮的关键约束**，它否掉了"把条做成窄窄一条居中胶囊"——
内容约 844px，在 2048 宽下两侧各空 602px，**那是浪费掉的底板，不是留白**。⇒ 做成**贴底通栏**。

## 三、定稿的决策（4 条）

| # | 决策 | 理由 |
|---|---|---|
| B1 | **图让出底部 64px**（= 工具条 48 + 间隙 16），上/左/右**仍各 16px**不变 | 上/左/右与改之前逐字一致 ⇒ 不顺手改掉别的维度 |
| B2 | 工具条改**贴底通栏**（`left:0;right:0;bottom:0;transform:none`） | 「下方的空间尽可能利用」；`transform` 必须一起去掉，否则整条左移半屏（探针 ③专测这条） |
| B3 | 条内改**左信息 · 右操作**：左=名称+计数，右=定位/上一条/下一条 + 原有 6 颗 | 2048 宽下居中一坨会挤在中间、左右对称留白，读起来像"漂浮的孤岛"；左信息右操作是资源管理器 / Photos / Figma 的通用骨架 |
| B4 | **次要操作不收进「⋯」**，10 个节点全留在明面上 | 主人原话「符合人类操作习惯和方便快捷」。而且这个场景条上每个动作都用得上（看图 ⇒常旋转/缩放），折叠反而是"多点一次" |

**顺序**：原有 6 颗**一颗没动、✕ 仍在最右**（上次「下载紧邻 ✕ 造成误触」的教训，见 `DESIGN-PREVIEW-NAV` §一 D6）。
新的三样（定位/上一条/下一条）排在按钮组**最左**，与旋转缩放分隔——
「在哪 / 看哪条」一组，「把这条图怎么变」另一组。

## 四、改动清单（全部在 `src/views/FileFinder/index.vue`）

1. **`renderToolbar`**：从"一串平铺"改成**两个 span 分组**（`PREVIEW_GROUP_LEFT/RIGHT_STYLE`，
   右组用 `margin-left:auto` 分左右，不改 naive-ui 的 `justify-content`）。
   名称的 `max-width` 从写死的 `320px` 放宽到 `min(46vw, 720px)` —— 通栏之后左侧能吃下更多。
2. **新增一个非 scoped `<style>` 块**（文件末尾），三条规则：
   - `.n-image-preview-wrapper { padding: 16px 16px 64px }` ← **唯一真正让出空间的改动**
   - `.n-image-preview-toolbar { left:0;right:0;bottom:0;transform:none;height:48px;padding:0 16px;border-radius:0;background:rgba(0,0,0,.62);box-shadow:inset 0 1px 0 rgba(255,255,255,.08) }`
   - `.n-image-preview-toolbar .n-base-icon:hover { opacity:.65 }`（naive-ui **没给**工具条图标写 hover，
     `cssr:35-38` 只有 padding/font-size/cursor + 一个 fade-in transition ⇒ 这里补的是它没有的东西）
3. **其余零改动**：不动`previewedImgProps`、不动 `provide`、不动 naive-ui 任何内部文件。

### 为什么动wrapper 而不是图

`.n-image-preview-wrapper` 是 `position:absolute; inset:0` 的 flex 容器（`cssr:39-46`），
而图的 `width:100%; height:100%` 是**相对内容盒**解析的 ⇒wrapper 加 padding，图的可得区域跟着缩。
直接改图会先和 `previewedImgProps` 的 inline style 打架（inline 赢过类规则）。

### 为什么那个块不带 scoped

工具条与图都被 naive-ui **teleport 到 body**，`<style scoped>` 的 data-v 属性只打在本组件模板里的元素上，
够不到它们（同 `HistoryTable/index.vue:1069` 那个非 scoped 块的先例）。
隔离靠 `.n-image-preview-container` 前缀 **+ 多一层祖先**提高特异性：
naive-ui 的规则是 cssr **运行时注入**的单类选择器，同特异性的先后顺序不可控；
加上祖先层后变成 (0,2,1) 对 (0,1,0)，**稳定赢过顺序** ⇒ 不必写 `!important`。

## 五、代价与收益（实测，非推理）

| | 改之前 | 改之后 |
|---|---|---|
| 图元素盒高 | `100vh - 32` | `100vh - 80` |
| 被工具条遮住的高度 | **88px** | **0** |
| **实际可见图高** | `100vh - 120` | **`100vh - 80`** |

⇒ 可见高度**净增 40px**。方向和直觉相反：让出 64px，但换掉了原来被压住的 88px。
**"图让出底部"这个动作在净效果上是把图放大了，不是缩小。**

**附带收益**：「点图外关闭」**白捡回来了**。
wrapper 的 padding 那圈不属于图（命中 overlay）⇒此前它是被"图铺满视口"吃掉的
（见 `preview-fill/README.md`：那时只剩最外圈 16px 可点）。
顺带：以前图底那 88px 被遮住、点不到，现在图底 16px 间隙可点。

**已知的小损**：
1. 工具条从"浮在图上的一小块"变成"贴底一整条48px 高的黑带"⇒ 图的视觉重心上移了 40px。这是布局改变的必然结果，不是缺陷。
2. 窄窗口（< 900px）下名称的 `min(46vw,720px)` 会变小到 400px 左右 —— 名称本来就该被截断，不影响按钮。
   ⚠️ **未实测**：minWidth 是 1024（`electron/main/index.ts:65`），所以生产里最窄也就 1024，`46vw ≈ 471px`，够用。

## 六、已实测 / 待目视

**已实测**（`docs/probes/preview-bar/`，真 Chromium，视口 1400×900 与 2048×1280 两档，11 条断言全过）
- 工具条真贴底、真通栏、左缘 == 0、`transform:none`（**残留 `translateX` 会让整条左移半屏**，专测这条）
- **图不再被工具条压住**（`imgOverlapsToolbar: false`，间隙恒16px）；竖图那档同样成立
- 图的外边距上/左/右仍各 16px（没顺手改别的维度）
- **点图外能关**：四条间隙命中的都是 `n-image-preview-overlay`，点左侧间隙后预览层真的关掉
- 长名称（108字）被 ellipsis 裁掉，**右边的按钮组纹丝不动**（名称右缘恒 736、末颗按钮右缘恒 2034，换名前后一致）

**待主人真机目视**（无头测不到的部分）
- 通栏底板的观感：`rgba(0,0,0,.62)` + 1px 上边线，在浅色主题下够不够清楚
- 名称放宽到 720px 后长文件名的截断位置好不好看
- 按钮"散开"之后的点击手感（原来挤在中间一小块，现在从 x=1000 排到 2034）
- 图底那16px 间隙的可点性（探针说能点，真机上手感如何）

**验收方式**：纯渲染层改动 ⇒ **重启 dev 直接看**，**不用重扫盘**（没碰扫描/缓存逻辑）。
