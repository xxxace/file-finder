# 实现 · 补封面「换封面」（2026-10-02）

> 设计：`docs/DESIGN-PM-manual-pick-2026-10-02.md` + `docs/DESIGN-UIUX-manual-pick-2026-10-02.md`（v5）
> 本文记录**实际落地**的结果：怎么用、改了什么、验证到哪一步、哪些还没实测。

---

## 一、怎么用（三步）

```
① 「更多」下拉 → 「换封面」          ← 进入挑选（网格变成可点选，双击打开照旧）
② 点格子选中（有封面的才点得动）       ← 选目录格子 = 它下面所有封面算一批（按演员/文件夹批量）
③ 状态条上点「换封面…」→ 抓取 → 确认   ← 走的是原来那个补封面面板，一条链路
```

- 状态条（网格下方那条）：`换封面：点有封面的格子选中 · 已选 N 处` + `[清空][退出][换封面…]`
- `Esc` 退出模式；模式态下 `S` / `D` / `Backspace` 被短路（**F5 保留**）
- **退出即清空选择**（避免下次进来看到一堆"不知道什么时候选的"）
- 选择按**盘内相对路径**存 ⇒ 切目录、按 ↻ 刷新都不会丢

**能选什么**：已经有封面的 —— 封面卡（`type:'image'`）或**有脸的目录**（`folder` 且带 avatar）。
裸视频和没脸的目录**选不动**（它们是「补封面」的活，两边互补、不重叠）。

## 二、⭐ 三条我定死的决策（设计评审时发现的地基问题）

| # | 问题 | 定案 | 为什么 |
|---|---|---|---|
| 1 | "换掉的是哪个文件"从未定死（前面几版说"不碰 `avatar.jpg`/`cover.jpg`"，v5 说"覆盖那张脸"，两句打架） | **按类型分两种**：<br>· 封面卡 → **覆盖**它自己那张图（`dir/<封面图名>.<ext>`）<br>· 有脸目录 → **新建** `<目录>/<目录名>.jpg` | 封面卡的旧图**只能**覆盖（新增一张会变成两张图竞争 `handleCover` 的"第一个图片"，顺序不定）；<br>有脸目录**必须**新建 —— `handleCover` 第一步就摘掉 `avatar.jpg`/`cover.jpg`，新图自动成为脸，**旧文件一个都不用动**（零破坏、零备份） |
| 2 | "单击选中"与现有行为冲突（网格的图单击本来会弹放大预览；目录脸只显示 70% 且不让点开） | 模式态下：单击=选中，并**关掉图片预览**（`:preview-disabled="picking"`）；目录脸**临时放到 100%** | 否则一下点下去既弹预览又切换选中，两个动作打架。判断"糊不糊"靠格子里的图本身（6 列也有 200~320px），不靠点开 |
| 3 | 状态条位置不常驻（`.scan-bar` 只在 `scanning` 时出现） | 条件改成 `scanning \|\| picking`，两种状态**互斥**（进模式时扫描已停） | 工具条铁律是"绝不换形、子元素恒定"，所以模式信号只能住这里 |

## 三、改了什么

### 后端（4 个文件）

| 文件 | 改动 |
|---|---|
| `electron/server/assistant/scan.ts` | `TargetKind` 加 `'cover'`；新增 `FacePick` / `collectFaces()` / `relOfPath()` / `diskNameOf()`（**零读盘**，只读缓存） |
| `electron/server/assistant/apply.ts` | `ApplyGroup` 加 `overwrite`；`buildGroups()` 支持 `cover`（分组键带上 `kind`：**同一个路径的 cover 与 dir 不能互吞**）；`runApply()` 加**覆盖前备份**；新增 `backupCover()` |
| `electron/server/assistant/grab.ts` | `runGrab(…, force)` —— **绕开命中缓存**（否则重抓拿回同一张图）；`GrabRow` 加 `name`（确认卡标题要用） |
| `electron/server/assistant/index.ts` | 新路由 `POST /assistant/faces`；`startGrab` 透传 `force` |

### 前端（2 个文件）

| 文件 | 改动 |
|---|---|
| `src/views/FileFinder/index.vue` | 「更多」加一项 `换封面`；`picking` 叠加态（`@click` 选中、选中角标、`.pick-badge` / `.pickable` / `.picked` 样式）；状态条双形态；`Esc` 与单键短路 |
| `src/views/FileFinder/AssistantCoverModal.vue` | `setShowModal(v, picks?)` —— 带 picks 走 `/assistant/faces`（`faceMode`）；抓取带 `force:true`；确认弹窗/空态/tag 文案按模式分开 |

### 关键实现细节（防 BUG 的地方）

1. **路径口径**：主界面下发的 `item.dir` 是**完整路径**（`toWire()` 补了盘符），而缓存里存的是**盘内相对路径**。
   `relOfPath()` 负责归一，并且认三种形态：`H:/x`、只读锚点 `#<serial>/x`、**已经是相对路径**（幂等）——
   这个 BUG 是探针跑出来才发现的。
2. **角标绝对定位**：网格 6 列的宽度是"margin 撑间距 + `width:100%/6−10px` 补偿"算出来的，
   任何参与布局的新元素都会带偏它 ⇒ 角标用 `position:absolute`，选中态**复用已有的 `border`** 只改颜色。
3. **备份失败 ⇒ 放弃覆盖**：宁可这条记失败，也绝不在"没有退路"的情况下覆盖用户的文件。
   源文件不存在（缓存过期）**不算失败** —— 没有可毁的东西。
4. **备份落系统盘**（`~/.file-finder/assistant/cover-backup/<serial>/`），文件名 `时间戳__路径哈希__文件名尾巴`：
   盘内相对路径可能很长，Windows 有 260 字符上限，哈希保唯一、尾巴保可读。**不在移动硬盘上留 `.bak`**。
5. **分组键带上 `kind`**（`${kind}|${writeRel}`）：不是修既有缺陷 —— 原来的 `dir|layerDir` 对
   「没脸目录」本来就够用（每个目标天然不同层）。**是新功能要的**：`cover` 与 `dir` 可能指向
   同一个路径，只按路径分组会让它们互相吞掉。

## 五、第二轮修复（2026-10-02 · 真机反馈 2 条 + 顺着链路再抓 2 条）

| # | 用户看到的现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 选中角标**不是圆的、变成一条** | `.image-box-item span` 那条规则（`index.vue:1681`）里有 `width:100%` + **`height:38px !important`**，而我的角标是 `<span>`，被它拉长 | 角标改用 **`<i>`** —— 换元素最省事，不必跟 `!important` 打架；另补 `display:block` / `box-sizing` / `font-style:normal` 防御 |
| 2 | 点「换封面…」**只是弹出补封面界面**，换不了 | **三个断点叠在一起**（A/B/C，见下） | 三处都修 |

**断点 A · 打开面板不重算清单。**
原来只在"从没选过盘"时才自动扫（那段逻辑在 `loadDisks` 里），于是**第二次打开面板永远显示上一次的清单**
—— 从「补封面」切到「换封面」，看到的还是"缺封面的"那一批。
⇒ `setShowModal` 改成：先挂回正在跑的任务，**否则一律重算**；`loadDisks` 里那句自动扫删掉（免得重复扫一次）。

**断点 B · 盘序列号根本没传。**
主界面渲染网格时手上只有路径（`H:/…`），**拿不到 serial**；而清单必须按 `(serial, relPath)` 查缓存
⇒ 后端查的是"弹窗自己选的那块盘"，多半对不上 ⇒ 展开结果 0 条。
⇒ 新增 `serialOfPicks()`：服务端从 picks 反推序列号（完整路径 → 盘符换；只读锚点 `#serial/…` → 直接取），
并把结果**回给前端**顺手把盘选对上；「换封面」时盘选择器**禁用**（改选没意义、还会被下一次展开弹回去）。

**断点 C · 查询词（最隐蔽的一个）。**
封面卡条目的 `name` 是**封面图文件名**（`handleCover` 的 `info.name = getFilename(file)`，
可能是 `cover` / `1` / `poster`），拿它 `parseTitle` **必然认不出番号**
⇒ 抓取端一律记成 `no-id` **静默跳过**，用户看到的就是"点了换封面，什么都没发生"。
⇒ `ScanTarget` 新增 `query?`，由 `collectFaces` 的 `queryOf()` 在扫描阶段算好（条目名 → 所在层名兜底）；
`grabOne` 优先用它、**没有才回落到 `parseTitle(name)`** ⇒ 「补封面」那条路径一个字节没变。

> **为什么会漏这三个（系统性根因）**：我的探针只覆盖**纯函数逻辑**（分组、展开、去重、路径口径），
> 而 A/B/C 全是**跨模块的数据口径**问题（序列号从哪来 / 清单何时重算 / 查询词由谁定）——
> **纯函数级探针天然照不到它们**。正确姿势是**沿着"用户点一下会发生什么"把链路逐步走一遍**，
> 而不是只测自己新写的那几个函数。

### 第三轮修复 · 弹窗打开后一条都没有（真机反馈）

**证状**：选中若干格子 → 点「换封面…」→ 弹窗出现了，但显示空态（"找不到你刚在主界面选的那些位置"）。

**根因：前端一个事件回声，把我刚传进去的选择冲掉了。**（不是后端的问题）

```html
<!-- 原来 -->
<n-modal :show="visible" @update:show="setShowModal">
```

- `setShowModal(true, picks)` 先把 `visible = true`、`facePicks = picks`
- 但 `visible` 一变，`n-modal` 会**回声** `update:show(true)` —— **事件只带一个 boolean**
- 于是同一个 `setShowModal` 又被调一次，此时 `picks === undefined`
- 而里面写的是 `facePicks.value = picks ?? []` ⇒ **刚设好的选择被清成空数组**
- 后端收到 `picks: []` ⇒ 直接返回空 ⇒ 空态

⇒ 修法两条，**双保险**：
1. `@update:show` 改接一个**只管关闭**的 handler（`onModalShowChange`）——
   打开永远是程序主动调的（带 picks），回声不该参与；
2. `setShowModal` 里改成 `if (picks) facePicks.value = picks` —— 没显式传就**不覆盖**。

**顺手加的健壮性**（同一轮）：
- 反推不出盘的序列号时，**在每一块有缓存的盘上再找一遍**（`loadMeta()` 拿 serial 列表，零读盘）。
  "这个位置在哪块盘的缓存里"是可以直接查出来的事实，不该因为推不出盘符就放弃。本机有 6 块盘记录。
- `/assistant/faces` 找不到也返回 **200 + 空 + `probed`**（查了几块盘），空态如实显示
  "已经查过 N 块盘的缓存" —— 让用户看得出系统确实找过了，而不是像坏了一样。
- `relOfPath` 增补**反斜杠**与**盘根形态**（`H:` 不带斜杠，见 `driveIdentity` 的 `toFullPath`）的用例。

**又是同一类根因**：这一轮是**前端事件时序**，上一轮是**跨模块数据口径** ——
两者都在**纯函数级探针的视野之外**。⇒ 结论强化：
**新链路必须沿着"用户点一下会发生什么"逐步走一遍**，纯逻辑探针只能保证"我写的函数是对的"，
保证不了"这条链路是通的"。**用户跑一次真机，胜过我再写十个探针。**

### 第四轮修复 · 真根因（用户给了 HAR，一次定位）

**证据**（`localhost.har`）：`POST /assistant/faces` → **200**，请求体正常 ——
5 个位置、`dir` 是完整路径（`D:/sample/videos/…/示例演员A/TST-015`）、`name`/`ext` 齐全、`kind:'item'`；
响应 `{"code":200,"serial":"TST00001","targets":[],"probed":6,"received":5}`
⇒ **收到 5 个位置、6 块盘的缓存都查过、一条都没匹配上。**

**根因：位置拼错了基准，永远差一层。**

`server/index.ts:251` 调的是：

```ts
const converged = await handleCover(filepath, serial, joinRel(storeDir, file));
```

⇒ 收敛出来的封面卡，它声明的 `dir` 是**它代表的那个子目录**（`…/示例演员A/TST-015`），
但它落库时挂在**父层文档**（`…/示例演员A`）的 `data` 里。

而 `collectFaces` 拿**文档的 key（`docDir` = 父层）**去拼位置：
`selfRel = joinRel(docDir, 图名)` ⇒ 得到 `…/示例演员A/TST-015.jpg`，
**而前端传的是 `…/示例演员A/TST-015`** —— 差了最后一层，一条都对不上。

**修法（两处，同一个"层"的问题）**：
1. 位置基准改成**条目自己的 `dir`**（`atDir = e.dir || docDir`），`selfRel` 与下发目标都用它；
2. `scopes` 的命中判定加一条 `atDir === s` —— "选中那个目录格子"时，卡片本身就**属于**那个目录。

**⚠️⚠️ 为什么前四轮全漏了它（这一轮最重要的教训）**：

我的探针是这样模拟前端的：`dir: 'Z:/' + d.relPath` —— **用的是文档的层**。
而 `collectFaces` 也用文档的层拼 —— **两边用的是同一个错误假设**，于是自洽、于是全绿。
**"用自己的假设去验证自己的假设"，探针越全量越像真的。**

⇒ 这一轮把探针改成**真实形态**（`dir: 'Z:/' + e.dir`）之后，立刻复现：

```
❌ 全库 6 块盘 / 1040 条"有脸"条目，全部按前端形态命中（实得 115）   ← 改前
✅ 全库 6 块盘 / 1040 条"有脸"条目，全部按前端形态命中（实得 1040）  ← 改后
```

**能复现的才算验证。** 探针的"输入"必须来自**真实来源**（HAR / 真库字段值），
不能来自我脑子里的模型 —— 否则测的只是"我的模型自不自洽"。

**这一轮还顺手做的**：临时诊断代码（`faces-debug.log`）已全部删掉；
空态保留 `received` / `probed` 两个数字（那不是调试，是给用户的解释：
收到 0 个 = 选择没传过来；收到 N 个 = 位置没匹配上）。

## 六、⚠️ 还没实测的（诚实标注）

1. **真机跑一遍完整流程**（进模式 → 挑 → 抓取 → 确认 → 写入 → 刷新看新脸）——**未做**。
   探针只覆盖了纯逻辑，**触摸不到 UI、也碰不到盘**。
2. **`handleCover` 摘掉旧头像后新图是否真的成为脸** —— 这是"有脸目录走新建"成立的**前提**，
   按代码逐行读是成立的（`isDirCover` 先摘、剩下的图收敛），但**没有在真机上见过一次**。
3. **备份真的写进系统盘、且原图能被还原** —— 代码写了，**没跑过**。
4. **`rename` 覆盖已有文件**：探针在**合成文件**上过了 3/3，**没在真实封面目录上试过**。
5. **批量规模**：一次挑几十上百张时的耗时、取消、部分失败的观感 —— 未测。
6. **内存**：`thumbStore` 那个只增不减的 Map，清单里出现过的条目会被登记（约 47 KB/张）。

## 八、已知取舍（不是遗漏，是选过的）

| 取舍 | 理由 |
|---|---|
| 入口藏在「更多」下拉里 | 用户明确要求"不要搞出太多界面和入口"＋工具条铁律（子元素恒定、绝不换形）。代价可发现性差 |
| 不做任何自动判据 / 排序 / 预选 / "糊"的视觉标记 | 用户否过三次 |
| 不做撤销入口（只有备份文件） | 备份已经落地；"从备份一键还原"是独立工作量，列 P1。**每条覆盖都会把备份的相对路径写进结果行与 `apply.log`**（D7 的可追溯义务） |
| 不显示"共 M 张"（只显示"已选 N 处"） | 展开数量要额外请求；展开是在打开面板那一刻做的，面板里会显示真实条数 |
| 键盘 roving tabindex 未做 | 独立工作量，列 P1（**已知缺口**） |
