# 盘筛选控件重设计（2026-10-04）

> 结论一句话：**把「盘」的 `n-select` 下拉换成一行可换行的 chip 组**，chip = `盘符 · 目录数` + 一枚状态圆点（在线绿 / 离线灰）。
> 状态：**已实现（2026-10-04，含第 2/3 轮）** —— typecheck / 生产构建 / 无头 Chrome 实测均通过；
> **待主人重启 dev 后真机目视**（重点是 `n-tooltip` 的观感）。本文件是本次改动的设计来源与取舍记录。
> 第 2 轮 = §11（只显示有缓存的盘、把「打开存放文件夹」挪进「备份与迁移」）；第 3 轮 = §12（表格行高）。

## 一、用户原话

> 「缓存记录的下拉框过滤我感觉体验不太好，尤其是盘多起来的时候，你之前这样子取舍是因为要显示多少个目录和条目，但没什么意义；重新分析和设计，可以上网搜索和借鉴。
> 我本人给你两个想法（不是强制的）：1. 学 windows 的【设备和驱动器的界面】…… 2. 用 chip 或者 tag 来做，超出一定长度再想办法收纳。
> 你分析清楚我的意图和需求，用正确的方式设计出优秀好的界面和 UIUX。」

拆解：
- 核心痛点 = **盘一多，下拉里那几行长文本没法扫**。
- 他主动怀疑「目录数 / 条目数」这层信息的价值 —— 但**不等于要删掉计数**（已当面确认：保留目录数，只去掉条目数）。见 §3.2。
- 两个想法是**备选**不是命令，可被证据否决（§4.2 否决了磁贴）。

## 二、现状（证据：静态，源码可复算）

| 项 | 位置 | 事实 |
|---|---|---|
| 控件 | `src/components/HistoryTable/index.vue:83-84` | `<n-select :options="diskOptions">`，宽 320px |
| 选项文案 | 同文件 `:437-449` (`diskLabel`) | `H: · 43 个目录 / 214 个条目`；离线 = `离线(BF7A) · 3 个目录 / 12 个条目` |
| 「全部」项 | 同文件 `:469-472` | `全部盘 · 216 个目录` |

问题（三条，互相独立）：
1. **长文本行表达"可选项"**：每行都是「盘符 + 两种计数」，盘一多就是字墙；扫视成本随盘数线性上升。
2. **信息密度错配**：下拉的价值在「选哪块盘」，而每行用了一半篇幅讲「有几个条目」——这不是选盘时要用的判据。
3. **单位不一致**：首项「N 个目录」与其余项「N 目录 / M 条目」单位不同，选项之间不可比。

## 三、已查证的事实（改动前必须先认这些）

### 3.1 每块盘我们能拿到什么（`electron/server/index.ts:1026-1041`）
```
serial / drive(盘符，离线为空串) / root / label / online / folders / covers / lastScanAt
```
- `folders` = 该盘缓存过的**目录条数**；`covers` = `count` 累加 = **条目数**（`index.ts:996` 命名是历史包袱，实为条目）。
- `label` **永远是空串** —— `electron/utils/driveIdentity.ts:83` 的 `probe()` 写死 `label: ''`；注册表(`DiskRecord`)只有 `label/firstSeenAt/lastSeenAt`，**不存盘符**。
- 全局 `stats.folders` = 全部目录数（= 各盘 `folders` 之和）。

### 3.2 用户的裁决（本轮当面确认，视为前提，不再论证）
- 控件形态 = **chips**（否决磁贴）。
- 离线**不做文字强调**，只靠状态点：**在线绿 / 离线灰**。
- chip 信息 = **盘符 + 在线状态 + 目录数**（去掉条目数）。

### 3.3 关键推导：磁贴为什么做不了（逻辑推导，非实测）
Windows「设备和驱动器」磁贴的识别度来自 **容量条 + 卷标**：
- 容量条需要向每块盘取「空闲/总容量」（`GetDiskFreeSpaceEx` 类调用 = **碰盘**）——撞最高优先级；**离线盘根本取不到**。
- 卷标恒为空串（3.1），画不出名字。
⇒ 磁贴会退化成「盘符方块 + 一条没有数据的灰条」，同时比 chips 多占约 1/3 屏高，挤掉表格。

### 3.4 离线盘的"名字"只能是序列号后 4 位（静态可复算）
盘符只在"盘插着"时存在；离线盘的地址是只读锚点 `#serial/relPath`（`index.ts:1132`），
`offlineLabel()`（`src/utils/index.ts:96`）给的是 `离线(后4位)`。
⇒ chip 的"名字位"：在线填 `H:`，离线填序列号后 4 位（如 `BF7A`）。**没有第三种身份可用。**

## 四、决策

### 4.1 采纳：一行 chip 组
- 位置：替换现有 `g2-disk` 行里的 `n-select`，与「打开存放文件夹」同行（按钮靠右、不随之换行）。
- 顺序：`全部` 在首 → 在线盘按盘符升序 → 离线盘按序列号升序。
- 溢出：**chip 区内换行**（`flex-wrap`），不横向滚动、不折叠隐藏。

### 4.2 否决：Windows 磁贴
理由见 §3.3 —— **不是审美取舍，是数据拿不到**。若将来真要做，前提是"愿意为容量条读一次盘"，需用户另行批准。

### 4.3 否定"删除计数"这条路
用户原话被读成"计数没意义"，但在 grill 中确认：他要删的是**条目数**和**长文本行**，目录数保留。
⇒ 计数保留，但降为 chip 里的次要小字。

## 五、规格

### 5.1 chip 内容
```
全部 · 216            ← 「全部」项，数字 = 目录总数（stats.folders），与各盘同为"目录数"，量纲一致
● H: · 96             ← 在线：绿点 + 盘符 + 该盘目录数
● BF7A · 6            ← 离线：灰点 + 序列号后4位 + 该盘目录数
```
- 数字取 `d.folders`；`folders === 1` 时仍写数字（不写裸盘符，避免与"名字"混淆）。
- **只显示有缓存的盘**（`folders > 0`）—— C: 这种从没收录过的系统盘不再出现（见 §11.1）。
  唯一例外：**当前选中的那枚永远留着** —— 否则走到"把某盘的记录全删了"那一步，
  过滤条件还在、chip 却消失了，界面会变成"没有任何 chip 选中、表格却是空的"。

### 5.2 状态
| 状态 | 表现 |
|---|---|
| 未选中 | 白底、1px 灰边（`#dcdcd6`）、深色字（`#4a4a46`） |
| 选中 | 浅蓝底（`#e6f1fb`）+ 蓝边（`#85b7eb`）+ 蓝字（`#185fa5`）；**圆点颜色不变**（绿/灰照常）—— 否则选中态会把在线状态淹掉 |
| hover | 边框加深一档 + 极浅底（`#f8f8f6`） |
| 键盘焦点 | `:focus-visible` 时 `outline: 2px solid #2080f0`（鼠标点不亮，只有键盘会亮） |
| 在线 | 圆点 `#22c55e` + 一圈 2px 淡绿环 `rgba(34,197,94,.22)`（用户 2026-10-04：原 `#639922` **太暗**，要"设备在线"的那种感觉） |
| 离线 | 圆点 `#b4b2a9`（**不加虚线、不加"离线"二字** —— 用户明确要求） |
| 名字 / 数字 | 名字 `font-weight:500`；数字淡一档（`#a9a9a3`），主次分明 |

⚠️ 两点实现注意（都已落进代码）：
1. 选中态**不加边框宽度**（1px→2px 会让这枚高 2px、整行跟着错位），只换颜色。
2. 在线那圈"光环"用的是 `box-shadow: 0 0 0 2px`（0 模糊 = 实心环），不是发光。

### 5.3 悬浮提示（2026-10-04 新增 —— 用户的第 2 条要求）
用户原话：「显示离线两个字没意义，要不就鼠标悬浮的时候可以显示 状态 盘符或者标识 总目录 总条目 等信息？」
⇒ chip 面上只留三样（状态点 / 名字 / 目录数），**完整明细进 `n-tooltip`**：

| 行 | 「全部」chip | 盘 chip |
|---|---|---|
| 标题 | 全部盘 | 在线 `H:` ／ 离线 `序列号 FE91E472`（chip 上只有后 4 位，这里给全） |
| 状态 | 盘数 5 | 在线 ／ 未插入（看的是缓存） |
| 目录 | 216 | 该盘目录数 |
| 条目 | 1471 | 该盘条目数 |
| 最近扫描 | 全库最近一次 | 该盘最近一次 |

- `trigger="hover"` / `:delay="180"` / `placement="top"` —— 均为 Tooltip 受支持的 prop（已在 `node_modules/naive-ui/es/tooltip/src/Tooltip.d.ts:33/37/46` 核对，不是猜的）。
- 明细行 `white-space: nowrap`：提示靠内容自动撑宽，不换行就不会被拉高。
- ⚠️ 提示内容的样式**不能**挂 `.cache-panel` 前缀 —— 弹出层被 teleport 到 `body`、不在卡片里，加了前缀一个都命中不了；改用专属类名 `.disk-chip-tip` 做成全局规则。

### 5.4 布局
```
.g2-disk { display:flex; align-items:flex-start; padding-bottom:10px; }
.disk-chips { flex:1 1 auto; display:flex; flex-wrap:wrap; gap:6px; min-width:0; }
```
- 用**裸 flex**，不用 `n-space`（naive-ui 2.45.3 每个子项写死同一 key，子元素个数变化会重复 key；先例 `docs/FIX-2026-09-24-nspace-duplicate-keys.md`）。
- 「打开存放文件夹」2026-10-04 已挪进「备份与迁移」（见 §11.2），这一行现在只剩盘条 ——
  于是盘条拿到整行宽度（"盘多"时正是它最需要横向空间）。

### 5.5 交互
- 点击 chip = 单选过滤：写 `model.serial` → `onSearch()`（复用 `handleSerialChange`）。
- 再点已选中的 chip = 取消选中 → 回到「全部」（= `serial: ''`）。
- 点「全部」= 清除过滤。
- **不新增确认、不新增请求路径**；仍走 `getHistrotyList()` 的唯一出口。
- 键盘：chip 是**真实 `<button>`**（不是 `span`/`NTag`）⇒ 天然可 Tab、可 Enter/Space；选中态报 `aria-pressed`，另给 `aria-label`（chip 面上的「全部 216」对读屏不足以说明它是什么控件）。

### 5.6 实现基座（最终选择）
- **原生 `<button class="disk-chip">` + 自定义 CSS**。不用 `n-button`，更不用 `n-tag checkable`。
  - 不用 `n-tag`：`node_modules/naive-ui/es/tag/src/Tag.mjs:72-80` 内部同时调 `onUpdateChecked` / `onUpdate:checked` 两套口径，且渲染成 `span`（非控件）—— 键盘不可达。
  - 不用 `n-button`：chip 要"点 + 名字 + 数字"三段加离线灰点等自定义样式，套 `n-button` 反而得压掉它一堆默认样式。
- 状态点用内联 `<span>` 画（7px 圆），不引图标资源。
- ⚠️ **布局安全性已核实（静态证据，读的是真实源码）**：`n-tooltip → Popover → VBinder / VTarget` 这条链是**无包裹渲染** ——
  `vueuc/es/binder/src/Binder.js:129-131` 的 `render()` 直接返回 slot；`Target.js` 的 `render()` 返回 slot 的首个 vnode（就是我们的 `<button>`）；
  `Follower` 走 `LazyTeleport`（首次显示前不渲染，之后 teleport 到 `body`）。
  ⇒ `.disk-chips` 的子节点就是那些 `<button>`，flex 换行**不会**被包一层 div 破坏。

### 5.7 溢出策略
- 换行（`flex-wrap`）。无头 Chrome 真机实测（1040px 面板）：**7 枚 chip 一行放得下、不换行**。
- 若将来盘数超过约 3 行 → 再议（候选：横向滚动 + 右缘渐隐，或"更多"折叠）。**本次不做**，不为未发生的情况加实体。

## 七、边界情况

- **0 盘有缓存**（全新机器，或除 C: 外没扫过任何盘）：只有「全部」一枚 chip，表格走既有空态。
- **1 盘**：`全部 · N` + 1 枚 chip。正常。
- **选中某盘后它的记录被删光**：该盘 `folders` 变 0，本该被"只显示有缓存"滤掉 ——
  所以规则给了例外（当前选中项永远留）：chip 变成 `X: · 0` 且仍高亮，表格空态文案改成「这块盘还没有缓存记录」。
- **克隆盘（同序列号）**：服务端会返回两条同 serial 记录（`index.ts:1044 findDuplicatedSerials`）。
  现有下拉已经会渲染两个同 `value` 的选项；chips 同样会出现两枚同 serial。
  **本次沿用现状**（顶部已有「检测到克隆盘」警示，`index.vue:52-56`），不额外处理 —— 但需在实现时用 `:key="d.serial + d.drive"` 防 Vue 复用错乱。
- **盘同步中（diskLoading）**：chip 用上一次列表渲染，不显示骨架；刷新按钮已有 loading 态。
- **长序列号 / 未来加卷标**：chip 文字单行不换行（`white-space:nowrap`），超出可 `max-width + ellipsis`（当前数据不会触发）。

## 十一、第 2 轮决定（用户 2026-10-04，紧随 chips 落地）

### 11.1 只显示有缓存的盘
用户：「像 C 盘这种没收录过的是不是可以不显示？也就是只显示有收录的盘符？」
**采纳。**

⚠️ 但"盘数"在这个面板里有两处，**必须同改**，否则自相矛盾：

| 位置 | 改前 | 改后 |
|---|---|---|
| 盘条 chip 列表 | 所有挂载卷 + 有离线记录的盘（**含 C:**） | 只留 `folders > 0`（+ 当前选中项） |
| 总览句「N 块盘」 | `drives.length + offline.length`（**含 C:**） | `new Set(metas.map(m => m.serial)).size` = 有缓存的盘数 |

- 依据（静态）：`electron/utils/driveIdentity.ts:44` 的 `LETTERS = 'CDEFGHIJKLMNOPQRSTUVWXYZ'` ——
  `scanDrives()` 直接 stat C–Z，所以 **C: 一定会以 `folders: 0` 出现在 `/getDisks` 的 `disks` 里**。
- 语义统一：总览那一句其余各项（目录 / 条目 / 已读到 / 最近扫描）讲的都是"缓存里有什么"，
  只有"盘数"混进了没缓存的盘。改后整句同一口径：**有缓存的盘在几块上、共多少目录条目、读到多少字节**。
- ⚠️ 服务端这处改动**不新增任何读盘**（`metas` 早已在内存，纯计数）。
- 边界另见 §7（选中项被删光的情形）。

### 11.2 「打开存放文件夹」挪进「备份与迁移」
用户：「打开存放文件夹这个按钮是否要放到备份与迁移里？」
**采纳。**

原状：它守在折叠区**外面**（`DESIGN-CONVERGED-2026-09-24.md` §三 把它定义为"最小、只读、零新概念"的出口），
代码注释里的理由是「它是唯一一个不碰任何数据的出口，留在外面」。**推翻它的四条理由**：

1. **原理由本来就站不住**：这个折叠区不是纯危险区 —— 备份是安全的、合并只增不删；
   真正危险的只有「从文件还原」，而它是靠**自己那身红**标出来的，不是靠分组。
2. **它是同一件事的另一面**：备份 / 还原 / 合并是**自动**搬运整库；打开文件夹是**手动**搬运的入口
   （`searchCache.db` 和各份备份都躺在那个文件夹里）。语义上是第四位成员。
3. **它压在盘条右侧要吃掉约 110px** —— 而盘条正是"盘越多越需要横向空间"的那一行。
4. 折叠区里其它三项都带一句 hint，加进来后风格统一。

**代价与补偿**：位置原本承担"这是安全出口"的信号，现在改由 hint 明说 ——
「只打开文件夹、不动任何数据（缓存库和备份都在这儿）」。
代价是**多一次点击**（折叠区默认收起）；换来的是顶部少一个控件、盘条拿到整行宽度。

## 十二、表格行高与每页条数（用户 2026-10-04，第 3 轮）

用户：「缓存记录的表格的 `--n-td-padding` 可以设置为 2px」。

**落地为 `2px 12px`（垂直 2px、水平保留 12px），不是字面的 `2px`。** 依据是实测，不是判断：

| 配置 | 行高 | 表头文字 vs 单元格文字 | 表头高 |
|---|---|---|---|
| `12px`（naive-ui medium 默认，见 `styles/_common.mjs`） | 47px | 0px | 47px |
| `2px`（字面） | 27px | **−10px（错开）** | 47px |
| **`2px 12px`（采用）** | **27px** | **0px** | 47px |

- 错开的原因：表头用的是**另一个**变量 `--n-th-padding`（仍 12px）。td 四周全收成 2px 后，
  左对齐的列（盘 / 目录）表头文字就比单元格文字右移 10px。
- **「垂直 2px」已经拿满全部行高收益**（47→27，一屏多出约七成行），水平留 12px 只为保住对齐。
- 实测手段：真 Chromium + `Range.getBoundingClientRect()` 量文字左缘、再量行高/表头高。
  图见 `docs/DESIGN-DISK-FILTER-2026-10-04-td-padding.png`。

⚠️ **这里的 `!important` 是必需的**：naive-ui 的主题变量是**内联**挂在表格根节点上的 ——
`App.vue` 的 `n-config-provider` 没开 `inline-theme-disabled`，于是
`node_modules/naive-ui/es/data-table/src/DataTable.mjs:439` 把 `--n-td-padding` 作为 element style 写入
`.n-data-table`。普通 CSS 规则赢不了内联样式。实测：带 `!important` 算出 2px、不带算出 12px。
变量写在根节点、td 是继承来的 ⇒ 一条规则就够，不用逐层写。

**没做、等你一句话**：表头仍是 47px（行只有 27px）。
要更齐可把 `--n-th-padding` 收到 6px（表头 → 34px），那是另一个决定，没有擅自动。

### 12.1 每页条数 16 → 30
行高收到 27px 后，默认每页条数跟着从 16 提到 **30**（用户 2026-10-04）——
不然省下来的高度等于白省，还是得不停翻页。

- `page-sizes` 里补了 `30`：**必须有**，否则分页器的"每页条数"下拉表示不出当前值（这个坑原注释里已经记过一次）。
- `16` **保留**在列表里：它是用户之前定过的值，留着能随时切回去。
- 估算（**未真机量**）：1280 高的窗口 → `86vh ≈ 1101px`；扣掉卡片外壳约 212px 与表头 47px，
  剩约 842px ÷ 27px ≈ **31 行** ⇒ 30 行放得下。
  窗口更矮时会轻微滚动 —— 滚的是**表格自己**（`flex-height`），不会把外面那几行顶走。
- `handlePageSizeChange` 早就会把页码拉回第 1 页（见 §6 那条注释），所以改大小不会落到空页。
