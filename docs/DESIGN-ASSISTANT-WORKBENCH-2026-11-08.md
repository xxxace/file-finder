## 一、结论先行（三条结构决策）

| # | 决策 | 为什么是它 |
|---|---|---|
| 1 | **一个容器**：两个功能共用同一副骨架（顶栏 44 + 主区 + 底栏 52），不再是「100vw 卡片」vs「90vw 弹窗」两种东西 | 同一个入口菜单下的两个动作，长得像两家的产品，这本身就是"廉价"。容器统一后，后续任何助手类面板（规则编辑器、过验证）都能挂进来 |
| 2 | **一条底栏承担全部状态**：idle / 运行 / 暂停 / 完成 都在同一个 52px 节点里形变 | 现在是「进度一行 + 底部按钮一行 + 抓取结果另一张表」三处分散。同节点形变是动效里贡献最大的一条（`STUDY-MOTION` 机制 1），且省掉 50px 垂直空间 |
| 3 | **砍掉"确认写入"弹窗**：写入与否直接在卡片勾选上决定 | 现在：扫描勾一次 → 抓取 → 弹窗里再勾一次 → 写入。同一个决定问了两次。合并后抓到的默认保持勾选，取消个别即可，能力一个不少 |

## 三、统一骨架

```
┌ 44 顶栏 ─────────────────────────────────────────────────────────┐
│ ←  补封面 │ 待补 24 · 认不出 3 · 跳过 12        [盘▾] [重扫] [⋯] │
├ 主区（唯一滚动容器）────────────────────────────────────────────┤
│  补封面：封面卡片网格（5 列，3:2）                               │
│  头像回收：行卡片（头像 48 + 名字 + 识别名 + 状态 + 换图）        │
├ 52 底栏（同节点形变）────────────────────────────────────────────┤
│  ● 抓取中 12/24 · 命中 10 被拦 1        [暂停] [终止]            │
│  ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔ 进度线画在底栏上边缘，0 布局占用              │
└──────────────────────────────────────────────────────────────────┘
```

**为什么不额外加"任务条"**：底栏本来就是"这一批怎么办"的位置，任务运行时它就是任务条。两条底栏等于让用户在同一块地方读两份状态。

**为什么进度画在底栏上边缘**：2px 一条线，横跨全宽，扫一眼就知道跑到哪；不占任何垂直空间，且**两个阶段（匹配 → 写入）共用同一条 DOM**，天然是"同一件事在推进"。

## 四、补封面 · 规格

- 卡片：`6px` 内边距 + 封面 `3:2` + 标题（12px/500，单行省略）+ 路径（11px，中间省略）+ 类型（目录 / 覆盖 / 裸文件，11px 右对齐，**不加底色标签**）。
- 勾选：左上 20px 方块；选中 = `outline 2px var(--ff-highlight)` + 方块填蓝（沿用主界面网格的选中语汇，不另发明）。
- 卡片四态：

| 态 | 视觉 |
|---|---|
| `idle` | 占位块（暗灰渐变 + 番号水印） |
| `run` | 占位降透明度 + 三点脉动（**不用 Canvas**，见 §七） |
| `ok` | 封面淡入（`blur 8px→0` + `scale 1.03→1`）+ 左下角站点小标（JavBus / Gfriends）+ `已写入` |
| `blocked / miss / err` | 1px 描边染色（warn / warn / danger），小标写原因；**不做色块** |

- hover：**只**让封面图 `scale(1.02)`，卡片不抬升（禁用清单：hover 位移会让网格"抖"）。

## 五、头像回收 · 规格

- 行卡片 64px 高：勾选 18 · 圆头像 48 · 文件夹名 + 路径 · 识别名输入框 · 状态 · 换图。
- 头像未就位时：`--ff-field` 底 + 人形描边图标；未找到的行头像圈改**虚线**（warn 色），识别名输入框同步描 warn 边——一眼看出"这行要你动手"。
- 匹配逐条推进：命中一行就地变绿并自动勾选，**不再等整批跑完才出结果**。
- 保留 `换图`（手动 URL）在行内，不再塞进 popover 两层。

## 六、异步任务（这是本次的实质增量）

| 阶段 | 现状 | 重设计 |
|---|---|---|
| 补封面 · 扫描 | 同步、零读盘、<100ms | 不动。只在 >150ms 时显示骨架，避免闪一下 |
| 补封面 · 抓取 | job（已有） | 进度线 + 计数（命中/被拦/未找到）+ 暂停/继续/终止 + **逐条落到卡片** |
| 补封面 · 写入 | job（已有） | 同上；完成时底栏一次性光雾（§七） |
| 头像回收 · 扫描 | 同步 + 顺带匹配（黑洞） | **只出候选**（服务端砍掉 `avatarScan.ts` 的 5 并发匹配段），毫秒级 |
| 头像回收 · 匹配 | 无（藏在扫描里） | 前端逐条调 `/assistant/avatar/match`（接口已存在，控制并发 4）⇒ 真进度、可暂停、可终止、**单条可重试** |
| 头像回收 · 写入 | 一次性 POST | 新增 `kind:'avatar'` job：闸门暂停、逐条进度、终止保留已写入 |

**判据**：暂停 = 不再取新条、在飞的跑完（与 grab 的语义一致，`jobs.ts:48` 的 Gate 直接复用）；终止 = 立刻停取 + 已产出的全部保留。

## 七、动效预算（该有才上，共 6 处）

| # | 位置 | 机制 | 参数 | 来源 |
|---|---|---|---|---|
| 1 | 卡片/行首次入场 | 位移 + 淡入，stagger | 22ms/项，`200ms ease-move` | 机制 4 延迟阶梯 |
| 2 | 封面/头像落地 | 模糊转清晰（同节点） | `blur 8→0 / scale 1.03→1`，`200ms`，透明度延后 50ms | 机制 1 同节点 + 机制 5 模糊 |
| 3 | 底栏状态切换 | 同节点形变 + 文字上下错位替换 | 旧字 `90ms` 上移淡出，新字 `200ms` 下移淡入 | transfer-glow 的 `announce()` |
| 4 | 进度线 | 线性推进 | `scaleX`，`200ms linear`（**进度不用缓动**，缓动会骗人） | — |
| 5 | 完成瞬间 | 局部白雾一次 | `620ms`，只覆盖底栏 150px 高，`opacity ≤ .14` | transfer-glow 降级版 |

**明确不做的**：卡片 hover 抬升、列表二次入场、数字滚动、全屏粒子（thinking-particles）、玻璃拟态。

## 七·五、加载语言（loading）· 参考 LeiBox `ai-generating` + `transfer-glow`

原则：**等待必须说明"是什么在等"，而不是转圈**。按信息量分三档，谁也不能冒充谁：

| 档 | 用在哪 | 形态 | 为什么不是别的 |
|---|---|---|---|
| **骨架** | 清单还没到（重扫 / 首次打开）；**无可度量进度** | 8 张卡 / 10 行的静态块，`opacity .55↔1` 呼吸 1.6s | 不用扫光条：扫光是最廉价的 loading 语言，且暗示"在动=有进度" |
| **点阵** | 逐条抓取中：每张卡、每个头像位 | Canvas 点阵，两个 Lissajous 焦点扫过，点的大小与亮度随距离衰减 | 语义精确对齐「这张图正在被取回」；比三点脉动高级，比 spinner 有信息 |
| **进度线 + 计数** | 有真实 `processed/total` | 底栏上边缘 2px 线 + `12/24` | 有真数据时不该用氛围动画，那会骗人 |

**点阵的移植参数**（原式 `AiImageGenerationEngine.js`，只改三件事）

| 项 | 原式 | 我们 |
|---|---|---|
| 网格 | 20×20，节距 18（盒 420） | 节距 = `min(w,h)/6.5`，行数列数由尺寸算（48px 头像位 → 6×6） |
| 点径 | 节距 × 0.67（12px） | 节距 × 0.42（画布小一个量级，照抄会糊成一片） |
| 缩放 | 0.333 → 0.65 | 0.42 → 1.0（点本来就小，需要更大的相对变化才看得见） |
| 强度 | `pow(1-d/R, 1.4)`，R = 110 ≈ 6 节距 | 公式不动，R = 5.2 节距 |
| 焦点 | 2 个 Lissajous，第二个带 0.35 速度调制 | 照抄（这是"呼吸"的来源） |
| 颜色 | `#e4e4e7 → #989898` | `rgba(255,255,255,.07→.57)` —— **纯白 alpha，不引入彩色** |

**性能纪律**（比公式重要）
- **一个共享 rAF** 驱动所有场；场停了立刻出队 ⇒ 空闲零帧（与 galaxy 进度条同一条纪律）。
- 只在 `data-st="run"` 时入场；**停止绘制但不清画布**，靠 CSS `opacity 200ms` 淡出，避免硬切。
- `prefers-reduced-motion` ⇒ 只画一帧静态场，不跑循环。
- 并发是**真并发**：抓取 5、写入 3。原型第一版"每 180ms 派 5 条"会飞出 15 条在飞（自检抓到 10 个点阵同时动），已改成派发前查在飞数。

**`transfer-glow` 的两条被用在语义正确的位置**（不是抄视觉）
1. `announce()` 的**旧字上移淡出 / 新字下移淡入** → 底栏在「匹配中 → 写入中 → 完成」三段之间换文案，位置不动、不跳动。
2. 一次性的**光雾** → 只在写入全部完成时出现 `620ms`，且降到纯白 `≤ .14`、只覆盖底栏 150px（原式是粉金 240 粒子 + Canvas，照抄会变成烟花）。

**明确不做**：`n-spin` 转圈（全部替换掉）、扫光条、全屏粒子（`thinking-particles`）、数字滚动、玻璃拟态。

## 八、与既有铁律的自检

- **读盘**：全部渲染层 + 接口层改动，**零新增读盘**。头像匹配仍走原有网络请求；写入仍走原有下载通道。
- **无彩**：光雾是白色（`rgba(255,255,255,.14)`），不引入彩色；高亮色仍只在选中/焦点。

- **禁止手动输路径**：未新增任何路径输入。
