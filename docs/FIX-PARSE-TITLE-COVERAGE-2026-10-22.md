## 二、真实结论：270 条 unmatched 里只有 2 条是"漏"

改前 270 条 unmatched（界面上主人看到的 23 是其中一块盘）。**唯一真漏是主人圈红的两条**：

| 样本（占位） | 真实结构 | 老规则为什么打不中 |
|---|---|---|
| `TSK-S51` | 字母段 + `-` + **字母+数字** | 数字段被写死成 `\d{2,6}` |
| `TST2A3B-21` | 字母段**含数字** + `-` + 数字 | 字母段被写死成 `[A-Za-z]{2,8}` |

两者同根：老规则假设「字母段=纯字母、数字段=纯数字」，而真实番号两侧都能混。

## 三、四遍实测才定下来的改动（`match.ts`）

| # | 改动 | 依据（真实库实测） |
|---|---|---|
| ② | 字母段 `[A-Za-z]{2,8}` → `[A-Za-z][A-Za-z0-9]{1,7}` | 补 `TST2A3B-21` / `X28-123` |
| ③ | **新增**：字母段 + `-` + 单字母+数字 | 补 `TSK-S51` / `-S01` / `-C02` 系列 |
| ②③ | 分隔符 `[-_ ]` → `[-_]`（**去掉空格**） | 实测 `示例歌手 - XYZ (2018 - Hip Hop Rap) [Flac 16-44]` 被认成 `XYZ-2018`（音乐专辑目录） |
| ④ | **新增**：6 位数字 + `-`/`_` + 2~4 位序号 | 补 Caribbean 日期型 `991231-999` / 下划线变体 |

④ 的左段**必须 6 位**，这是它与分卷 `1-2` / `10-1` 唯一可分的信号 —— 别放宽。

### A/B 实测（368 个名字，**合并前**测的）

```
一致 366 · 新认出 2 · 值变了 0 · 反而认不出 0
  "991231-999"  → 991231-999
  "991231_999"  → 991231-999
```

⚠️ 这组数字只能在**合并前**复现：规则进 `match.ts` 之后 `ab.mjs` 的 `CAND` 与源码一致
⇒ 现在复跑恒为 `一致 366 · 新认出 0`。要再量新想法，必须把 `CAND` 换成候选规则。

早期版本（只加 ②③、去掉空格）的差异集：新认出 `TSK-S51` / `TST2A3B-21`、值变了 **0**、反而认不出 **1**（=`示例歌手…` 那条，正是要修的误判）。

| #1 | 23 | **21** | -2 = 主人圈红那两条 |
| #5 | 84 | **83** | -2 认出（`991231-999` 两条）+1 暴露（见下）|

## 六、仍然故意不覆盖（要认就得付代价）

| 形态 | 例子 | 为什么不做 |
|---|---|---|
| 连写 | `TST001` | 与 `tst26`/`tst64` 形式上不可分。要认只能靠**厂牌白名单**（维护一份会过时的表）——不建议 |
| 纯数字-数字 | `MMDDYY_NNN` 已由 ④ 覆盖；`1-2`/`10-1` 永远不认 | 与分卷不可分 |
| 空格分隔 | `ABC 123` | 去掉空格换来的是"不误判英文标题"，代价是这类进 unmatched 可手动补 |
| 自制品 | `示例作者520-标题` | 站点根本无此作品，硬搜只会抓到别人的片子 |

取舍依据沿用 `match.ts` 既有原则：**漏 = 零破坏（进清单可手动补）；误判 = 白搜 + 可能写错封面**。
