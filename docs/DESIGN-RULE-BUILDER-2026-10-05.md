# 可视化规则编写器 · 设计草案 v1（2026-10-05 · 待主人批准）

> v1 修订（自我压力测试后）：补上 **3 处会导致"普通用户做不成"的遗漏** ——
> ① 点击后 `target="_blank"` 开新窗 ⇒ 抓取窗停在列表页 **且窗口泄漏**；
> ② 普通用户**无法推导**入口 URL 模板；③ 普通用户**无法手写**动作选择器（必须"录一遍"）。
> 详见 §11 设计自检。状态：**未批准前不动代码**（brainstorming HARD-GATE）。

---

## 0. 目标

**做**：用户可**新增/编辑站点规则**并试跑通过 → 抓取可用。四件事全部"看得见摸得着"：

| # | 能力 | 用户动作（人话） |
|---|---|---|
| 1 | **反推入口** | 你在可见窗里打开一个已知作品的页面 → 工具自动把番号位置换成 `{q}`，得到 URL 模板 |
| 2 | **录制动作** | 你在可见窗里自己搜一次（打字 + 点搜索）→ 工具把你做过的两步记成动作序列 |
| 3 | **点选图片** | 鼠标点哪张图就抓哪张（或点一个容器，抓里面全部图）→ 自动生成选择器 |
| 4 | **试跑闸门** | 一键试跑，三段式回显；没通过不许保存 |

**明确不做（YAGNI）**：不引任何爬虫/RPA/浏览器自动化依赖（§8）；不做列表页批量/翻页抓取；
不做多站 fallback 优先级（字段留位）；不做 JSON 高级编辑（CodeMirror 6）/导入导出/定时体检（→ P3.3）；
**不碰移动硬盘**（只读写系统盘 `~/.file-finder/assistant/rules.json` ⇒ 零读盘）。

## 1. 三段式模型（标准化/流程化的落点）

```
① 入口 → ② 动作（可空）→ ③ 抽取
URL 模板     输入 / 点击 / 等待      图片 / 标题 / 演员
{q}          把搜索框填上再点搜索     候选链命中即用
```

②为空时行为与现在**完全一致**（javbus 这类 URL 直接带番号的站零改动）。
该划分与 MetaTube 的 provider、JavSP 的 scraper 组织同构（第三方背书）。

## 2. 数据模型（只做加法，向后兼容）

```ts
export interface SiteRule {
  id: string; name: string; enabled: boolean;
  detailUrl: string;                    // 含 {q}
  transport: 'browser';
  needsCookie?: boolean;
  queryTransform?: QueryTransform;
  steps?: ActionStep[];                 // ★ 新增（可空）
  fields: SiteFields;
}

export type ActionStep =
  | { act: 'type';  selector: string; value: string }   // value 支持 {q}
  | { act: 'click'; selector: string }
  | { act: 'wait';  selector?: string; ms?: number };   // 等元素出现 / 等时长

export interface SiteFields {
  cover?: FieldRule; title?: FieldRule; actress?: FieldRule; actressLink?: FieldRule;
  images?: FieldRule & { pickAll?: boolean };   // ★ 新增：一组图（剧照/多图）
}
```

**兼容策略**：只做加法、不做破坏性变更；存量 `rules.json` 无需迁移（实测磁盘 5 条与内置预设一致）。
暂不引入 `schemaVersion`（YAGNI，将来真有破坏性变更再加）。

## 3. 后端改动

### 3.1 新增 `runSteps()` —— 本次设计最关键的结构性注意点

```
runExtract = 幂等抽取 ⇒ 反复执行无害 ⇒ 可以轮询
动作序列   = 有副作用 ⇒ **只能执行一次**（重复点击 = 重复提交 / 跳错页）
```

现有 `runExtract` 是 `while(...) 执行 script 直到返回真值`；若把 click 丢进去，click 返回 undefined
⇒ **循环不退出 ⇒ 反复点击**。⇒ **动作与抽取必须是两条通道**。

```ts
runSteps(url, steps, extractScript, opts): Promise<{
  ok: boolean; cf: boolean; err?: 'cloudflare'|'timeout'|'aborted';
  steps: { index: number; act: string; ok: boolean; why?: string }[];
  fields?: ExtractedFields;
  httpStatus?: number; pageTitle?: string;   // 试跑定位用
}>
```

执行语义（顺序固定）：
1. `loadURL` → 轮询等 CF 清除（复用 `CF_DETECT`）。
2. 逐步执行 `steps`，**每步最多一次**；失败即中断并记录 `why`（区分"选择器没找到"与"页面没取到"）。
3. 动作结束后执行抽取脚本（**这一步幂等，可轮询/重试**）。
4. 窗口必销毁 + `trackWindow/untrackWindow`。

### 3.2 ⚠️ `_blank` / `window.open` 必须接管（v1 新增，硬伤）

静态证据：`setWindowOpenHandler` **只在主 UI 窗**设置了（`electron/main/index.ts:87-90`，行为 = `shell.openExternal` + `deny`）；
**抓取窗没有任何处理**。站点若用 `target="_blank"` 打开搜索结果（很常见），点击后会：
1. **新开一个不受控窗口**（未 `trackWindow` ⇒ `window-all-closed` 永不触发、应用关不掉，且可能闪现在屏幕上）；
2. 原抓取窗**停在搜索结果列表页** ⇒ 抽取到的是列表页、**不是详情页** ⇒ 抓取失败。

修法（在 `runSteps` 里给抓取窗设置）：
```ts
win.webContents.setWindowOpenHandler(({ url }) => {
  // 同窗导航：保持 session / CF 一致，且只有一个窗口要管
  if (/^https?:/i.test(url)) void win.loadURL(url);
  return { action: 'deny' };
});
```
并把点击后的等待语义统一成：**等"URL 变化或目标元素出现"**（`wait` 支持两种）。

### 3.3 `dryrun` 增强（PRD §437 已记录的必做项）

现状（静态证据 `assistant/index.ts:92-99`）只回 `{ url, ok, cf, err, fields }` ⇒ 对 404 页也是"加载成功但抽不到"，
**分不清"这个番号在该站不存在"和"选择器写错了"** —— 校准规则时的主要绊脚石。
增强：回传 `httpStatus` + `pageTitle` + `steps`（每步结果）。

### 3.4 保存校验

- 后端**软校验**：`detailUrl` 缺 `{q}`、空 selector、空候选链 ⇒ 拒绝。
- 硬闸门（**没试通不许存**）放**前端**（保存按钮可用性 = 最近一次试跑是否通过，AC-7）。后端不强制，免得挡住脚本化调用。

## 4. 三个"看得见摸得着"的能力（复用同一个可见窗形态）

复用 `passChallenge` 已验证的形态：`1000×720` / `show:true` / 同一 `persist:assistant` / 同一 `CHROME_UA`。

### 4.1 反推入口模板（价值最高）

用户打开一个**已知作品**的页面 → 取 URL → 用**既有 `parseTitle`** 识别其中番号 → 把该片段替换为 `{q}`。
> 例：打开 `https://站点/ABP-123` ⇒ 自动得到 `https://站点/{q}`。
> 番号识别不出时，退化为"让用户把番号那一段**框选**出来"（拖选文本，仍然不需要懂技术）。

### 4.2 录制动作

用户在可见窗里**自己搜一次**（点搜索框、打字、点搜索）→ 监听 `input` / `click` → 生成 `steps`。
- 与 4.3 **共用同一个选择器生成器**（见下）。
- 用户手动点进详情页**不算一步**：由 §3.2 的同窗导航自然记录为 URL 变化。
- 步数上限（如 8 步）+ 每步可视化增删/调序。

### 4.3 点选图片

`mousemove` 高亮（outline 2px）+ 跟随提示条（显示将生成的选择器）；`click` 捕获回传后关窗；`Esc` 取消。

**选择器生成策略（稳定性分级 = 标准化的核心）**
1. `#id`（若唯一）
2. `meta[property="og:image"]`
3. `[data-*]` 稳定属性 + tag
4. `tag.classA.classB` —— 用 `querySelectorAll(sel).length === 1` 验证唯一性
5. 逐级加父级限定；仍不唯一才用 `nth-of-type`（**UI 标红：站点改版必失效**）

**多图**：可先点"容器"，再取容器内**全部** `img`（`pickAll:true`）；懒加载图已有 `rawSrc()` 兜底（`data-src/data-original`）。
**选完立刻自动试跑**，通过才允许保存。

## 5. 前端（四步向导，沿用现有骨架）

落在 PRD §4 已规划的全屏 `n-modal`**左栏第 ② 项「站点规则」**（骨架照抄 HistoryTable）。

| 步 | 内容 | 校验 |
|---|---|---|
| ① 入口 | 站点名 + **「打开页面自动反推」** + URL 模板 + 查询词变换 | 必须含 `{q}`，或显式勾"无需查询词" |
| ② 动作 | **「录一遍」** + 步骤列表（动作/选择器/值）+ ↑↓ 调序 + 删除 | 选择器非空；**可整段跳过** |
| ③ 图片 | **「点选图片」** 或手填；可切"容器内全部图" | 必须过 `COVER_BLACKLIST`（命中要**提示**，不静默丢弃） |
| ④ 试跑 | 三段式回显：页面取到没（状态+标题）→ 每步结果 → 各候选命中值 | **封面未通过 ⇒ 保存禁用** |

UX 纪律：每步一屏、**默认可跳过**；术语换人话（"输入框选择器"→"搜索框"）；失败只说"卡在哪 + 一个动作"；
沿用两条不许动的样式纪律（`.toolbar{flex-wrap:nowrap}`、`.header-bar .n-input{width:200px}`）。
**手填选择器降级为"高级模式"**（折叠区）—— 对普通用户隐藏，对你自己可用。

| 段 | 失败 | 文案（人话） |

| ① 页面 | CF / 404 / 超时 | 「站点要人工过一次验证」/「这个番号在该站不存在」/「页面打不开，可能站点改了域名」 |

## 8. 为什么**不引**爬虫/RPA 库（联网调研，2026-10-05）

| 候选 | 为什么不引 |
|---|---|
| puppeteer / playwright + stealth | `puppeteer-extra-stealth` 已停维护、被 CF 主动识别；Playwright 开箱即被 Turnstile 检出。我们已有**真 Chromium 隐藏窗 + 真 session + 人工过一次验证**（javbus 实测 100%）⇒ 引它是**降级**。 |
| browser-use / Stagehand / Skyvern | 都要自带 LLM key，每动作一次模型推理（10 步 ≈ 30+ 调用）。它们解决"选择器写不住"，我们缺的是"人改规则"的 UI。 |
| Crawlee / Scrapy / cheerio | 无浏览器栈、过不了 CF；PRD §六 已明确不引。 |
| **借鉴（非依赖）** | JavSP「每天自动测试一次站点抓取器」→ 后续规则体检；JavSP `active_scrapers` / MetaTube provider priority → 多站 fallback 参照。 |

动作与拾取全部用 `executeJavaScript` 在页面内完成 ⇒ **零新依赖**。
反证：现有 `buildExtractScript` 同机制已在 javbus 等站**真机实测 100% 命中** ⇒「页面内注入不受站点 CSP 影响」**已被实测证明**，非推测。

## 10. 风险与注意点

1. ⚠️ **动作只能执行一次**（不能像抽取那样轮询）⇒ 独立通道。
2. ⚠️ **`_blank` 必须接管**（§3.2）—— 否则功能失败 **且** 窗口泄漏（应用关不掉）。
3. ⚠️ **任何新窗口都要 `trackWindow`**（既有坑）。
4. ⚠️ **可见窗互斥**：人工过验证窗与拾取/录制窗不能并存。
5. ⚠️ **`cf_clearance` 绑 IP+UA+TLS** ⇒ 拾取/录制/试跑/正式抓取必须同 partition（已满足）且 UA 一致（`CHROME_UA`）。
6. ⚠️ **拾取器注入脚本返回 Promise**（等用户点击）；页面导航/关窗会让它永不 resolve ⇒ 必须**超时 + 取消**（复用 `signal`），否则挂住请求。
7. ⚠️ **黑名单可能误杀**：拾取到的图命中黑名单要**提示**（"可能不是封面"），不静默丢弃。
8. ⚠️ **懒加载图**：拾取时可能尚未加载（`src` 空）；`rawSrc()` 已兜 `data-src/data-original`，UI 仍要提示"这张还没加载出来"。
9. ⚠️ **规则失效是常态**（站点改版）⇒ 试跑要能反复跑；"最后成功时间"留给 P3.3 体检。
10. 只写 `rules.json`（系统盘）⇒ **零读盘**，不触发最高优先级红线。
11. 保存闸门放前端；后端只做软校验。
12. 不引依赖、不改 `CACHE_*`、不碰 `bin/` 与索引库。
13. **成功率不承诺 100%**：站点千差万别（要登录 / canvas 渲染 / 图片加密 / 强风控）。既有降级链（认不出番号 → 视频抽帧 → 手动 URL）继续兜底。

## 11. 设计自检（六问 + 三处遗漏）

| 问题 | 结论 |
|---|---|
| 方案是否合理成立？ | **骨架成立**（三段式、动作/抽取分通道、录制与拾取复用可见窗）；但 v0 **不足以让普通用户成功**，v1 已补 3 处。 |
| 是否有遗漏？ | **有 3 处真遗漏**（见下），已补进 v1。 |
| 设计是否合理？ | 合理：只做加法（不动存量规则）、失败可定位（三段式回显）、闸门前置（试跑通过才存）。 |
| 是否契合项目？ | 契合：零新依赖、零读盘、复用 CF 通道/可见窗/jobs/queue/全屏 n-modal 骨架；仅改主进程一处（要重启 dev）。 |
| 能否"点脑子就能操作"？ | **v0 不能**（用户推不出 URL 模板、写不出选择器）⇒ v1 用**反推 + 录制 + 点选**替代一切手写。 |
| 是否有把握落地？ | P3.1 **有把握**；P3.2 **中等**（窗口生命周期与导航时序是主要不确定项，且只能真机验）。 |

### 三处真遗漏（v1 补法）

1. **`_blank` 开新窗** ⇒ 抓取窗停在列表页 + 不受控窗口泄漏。
   补：抓取窗设 `setWindowOpenHandler` → `deny` + **同窗导航**。（静态证据：`main/index.ts:87-90` 只给主窗设了）
2. **入口模板普通用户推不出来** ⇒ 补「**打开一个已知作品页自动反推 `{q}`**」，复用既有 `parseTitle`。
3. **动作序列普通用户写不出来** ⇒ 补「**录一遍**」，与拾取器共用同一套选择器生成器。

### 另两处实现细节遗漏（非致命，已进风险清单）

4. 拾取器注入脚本的 Promise 可能永不 resolve（导航/关窗）⇒ 超时 + 取消。
5. 未引入 `schemaVersion`：只做加法的兼容策略已写明；将来需要破坏性变更时再引入。
