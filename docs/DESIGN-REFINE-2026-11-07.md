## 一、为什么是现在

主人原话：「不要让我们的界面看起来就很廉价杂乱」。

**诊断不是靠感觉，是数出来的**（`src/**/*.vue` 静态统计，可复算）：

| 旋钮 | 现状 | 红线（克制极简） | 结论 |
|---|---|---|---|
| 字号档位 | **9 档**：10 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 16 / 26 | ≤ 6 档，档间跳跃不爬坡 | 12.5 / 11.5 是纯爬坡，肉眼无差 |
| 标题 ÷ 正文 | 13 ÷ 12 = **1.08** | 需"一眼可分" | 等于没分 |
| 圆角档位 | **7 种**：0 / 2 / 3 / 4 / 6 / 8 / 9 | ≤ 3 档且同心 | 同屏两组圆互相打架 |
| 文字灰阶 | 硬编码 12 种（#999 #666 #a9a9a3 #b5b5bd #9ca3af #7a8da9 …） | 一屏 ≤ 3 档 | 绕开 token，灰阶失控 |

**「廉价」的机制**：便宜感的本质不是丑，是**处处差不多**——字号挨着、灰阶挨着、圆角挨着。
眼睛读不出主次，就判定为"随便做的"。

**同样重要的一条反证**：我按像素量了 WorkBuddy 截图（1265×795 原图取众数色）：

| 位置 | 实测 |
|---|---|
| 内容画布 | `#141414` |
| 侧栏 / 顶栏 | `#1f1f1f` |
| 激活项 | `#313131` |
| 分区 | 靠明度差，无分割线 |

本项目现在是 `#18191c` / `#1f2022` —— **只差一档**。
⇒ 所以"照抄它的配色"几乎没有收益，**真正要抄的是层级纪律与控件克制**。

## 二、目标 / 非目标 / 反目标

**目标**
1. 一屏内**一眼读出主次**：谁是标题、谁是数据、谁是说明。
2. 控件形态**收敛到 3 种**（填充输入框 / 图标钮 / 文字按钮），高度、圆角、hover 全站一致。
3. 深色下**不用投影**分区，改用 1px 半透明发丝线 + 三档明度。
4. 五个界面（网格 / 缓存 / 设置 / 清单 / 外壳）**同一套语言**，不是五个作者各写一套。

**非目标**
- 不改布局结构、不改信息架构、不增减任何功能。
- 不换 naive-ui、不引入 UI 库、不引入动画库。
- 不动网格列数与密度三档逻辑（10-29 刚落地）。
- 不做主题切换动效升级（保留现有 120ms）。

**反目标（做到就算失败）**
- 为了"高级"降低信息密度 —— 一屏 12 个封面必须保住。
- 为了"统一"把交互改得他不认识 —— 双击、S/F5/D、面包屑全部原样。
- 出现"看起来更花"的界面：无彩不是加灰，是**减色**。

## 四、设计语言 v2

### 4.0 从 WorkBuddy 侧栏提取的七条（实测，已内化）

**测量方法**：侧栏截图原图 446×1230。缩放比按字号反推 = **1.32**
（12px 分区标签 ink 16px、13px 列表项 ink 17px、14px 导航项 ink 20px，三点互相印证），
下列几何值都已换算成逻辑 px。取色方法：文字取其笔画核心像素（抗锯齿最亮处），非平均值。

| # | 提取到的规则 | 实测依据 | 我们照抄什么 |
|---|---|---|---|
| 1 | **文字只有 2 档色** | 主文 `#e9e9e9`、次要 `#8f8f8f`；全图再无第三种文字灰 | **砍掉 text-3**。弱化靠字号降到 11，不靠第三档灰 |
| 2 | **图标与所在行文字同色** | 导航行图标 = 标签 = `#ffffff`；空间行图标 = 标签 = `#e9e9e9` | 不做"灰图标 + 白文字"；图标继承行色，整行一起亮暗 |
| 3 | **行高 30 / 行距 2.6** | 行距实测 43px ÷ 1.32 = 32.6 | 列表行 34、表格行 36（数据表略高于聊天列表） |
| 4 | **分区只靠留白 + 12px 灰标签** | 全侧栏 **零分割线**；"任务（7）"→ 首行 14px，组间距 20 | **删掉我上一版提的 1px 分割线**，改用留白 |
| 5 | **激活态 = 圆角 8 的 30px 灰底** | 胶囊实测 418×40 ⇒ **317×30**，圆角 8，`#313131`；无边框、无色条、无阴影 | 左轨与列表统一这个形态（左轨因图标钮放大到 40×40，圆角 10） |
| 6 | **图标 16px、统一描边体** | 图标 ink 18px ÷ 1.32 ≈ 14 主体 / 16 外框，与文字间距 6~8 | **我们现在 15 个图标里 2 个是实心**，见 §4.7 |
| 7 | **字重只用 400 / 500** | 标题 `WorkBuddy` 500~600，正文全 400，全图无 700 | 全站禁 600 / 700 |

> ⚠️ **修订 3（2026-11-08，字重 500 在中文上不生效）**
> 第 7 条照抄 WorkBuddy 是有前提的：**它这套规则只在西文成立**。
> 本机实测（注册表 + 字体文件）：
> - `Segoe UI` → `SegUIVar.ttf`，**可变字体**（300~700 连续）⇒ `font-weight: 500` 有真实效果
> - `Microsoft YaHei` → `msyh.ttc` / `msyhbd.ttc` / `msyhl.ttc`，**只有 300 / 400 / 700**
>
> CSS 字重匹配规则（Fonts 4）：请求 500 而字体缺 500 时，先向下取 ≤500 的最大值（400），
> 不会跳到 700，也不会合成。⇒ **中文写 `font-weight: 500` 等于写 400**，视觉上零变化。
> 日文假名同理：字体栈里没有日文字体，假名先被雅黑接住（雅黑含假名）；
> 系统虽然有 `Yu Gothic Medium`（=500），但它排在雅黑之后，永远轮不到。
>
> **结论**：`400 / 500` 只是"代码里允许出现的两个值"，**不是中文能拿到的两档视觉层级**。
> 中文的主次必须由 **字号 + 颜色 + 独占一行** 承担（这也正是 §4.2 字阶表的真实作用）。
> 想让中文真有 500，只有两条路：把可变中文字体打进包里（`NotoSansSC-VF` 子集化后数 MB），
> 或者接受"中文只有 400/700"这个平台事实。
>
> ✅ **同日已按第一条路解决**：`public/fonts/` 自托管 **Geist Variable（西文）** + **MiSans VF（中文）**，
> 两者都是可变字体，`font-weight: 500` 现在**真的会取到 500 的字形**。
> 代价是 +4.6MB 包体，以及 MiSans 按 `unicode-range` 分片只覆盖常用字 ——
> 生僻字继续走系统字体兜底（回退链见 `tokens.css` 的 `--ff-font`）。

**关于字体家族**（他问的重点）：比对字形，WorkBuddy 用的就是 Windows 默认的
**Segoe UI + 微软雅黑**，与 `navie-theme.ts` 里的 `FONT_FAMILY` 完全一致。
⇒ **不需要引入任何字体**。离线包里塞中文字体是几十 MB 的负担，收益为零。
差距不在字体，在 **字号 / 字重 / 行高 / 间距** 这四件事——这也正是上面七条在管的东西。

**"协调"到底从哪来**（这是"看着舒服"的机制，不是玄学）：
1. 所有可点元素都是**同一个形状**（圆角 8 的块），只是底色深浅不同；
2. 图标与文字**共用一种颜色**，不各说各话；
3. 左右内边距**对称**（实测 12 / 12），没有任何元素贴边；
4. 层级**只由字号和留白表达**，颜色只分"主 / 次"两级；
5. 每一组的**行距相同**（32.6），所以整列有节奏，眼睛能顺着往下滑。

### 4.1 明度分层（三档面 + 发丝线，深色不加投影）

| 语义 | 深色 | 浅色 | 用在哪 |
|---|---|---|---|
| canvas 画布 | `#141414` | `#f7f7f8` | 内容区底 |
| panel 面板 | `#1f1f1f` | `#ffffff` | 左轨 / 工具条 / 表头 / 卡片底 |
| raised 悬浮 | `#2a2a2a` | `#f0f0f1` | 输入框 / hover / 弹层内的块 |
| hairline | `rgba(255,255,255,.08)` | `rgba(0,0,0,.08)` | 分区线（强调版 `.14`） |
| text-1 主文 | `#ededed` | `#1a1a1a` | 标题、数据、当前项 |
| text-2 次文 | `#8f8f8f` | `#5c5c5c` | 说明、未选中、时间、占位符、eyebrow |

**规则**：**只有 2 档文字色**（照抄 WorkBuddy 实测值）。层级不再靠第三档灰，
而是靠 **15 / 13 / 12 / 11 的字号差 + 500 字重**。`#999` `#666` `#9ca3af` `#a1a1a1` 一律回 token。

**语义色**（唯一的例外，见 §六 判断 1）
- 错误 `#e05a5a` / 警告 `#d8a52b` / 成功 `#5fa87a`
- 只用于**文字与 1px 描边**，不做色块背景、不做图标填充。

### 4.2 字阶（4 档）

| 角色 | 规格 | 行高 | 用途 |
|---|---|---|---|
| 页标题 | 15 / 500 / `text-1` | 22 | 每屏唯一一个 |
| 卡片标题（封面名） | **15** / 500 / `text-1` | 20 | 网格卡片（2026-11-08 由 14 抬到 15） |
| 区块标题 | 13 / 500 / `text-1` | 20 | 设置页分区 |
| 正文 | 13 / 400 / `text-2` | 20 | 说明、表格内容 |
| 次要 | 12 / 400 / `text-2` | 18 | 辅助说明、域名、时间 |
| eyebrow | 11 / 500 / `text-2` / `letter-spacing: .08em` | 16 | 表头、统计标签、计数 |

数字一律 `font-variant-numeric: tabular-nums`（表格与统计不跳动）。

> **关于 1.8 倍红线**：那是营销页的尺子。工具界面没有 hero，15/13 = 1.15
> 靠 **字重 500 + 纯白 + 独占一行** 补回主次。真正要消灭的是"12 vs 13 这种没差"。

### 4.3 圆角（3 档，同心）

| 档 | 值 | 用在哪 |
|---|---|---|
| 卡片 / 面板 / 弹层 | 10 / 12 | 表格容器、弹层 |
| 控件 | 8 | 输入框、按钮、图标钮、封面 |
| 圆点 | 999 | 头像、状态点 |

**同心规则**：内元素 R = 外容器 R − 内边距。嵌套时不许出现"大圆里套小尖角"。

### 4.4 间距（4 的倍数，三层递减）

| 层 | 值 |
|---|---|
| 区块之间 | 24 |
| 卡内 padding | 12 ~ 16 |
| 元素之间 | 8 |
| 页边距 | 20 |

**硬规则**：区块间距 > 卡内间距 > 元素间距。三个数必须递减。

### 4.5 控件（统一到 3 种形态）

| 形态 | 规格 | 说明 |
|---|---|---|
| 填充输入框 | 高 30/32，R 8，底 `raised`，无边框；focus 加 1px `hairline-strong` | 搜索框也走这个 |
| 图标钮 | 28×28，R 8，透明底；hover `raised`；激活 `raised` + `text-1` | 密度 / 刷新 / 平铺 / ⋯ |
| 文字按钮 | 高 30，R 8，透明底 + hover `raised`；主按钮＝白底黑字 | 确认类动作 |
| chip（仅只读标签） | 高 22，R 6，底 `raised`，字 11/500 `text-2` | 盘标签、状态标签 |

**状态表达（无彩怎么表达）**
- hover：只改描边 `.08 → .20` 或底色 → `raised`，**不位移、不投影**
- 选中：2px `text-1` 内环，或反色底（白底黑字）
- 焦点：`0 0 0 2px rgba(255,255,255,.35)`（浅色为 `rgba(0,0,0,.25)`）

### 4.6 状态表达（修订 1 后：高亮只出现在三处）

| 场景 | 现在的表达 | 改成 | 用高亮色？ |
|---|---|---|---|
| 左轨当前页 | 粉色图标 + 粉色底 | 40×40 圆角 10，底 `raised`，图标 `text-1`；其余 `text-2` | **否**（明度） |
| **网格卡片选中** | 3.5px 蓝环 + 标题 600 蓝 | **2px `--ff-highlight` 环** + 标题 500 高亮色 | **是** |
| **网格卡片悬浮** | 图放大 + 标题变蓝 | 保留：图轻微放大 + 标题转 `--ff-highlight` | **是** |
| **输入框焦点** | naive 默认蓝环 | 1px `--ff-highlight-line` 描边，无外发光 | **是** |

### 4.9 按钮系统（4 种形态 × 4 个状态）

**现状问题**：工具条 8 个控件，**7 种底板**——填充块（盘/面包屑）、1px 描边钮（返回/更多/密度）、
无底图标钮（平铺）、圆形描边钮（刷新）、亮填充框（搜索）。同权重、同高度都做不到，
所以一眼"拼装感"。

| 形态 | 尺寸 | 圆角 | 默认 | hover | 激活 / focus | 禁用 |
|---|---|---|---|---|---|---|

> ⚠️ **修订 2（2026-11-08，文字钮默认色 `text-2` → `text-1`）**
> 原文写"默认 `text-2`、hover `text-1`"，实施后立刻出事：naive 的 `textColor` 与
> `textColorDisabled` **同值**（原厂都取 `textColor2`），只靠 `opacityDisabled` 区分。
> 按钮又是**透明底**，没有底色可以替文字撑"可点"这件事 ⇒
> 真正可点的按钮和真禁用的按钮长得一样（主人当场点出：换封面底栏里唯一可点的「退出」被读成 disabled）。

> ⚠️ **修订 4（2026-11-08 晚，悬停 / 选中拆成两档）**
> 表里 hover 与"激活"同值 `#2a2a2a`，实施后两个问题同时出现：
> ① 它与左轨的选中灰（浅 `#ebebeb` / 深 `#313131`）**不是同一个值** —— 鼠标扫过左轨和扫过工具条是两种灰；

> ⚠️ 这里**没有**采用"选中换实心图标"那条更明显的路 —— 它破 §4.7「只用 Outline 单一套」。
> 若浅色下仍嫌选中不够跳，再谈那个（代价是图标体系分叉）。


**选形态的规则**
- 只有图标 ⇒ 图标钮；有图标 + 有文字 ⇒ 文字钮（WorkBuddy 除「发现应用 ⌄」外没有第三个变体）
- **每屏最多 1 个主按钮**
- 输入类 ⇒ 填充框
- **禁止**：圆形按钮、带底色的 tag 当按钮用、同一行出现两种圆角

**关键技术点（这是"不打补丁"的地方）**
1. naive-ui 的默认按钮自带 `border: 1px solid`。要变成透明无边框，
   **不能写 `border: none`**——那样高度会少 2px，hover 时整行跳一下。
   正确做法：`border: 1px solid transparent`（保留占位）。
2. 全部走 `themeOverrides.Button`，键名按 naive 的 `{属性}{状态}{语义}` 命名
   （已在 `node_modules/naive-ui/es/button/styles/light.mjs` 核对）：
   `colorHover` `colorPressed` `textColor` `textColorHover` `border` `borderHover`
   `borderPressed` `borderFocus` `borderRadiusSmall` `heightSmall` `fontWeightStrong`。
   **不在 scoped CSS 里逐个 `!important`**。
3. `moreMenuProps` 里的 `--n-option-color-hover: rgba(110,123,173,.16)` 是**蓝灰**，
   与无彩方案冲突 ⇒ 改 `rgba(255,255,255,.06)`；`--n-border-radius` 4 → 8；
   `--n-font-size` 14 → 13（对齐字阶）。

### 4.10 设计系统：三层 token + 唯一出口（为"以后好改"服务）

**分层**

| 层 | 放什么 | 谁能用 |
|---|---|---|
| **L1 原始值** | `--ff-n0/n1/n2/n3`、`--ff-space-*`、`--ff-r-*`、`--ff-fs-*` —— 只有数值，没有用途 | **只有 tokens.css 自己** |
| **L2 语义** | `--ff-canvas / --ff-panel / --ff-raised / --ff-line`、`--ff-text-1/2`、`--ff-accent`、`--ff-danger`、`--ff-h-table` | 组件与 naive 映射 |
| **L3 落地** | `naive-theme.ts`（语义 → naive 键）+ `ui.css`（语义类） | 业务模板只写类名 |

**为什么要留一个 `--ff-accent`（现在它等于白）**
无彩是**当前裁决**，不是永久裁决。留一个语义位，将来想换回品牌粉只改这一行，
组件里一个 `color:` 都不用动。**把这个位删掉才是真的锁死。**

**唯一出口（三条不许破）**
1. 业务 `.vue` 里**禁止出现 `#hex` / `rgb(`** —— 只有 `tokens.css` 可以。
2. naive 的颜色与圆角**只走 `naive-theme.ts`**，不在 scoped CSS 里 `!important` 硬改。
3. 同一个值**不许写两遍**。

**⚠️ 实现方式（这里有个坑，已静态查证）**
naive-ui **不能**在 `themeOverrides` 里直接写 `var(--ff-...)`：
它在 JS 里会对 `primaryColor` 做 `changeColor()` 解析，
实测 `node_modules/naive-ui/es/dropdown/styles/light.mjs:47`、
`input/styles/dark.mjs:69`、`checkbox/styles/light.mjs:44` 都用了。
传 `var()` 进去会解析失败 ⇒ 组件颜色变黑或直接丢样式。

⇒ 正确做法：`naive-theme.ts` 用
`getComputedStyle(document.documentElement).getPropertyValue(...)` 读 L2 变量，
包成 `computed(() => ...)` 依赖 `isDark`，切主题时自动重算。
**tokens.css 仍是唯一真相源，naive 拿到的是真 hex。**

**护栏（正面回答"以后会不会复发"）**
新增只读探针 `docs/probes/tokens/no-raw-color.mjs`：
扫 `src/**/*.vue` 与 `src/**/*.ts`（`styles/tokens.css` 除外），
命中 `#xxxxxx` 或 `rgba(` 即报错。
**今天跑会命中 12 处硬编码色 + 7 种圆角；改造完成后必须为 0。**
这是唯一能挡住"下次又有人塞个 `#999` 进去"的机制——靠自觉一定会复发。
