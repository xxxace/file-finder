# 多分片选择器重构（2026-11-11）

> 对象：「一个封面下有多个文件」（同一部片的 `A/B`、`前編/後編`、`CD1/CD2`）时
> 按回车 / 双击弹出的那一层。
> 代码：`src/views/FileFinder/{useFileListPopover.ts, fileNameSplit.ts, index.vue, styles/list.less}`
> 音效：`src/utils/sfx/{recipes.ts, index.ts}`

---

## 一、为什么重构（2026-11-11 业主判断：「感觉有些和我们的界面设计系统不一致」）

不只是"不好看"，是三件事各错一处：

| # | 现象 | 根因 |
|---|---|---|
| 1 | 弹出层里冒出一个紫红色立体方块 | 用的是 `fiv-icon-*`（`fileTypeIcon/` 那套 Windows 大图标），而全站其余位置是封面图或 `n-icon` 线条 —— **两套视觉语言** |
| 2 | 名字居中折行、大小孤零零吊在卡片最底 | `.file-item` 是 150×116 的卡片，只装三个短字段；`.file-size` 用了 `margin-top: auto` 把它推到 116px 之外 ⇒ 判断"选哪个"要上下扫两趟 |
| 3 | 横排 + `←→` | 与网格方向键**同键不同义**；≥4 个文件换行后 `←→` 还会跨行（`↓` 只是 `+1`） |

还有一层**更靠前**的问题：`TST-001A/B` 是同一部片的分片，界面把它画成了
"两个并列的独立作品"——没有段序号，也没有"从第一段连着看"的路径。

### 业主裁决（2026-11-11，逐条）

1. **只做视觉层**（方案 A）。"我们不是内置播放器，你的连续播放没有意义" ⇒ **不做连播、不加段序号**。
2. **不要冗余文案**：不显示"共 2 个分片"、"合计 5.23 GB"这类提示。
3. **名字过长要保留前后两部分、中间省略**，**扩展名必须完整显示**。
4. **回车仍然先弹层**（不改既有动作）。
5. 音效：**方向键移动与鼠标悬浮用同一个音**，**回车另一个音**；取自 React Bits Sound Lab，**名称对得上行为的优先**。

## 二、方案：纵向菜单（材质 = tooltip 那一套）

不新造一套：尺度复用右键菜单（`ctx-menu.css`），**材质复用 tooltip**（`--ff-tooltip-*`）。

**为什么是反色深片而不是 naive popover 的白底**（业主 2026-11-11：「不要现在这种
n-popover 的样式，还带小三角形不好看」）：这层浮在**封面照片**上。浅色白片压在照片或
白卡片上都"没有边界可依"——这正是 `tokens.css` 里 `--ff-tip-*` 那段注释的原判据。
反色深片是唯一在任何底色上都立得住的材质。

| 项 | 取值 | 来源 |
|---|---|---|
| 材质 | `--ff-tooltip-bg` / `-text` / `-shadow` / `-backdrop`，圆角 8，**无箭头** | tooltip 同款（`FluidTipHost.vue`） |
| 容器 | `width: 300px`，内衬 4px，`gap: 1px` | 对齐 `.ctx-menu` |
| 行高 | 32px | `--ff-h-head` |
| 图标 | 16px `n-icon` 线条（`VideocamOutline` / `ImageOutline` / `MusicalNotesOutline` / `DocumentOutline`） | 与 `.ctx-item` 同族 |
| 名字 / 大小 | `--ff-fs-body` 白 / `--ff-fs-eyebrow` 白 + `opacity .62`，右对齐 | — |
| 悬浮 | `--ff-tooltip-hover`（白光 10%） | 新 token，反色片专用 |
| 选中 | `--ff-highlight` 实蓝底 + `--ff-on-highlight` 白字 | macOS 深色菜单同逻辑 |
| 键位 | `↑↓←→` 全部接受，`Enter` 打开，`Esc` 关闭 | `←→` 是照顾网格的肌肉记忆 |
| 定位 | 键盘：锚点 = 卡片**下沿** + `bottom-start`；鼠标：事件坐标。两者都过一道视口收敛 | 见下 |

**定位被改了三次，判据记在这里别再摆**：

| 版本 | 锚点 | 结果 |
|---|---|---|
| 初版 | `r.bottom`，无收敛 | 卡片靠屏幕底时整层溢出 ⇒ 业主「太靠下」 |
| 第二版 | `r.top` + 收敛 | 改过头 ⇒ 业主「又太靠上了」 |
| 第三版 | `r.bottom` + 收敛 | 位置对了，但离文件名还差一截内边距 |
| **现在** | **`r.bottom - 6` + 收敛** | 够空间时贴着**文件名称的下沿**；撞到视口底才上移恰好够的距离 |

业主原话：「尽量在文件名称下面，当然不够空间或者触达边缘时才适当的位移」
→「默认能不能上调 4-8px？太靠下了，离名称太远了」。

⇒ **初版「太靠下」的真因是缺收敛，不是锚点错**。这条弯路记下来：遇到"位置不对"
先查有没有边界收敛，别急着换锚点。

那 6px 的来源：`r.bottom` 是卡片**盒子**底边，盒子底部还留着 `--item-pad-b`
（`grid.less`：宽松档 6 / 紧凑档 4）给标题的呼吸空间。减 6 正好落在标题文字下沿。
不读 `--item-pad-b` 是因为它在 `.image-box` 上按密度档设、JS 侧读不到，而两档只差 2px。

`clampIntoViewport()` 的实现要点：
- `:x/:y` 是**固定坐标**，naive 在 manual 定位下**不做翻转**（只有 trigger 挂在元素上
  时才自动 flip）⇒ 边界必须自己收。
- `nextTick` + `rAF` 后量一次实际矩形（`nextTick` 只等本组件渲染，等不到 naive 内部
  写完 style；rAF 落在同一帧绘制之前，配合淡入第一帧透明，看不出修正）。
- 超下/超上/超右各平移回视口内 8px，**只平移不翻转**：≤5 行 ≈170px，平移几十像素就够；
  翻转会让弹层跳到卡片另一边，与"从这张卡展开"的手感断掉。
- 鼠标那条路的锚点（`e.clientY`，卡片中部）**不要跟着改**：点哪儿用哪儿是它的语义。

⚠️ **三条不能混用的色系**（一旦有人"统一一下"就会坏）：
- 这一片是 86% 黑，`--ff-text-1/2` 在深色主题下是浅色，压上去会跟白字重色 ⇒ 行内一律 `--ff-tooltip-text`。
- `--ff-menu-hover` 是**黑/白双向自适应**的（浅色黑 14% / 深色白 12%），压在恒定的深片上
  浅色主题那边会消失 ⇒ 反色片上的悬停必须用 `--ff-tooltip-hover`。
- `--ff-highlight-weak`（淡蓝 12%）在 86% 黑上几乎看不见 ⇒ 选中用实蓝。

⚠️ 选中态**不画边框**：32px 的行上加 1px 框会盖过文字，读起来像输入框。

⚠️ 改 popover 壳的三件事必须一起做（`ctx-menu.css` 里有完整注释）：
`:show-arrow="false"`（三角是独立 DOM，CSS 藏不干净）· `--n-*` 带 `!important`（naive 内联主题变量）·
属性再补一份（防变量名变更）。变量名已对 `naive-ui/es/popover/src/styles/index.cssr.mjs` 核过：
`--n-color` / `--n-text-color` / `--n-border-radius` / `--n-box-shadow` / `--n-padding`。

## 三、中间省略（`fileNameSplit.ts`）—— 本次的硬要求

### 为什么不能只用 `text-overflow: ellipsis`

它只从**尾部**切。而这一层几个文件名的前缀往往一模一样，区分点（`A`/`B`、`前編`/`後編`）
**和扩展名都在尾部** ⇒ 尾部省略正好把唯一的区分点藏起来。
（`list.less` 里那条"必须折 3 行"的老约束就是为此写的，本次是**替换**它，不是绕过它。）

### 做法：两段拼接，零测量

```ts
splitFileName('TST-001B.mp4')
// → { head: 'TST-001',  tail: 'B.mp4' }
splitFileName('[TST-002]完全版 特典映像 前編.mp4')
// → { head: '[TST-002]完全版 特典映像',  tail: ' 前編.mp4' }
```

- 尾段 = **扩展名 + 前 3 个字符**（`TAIL_KEEP = 3`），CSS 给 `flex: 0 0 auto` ⇒ 永不收缩。
- 头段 `min-width: 0` + `text-overflow: ellipsis` ⇒ 吃掉剩余宽度、只在放不下时出省略号。
- **宽度够时两段首尾相接、中间没有省略号** ⇒ 视觉上就是一个完整文件名，不会平白多个 `…`。

**为什么不用"逐字符测量 + 预算分配"**：那套每次换字体、缩放、DPR 变化都要重算，
而且 `Geist / MiSans VF` 没加载完时量出来是错的。两段拼接是**结构性**正确，不是算出来的。

⚠️ 两段之间**不许有空格或换行**（模板里写在同一行）—— 否则宽度够时中间也会裂一道缝。

## 四、音效

| 动作 | 音色 | Sound Lab 名称与官方描述 |
|---|---|---|
| 方向键移动 / 鼠标悬浮 | `Halo` | "A warm confirm for **choosing a card**." 0.36s / -19dB |
| 回车 / 双击选定 | `Halo` | 同上 |

⚠️ 2026-11-11 业主改口：移动原本用 `Notch`（"A soft detent for steppers"，0.06s），
当天改成也用 `Halo` ⇒ 移动与选定**同音**。代价是听不出"走了一格"和"已经打开"，
靠视觉兜；要恢复区分度，把 `EVENT_RECIPE['file-move']` 改回 `SFX_RECIPES.notch` 即可
（配方还在，没删）。

### 为什么否掉名字最直白的 `Enter`

官方配方第一层是 `{ type: 'sample', ...THOCK }` —— **真实笔记本键帽录音**，
要拖 `samples.js`（98KB base64）才出得了声。本仓 13 个音效全是 Web Audio 合成、零音频资产；
为一个回车引整套采样、还开一个"录音音色族"不划算。

按业主判据衡量：`Halo` 对的是"选一张卡"这个**行为**，`Enter` 对的只是"按了哪个键"。

### 破例记录

`sfx/index.ts` 第 ① 条纪律原本写"hover / 方向键 / 打开预览一律不配"。
本次是**主人指定**的第二处例外（第一处是 2026-11-09 左轨 hover）。
理由：那一层只有 2~5 行、全是同名近似项，光标落在哪一行**没有视觉锚点**，
声音是唯一能确认"我走了一格"的反馈。已在文件头注释里记明，避免被后来者当 bug 改回去。

⚠️ 走到列表**尽头不再出声**（`moveTo` 里 `i === fileCursor` 时直接 return）：
按到底还在响，用户会以为光标还在往下走。

## 六、待验（需真机目视）

1. 弹层是不是 tooltip 那种反色深片、**没有小三角**、没有残留的 naive 白边。
2. 名字很长时，`…` 是否落在头部、扩展名与 `A/B` 是否完整保留。
3. 悬浮（白光 10%）与键盘光标（实蓝白字）在同一行上是否能分得清。
4. 浅色 / 深色两个主题都要看：深片在两个主题下都要有边界（浅色靠落影、深色靠内发丝）。
5. 靠屏幕底部的卡片展开时，弹层是否翻到上方且不压住卡片。
6. 长按方向键：是否每格一声、到头是否静音。
7. 回车连按是否仍只起一个播放器进程（`e.repeat` 守卫 + 页面侧 2s 锁，两道都在）。
