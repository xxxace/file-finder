## 一、主窗口初始尺寸：`800×860`(默认宽) → `1280×860` + 限下限 `1024×640`

**改动**：`electron/main/index.ts` · `createWindow()`

```
width:  Math.min(1280, wa.width  - 40)      // wa = screen.getPrimaryDisplay().workAreaSize
height: Math.min(860,  wa.height - 40)      // 860 是用户原本就在用的高度，保留
minWidth: 1024,  minHeight: 640
```

**为什么是 1280（不是"看着舒服"）**：这是**实测夹出来的**，不是审美取整。

| 窗口宽 | 导航区宽 | 头部高 | 工具条 | 结论 |
|---|---|---|---|---|
| 640 | 224 | 37 | 不溢出 | 导航区裁内容（既有局限） |
| 800 | 376 | 37 | 不溢出 | 导航区裁内容（既有局限） |
| **1024（= minWidth）** | **488** | 37 | 不溢出 | **不裁 ✓** |
| **1280** | **616** | 37 | 不溢出 | **不裁 ✓** |
| 1920 | 936 | 37 | 不溢出 | 不裁 ✓ |

⇒ 1280 是"头部恒 37px、工具条不溢出、面包屑有 616px"的最小舒适档。
（改造前的完整形态在这四档是 **196/196/116/76px**——高度是窗口宽的函数，见 `probes/header-width/`。）

**这台机器的实测**（`docs/probes/win-size/out.txt`）：

```
分辨率 2048 × 1280 · 可用区 2048 × 1232 · 缩放 1.25
实取   1280 × 860（基准值，未触发小屏收窄）
判据   6/6 ✅（含 minWidth/minHeight ≤ 可用区）
```

⚠️ `minWidth: 1024` **不是脑补约束**：实测 640/800 下 `.nav-zone` 会裁掉内容（面包屑 + 根 chip + 返回
三样本来就挤）。1024 是"已知崩坏线之上的第一档"，让用户**拖不到**那两个档。
不想要这个限制的话删掉那两行即可，与其余改动无关。

**`Math.min(..., wa - 40)` 只为小屏兜底**：1366×768 这类屏放不下 860 高，不减的话开局半个窗口在屏幕外
（Windows 允许窗口比屏大，不会替你收）。**证据等级：实测**（探针在真 Electron 下取 `screen` 真实值）。

## 二、右键菜单新增「复制文件名（去后缀）」

**改动**：`src/views/FileFinder/index.vue` · ctxMenu 模板 / `onContextMenu` / `copyNameStem`

```
菜单现在是两项：  复制文件名            → ABC-123.mp4
                  复制文件名（去后缀）  → ABC-123
```

**为什么是"加一项"而不是"改原来那项"**：原来那个含扩展名的名字是**刻意的**（注释写明了：
"那是资源管理器里真能搜到的名字"）。为了新用途把它改掉 = 拿掉一个能力换另一个。
两个都留着，各有各的场合（粘贴到搜索框找片 → 去后缀；去资源管理器搜 → 含后缀）。

**不需要自己找最后一个 `.`**：服务端本来就把 `name` 与 `ext` 分开给（`fileNameOf` = `` `${name}.${ext}` ``），
所以 `item.name` 就是答案。少一处会算错的地方（`xxx.tar.gz` 这种多后缀，剥点剥不对）。
→ **零新增字符串处理**，只是把已有的两个字段各复制一次。**证据等级：静态**（类型检查通过；行为未在真机点过）。

## 三、条目数角标：工具条 → 面包屑的**当前段**

**改动**：`src/views/FileFinder/index.vue` · 模板（挪出工具条 / 两处面包屑分支）+ `<style scoped>`（新规则）

**为什么挪**：它量的是"**这一层**有多少条目"，却住在工具条、还夹在两个动作控件之间 ⇒
被读成「缓存记录」按钮的角标（`index.vue` 的注释自己也承认这个风险，`DESIGN-CACHE-PANEL` 里挂着"挪不挪？"）。
挂到它真正描述的那一段上，**位置本身就是说明**，不用再补 tooltip。

**实现：`::after` + `attr()`，不新增 DOM 子元素**

```html
<n-tag class="crumb crumb-current" :data-count="i === last ? crumbCount : null">
```
```less
.crumb-current[data-count]::after { content: attr(data-count); /* 红胶囊 */ }
```

两条理由，都不是审美：
1. **这一组的子元素个数在本项目是敏感量**（n-space 重复 key 事故同族，见 `FIX-2026-09-24-nspace-duplicate-keys.md`）
   —— 伪元素不进 DOM，个数一个都不变；
2. **tag 内部的 `.n-tag__content` 是 `overflow: hidden`**，真塞一个 `<span>` 进去会被裁掉；
   而 `::after` 挂在**根元素**上（n-tag 是 inline-flex），是 content 的**兄弟**，不在那个裁剪盒里。

`fileList.length` 为 0 时返回 `null` ⇒ Vue 不渲染该属性 ⇒ 选择器整条不命中 ⇒ 不画。
等价于原来的 `v-if="fileList.length"`，不需要再写一次判空。

**实测**（`docs/probes/header-width/out.txt`，5 档 × 真 Chromium + 真编译 scoped CSS）：

```
new 头部高（各宽度）：640→37  800→37  1024→37  1280→37  1920→37     ← 常量 ✓
new 角标 ::after content：["35","35","35","35","35"]              ← 规则真命中（不是 none）✓
new 导航区不裁内容：1024 / 1280 / 1920 不裁；640 / 800 裁
对照·关掉角标：      640 / 800 同样裁 ⇒ 那两档的裁剪是**既有局限**，与本次改动无关
⇒ 角标没有新增任何一档裁剪 ✓
```

**副作用（好事）**：角标搬走后工具条少 26px + 一格 gap ⇒ 640px 下导航区 **189 → 224px**（+35px）。

**证据等级：实测**（几何 + 伪元素 content + 截图三样）。
⚠️ **观感（红胶囊的圆角/间距/字重是否好看）未在真机目视** —— 只有探针截图，属于 `.png` 层面的目视。

## 五、网格左右贴边（首格 `margin-left` / 每行末格 `margin-right` 归零）

**改动**：`src/views/FileFinder/index.vue` · `.image-box` 加两行

```less
.image-box { margin-left: -5px; margin-right: -5px; }
```

### 问题是什么（静态证据）

`.image-box-item` 的算法是"**用 margin 撑间距，再用宽度把它补偿回来**"：

```
width: calc(100%/6 − 10px)      ← 每格宽度（--item-gap: 10px）
margin: 10px 5px 0px            ← 左右各 5px
⇒ 每格占位 = (100%/6 − 10px) + 10px = 恰好 100%/6   ⇒ 一行正好 6 个
```

代价：**容器左右边缘也各被吃掉 5px**（首格的 margin-left、每行末格的 margin-right）。
`.header-bar` 与 `.image-box` 同在 `.file-finder` 的 10px padding 里 ⇒
头部从 10px 开始，网格从 15px 开始 —— **整片网格比头部内缩 5px**。

### 为什么不是"删掉首/末格的 margin"（= 补丁，而且在这里会算错）

- 格子宽度是按"**margin 会被补偿**"设计的。只删首尾 margin、宽度不动 ⇒
  每行右端空出 5px，**左右还不一样宽**，比现状更糟。
- 列数在下面的断点里**是会变的**（6 / 5 / 3 / 2 / 1 列），任何写死 `6n` 的
  `:nth-child` 式子都会在窄窗下失效。

### 为什么不是 `gap`

`gap` 方向是对的（边缘天然为 0），但换过去必须**同步重算 `--item-width` 在 5 个断点里的每一个值**
—— 因为 `gap` 不占格子宽度、而 `margin` 占。那等于把"改一个百分比就能改列数"
变成"每个断点要改两个数字"。负 margin 只加 2 行，**断点和 item 的算法一个字都不动**。

### 实测（`docs/probes/grid-6col/out.txt`，真 Chromium + 真编译 scoped CSS）

```
                    头部          网格容器        首格左 · 末格右
改动前 @1920     10…1910      10…1910       15 · 1905      ← 左右各内缩 5px
改动前 @1280     10…1270      10…1270       15 · 1265
改动前 @1024     10…1014      10…1014       15 · 1009
改动后 @1920     10…1910       5…1915       10 · 1910      ← 与头部严丝合缝
改动后 @1280     10…1270       5…1275       10 · 1270
改动后 @1024     10…1014       5…1019       10 · 1014
判据 15/15 ✅   首格/末格相对头部 = 0；一行**仍是 6 个**（实测，非按公式推）
```

截图 `shot-before.png` / `shot-after.png`（同为 1280px，并排可对比）。

### ⚠️ 本次**未动**的东西（都是刻意保留）

| 没动 | 为什么 |
|---|---|
| `--item-width` / `margin: 10px 5px 0px` / `width` 公式 | 它们是**一套**，动一个必须动另一个。负 margin 让整套保持原样就达成目标 |
| 5 个响应式断点（≤600px 5 列、≤400px 3 列、≤300px 2 列、≤200px 1 列） | 是用户写下的特性。⚠️ 顺带一提：主窗口 `minWidth: 1024` ⇒ 这几档**实际触不到**，属于潜在的死代码 —— 但那是另一件事，不在这里删 |
| `.file-item`（popover 里的文件列表） | 它住在 `.hstack` 里，那个容器**已经有 `gap: 12px`**，是另一套耦合的算法。跟着改会顺手改掉 popover 的观感 |
| `.image-box-item` 的 `padding: 0 2px` + 1px 透明边框 | 用户说的是 **margin**。去掉 padding 会让 hover 边框紧贴图片。⇒ 图片距容器边仍差 3px，**要不要一起去掉，等用户定** |

**证据等级：实测**（3 档 × 前后对照 × 几何 + 截图）。**真机观感未目视。**

## 六、文件夹条目显示大小（缓存聚合，**零读盘**）

**改动**（前端 **0 行**）：

| 文件 | 改什么 |
|---|---|
| `electron/server/nedb.ts` | 新增 `loadSubtreeBytes()`（取数）+ `mergeSubtreeBytes()`（**纯函数**，归并） |
| `electron/server/index.ts` | **`wire()` 里补 size**（新增 `diskNameOf` / `safeSubtreeBytes`）；`toWire` / `toAnchor` 改 async 并透传 `(serial, relPath)` |

前端一个字没动 —— `:title="item.name + ' ' + getSize(item.size)"` 早就接好了，
`size` 一直是 0 所以显示 `—`。

**根因**：Windows 上 `fs.stat()` 对目录返回的 `size` **恒为 0**（NTFS 目录项不记字节数），
而"目录多大"在 Windows 上**没有任何一次系统调用能给出**。
递归遍历算 = 读盘 ⇒ 走缓存：每条记录的 `withBytes` 已经隐含了"那一层文件的字节总量"。
详见 `docs/ANALYSIS-folder-size-2026-10-02.md`。

### ⚠️ 落点第一版是错的，全过程记在这里

第一版把聚合加在 **`readFolder`** 里，交付后用户实测：**重启服务，hover 仍然全是 `—`**。

根因是 `openFolderController` 有**两条取数路径**：

```ts
const cached = noCache ? null : await findCache(serial, relPath, mode);
const doc = cached ?? (await scanAndCache(serial, drive, relPath, mode));
```

**浏览一个已缓存的目录走的是 `findCache` 短路，压根不经过 `readFolder`** ——
所以补在那里的 size 只有"点刷新（`noCache=true`，真扫一遍）"才看得到。
用户平时浏览的每一个目录，都是缓存命中那条路。

而且它还有**第二个更坏的后果**：`readFolder` 的返回值会被 `scanAndCache` **写进缓存**，
目录的 size 就以"子树总量"存进了库 —— 而缓存面板的 `bytes` = `data.reduce(Σ size)`
⇒ **双算**（子树被累加两次）⇒ 面板的大小列会整体失真。
（`probes/cache-panel-*` 当初实测过"双算 = 0"，这个改动差点把它打破。）

⇒ **正确落点是 `wire()`**，而且这不是新发明的规矩 ——
项目自己早在 `wire()` 上面写着：

> **所有**下发路径都必须过这里，且只留这一处。……**出口只有一个**，谁都不需要记得自己清一遍。

（那次是"缩略图登记漏了一条路"，同型的坑。）补在 `wire()` 里：
① 两条取数路径都会过；② 它是**下发态**，构造新对象、**不回写库**。

**三条容易 quietly 写错的边界**（抽成纯函数就是为了能单独喂数据验证）：

1. **路径边界** —— 用 `baseRel + '/'` 匹配，不是裸 `startsWith`（否则 `a` 吃掉 `ab`）；
2. **当前目录自己那条记录必须排除** —— 它的 bytes 是"这一层的直接文件"，不属于任何子目录；
3. **盘根**（`baseRel = ''`）—— 所有本盘记录都是后代，但盘根自己那条（`relPath = ''`）要跳过。

**键必须用"磁盘真名"**：查表用的键来自库里 `relPath` 的段名 = `readdir` 给的**原样名字**，
而 `item.name` 是**削过扩展名**的（`getFilename`）⇒ 新增 `diskNameOf()` 把 `ext` 拼回去。
带点目录名（`v1.2`）靠这个才对得上。

**降级**：`safeSubtreeBytes` 包住 —— `wire()` 是**每条下发数据的必经之路**，
让它抛出去的话，缓存库损坏/还原中会从"某个目录没有大小"退化成"**整个目录列不出来**"。

**验证**（`docs/probes/folder-size/verify.mjs`，**17/17 通过**）：

```
① 边界（构造数据）12 条 —— 含 a vs ab、a/x/deep 归到 x、盘根、serial 过滤
② 真库三路对照：213 条记录逐条比，归并版 vs 独立朴素实现 **0 不一致**
③ 守恒律：Σ(子树) == 子树内记录 bytes 之和 —— **0 条破**
④ loadSubtreeBytes（含 loadMeta）中位 0.84 ms
⑥ 端到端：**cached.data 里的 208 个目录条目 100% 查得到**，其中 205 个 size > 0
   ← 这一段就是针对上面那个失效模式补的：模拟 `wire()` 那一步，验证"条目名 → 键"对得上
```

**未实测**：真机（改的是服务端，**要重启 dev**）。

## 七、应用图标（桌面 + 窗口左上角）

**用户原话**：「我想给这个应用生成一个专属图标，包括桌面和窗口左上方的小图标」。
先从三个方向（色块镜 / 色块镜·播放 / 无底镜）里选了**甲 · 色块镜**：
渐变圆角方块 + 白色放大镜，镜片里是 2×2 缩略图网格 —— 语义直接对上"在缩略图网格里找文件"。

### 改了什么

| 文件 | 动作 |
|---|---|
| `build/icon.svg` | **新增**，矢量源，唯一的真相源 |
| `build/icon.ico` | **新增**，`16/24/32/48/64/128/256` 七档内嵌 PNG —— exe / 桌面快捷方式 / 开始菜单 |
| `build/icon.png` | **新增**，1024×1024 —— mac 兜底 |
| `public/favicon.ico` | **替换**（原来是 electron-vite-vue 脚手架的残留图标）—— 窗口左上角 |
| `electron-builder.json5` | `win.icon` / `mac.icon` / `directories.buildResources` |
| `docs/probes/icon-render/` | **新增**，生成脚本 + 证据 + 目视对照页 |

`electron/main/index.ts:57` 与 `index.html:5` **一个字没动** —— 它们指向的就是 `public/favicon.ico`，
换掉那个文件即可。

### 顺手发现的真问题：桌面图标根本不是自己的（静态证据）

`electron-builder.json5` 原**没有 `icon` 字段** ⇒ 打包出来的 exe、桌面快捷方式、开始菜单
用的全是 **Electron 默认图标**。窗口左上角那个是脚手架残留。
⇒ 这次补上 `win.icon` 才真正有"专属图标"。

### 为什么是手写矢量，不是 AI 生图

`ImageGen` 能生图（约 5–10 积分/张），但这个标记是**几何的**（圆、圆角方块、等距网格）——
AI 画精确几何常出现不对称与多余装饰，反而更差；而且出的是位图，还得再转 ICO。
矢量的额外好处：任意尺寸无损、透明底天然、进 git 可 diff。

### 生成方式：无头 Electron 光栅化 + 自己拼 ICO

实测这台机器上**没有任何 SVG 光栅化器**（`sharp` / `@resvg/resvg-js` / `canvas` / `jimp` /
`cairosvg` / `Pillow` / ImageMagick 全无）。所以照抄仓库既有先例（`probes/header-width/`
用真 Chromium 截图），用无头 Electron 光栅化 —— 附带好处是**渲染它的就是预览里那套 AA**。

## 八、多部组成的 popover 点不动 + 预览工具条的「下载」（2026-10-02 晚 · 用户反馈两条）

> 证据等级：**实测**（`docs/probes/popover-pick/`，真 Electron 无头 Chromium + 从活源码切出来的
> markup + 真实编译的 scoped CSS）。两条都先复现、再改、再复跑。

### 用户报的两条

1. 一个作品由多部组成时，双击卡片弹出的**文件列表**，点哪一部都打开**第一部**；
2. 预览封面时把**下载**按钮去掉（老是误触）。

### 根因（一条链）

**预览那张图把视口铺满了，于是它把「双击」的第二下吃掉了。**

- `previewedImgProps` 的 `width/height: 100%` 让预览 `<img>` 实测占 **1370×871**（窗口 1400×900），
  而 naive-ui 的 `.n-image-preview` 是 `pointer-events: all`（外包层是 `none`）；
- 实测：双击卡片后，`dblclick` 的 target = **`.n-image-preview`** ⇒ 卡片的 `@dblclick`
  （`handleOpen`）**永远收不到** ⇒ 多部组成的封面**弹不出文件列表**；
- 本该落在列表上的点击**漏到下层卡片**上，而卡片那条路是
  `files.find(VIDEO_EXT_RE)` ⇒ **永远第一部片子**（用户报的那条）；
- 顺带解释了第 2 条：预览铺满后**点图外关不掉**（遮罩 `z-index: -1` 在图的下面），
  只剩 ✕ / Esc，而「下载」就紧挨着 ✕ ⇒ 老是点到它。**而且它真的会去读移动硬盘**
  （下载的就是 `/raw` 那条原图），与「少碰移动硬盘」这条第一目标冲突。

### 改动（两处，都用 naive-ui 已有的口子，没有新机制）

| 文件 | 改了什么 | 用的是哪个口子 |
|---|---|---|
| `src/views/FileFinder/index.vue` | `n-image` 加 `:render-toolbar="previewToolbar"`，工具条去掉「下载」那颗 | `Image.mjs` 透传 `renderToolbar` |
| 同上 | `previewedImgProps` 加 `onDblclick`：**关掉预览 + 把这一下双击还给下面那张卡片** | `ImagePreview.mjs` 的 `handlePreviewDblclick` 会转发 `previewedImgProps.onDblclick` |

`onDblclick` 里两件事都走已有的路：关预览 = 点它自己的遮罩（遮罩的 `onClick` 就是 `close()`）；
还事件 = 按坐标 `elementsFromPoint` 找出 `.image-box-item`，`dispatchEvent` 一下双击，
走卡片自己的 `handleOpen`（不复制一份打开逻辑）。

**代价（知情选择）**：预览图本身的双击放大没了 —— 工具条里的「原始大小」那颗照旧在，功能没少。
