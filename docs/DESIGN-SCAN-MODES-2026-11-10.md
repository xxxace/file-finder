# 扫描三入口重构 · 更新读取 / 刷新 / 重新读取

**日期**：2026-11-10
**状态**：已落地（主进程 + 渲染层都有改动，**必须重启 dev**）
**起因**：主人原话「我改了名称或者把某个影片用文件夹包了一层，用补全这一片可以发现新包装的文件夹，
但改名还有之前未包装的还是在视图列表内，然后还要点一下刷新或者重读这一片才能更新」。
**旧三个入口的问题**：它们落在一张 2×2 表的三格里（范围 × 数据源），而用户脑子里只有一条轴 ——
「我改了 → 让它对上」。所以必须点两次，且第一个按钮的名字（「补全」）暗示它已经做完了。

| 旧动作 | 范围 | 数据源 |
|---|---|---|
| 刷新（↻ / F5） | 当前层 | 强制读盘 |
| 补全这一片 | 整片递归 | 缓存优先（缺的才读） |
| 重读这一片 | 整片递归 | 强制读盘 |

---

## 一、新分工

| 动作 | 位置 | 做什么 | 读盘量 |
|---|---|---|---|
| **刷新** | 右键菜单通用组第一位 + 顶栏 ↻ + F5 | 只重读**当前这一层** | 1 次 readdir + 逐条 stat（+ 新条目抽帧） |
| **更新读取** | 右键菜单（替换「补全这一片」） | 整片核对：当前层**逐条比对**，其余层**每层 1 次 stat**，只有变了的才真读 | 每层 1 stat；变化层再加一次全读 |
| **重新读取** | 右键菜单（替换「重读这一片」，带确认） | 整片每层都真读 | 全部层 |

「补全这一片」这个动作没有丢：它被并进「更新读取」（见 §三·3）。

## 二、探测信号：目录自己的 mtime

`SearchCache` 新增 `dirMtime?: number`（`scanAndCache` 写缓存时 `stat` 目录拿一次）。
NTFS 上**同一目录内增 / 删 / 改名 / 加一层文件夹**都会更新它 ⇒ 一条信号覆盖绝大多数真实改动，
代价是每层 1 次 `stat`（不是 readdir，更不是逐条 stat）。

老缓存没有这个字段 ⇒ 判为"不知道，当它变了" ⇒ 重读一次并把字段补上（**不需要升 `CACHE_VERSION`**，
与当年加 `srcMtime` 同一条思路）。

**实测（本机 NTFS，2026-11-10）**：

| 改动 | 目录 mtime |
|---|---|
| 新增文件 / 改名 / 包一层文件夹 / rename 覆盖 | 变了 ✓ |
| 就地写内容、`copy` 覆盖同名 | **没变** ✗ |

## 三、三个关键设计

1. **当前层永远逐条比对**（`openFolder?noCache=true`）。上表第二行就是盲区：同名文件被内容替换时
   目录 mtime 不动，而这一层正是用户**此刻盯着**的那一层 —— 盲区只可能在这里被察觉。
   所以把"最贵最准"的手段只花在这一层，其它层用便宜的 mtime 近似。
   服务端本来就有复用闸门（`srcMtime` + `srcBytes` 比对，见 `readFolder` 三处），所以"逐条比对"的
   实际代价是 n 次 stat，**未变的条目不会重抽缩略图/帧**。

2. **没变的层要把子目录名单带回去**（`probeLayers` 顺带返回 `dirs`，来自缓存、零读盘）。
   否则"跳过这一层"就等于"跳过整棵子树"，下面没缓存的层永远补不到。

3. **「缺大图」的补扫搬进更新读取**（旧「补全」的第二职责）。`probeLayers` 用 `hasBin(previewNameOf(sig))`
   在内存里判（与 `wire()` 的 `previewReady` 同源、零读盘），带 `needsPreview` 回给前端；
   前端对这一层放弃捷径、真读一次。不搬的话，2026-10-04 图片出库留下那批"缩略图在大图不在"的
   旧层就再也没有入口可以修了 —— 这是合并动作时最容易漏掉的一条职责。

4. **结束必须有回音**（主人反复强调"点了不知道有没有执行"）：`更新读取` 结束时
   `notify` 一句 `更新了 2 个目录 / 核对了 37 个目录`；零变化说 `没有需要更新的目录`。
   状态条的动词也跟着模式变（`检查 12 · 待 4` vs `扫 12 · 待 4`）—— 只 stat 一层和真读一层是两件事，
   混着说就是骗人。

## 四、接盘要点

- 端点：`POST /probeLayers { serial, mode, rels: string[] }` → `[{ rel, changed, missing, dirs?, needsPreview? }]`。
  **批量**（前端一次探 24 个）：探测本身是 1 stat，但 500 次 HTTP 往返也是钱。
- 跨盘（junction 指到别的盘）：序列号对不上就走真读，不拿错盘的身份去查缓存。
- `'fill'` 分支还留着（`startScan('fill')`），但**菜单已经不暴露它**；`fill` 只用于"缓存优先"这条旧语义的兼容。
- 探测失败（请求报错）不影响正确性：没探到就走真读那条路，只是慢一点。

## 五、读盘清单（相对旧行为的变化）

| 场景 | 旧 | 新 |
|---|---|---|
| 改名 / 加层文件夹后点一次 | 补全(0 读) + 刷新(当前层全读) = 两次点击 | 更新读取 = 当前层全读 + 其它层各 1 stat，**一次点击** |
| 整片大改后 | 重读整片 | 重新读取（不变） |
| 只是想看看当前层对不对 | 刷新 | 刷新（不变） |

## 六、未验证（诚实标注）

- **真机目视未做**：改了主进程（`scanAndCache` / `probeLayers`）⇒ 必须重启 dev 才生效。
- `dirMtime` 在老缓存上第一次会全量当"变了"，也就是第一次「更新读取」等于一次「重新读取」——
  这是刻意的（宁多读一次，不漏一次），但第一次的时长会让人以为功能很慢。
- 深层（非当前层）里的"同名覆盖"探不到，要等用户走进那一层再点一次。
