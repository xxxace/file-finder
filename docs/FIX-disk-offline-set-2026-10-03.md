# 离线盘在下拉框里消失 —— 根因与修复（2026-10-03）

> 触发：主人两条提问 ——
> ① 「为什么插 U 盘和移动硬盘有区别：移动硬盘用唯一码当标识，U 盘被当成 C D E F 这些盘」
> ② 「C D E F 这些盘如果离线了，会导致旧记录无法通过缓存记录的下拉框过滤」
>
> 结论：**① 是理解偏差（代码里根本没有"盘类型"分支）**；**② 是真缺陷**，已定位并修复。

---

## 一、先答①：没有「U 盘 / 移动硬盘」之分，只有「在线 / 离线」之分

`driveIdentity.ts` 对**所有**盘符走同一条路：

```
fs.stat('X:/').dev   →   卷序列号(8 位大写十六进制)   →   缓存记录主键 (serial, relPath, mode)
```

`st_dev` 取自 `NtQueryVolumeInformationFile(FileFsVolumeInformation)`，**与盘符无关、与盘是"可移动"还是"固定"也无关**（静态事实：`driveIdentity.ts:5-17` 的注释 + 全库无 `DriveType` / `removable` 相关调用 —— 全项目 grep `U 盘|可移动|removable` **零命中**）。

显示层只有**一个**分支（`HistoryTable/index.vue:441`）：

| 状态 | 下拉框里显示 | 为什么 |
|---|---|---|
| `online: true` | `E: · n 个目录 / m 个条目` | 盘符是**当下可用**的地址，用户能点开 |
| `online: false` | `离线(后 4 位) · …` | 盘符已经没意义（`E:` 现在可能是别的盘），只能用身份码 |

⇒ 主人看到的"移动硬盘显示成唯一码、U 盘显示成盘符"，真相是：**那一刻移动硬盘没插、U 盘插着**。是插拔状态，不是盘的种类。

**但这暴露一个真实体验问题**：同一块盘在"插着/拔掉"两种状态下显示的名字不一样（`H:` ↔ `离线(AB12)`），而且盘符本身会被系统重新分配 —— 用户无法稳定认出"下拉里这行是哪块盘"。这就是主人说"为什么有区别"的直觉来源。**是否给在线盘也补上唯一码，属于改动 UI 文案，等主人裁决，本次未动。**

---

## 二、②的根因：离线盘的「全集」取错了源

`listDisksController` 原来这样算离线盘：

```ts
const offline = offlineSerials(registry, drives);   // registry = Object.keys(disks.json)
```

而 `disks.json` **只在 `?refresh=true`（用户点击「刷新」）时**才被 `syncRegistry` 登记（`index.ts:967-969`）。
⇒ 一块盘如果「插过 / 扫过 / 但从没点过刷新」，它**不在注册表里**；一旦拔掉，它既不在 `drives` 也不在 `registry` ⇒ **从 `disks` 数组里彻底蒸发** ⇒ 下拉框没有它的选项 ⇒ 它的缓存记录只能在「全部盘」里被看见，**无法按盘过滤**。

### 证据（真库实测，2026-10-03）

| 项 | 值 |
|---|---|
| 缓存库里的盘（`searchCache.db`） | 6 块 |
| 注册表里的盘（`disks.json`） | 6 块 |
| **库里有、注册表没有** | **1 块（3 条记录）** |
| 该盘记录的时间窗口 | 首见 `2026-10-02 18:08` — 末次 `18:12`（4 分钟内） |
| `disks.json` 的 mtime | `2026-09-30 23:15` —— **早于该盘首见** |

⇒ 这块盘是 10-02 那次插进来扫了 3 个目录就拔了，**注册表那一轮没赶上**，此后永久缺席。

### 同一个根因的第二个可见症状

- 面板顶部「总览」的目录数取自**库**：`stats.folders = metas.length`
- 下拉框「全部盘」的目录数取自**`disks` 求和**

两者在此 bug 下对不上：实测 **216（顶） vs 213（下拉）**，差额 3 正是那块漏掉的盘。

## 三、修复（3 处，全部在"全集来源"这一条线上）

### 1. `electron/utils/driveIdentity.ts` — `offlineSerials` 改吃「已知全集」

```ts
// 前：offlineSerials(registry: DiskRegistry, drives)
export function offlineSerials(known: Iterable<Serial>, drives: DriveInfo[]): Serial[] {
    const online = new Set(drives.map(d => d.serial));
    return [...new Set(known)].filter(serial => !online.has(serial));
}
```

函数仍是"离线判定"的**唯一出口**，只是不再自己决定全集该从哪来 —— 这件事只有调用方知道。

### 2. `electron/server/index.ts` — 调用点把全集改成「注册表 ∪ 缓存库」

```ts
const known = new Set([...Object.keys(registry), ...metas.map(m => m.serial)]);
const offline = offlineSerials(known, drives);
```

**为什么是"库 ∪ 注册表"而不是"只用库"**：保守 —— 注册表里那些"库里没记录"的盘仍按原样列出，**零行为回归**。让全集与**数据源同源**，才是结构上不可能再漏（判据：以后新增同类场景会不会复发 —— 只要库里有记录，就一定有选项）。

### 3. `electron/server/index.ts` — `registry[serial].label` → `registry[serial]?.label`

**这处不是顺手改的，是修复必然带来的连带点**：
`offline` 现在**必然**含"只存在于缓存库、从没进过注册表"的 serial（这正是第 2 处要修的形态），照原样写就是 `undefined.label` ⇒ **整个 `/getDisks` 变成 500 ⇒ 下拉框全空**。比原来的"少一个选项"严重得多。探针 ④ 段专门锁住这一点。

| 探针 `docs/probes/disk-offline-set/` | **13 PASS / 0 FAIL**，见 `out.txt` |

> ⚠️ **2026-10-04 复跑修订**：初版记的是 14 PASS，其中第 ② 段有一条
> 「旧版应该破 `>0` 处（= 复现出缺陷）」—— 那条**依赖"真库此刻恰好有一块盘不在注册表里"**，
> 而那个状态随用户点没点过「刷新」漂移：实测 **10-03 有 1 块 / 3 条记录，10-04 已变成 0 块**，
> ⇒ 它会**假 FAIL**（代码是对的，是判据错了）。
> 已把它**从判据降为观察项**；缺陷的稳定复现改由 ③ 段承担（构造数据，与真库状态无关）。
> ⇒ 现在 **13 PASS / 0 FAIL**，且**不再随真库状态漂移**。
| 真机目视 | **待主人重启 dev**（见下） |

探针的**判据是恒等式**，不是"当前数据恰好命中"：

```
∀ s ∈ 库里的 serial : s ∉ 在线  ⇒  s ∈ offline
```

它对**任意**在线组合成立（探针跑了 5 种组合含空集/全集/不相交），所以不随"用户点没点刷新"漂移。同一组场景下**旧实现破 3 处** ⇒ 原缺陷被复现。

⚠️ **本探针零读盘**：不扫任何盘符，`drives` 一律构造（只读本地的 `disks.json` 与库文件）。

### 目视验收点（重启 dev 后）

1. 下拉框里应多出一行 **`离线(后4位) · 0 个目录 / 3 个条目`** —— 就是那块 10-02 插过的盘；
2. 下拉框「全部盘 · **216** 个目录」应与顶部「总览」的目录数**相等**（修复前是 213 vs 216）。

## 五、未决 / 待裁决

1. **在线盘的显示名要不要带上唯一码？**（第一节末尾）—— 属 UI 文案改动，未动，等主人定。
2. **注册表还剩什么用？** 两处连带改动后，`registry` 只提供 `label`（`probe()` 写死 `''`，**恒为空**）和 `firstSeenAt/lastSeenAt`（**只写不读**）。它的"离线盘全集"职责已被缓存库取代。
   ⇒ 这引出「要不要在热插拔时也登记注册表 / 要不要干脆废掉注册表」的问题。**按铁律未擅动**：零引用 ≠ 该删，先问当初为什么留着。
3. **`syncRegistry` 只在 `?refresh=true` 时跑**这一行为本身没改。修好全集来源后，注册表缺登记**不再影响下拉框**，所以没有连带修的必要 —— 但如果将来要让 `label` 真的可用（给盘起名），就得重新安排登记时机。
