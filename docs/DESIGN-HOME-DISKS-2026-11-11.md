# 首页盘列表（空白区 → 「这台电脑」）· 2026-11-11

## 一、要解决的事

冷启动 / 清空导航后，主界面是**一片空白 + 一行灰字**（`index.vue:318` 的 `.empty-tip`，
文案在 `emptyTip` 的 `!hasAny` 分支，`index.vue:867`）。要去到内容，必须先点「缓存记录」找一行、
或者点左上角文件夹图标走系统对话框 —— 每次两次点击，且第二次是"从零开始找位置"。

目标：**空白区直接列出这块机器上"有缓存"的那几块盘**（= 缓存记录页顶部那排过滤 chip 的盘），
点一块盘直接落到**它缓存记录的最顶层**。零新增扫描。

## 二、非目标 / 反目标

- **不做"最近打开"**（业主 2026-11-11 明确）。首页只有盘，不掺历史列表。
- **不做容量条**（业主同日裁决）。剩余/总容量要读卷元数据，不确认会不会唤醒睡眠中的移动硬盘
  ⇒ 不做。卡片上的信息全部来自缓存聚合（纯内存）。
- 不做收藏夹/清单入口、不做"打开文件夹"卡通按钮（顶栏那颗彩色文件夹图标已经是入口）。
- 不重做缓存记录页：它仍是删/查/排序的地方，首页只是它的**快捷入口**。

## 四、方案（三选一，取 C）

**A. 前端另拉 `/getHistory?pageSize=5000` 再按盘分组**
不动服务端。代价：多一个全量请求；且"盘列表"与"顶层路径"来自两个接口，
两边口径将来可能漂（正是本仓库反复吃过的那类不变量）。

**B. 首页改成一块独立的"盘货架"屏（盘 → 该盘目录列表 → 目录）**
多一层。业主明确要"点开落的位置是该缓存记录记录的最顶层"⇒ 中间那层是多余的。

**C（选定）．`/getDisks` 每块盘多返回 `tops: [{ relPath, path, count }]`，前端直接渲染卡片。**
服务端本来就在同一个循环里遍历 `metas` 算 `folders/covers/lastScanAt`，
顺手取**每个 serial 下缓存路径森林的根**即可（祖先缓存过的不算顶层）—— 同一份内存数据，零读盘、零新请求。
`path` 用的是现有的 `toFullPath` / `toAnchorPath`，与 `/getHistory` 同一套地址口径。

## 五、交互定义

1. **卡片集合** = `/getDisks` 里 `folders > 0` 的盘（与缓存记录页 chip 完全同一规则）。
   在线在前、离线在后；同一块盘（克隆盘同 serial）按 `serial|drive` 区分 key。
2. **点卡片**：
   - `tops.length === 1` → 直接落那一屏（走 `openHistory` 这个既有出口，不自己拼 `enterScreen`）。
   - `tops.length > 1` → 卡片原地弹出**小菜单**（复用 `ctx-menu.css` 那套 Apple 纵向菜单），
     每一项 = 一个顶层目录（名字 + 条目数），选一个才进。**不猜**用哪一条。
   - `tops.length === 0`（理论不发生：folders>0 必有记录）→ 卡片不可点。
3. **"最顶层"的定义**（最终版见 §十四，这里是最初的写法、已被取代）：
   该盘所有缓存记录里**森林的根** —— 祖先缓存过的那层不算入口；**父层不许凭空造出来**。
   同层多条（cover/folder 两种模式、或 `/` 与 `\` 两种写法）去重，`count` 取大。
4. **离线盘**：点进去就是锚点（缓存视图，零读盘）。卡片**不降级成 disabled**
   （最终版见 §十五）：底色/文字/悬停与在线一致，只有图标灰度（= 灯灭）+ 名字前一颗灰点；
   第三行写「上次使用 MM-DD」。
5. **刷新**：沿用 F5（`atHome` 时被拦掉，所以首页另给一条：
   盘列表在 `ff-disks-changed` 与"回到首页"时各重取一次 `/getDisks`，不重探盘符）。
6. **一块有缓存的盘都没有**：保留今天那行灰字，文案不变（"还没选文件夹 —— 点左上角那个图标选一个"）。

## 六、视觉

  上：**拟物硬盘图标** + 名称（`H:` / 离线用序列号后 4 位）；下：`218 个目录 · 1471 条目` / `上次扫描 11-08`。
- **拟物图标**（业主 2026-11-11："不要线条的"）：新资产 `src/assets/disk-hdd.svg` ——
  银灰机身 + 前脸凹槽 + 绿色指示灯，随 `img` 直接引用（不需要光栅化，`<img src="*.svg">` 可用）。
  离线态不另做资产：`filter: grayscale(1); opacity: .55`。
- 不使用渐变/发光做卡片本身：那是背景装饰，正是"廉价感"来源（同启动画面那条裁决）。
  唯一的立体感来自硬盘图标本身。

## 七、零读盘账（硬约束自查）

| 动作 | 读盘 |
|---|---|
| 打开首页（取 `/getDisks`） | **0** —— `getDrives()` 进程内缓存 + `loadMeta` 内存 + 一次本地文件 `stat` |
| 取 `tops` | **0** —— 与现有 stats 同一份 `metas` |
| 点卡片进某一屏 | 1 次该目录（= 今天从缓存记录点同一行）；离线盘 = 0 |
| 图标 | 0 —— 打包内的 svg |

## 八、已知陷阱（写进实现注释）

1. `.empty-tip` 的 `emptyTip` 计算里 `!hasAny` 那一支要被首页**取代**，否则卡片下面还压着一行灰字。
2. `!hasAny` 时 `onRefresh` / 面包屑 / 右键菜单都处在"没有当前屏"的状态 ——
   首页只读盘列表，不要顺手调`onRefresh`（那条带 `noCache`，会真读盘）。
3. 卡片不要放进 `TransitionGroup` / 不要复用 `.image-box` 的网格项类：首页不是内容网格，
   混用 `.image-box-item` 会让 `useGridCursor` 的行缓存把卡片当成可选择条目。
4. 克隆盘：同 serial 两个盘符时 key 必须带 `drive`（缓存记录页已踩过）。
5. `tops` 只是**方便入口**，不是权限：盘符换了之后 `path` 失效 → 服务端已按"当下 `getDrives`"算地址，
   前端不做二次拼路径（纪律：懂得只有服务端）。
6. 若某条顶层记录已被删（`getHistory` 里不存在），`folders>0` 仍为真 ⇒ 卡片可点但进不去。
   这种情况由既有的 `notFound` 横幅兜住（会顺带自清该缓存记录），不额外加守卫。

### 实施时补上的几个漏（设计第一版没写）

1. **刷新按钮**在首页是**亮着但按下去什么也不会发生**（`onRefresh` 早退）——
   补 `atHome` 禁掉。一颗亮着的死按钮比置灰更容易被读成"程序卡了"。
2. **地址槽**空着会被读成"这条坏了" ⇒ 首页给静态段「这台电脑」（不可点：它不是一个位置）。
3. **搜索**与首页互斥：首页没有可过滤内容，卡片和「没找到匹配的内容」同时出现自相矛盾
   ⇒ `showHome` 带上 `!searchText`。
4. **插拔盘**：`onDisksChanged` 原来在没有当前屏时直接 `return`，停在首页插盘卡片不会出现
   ⇒ 补一条 `reloadHome()`。
5. **回到本页**（`onActivated`）：缓存记录页删过记录 / 收藏页动过条目都会改变"哪些盘有缓存"
   ⇒ 只在首页时重取（仍不带 `refresh=true`，不重探盘符）。
6. **右键**：首页没有"当前这一层"，空白右键全是空动作 ⇒ `HomeDisks` 根节点吞掉 contextmenu。
7. **首次响应前不说话**：`emptyTip` 的 `!hasAny` 分支等 `ready`，避免"还没选文件夹"闪一下再变出五张卡。
8. **折角**：多顶层才有（点了会弹菜单这件事要预告）；单顶层不给 —— 那会让人以为还要再选一次。
   折角绝对定位 + `has-multi` 补右边距，避免压在「上次扫描 11-08」上。

## 十一、第二轮（业主当场两个裁定）

### 1. 顶层判据错了：不是"全盘最小深度"，是"**森林的根**"

第一版拿 `relDepth` 的最小值当顶层，反例（业主给的）：

```
缓存了：videos · videos/xxx1 · videos/xxx2 · videos2/xxx1
第一版：min depth = 1 ⇒ 只给 [videos]        ← videos2/xxx1 凭空消失
正确  ：tops = [videos, videos2/xxx1]
```

**正确判据**：某一层路径若**它的任意祖先也缓存过**，它就不是顶层（进了上一级就能看到，
没必要并列摆出来）；而 `videos2` 自己没缓存过 ⇒ 它的子层 `videos2/xxx1` 才是一支的入口。
实现在服务端 `diskTops` 的 `parentOf` 逐级回溯 + `cached` 集合里查 —— 纯内存、零读盘。

⚠️ 这个判据的语义是"**缓存路径森林的根**"，与深度无关：一支深 4 层的独苗仍然是顶层，
一支只缓存了第 2 层的子目录只要它的父层没缓存，也仍然是顶层。

### 2. 首页常驻导航历史（`@home` 哨兵屏）

业主要求：「默认常驻空白首页在导航历史中，这样子我可以通过上一屏回到空白页」。

**为什么必须是一条真条目、而不是"栈空"这个状态**：原来 `index = -1 ⟺ 空数组`，
"回首页"只能 `reset()` ⇒ 数组一清、前进方向就没了 —— 从首页按「前进」回不到刚才那一屏。
现在首页 = `entries[0]`（`HOME_PATH = '@home'`），于是：

| 位置 | 后退 | 前进 |
|---|---|---|
| 首页（index 0） | 置灰 | 回刚才那一屏 |
| 任意一屏 | 回首页 | 若有尾巴则可用 |

落地清单（**每一处都是"`!hasAny` 换成 `atHome`"**，因为 `hasAny` 从此恒为真）：

- `useNavStack.ts`：`HOME_PATH` + `homeEntry()`；`reset()` 的注释写明"调用方必须立刻补首页"。
- `useScreenData.ts`：`loadScreen` 里 `@home` 走**新加的 `showHome()`** —— 不取数，
  只做"递增序号（让在飞的请求闭嘴）+ 清 loading + 清 failKind + `commit([], search)`（列表与词同一拍清）"。
- `index.vue`：`atHome` / `ensureHome()`（**setup 期**就补，不能等 `onMounted` —— 那要晚一帧，
  首帧会闪真正的空白）；`crumbs` 首页返回 `[]`（否则 `ancestorsOf('@home')` 会拆出一段假根）；
  `goStep` 加 home 短路（首页没有滚动位/选择器要恢复）；`setRoot` 两个分支都补首页；
  `enterScreen` 进屏前也补（冷启动直接吃跨页跳转时栈是空的）；
  刷新/平铺/扫描类动作/空白右键/`onDisksChanged` 全部按 `atHome` 判。
- 顶栏「刷新」在首页**置灰**：`onRefresh` 会早退，亮着却按不动比置灰更像卡死。

⚠️ `atHome` 的判据是 `currentPath === '@home'`，`atHome` 为真时**所有"这一层"的概念都不成立**
（没有目录、没有面包屑、没有可扫描的对象）。以后新增任何"对当前这一层做点什么"的功能，
第一句都必须是 `if (atHome) return` / `disabled`。

### 仍未实测

- 首页 ↔ 屏之间连按后退/前进（含中途点卡片开菜单）的实际手感。
- 真机里 `@home` 会不会漏进某一处取数（已按上面清单逐一堵，但没有跑过）。

## 十二、第三轮：还是把 `xxx1`/`xxx2` 摆出来了 —— 病根是"父层自己没被扫过"

业主 2026-11-11 第三报：「/videos /videos/xxx1 /videos/xxx2 都属于 /videos，
为什么你还是会把后面两个都提供给用户选择？」

**病根**：第十一节那条判据只排除"**祖先缓存过**的路径"。而 `/videos` 这种容器目录
常常**从来没被单独扫过**（扫的是它下面每一个合集）⇒ 缓存记录里根本没有 `videos` 这一行
⇒ `videos/xxx1`、`videos/xxx2` 都是"森林的根"，两条都留下来。规则没错，覆盖面不够。

**补两步**（实现在新文件 `electron/server/diskTops.ts`，纯函数、零 import）：

1. **同级折叠**：同一父级下 ≥2 个入口 ⇒ 折成父级一条（反复折到稳定）。
   - `videos/xxx1` + `videos/xxx2` ⇒ `videos` ✅（本轮修的正是这条）
   - `a/x1` + `a/x2` + `b/x1` ⇒ `a` + `b/x1`
   - `videos2/xxx1` + `music2/yyy1` ⇒ 原样（不共享父级，没有"同一堆"可合）
   - **绝不折到盘根**：`a/x1` + `b/x1` 折成"盘根"等于让用户点一下读整个盘根。
2. **大小写不敏感**：父子比对与分组都按小写（`queueCacheWrite` / `removeCache` 的既有约定）。
   否则同一层被扫成 `Videos` 与 `videos` 两种大小写时，父子关系当场断掉、子层全冒出来。

**两处刻意的例外**：

- **离线盘不折叠**：折出来的父层没有缓存，打开只会得到"这一层当时没缓存过"的空屏 + 横幅
  ⇒ 一个点不出东西的入口不如不给。离线保持"缓存到哪层就列哪层"（会看到多个兄弟，那是实情）。
- **`count` 是兄弟之和**：折叠出的父层自己没有缓存，没有真实数字；菜单上那个数只是量级参考。

**顺带修的一条真 bug**：`parentOf('videos')` 返回空串，而空串在缓存集合里代表"**盘根扫过**"。
第一版用 `while (p)` 循环，空串一进来就退出 ⇒ 盘根被扫过的盘，下面每一层都冒出来。
现在 `hasCachedAncestor` 显式判空串这一档。

**证据**：`docs/probes/disk-tops/run.mjs`（esbuild 打真源码、跑 13 个断言，含业主原话例子）
**13/13 通过**，输出落 `out.txt`。`node docs/probes/disk-tops/run.mjs` 一行复跑。

⚠️ 折叠出来的父层**大概率没有缓存**：点它 = 真读一次那个目录（`cover` 模式还会为每个子目录
找封面）。这是业主明确要的行为（"我要的就是 /videos"），但它确实是一次读盘 —— 与"点缓存记录"
那一跳的成本同级，不是新增的常驻扫描。

## 十三、第四轮：真的还在 —— 库里 relPath **带反斜杠**

业主 2026-11-11 第四报（附截图）：菜单里同时有 `videos`、`videos\aaa`、
`videos\bbb`、`videos\ccc`。

**截图本身就是证据**：菜单显示的是 `m.relPath` 原文，而它带 `\` ⇒ 库里的 relPath 真的有两种分隔符。
前几版全部按 `/` 切父子 ⇒ 这些记录的层级关系**一条都认不出来**，全都成了"森林的根"。
（父层 `videos` 自己是对的，所以它独自一条、子层各自一条 —— 与截图完全吻合。）

**修法**：`diskTops` 先把每条记录拆成三样 —— `disp`（`\`→`/` 归一，用于展示与父子判定）、
`key`（`disp` 小写，用于比较）、`raw`（库里原样，用于拼地址）。判据全部走归一形态，
**地址仍用 raw**：那些带反斜杠的老记录，缓存主键就是带反斜杠的那串，
拿归一形态去查会直接"这一层没缓存过"（离线盘最明显）。

**顺带记下的一条既有隐患**（不在本次范围内）：`openFolder` 用 `splitPath` 把 `\` 归一成 `/`
再 `findCache` ⇒ 这些老记录**永远命中不了**，每次点都真读一次盘，然后以 `/` 形态**再写一份**
⇒ 同一层可能在库里出现两条（一条 `\` 一条 `/`）。要治得在 `nedb` 的读写两侧一起归一，
那是一次数据迁移，别顺手改。

**证据**：探针补到 **17 个断言全过**，含业主截图那组原始数据（`videos` 35 + 三个 `videos\xxx`
⇒ 只剩 `videos`）、"反斜杠兄弟折叠"、"离线地址保留反斜杠"、"同层两种写法不重复"。

### 浅色主题下的选择菜单

业主："浅色主题下的选择菜单配色有问题，可以参考右键菜单的浅色配色。"
第二轮又说："都快和背景色融一起了，为什么不能用右键菜单的浅色参考呢？"

**为什么"参考右键菜单"没解决问题**：两块菜单本来就是同一块料（同一个 `.ctx-menu` +
同一个 naive popover 壳），而那个壳的底色 `popoverColor` 在浅色指向 **`--ff-raised`（#eef0f2 灰面）**。
右键菜单看着有边界，是因为它通常压在**封面照片**上；这块菜单压在**白卡片**上 ——
#eef0f2 与 #fff 只差约 4% 明度，所以"融一起了"。

**改法**（一条规则管两块菜单，不可能再漂）：
`.n-popover:has(.ctx-menu) { --n-color: var(--ff-popover) !important }`
+ 浅色下补 1px `--ff-line-strong` 发丝线（白面压白卡片，只靠明度差仍然没边界）。

- `--ff-popover` 浅色 = `--ff-panel`（#fff），深色 = `--ff-raised`（#242424）⇒
  **深色一个像素都没变**（两个 token 在深色是同一个值）。
- 深色**不加**发丝线（tokens 里既有裁决：深底靠明度差就够，加线只会脏）。
- naive `popover/styles/light.mjs` 实测：`color: popoverColor`，**没有任何 border** ——
  这条边界只能自己画。

另外（同日第二改）：这一层原来**一打开就把第 0 行涂上** `--ff-menu-hover` —— 浅色下那是
14% 黑压出来的深灰块，读起来像"这项已被选中"，与右键菜单（打开时干干净净）差着一档。
⇒ 改成 `cursorOn`：鼠标移入 / 按方向键之后才亮；`cursor` 仍从 0 起（回车照样能开第一项）。

## 十四、第五轮：**撤销**"同级折叠"（它就是"乱解析"）

业主 2026-11-11 给出三组原话数据，把定义钉死：

| 缓存里有什么 | 顶层 |
|---|---|
| `media/SET-A` · `media/SET-A/A` · `media/SET-A/B` | `media/SET-A` |
| `media/SET-B/COLL-A`（`SET-B` 自己从没扫过） | **`media/SET-B/COLL-A`** |
| 离线盘只有 `disk/album-x` | 那一条（唯一 ⇒ 不弹菜单） |

⇒ D 盘给的是 `media/SET-A` + `media/SET-B/COLL-A` 两条。

**判据 = 森林的根，且只此一条**：某层路径的任意祖先缓存过 ⇒ 它被上一级覆盖；
否则它就是那一支的顶层。**父层不许凭空造出来。**

⚠️ 第十二节那套"同级折叠"因此**整段删除**。它会把 `SET-B/COLL-A` 折成
`media/SET-B` —— 那一层用户从没扫过、点进去要真读一次盘，等于程序替他编了个入口。
**第三轮那次"修复"是错的**：当时真正的病灶是反斜杠（第四轮才找到），折叠只是碰巧
让那个例子看起来对了。（教训：同一症状连续两次"修好了"，先怀疑判据本身错了。）

⚠️ 顺带把 `opts.online` 也删了：折叠一消失，"在线/离线"对判据再无影响，
只在 `path()` 的构造里体现（在线给实时路径、离线给缓存锚点）。少一个开关少一处漂移。

**本轮自己踩的坑（探针当场抓到）**：`cached` 里存的是小写 key，
而 `hasCachedAncestor` 拿 `parentOf()` 的**原样大小写**去查 ⇒ 一个父层都匹配不上，
`media/SET-A/A` 直接过不了第一条断言。改成 `cached.has(p.toLowerCase())` 后 **14/14 通过**。

## 十五、第六轮：菜单排序 + 离线卡片的观感

### 1. 菜单按**路径序**，不按条目数

业主：「`media/SET-A` 不应该在 `media/SET-B` 上面吗？」

原来按 `count` 倒序（"条目多的最可能是他要的"）。错在把**目录清单**当成了排行榜：
同一支的子层会被别人的大数字挤到后面去，读起来没有结构。
现在 `relPath.localeCompare(..., 'zh')` —— 与缓存记录页的路径排序同一个口径（中文按拼音）。
探针加了断言：`zzz(1)` / `bbb(999)` / `aaa(2)` ⇒ `aaa, bbb, zzz`（条目数不参与排序）。

### 2. 离线盘不再装成 disabled

业主：「离线 disk 不需要搞得像 disabled，也不需要提示缓存可看，可以显示上次插入日期。」

| | 之前 | 现在 |
|---|---|---|
| 卡片底 | `--ff-canvas`（比在线盘暗一档） | **同在线**（`--ff-panel`） |
| 图标 | 灰度 + `opacity: .55` | **只灰度**（= 灯灭，不是"内容不可用"） |
| 名字 | `--ff-text-2` | **同在线**（`--ff-text-1`） |
| 第三行 | 「未插入 · 缓存可看」 | **「上次插入 MM-DD」** |
| 状态 | 靠整卡变灰 | 名字前一颗 **6px 点：在线绿 / 离线灰**（与缓存记录页那排盘 chip 同一语言） |

`上次插入` 的数据源是注册表的 `lastSeenAt`（`/getDisks` 新增下发该字段）。
⚠️ 注册表只在 `?refresh=true` 时登记，所以**从没点过刷新时它是空串** ⇒ 退回「上次扫描」，
标签跟着字段走 —— 不硬套一个"上次插入"去说谎（`useHomeDisks.timeLineOf`）。

第三行整句由**数据层**拼好（`timeLine`），模板里不再分支：
两种状态各写一套模板，是"日期算法改一次要改两处"的经典来源。

## 十六、第七轮：铺满可视区 + 拟物图标第二版

### 1. 去掉 `max-width: 1080px`

业主：「有空间为什么不用？应该和文件管理器一样吧？」

`.home-disks` 原来给了 1080px 上限，窗口一宽右边就空一大块。资源管理器是把内容
**铺满可视区**、列数随宽度涨 —— `auto-fill` + `1fr` 本来就会算，那个上限纯属多余。
删掉之后：1280 窗 ≈ 5 列，1600 窗 ≈ 6 列。列间距 10 → 12（铺满后 10 显得挤）。

### 2. 硬盘图标（`src/assets/disk-hdd.svg`）第二版

业主：「disk 的画风可以再优化一下，状态灯可以再大点亮点颜色，能营造更亮的拟物视觉最好。」

| | 第一版 | 第二版 |
|---|---|---|
| 指示灯 | r 1.75，无光晕 | **r 3.6**（≈2 倍）+ 6.4px 光晕 + 白色高光点 |
| 灯色 | `#38c46b` 平涂 | 三段竖向渐变 `#a6ffcc → #2cf287 → #0fae56`（亮心+暗底，才像"亮着的"） |
| 机身 | 单段渐变 | **五段**（白→浅灰→中灰→深灰→更深）+ 上沿 1px 金属折边高光 |
| 前脸槽 | 平涂 + 一条格栅 | 深→浅→更深 三段 + 内阴影线 + 两道格栅（小尺寸下读得出"凹"） |

验证方式：`env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe <临时脚本>
disk-hdd.svg out.png` —— 用无头 Electron 把 svg 在 44px / 96px / 灰度 / 深色卡上各渲一遍，

脚本只在 `/tmp`，不进仓库。

⚠️ 灰度态就是"灯灭"：`filter: grayscale(1)` 把绿灯变成浅灰，与"这块盘不在"是同一件事，

## 十七、第八轮：指示灯缩回去 + 图标第三版（真给体积）

业主：「你的圆点大到碰边界了不好，再缩一点，亮点效果如果你不知道怎么优化可以上网学习」
「disk 图标能再立体些吗？一样的可以上网找资源，有现成的直接用，没有才完善我们自己的」

**先找了资源**：搜到的可直接用的（Tango / Openclipart / Arweave CC0 等）都是 2008 那一代
clipart，蓝紫渐变 + 强高光，和这张卡（中性灰、无装饰）放在一起是两套语言；而且 44px 下
细节会糊成一团。⇒ 按业主给的次序「没有才完善我们自己的」，自己做体积。

第三版的三处（都在 `src/assets/disk-hdd.svg`）：

1. **指示灯缩回 r=2.0**：上一版 3.6 在槽高 9.5 里上下只剩 1.4px，"碰边"就是它。
   现在槽加高到 10.4，灯上下各留 ≈3px。
2. **亮度靠两层 bloom，不是一个大圆**：`feGaussianBlur` 2.1（宽晕）+ 0.7（紧晕）+
   实心灯芯 + 白色高光点。这是 LED 的真实光学——小亮核 + 外溢光，而不是"渐变球"。
3. **立体感三件套**：
   - 底下一枚模糊落影（`feGaussianBlur` 1.4）⇒ 从卡面"浮起来"；
   - 内圈一圈**渐变描边**斜角：上沿白 85% → 中段透明 → 下沿深灰 55%，
     **一个元素同时做出上亮下暗两道边**（这是"有厚度"最省的做法）；
   - 机身高光从硬边改成竖向渐隐，去掉"贴纸感"。

显示尺寸 44×31 → **44×33**（viewBox 48×36 同比，否则拉扁）。

⚠️ **滤镜在 `<img src="*.svg">` 里可用**（同文档定义，不跨资源）——已用一个 file:// 页面
按 `<img>` 方式渲过确认（`data:` 页面加载 file:// 图会被拦，第一次就是这么失败的）。
