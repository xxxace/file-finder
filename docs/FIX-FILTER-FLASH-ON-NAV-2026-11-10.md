# 换屏时"过滤失效、整份数据闪一下"—— 根因与修法（2026-11-10）

业主原话：
> 通过过滤框过滤出想要的文件夹，点击打开，这个过程中的等待（里面的视频抽封面帧）
> 视图界面的过滤效果会失效，重新渲染没过滤前的全部数据，等抽完帧视图才会进入该点击文件夹内渲染；
> 即使没有抽帧，接口请求也会让视图界面短期内一闪而过没过滤前的数据。

---

## 一、根因（证据等级：静态 + 时序推理；修法本身未实测，待真机目视）

`fileList = computed(() => filterByName(dataSource, searchText))` —— 视图 = **数据 × 关键词**。

两边的写入时刻**不在一拍**：

| 写入者 | 写什么 | 什么时候 |
|---|---|---|
| `enterScreen`（导航层） | `searchText = ''` | **点下去那一刻，同步** |
| `useScreenData`（取数层） | `dataSource = data` | `/openFolder` 返回后，**几百 ms ~ 数秒之后** |

⇒ 中间这段渲染的是「**上一屏的整份数据 × 空关键词**」= 过滤凭空失效、所有格子刷地铺满。
这段窗口的长度**就是接口耗时**，抽帧只是把它从"闪一下"拉长到"杵在那儿"。
`onBack` 是同一族的反向症状：它提前把父屏的词写回去 ⇒ 用**子屏的数据** × **父屏的词** 渲染一次。

⚠️ 这不是"某一行写错了"，是**两条状态各有各的生命周期**：词跟"导航动作"走，数据跟"响应"走。
所以任何"在导航处补一手、响应处再补一手"的改法都是补丁 —— 新增第 3 个导航入口就复发。

## 二、修法：词跟着数据落地，**同一拍**

新增唯一落点 `useScreenData.commit(data, search?)` —— `dataSource` 与 `searchText` 在
**同一个同步块**里写完 ⇒ Vue 按组件批一层 ⇒ 只渲染一次（新数据 + 新词），
中间态**在结构上不存在**。

- `loadScreen(entry, { adoptSearch: true })` 才携带词，值取 `entry.searchText`（NavEntry 本来就是每屏一份）
- 只两个入口传：`enterScreen`（进入）、`onBack`（返回）—— 都在这一个函数里，第 3 个入口忘不掉
- 刷新 / apply / 换盘降级**不传** ⇒ 同一屏重取，词原样不动（用户正在用的筛选不能被抹）
- `notFound` 失败也走 `commit([], search)`：这一屏已经不存在了，词不该留成"这一屏的"
- `search.from` 守卫：换屏等待可能几秒，用户在这期间改过输入框 ⇒ 不覆盖他打的字

`dataSource` 现在只有两个写入口：`commit()` 与 `setRoot('')`（后者与 `searchText=''` 同块，本就原子）。

## 三、顺带被修好的一条

`enterScreen` 原来那一行 `searchText.value = ''` 会先改一次 `fileList` ⇒
`useGridCursor` 的指纹 watch 把一次性的 `armed`（焦点意图）消费掉。原注释用
"先 noteIntent 排后"绕过去；现在这条写入不存在了，顺序依赖自然消失（`noteIntent` 仍保留在
任何"会改列表的动作"之后，纪律不变）。

## 四、验收（30 秒目视，两条都要看）

1. **进入**：搜索框输入词 → 过滤出 2~3 个文件夹 → 双击其中一个含视频的（会抽帧）
   → 等待期间网格应保持**过滤后的样子**（不铺满）、词仍在框里 → 数据到了才一起换成新屏。
2. **返回**：在子目录按返回 → 不应出现"半个列表被父屏关键词筛掉"的闪动；
   回到父屏后，词与筛选结果应**同时**恢复。

反向确认（防过度修正）：地址栏过滤词为空时进/出目录，观感应与改之前**完全一样**。
