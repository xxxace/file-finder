## 二、已查证的事实（代码级，可复算）

### 2.1 现在有 4 个动作会碰缓存

| 动作 | 入口 | 服务端请求 | 行为 |
|---|---|---|---|
| 打开目录 | 双击格子 / 面包屑 / 历史记录 | `openFolder?path=&mode=` | 命中缓存直接用；未命中→读盘+写缓存 |
| 刷新 | ↻ 按钮 / `F5` | `openFolder?...&noCache=true` | 跳过缓存、**强制读盘**、**覆盖**该目录缓存 |
| 补全缓存 | 工具条按钮 | 同「打开目录」，**递归整片** | 有缓存就跳过（不读盘）；只对没缓存的读盘+写缓存 |
| 重扫这一片 | 上面那个按钮的**悬停下拉** | 同「刷新」，**递归整片** | 每层都强制读盘 + 覆盖缓存 |

补全/重扫共同点：**串行**（一次一个目录）、每 20 个让出一次事件循环、可取消、
显示「已扫 n / 待扫 m」、**绝不碰用户眼前的网格**（`src/views/FileFinder/index.vue:496-499`）。

### 2.2 用户的担心：拔盘 + 刷新，会不会覆盖成空？

**结论：缓存不会被清空，但界面会显示为空、而且没有任何提示。**

证据链（静态，可复算）：
1. `findDriveByLetter()` 会**实时 `stat`** 盘符（`electron/utils/driveIdentity.ts:124`）→
   盘不在 → `probe()` 返回 null → 重扫后仍找不到 → **返回 `null`**（同文件 `:127-130`）
2. `openFolderController` 拿不到 disk → 走**不缓存分支**（`electron/server/index.ts:599-605`）
   → `readFolder(raw, mode, '', raw)` → **完全不写缓存**
3. 该分支的 `readFolder` 读不到目录 → `return []`（`electron/server/index.ts:222-225`）
4. 前端 `fetchFolder` 收到 `[]` → `dataSource.value = data` → **网格变空**；
   且**没有抛错** → 走 `.then` 分支 → **不触发任何错误提示**（`src/views/FileFinder/index.vue:372-391`）

⇒ 用户看到的是「网格空了 + 一个字的解释都没有」，**合理怀疑数据丢了**。
（缓存其实还在：盘插回来、重新点进去就恢复。）

### 2.3 ⚠️ 真正的缺陷：盘在、但这一层「临时读不到」→ **真的会写入空缓存**

`readFolder` 把两种情况混为一谈（`electron/server/index.ts:219-225`）：

```ts
try { files = await fsasync.readdir(diskDir); }
catch (e) { console.error('[readFolder] 读取目录失败:', diskDir, e); return []; }
//                                                            ^^^^^^^^^ 读不到 == 空目录
```

- 「目录**真的是空的**」→ `[]` ✅ 正确
- 「**读不到**」→ 也返回 `[]` ❌ **错**

而 `scanAndCache` **无条件**拿这个结果写缓存（`electron/server/index.ts:552-573`）：

```ts
const data = await readFolder(toFullPath(drive, relPath), mode, serial, relPath); // 读不到 → []
const doc: SearchCache = { v: CACHE_VERSION, ..., count: data.length, data, create_at: ... };
await queueCacheWrite(serial, relPath, mode, async () => {
    await removeCache(serial, relPath, mode);   // ← 删掉旧记录
    await insertCache(doc);                     // ← 插入空记录
});
```

**触发条件**（**都不需要拔盘**）：
- USB 供电抖动 / I/O 错误导致某次 `readdir` 失败
- 目录权限被改
- 盘刚插上、卷还没就绪
- 网络路径（UNC）瞬时不可达

⇒ 一条真实缓存记录被**合法地覆盖成 `count: 0`**，旧记录**拿不回来**
（nedb 是「删旧 + 插新」，不是追加版本）。

> **证据等级：静态证据（可复算）+ 推理。** `readdir` 对不存在的目录抛 `ENOENT` 是 Node 既定行为。
> **未实测**：没有真拔盘 / 真造 I/O 错误复现。

**这一条与交互设计的关系**：任何「刷新 / 重扫」按钮的视觉设计，
**底下必须先有这个修复**。否则"防误触"只防住了手滑，防不住"点到了就毁数据"。

## 三、现有入口设计的 4 个问题（用户问"你确定合理吗"）

**最强的证据是用户自己提的第一个问题**：「补全缓存和刷新按钮的作用有什么区别？」
—— **用户需要问"区别"，就说明入口设计失败。** 好的入口不需要说明书。

| # | 问题 | 说明 |
|---|---|---|
| 1 | **「重扫这一片」不可见** | 藏在悬停下拉里，不悬停就不知道它存在。而它恰恰是「目录增删改」的正解，也是最慢最重的操作 |
| 2 | **重操作反而零防护** | 悬停展开、点一下立刻开跑，**没有二次确认**。它要整片**强制读盘**（最伤移动盘的操作） |
| 3 | **三个动作语义重叠、命名不自解释** | 「刷新」vs「重扫这一片」对用户是同一件事（都"重新读一遍"），差别只是范围；「补全缓存」又像技术黑话 |
| 4 | **危险等级没有体现** | 只读的（打开）、补缺的（补全）、全量重读的（重扫）、覆盖的（刷新）在视觉上完全同级 |

## 四、约束（不许越界）

**必须保留的用户特性（用户声明过，默认神圣，不许改）**
- 双击格子才打开（单击不打开）；双击封面条目 = 打开里面的视频
- 封面收敛：有封面图的目录收敛成一个封面条目；`avatar.jpg`/`cover.jpg` 当目录图标、不单列
- 快捷键：`S` 搜索 / `F5` 刷新 / `D` 选文件夹
- 搜索支持拼音首字母
- 面包屑跳转；进子目录清空搜索词、返回恢复；返回恢复滚动位置
- 空状态只有一行浅灰小字（失败时不显示）

**硬要求**
- **最高优先级：减少对移动硬盘的读写。** 任何设计（例如"后台自动监控目录变化"）
  如果增加读盘，**先否决**
- 串行访问、一次一块盘（USB 供电是真风险，不是性能问题）
- 不升 `CACHE_VERSION`
- 前端 = Vue 3 + **naive-ui 2.45.3**；工具条在网格上方
- 交付物要能落地成 naive-ui 组件，**不要给无法实现的交互**
