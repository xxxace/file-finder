## 二、一个必须先说清的矛盾

方形的 CD 盒里飞不出 3:4 的竖卡 —— 但如果因此改卡片比例，就退回到"卡牌"了。

**解法：盒里装的不是"卡片"，是专辑内页。**

真实 CD 盒里就是一张方形 booklet + 一张折叠海报。所以：包装（方）+ 爆开后飞出的 5 张竖版（3:4）= **内页海报**，物理上自洽，视觉上仍然是"从 CD 盒里抽出来的东西"。

每张内页的视觉：封面占满 3:4 之上、底部一条黑底信息栏（作品名 / 编号 / 盘符·大小）、右上角一枚小圆贴纸（表示这张来自哪块盘）。

## 三、视觉

### 3.1 未拆封的盒（舞台中央，约 300×300）

- 方形黑壳，左侧 6px 书脊（侧看有厚度），壳内封面纸内缩 6px
- 封面是**匿名封面**：同心圆 = 光盘正面俯视的轮廓，中央小孔。**不出现任何具体作品** —— 拆开前必须不知道里面是什么，这是抽卡的全部悬念
- 一层收缩膜：一条斜向高光带（`mix-blend-mode: screen` + 低不透明度）、四角有一条折痕线、右上角一枚拉条三角
- 盒底一条窄信息栏：`随机一包 · 5 discs`
- 右上角圆形贴纸：`5`

### 3.2 拆封 → 爆开（约 900ms，分段）

1. **0ms** 拉动条撕开收缩膜：膜从右上角裂开，沿一条不规则路径（96 段折线，随角度抖）撕成 12 片，向两侧飘走并淡出
2. **180ms** 盒盖绕左铰链翻开（`rotateY` 到 -105°，带 3 次回弹的弹簧）
3. **320ms** 5 张内页从壳里依次弹出（间隔 60ms，起点在壳内、终点的扇形位置），走弹簧位移 + `rotateZ` 微旋
4. **同时** 彩带从壳体缺口喷出（Canvas 2D，90~120 片，重力 + 空气阻力 + 自旋）
5. **900ms** 落定，底部浮出「再来一包」

减少动态效果（`prefers-reduced-motion`）⇒ 跳过 1~4，直接落定。

### 3.3 五张内页的排布

- 扇形：中间一张最高、两侧依次下沉并外旋（-9° / -4.5° / 0° / +4.5° / +9°），叠压顺序从中间向外
- 悬停：那一张抬起 12px、放大 1.04、倾斜跟随鼠标（±12°，弹簧软化），全息反光层跟着位移
- 反光：一层随倾斜角移动的线性渐变（彩虹色相，`hue-rotate` 由倾斜量驱动）+ 一层极细的噪点蒙版 + 一层白色高光束（`screen`）。三层叠加才像箔，单层渐变一定是"塑料感"
- 键盘：左/右选中相邻、`Enter` 播放、`空格` 再来一包、`Esc` 回首页

### 3.4 离线卡

- 整卡 `opacity: .42` + 灰度 `.6`，右上角贴纸换成红底白字「离线」
- 双击 ⇒ 提示"磁盘未在线"（用 `notify('warning')`），不自动换卡

## 四、交互流程

```
左轨第 5 项「手气不错」
  ↓ 进入 /lucky，池子加载（首次约几十毫秒，纯内存）
  ↓ 舞台中央一个未拆封 CD 盒 + 右上角勾选框「包含离线盘」
  ↓ 点击 / 空格 / 向下拖动拉条
  ↓ 撕膜 → 开盖 → 5 张内页扇形展开 + 彩带 + 音效
  ↓ 双击任意一张 → 解析锚点 → 系统播放器播放（toast：已交给播放器）
  ↓ 「再来一包」/ 空格 → 回到未拆封状态，重新抽 5 张
```

- 池子 < 5 ⇒ 抽多少算多少（不补齐、不重复）
- 池子 = 0 ⇒ 空态卡："还没有已缓存的封面，先去「文件」浏览扫描"
- 取消勾选「包含离线盘」⇒ 只从在线盘抽；切勾选会**重抽**（不是过滤现有 5 张）
- 连抽两次不会完全一样：记住最近 10 个已抽 `sig`，本轮优先排除（排除后不足 5 张时放开）

## 五、数据链路（全部走现有接口）

```
GET /getAllCovers              → items[]: {id, name, dir, relPath, key, serial, sig, type, ext, size, files}
GET /getDisks                  → disks[]: {serial, online, drive, label}
GET /thumb?k=t-<sig>.enc       → 封面（已缓存，零读盘）
GET /resolveAnchor?path=#S/... → 实时路径
ipcRenderer.invoke('openFile') → 系统播放器
```

「这张卡怎么变成播放」这段逻辑**目前在 `src/views/Tunnel/index.vue` 的 `handleSelect` 里**（找视频 → 拼锚点 → resolveAnchor → openFile）。
按"同一件事多条路径必须共用一份实现"，抽出来：**`src/views/FileFinder/openCover.ts`**，隧道页与抽卡页共用，隧道页只是把内联实现换成调用（行为一字不改）。

## 六、技术方案与取舍

**用 CSS 3D + Canvas 2D + Web Audio，不引 three.js。**

- 项目已有 three.js（3D 漫游页），但那是"一个持续渲染的 3D 场景"；这里要的是"一次 900ms 的动画 + 5 张会倾斜的平面"。为一个平面卡片引入 WebGL 场景（渲染循环、纹理上传、dispose 纪律）是拿大炮打蚊子，而且逐帧 canvas 在低端机上比 CSS compositor 更耗电。
- 参考站本身就是纯 CSS 3D + Canvas 2D，证明这条路够用。
- 音效走项目已有的合成引擎（`playSfx`），新增两个配方：`lucky-tear`（撕裂：滤波噪声爆发 + 快速衰减）、`lucky-burst`（爆开：低频撞击 + 上行泛音）。不新增音频文件。

## 七、样式纪律（AGENTS.md 硬约束）

- 抽卡页所有颜色必须来自 `var(--ff-*)`。光盘银、壳边反光、箔彩虹这些新色**先在 `tokens.css` 加语义令牌**（`--ff-disc-*` / `--ff-foil-*`），SFC 里一个 `#hex` / `rgba()` 都不许出现（护栏探针 `docs/probes/tokens/no-raw-color.mjs` 会抓）。
- 浅色/深色两套都要成立：箔彩虹在深色下提亮度、在浅色下降饱和，避免"塑料糖纸"。
- `--ff-highlight` 系列只用于选中/悬浮/焦点三处，不得挪用为装饰色。
