## 一、背景：为什么立这条规

2026-10-04 他当面质问：「`index.vue` 2000 多行，还有在代码里不断的加注释合理吗？」

实测数据（`grep -cE "^\s*(\*|//|/\*)"` + `wc -l`）：

| | 行数 |
|---|---|
| `src/views/FileFinder/index.vue` 总行数 | **2304** |
| 纯注释行 | **864（37.5%）** |
| 代码行 | 1263 |
| 空行 | 177 |

**结论：是真问题，不是抱怨。** 代码只占 55%，注释比空行还多 5 倍。

## 二、判据（一句话）

> 注释是给**下一个改这块代码的人**看的，他需要「这行为什么是这样、不改会怎样」，
> **不需要**「我当时怎么推出来的」。

## 三、三类注释，只留第一类

| 类 | 例子 | 处置 |
|---|---|---|
| **判据 / 陷阱** | 「`scoped` 够不到 teleport 的 DOM ⇒ 要非 scoped + 前缀多一层祖先（cssr 运行时注入，同特异性先后不可控）」 | ✅ **留 1~3 行** |
| **实测数据表 / naive-ui 行号索引 / 方案比选** | 「480×270 抽帧 → 显示 1833×1031，≈3.8 倍插值」 | ⛔ **搬进 `docs/`**，代码旁留一行「详见 `docs/XXX.md` §N」 |
| **推理过程**（"为什么这样想"、我的自我论证） | 「业界都这么做，我选了 A 不选 B 因为…」 | ⛔ **删**（属commit message / 设计文档） |

**为什么第 2/3 类要搬走**：它们有**时效**。naive-ui 升个版本行号就错、方案换了结论就废，
但留在代码里会让人当权威。判据类**不老化**——它说的是"这个机制会咬你"，换实现也照样咬。

## 五、执行方式

1. **写之前**：新注释超过 5 行 ⇒ 先自问「这三类是哪类」。答不上来就是"过程"，砍到判据为止。
2. **写之后（别等他说）**：跑
   ```bash
   grep -cE "^\s*(\*|//|/\*)" <file>   # 注释行数
   wc -l <file>                        # 总行数
   ```
   比值进交付摘要。**超 30% 就自己提出来**，不要等他质疑。
3. **清理是独立一轮**：约 864 → 300 行。⚠️ **只动注释，一个 token 都不许碰代码**。
