## 二、我复算**不通过**的（它错了）

### 2.1 §1.1 体积：投影 **163 KB（不是 ~100KB）**；原始 data[] **69.0 MB（不是 78 MB）**

探针 `docs/probes/handover-audit/search-projection.mjs`（只读、已脱敏）：

```
条目总数 1471
原始 data[] 序列化        72,391,084 B = 69.04 MB     ← 文档写 78 MB
  其中 base64 缩略图两字段 72,082,978 B = 68.74 MB（99.6%）
投影 {name,dir,size,type,serial} 167,120 B = 163.2 KB  ← 文档写 ~100 KB
投影/原始 = 0.23%
```

- **方向不变**：163 KB 依然是"轻到毫无压力"，**结论（可下发）成立**。
- 但"78 MB"很可能是**误取了仓库根目录那份备份文件的字节数**（78,591,134 B = 78.6 MB），
  那是个**更旧的、不同的库**（09-24）；真库文件 92 MB、其 `data[]` 是 69.0 MB。这正犯了它自己 §6 第 2 条判据。

### 2.2 §1.2 收益：**116 是统计口径错，真收益 = 113**

（一次性遥测：脚本按项目判据已删（结论已进本文 ⇒ 脚本是脚手架）；口径 = 复刻 `scan.ts:270` 的分类目录判据）

```
cover 模式 folder+avatar = 114   （文档写 116 —— 那是"全部记录"口径，含 2 条非 cover 模式）
  ├ 分类目录（按 scan.ts:270 会被继续跳过）= 1
  └ 单片目录（真正的目标）= 113
⇒ 真收益 = 113
```

- 文档 §1.2 写"116 个目录…（旧文档写 113 —— 差异是统计口径）"，把这句当**无害的口径差**打太极。
  **实际上旧文档的 113 才是对的**：`gatherCacheDocs` 只读 `mode:'cover'` 的文档（`scan.ts:291`），
  非 cover 的 2 条**根本进不了扫描**；而分类目录会被 `:270` 继续挡掉。
- 这错误的**根源在 `VERDICT` §五 第 5 行**：一次"字段纠错"顺手把统计范围也换了（`113`→`116`），
  **纠错动作本身引入了新错**。交接件忠实继承了它，没复核。

### 2.3 §1.2 修法："抽共享判据函数、两处都调" —— **不成立（且漏了第三处）**

文档主张 `:263` 与 `:472` 是"同一判据"，必须抽成一个共享函数让两处都调。我读代码后**反对**：

- 两处**表达式相同、语义不同**：
  - `:263`（`evaluateDocs`）回答的是「**要不要给这个目录补脸**」（补脸闸门）；
  - `:472`（`deepScanMissingCovers`）回答的是「**深度重扫要不要下钻进这个子目录**」，
    它自己的注释写明理由是"恢复缓存世界的不变量：有脸的目录从不拥有自己的文档"——**不是补脸判据**。
- **它漏了第三处**：`scan.ts:632`（`collectFaces`，"换封面"）用的是**同一个 `avatar` 谓词的反向**：
  `if (e.type === 'folder' && e.avatar)` → 收进"已有脸、可替换封面"的目标集。
- ⇒ 一旦按它说的"把 `avatar` 谓词收成共享函数"并把语义从"有没有"改成"够不够大"，**第三处会连带变**：
  小图目录会**从"换封面"的清单里消失**（而它们恰恰是最该换掉的那批）。**这是它没有考虑到的回归。**

**正确做法**：new 一个语义明确的小函数（如 `needsFaceSupplement(e)`）**只用于补脸闸门**；
`:472` 的"下钻闸门"是否随之改，需要**先论证**（它没论证）；`:632` 必须显式决定去留。
**"同文本 ≠ 同语义"** —— 这条恰好是它 §6 自己立的判据，却在这里没执行。
