# 方案：地址栏（面包屑）快捷操作（2026-11-14）

> 触发：业主截图（形如 `此电脑 › 盘符 › 目录 › 当前层`），「地址栏也调整优化一下，方便用户快捷操作」。
> 本文件只出方案，**未改任何交互代码**。

## 一、现状能力盘点（静态核实，非推测）

| 能力 | 现状 | 位置 |
|---|---|---|
| 点某段 → 跳到该层 | ✅ 有（压导航栈，能返回） | `index.vue:1385` `onCrumbClick` |
| 悬停某段 → 看全路径 | ⚠️ 有，但是**浏览器原生 `title`** | `index.vue:94,104` |
| 段上右键 | ❌ 无 | — |
| 复制当前路径 | ⚠️ 只有文件列表右键菜单里有 | `useContextMenu.ts:113` |
| 回父目录 | ❌ 无专用入口（`←` 是"上一屏"，不是父级） | — |
| 切到同层其它目录 | ⚠️ 只能靠 `▤` 重新选文件夹 | `FolderSelector` |
| 首页「此电脑」 | 纯文字，**不可点**（刻意：点了没去处） | `header.less:83` |
| 手输路径 | ❌ **禁止**（硬约束 #5，2026-09-30） | — |

**真正的洞只有两个：**
1. **深路径下拿不到路径文本** —— 复制只能回列表里右键，而列表右键复制的可能是**文件**路径不是**当前目录**路径。
2. **「上一屏」≠「父目录」** —— 从搜索结果/收藏夹跳进来的目录，`←` 回的是搜索屏，不是上一层文件夹。

## 二、候选方案与读盘成本

| 档 | 方案 | 读盘 | 新增视觉 | 判断 |
|---|---|---|---|---|
| **A** | 面包屑**任意段右键菜单**：复制路径 / 在资源管理器中打开 / 从这层重新读取 | **0** | 0（复用 `.ctx-menu` 材质） | ✅ 推荐 |
| **B** | 键盘 `Alt+↑` = 回父目录 | **0**（父级已在 `ancestorsOf` 结果里） | 0 | ✅ 推荐 |
| C | 地址槽空白处双击 → 复制完整路径 | 0 | 0 | ⚠️ 绑定反直觉，不做 |
| D | 段右侧下拉箭头 → 列同层子目录 | **要枚举目录** | 箭头 | ❌ 违反最高优先级，除非业主特批 |
| E | 顶栏再加一颗 `↑` 按钮 | 0 | +28px | ❌ 顶栏宽度预算 11-08 刚定完，不塞 |
| F | 地址栏可编辑 / 手输 | 0 | 大 | ❌ 违反硬约束 #5 |

> D 的否决理由要说清：枚举子目录 = `readFolder`，在移动硬盘上是寻道 + 耗电。
> 而且 `▤`（选文件夹）已经覆盖"去别的地方"这个需求，D 只是把它变成"少点一次"。

## 三、推荐：A + B

### A · 面包屑段右键菜单

```
右键任意一段 ─┐
              ├─ 复制路径          （该段的完整路径，不是当前目录）
              └─ 在资源管理器中打开
```

**为什么右键而不是左键点空白**：左键点段已经有语义（跳转），空白区没有容身之处（槽被段填满）。
右键是"对这一段做点什么"的零歧义入口，且与文件列表的右键心智一致。

**实施要点**
- 复用 `ctx-menu.css`（它已经显式抄了 `--ff-tooltip-*`，视觉与顶栏 tooltip 同源）。
- 定位复用现有 `n-popover` 的 `trigger="manual"` + `:x/:y` 写法（`index.vue:429` 已有同款）。
- 三种锚点（文件项 / 空白 / 面包屑段）**不要各写一套菜单** —— 现有 `useContextMenu` 已经是
  `items + 状态` 的结构，加一组 items 即可；菜单项的 `disabled` 用闭包算，不预先建数组。
- 首段是盘符或「清单」根段：`复制路径` 给盘符根（`D:\`）或清单名，不拼假路径。

### B · `Alt+↑` 回父目录

- 面包屑倒数第二段即父目录：`crumbs.value[crumbs.value.length - 2]`，走同一个 `jumpTo`。
- 首页 / 清单屏 / 已在盘根 ⇒ 无效（不提示、不报错）。
- ⚠️ 键盘归属：`Alt+↑` 现在有没有被占用需实测（`useKeyboard` 里 `Alt+→` 已用于前进）。
  `Alt+↑` 与 `Alt+→` 同族，不会有组合键冲突，但要确认没有被输入框/编辑器拦下。

**为什么不给 B 配按钮**：`←` 已经在那个位置，再放 `↑` 两颗箭头并排会被读成"两倍后退"。
键盘绑定 + 段右键菜单里的「在上一层打开」足够。

## 四、附带修（与任务 1 同源）

`index.vue:94,104` 面包屑段的 `:title` 是全站 37 处原生 `title` 之一 —— **它就在顶栏里**，
悬停按钮出黑片、悬停面包屑出系统灰块。若采纳任务 1 的档 1，这里应一并换成 `v-tip`。

## 五、实施记录（2026-11-14 已落地）

### 审查阶段发现的 4 个缺陷（都在动手前修掉了）

| # | 缺陷 | 后果 | 处理 |
|---|---|---|---|
| 1 | 原方案让 crumb 模式沿用整份菜单，而 `dirActions`（刷新/补封面/重新读取）是"当前这一层"的工具 | 挂在祖先段上分不清作用对象；"重新读取"还会给读盘开第 4 个入口 | 模板里给工具组加 `v-if="ctxMenu.mode !== 'crumb'"`，并把「清空导航历史」一起排除 |
| 2 | `Alt+↑` 若父级是盘根，`jumpTo` 会跳 | 与 `onCrumbClick` 判据不一致（那边明确不跳盘根，因为盘根通常没缓存、会真读一次盘） | `goParent` 里 `if (parent.kind === 'root') return` |
| 3 | 锚点路径（`#序列号/…`）直接 `copyText` / `openPath` | 复制出用户粘贴不了的东西；打开必然失败 | 加 `crumbRealPath()`：锚点走 `resolveAnchor` 当场换真路径，换不到就提示"这块盘不在线" |
| 4 | `picking`（换封面）模式没短路 `Alt+↑` | 挑图过程中屏被换掉，选中的格子还在但看不见 | 与 `Alt+←/→` 同一行一起 return |

**第 3 条顺带印证了一条老教训**：判据要落在**事实**上。用 `path.startsWith('#')` 判"盘在不在"就是拿
路径形态当事实（锚点在盘插回来后是可以换到真路径的）。所以不是"锚点就禁用"，而是"点了当场问一次"。

### 落地内容

| 位置 | 改动 |
|---|---|
| `useContextMenu.ts` | `mode` 增加 `'crumb'`；加 `crumbPath` 字段（带注释说明为什么不渲染工具组） |
| `index.vue` 模板 | 两个 `n-tag` 加 `@contextmenu.prevent`；ctx-menu 新增 crumb 组（两项）；工具组/导航组排除 crumb |
| `index.vue` 脚本 | `onCrumbContextMenu` / `crumbRealPath` / `copyCrumbPath` / `openCrumbInExplorer` / `goParent` |
| `index.vue` 键盘 | `keyup` 增加 `Alt+↑`；`picking` 分支短路列表补 `ArrowUp` |

**`Alt+↑` 不和网格方向键打架**：`useGridCursor.ts:510` 开头就有 `if (e.altKey) return;`，
带修饰键的方向键它一律不接 —— 所以这里不需要像 `←/→` 那样再补一条守卫（已核实源码）。

### 刻意不做

- **「从这层重新读取」**：业主 2026-11-14 定过"读盘只归文件视图那三个扫描入口"，
  在面包屑右键里加"重新读取"等于给读盘开第 4 个入口，与刚收敛的口径直接冲突。
- **给 `Alt+↑` 配按钮**：顶栏宽度预算 11-08 刚定完；且 `←` 旁边再放 `↑` 会被读成"两倍后退"。
- **UI 里宣传 `Alt+↑`**：与 `Alt+←/→` 同族，属于熟练用户快捷键。若日后要露出，
  落点是它所在菜单项的键帽，不是新按钮。

## 六、追加：「此电脑」进链（2026-11-14 业主第二轮裁决）

原方案把「此电脑」当成"首页时的占位文字"，业主否掉：**它应该是面包屑的第一段**，
点了回磁盘列表（资源管理器同形制），前面加一枚显示器图标；而**真正的盘符根仍然不可点**（装饰）。

| 改动 | 位置 |
|---|---|
| `crumbs` 恒以 `HOME_CRUMB` 开头（首页时数组只有它这一段） | `index.vue` computed |
| `onCrumbClick` 加 `path === HOME_PATH` 分支 → `enterScreen(HOME_PATH)`；**首页时显式不动作**（`cursor: default` 拦不住 click） | 同上 |
| 首段加显示器图标 + `crumb-home` 类；`crumb-root` 排除 HOME_PATH（那个类同时意味着"不可点"） | 模板 + `header.less` |
| 分隔符判据 `:not(.crumb-root)` → `.crumb + .crumb` | `header.less` |
| 删掉 `.nav-home`（静态占位段不再需要） | 模板 + `header.less` |
| `goParent` 加一条：父级是「此电脑」⇒ 回首页（盘根按 `Alt+↑` 就该到这） | `index.vue` |
| 右键菜单排除「此电脑」段（它的 path 是 `@home` 哨兵，复制出来没用） | 同上 |

**顺带修掉一个死交互**：`.crumb-current` 一直缺 `--n-color-hover: transparent` ——
11-08 的注释写着"当前段没有底色 = 不可点"，但代码没写，于是当前层悬停有底色、点了没反应。
首页的「此电脑」成了当前段之后这个毛病更显眼（整条槽只有它一段）。

**关于标题**：`.crumb` 的原生 `title` 是"看全文"，而「此电脑」没有可看的全路径 ⇒
这一段**不给 title**，不把"动作说明"混进"全文预览"那套里。
