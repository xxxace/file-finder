## 二、图片缓存：出库 + 补上"预览大图"（**缓存格式 v2 → v3**）

**改动**：`electron/utils/{binStore,cacheCrypto,zip}.ts`（新）· `thumbnail.ts`
· `server/index.ts` · `nedb.ts` · `main/index.ts` · 渲染层 `previewSrcOf` · 删 `thumbStore.ts`

1. **缩略图从库里搬出去**：原来以 base64 存在记录里（`thumbData`/`avatarThumbData`），
   白交 **+33%**（实测 39 KB 的 JPEG 存成 base64 = 52 KB；`gzip` 只能把这一层捞回来、
   对 JPEG 本身 0 收益）⇒ 改成数据目录下的 `bin/<名字>.enc`（逐文件加密，随机 IV）。
2. **档位实测下调 480 → 384 / q78**（真库 400 张真缩略图：480 均值 39 KB、**384 均值 23 KB**，
   396 张更好）。本机 dpr 1.25、6 列 ⇒ 一格约 400~427 设备像素 ⇒ 384 是 1.04~1.11 倍插值
   （照片上看不出）。`probes/thumb-tier/`
3. **一次解码出两张图**（网格的 384 + 预览的大图长边 2048，源是够小的 JPEG 就**原样存**）
   ⇒ **零额外读盘**。大图在扫盘那一刻就生成；老条目第一次看时由 `/preview` 现场生成并**存下来**。
4. **一个 `sig` 命名两个尺寸**（`t-<sig>` / `p-<sig>`，取**缩略图**内容的 sha1）
   ⇒ 换封面 ⇒ 两个 URL 都变 ⇒ 浏览器 `immutable` 缓存不会拿旧图挡着。
5. **离线也能看到清晰封面**：以前离线层只能用缩略图铺满视口（≈3.8 倍插值 = 糊），
   现在离线看的是本地那张大图。
6. **一次性本地迁移**把旧记录里的 base64 图片搬进 `bin/`（**不碰移动硬盘**，字节级核对通过）
   ⇒ 不用为了新格式把 5 块盘重扫一遍。

**实测结果**：库 **85 MB → 428 KB**；`bin/` 1349 个文件 / 50.7 MB；图片合计 **−41%**。
**读盘只少不多**：扫盘完全不变；在线看大图从"每次读一次"变成"第一次之后 0 次"。

**证据等级**：`typecheck` 0 error + 三处构建通过 + `probes/bin-migrate/` 字节级一致
（张数与总字节精确相等）+ 系统 `Expand-Archive` 解压校验（解出的文件 sha256 与原件逐字节一致）。
**未实测**：真机观感（384 够不够清晰、"停住 0.3 秒换清晰"的手感）。

### 交付后自查抓到的三处（其中两处是本轮自己引入的）

| # | 缺陷 | 实测证据 | 修法 |
|---|---|---|---|
| 1 | `sig` 锚在大图上 ⇒ 缩略图存成 `t-<大图指纹>`，**名字里不含自己的内容** | 遍历真仓 1349 个文件：t **1205 对 / 72 错**，p 全对 | 锚回缩略图；`t-`/`p-` 成为「同一源的两个尺寸」，与迁移一致 ⇒ 1205 个文件继续有效、零重出 |
| 2 | 懒生成不幂等 ⇒ 每次点开都重读一遍源 | 上一轮的"另存 + 302"解决不了：请求的名字来自**库**，不因重定向而变 | `/preview` **按请求的名字存**，302 分支整个删掉 |
| 3 | 备份在图片仓异常时**静默丢图**（导出只有库的包，界面还显示成功） | 代码审查 | 打包前 `binStoreFailed()` 为真 ⇒ **响亮拒绝** |

面板统计只报「库 428 KB」严重低估（图片 50.7 MB 才是大头）→ 加「图片 N 张 · X」。

## 三、扫盘：让写盘与解码重叠

**改动**：`server/index.ts` 的 `makeRenditions` / `readFolder` / `handleCover` / `flushRenditions`

实测一屏 216 个条目的成本（`probes/perf-tick/`）：解码 + 缩放 + 两次 JPEG 编码 **1.49 s**，
写 bin（432 次 write+rename）**1.39 s** —— **同量级，写盘不是可忽略的小开销**。
改成"只登记写盘 promise、扫描循环结束后统一 await" ⇒ 写盘（IO 等待）与解码（CPU）重叠。

**A/B（同一批素材、7 轮交替）**：每条等写完 **333 ms**（330–360）→ 登记不等待 **154 ms**（152–165）
⇒ **快 2.16×**，一屏省约 1 秒。**产出明文逐字节一致**（文件名集合 + 每个文件解密后的 sha1）。
不变式未放松：**"调用方拿到 sig 时文件一定已写完"**仍成立（`readFolder` 唯一出口就是那个 flush）。

**证据等级**：实测（上表）。**未实测**：真机上扫一层的墙钟（探针用 bin 里的图当素材，不读移动硬盘）。

## 四、备份 / 还原 / 合并：改成**一个 zip**

**改动**：`electron/utils/zip.ts`（新，store-only）· 三个端点 · `main/index.ts` 对话框 ·
`HistoryTable/index.vue` 文案

数据不再只是 `searchCache.db` 一个文件（图片搬到 `bin/` 了），所以"拷走那一个文件"不再等于
"拷走这份数据"。打进一个 `.zip`（库 + `bin/`）：**资源管理器双击就能打开**，里面有什么一目了然。
store-only 是因为内容已压不动（库是密文、图片加密后高熵 + JPEG 本身已压缩）。

**证据等级**：写→列→取往返逐字节一致 + **系统 `Expand-Archive` 校验**。**未实测**：真机走一遍按钮。
