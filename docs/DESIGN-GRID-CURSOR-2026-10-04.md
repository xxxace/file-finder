# 网格方向键导航 + 回车确认（2026-10-04 · 最终版）

> 目标：网格（文件 / 视频渲染区）支持 `↑↓←→` 移动一个**常驻选择器**、`Enter` 打开 / 确认。
> 约束：最小改动、模块化、行为与预览层统一、**零读盘**。
> 本版修掉 v1 的 3 个不成立点 + 2 个遗漏，并解决"多文件封面回车弹出文件列表怎么办"。

---

## 零、主人裁决（2026-10-04）

1. **图片用内置的**（不开外部看图软件）—— `Enter` 在图片上 = 开内置预览
2. **`Enter` 原则上 = 现在的双击**
3. 由此产生的必答题：一部片子有多个文件时，双击会弹文件列表 popover，**键盘进得去、出得来吗**

---

## 一、核心设计：把「当前格」和「预览的当前条目」认成同一件事

现状已经是半成品：

- `usePreview.previewKey` = "正在看哪一条"（`usePreview.ts:59`）——**它就是一个选择器**
- 网格里 `located` 类已画出选中态（`index.vue:1773`）—— 只是它 1.2s 就消失
- 定位动作 = 关预览 + 滚到那一格（`usePreview.ts:225`）

所以**不引入"选择器"这个新概念**，只补两件事：预览关着时方向键也能改它；定位后高亮常驻（定位只多闪一下）。

### ⚠️ 但**不能**直接把选择器做成 `previewKey`

`watch(previewKey, scheduleSharpUpgrade)`（`usePreview.ts:238`）会在 key 变化时排一个0.3s 后的
`/preview` 请求 —— 那条路会去读移动硬盘上的原图（第一约束）。
方向键每按一次就改一次 `previewKey` ⇒ 每按一次排一次读盘。**绝对不行。**

⇒ 新增**独立的** `cursorKey`，只在两个口子上**单向**同步（`previewKey → cursorKey`，无反向）：

| 口子 | 位置 | 动作 |
|---|---|---|
| 打开预览 | `openPreview`（`usePreview.ts:206`）| `cursorKey = keyOf(item)` |
| 预览里定位 | `locateInGrid`（`usePreview.ts:225`） | `cursorKey = previewKey` + 闪一下 |

`usePreview` 内部时序（清晰版升级 / 关闭 / 滚轮）**一行不动**。

## 二、`Enter` 打开什么：一张表说清

判据**复用已有的那一个**（`index.vue:609`）：`item.files?.length > 1` ⇔ 这是一张**封面卡**
（代表一个目录 / 一部片子），不是一张真图片。

| 条目 | 内置预览显示什么 | 现在双击做什么 | **`Enter`** | 为什么 |
|---|---|---|---|---|
| 封面卡（image + files>1）| 封面图 | 弹文件列表 popover | **弹 popover**（＝双击，无例外） | 选择"哪一部"是这一步的固有职责，跳过就打开了错的片子 |
| 图片（无 files）| 这张图 | 跳系统看图软件 | **开内置预览** | 裁决 1。内置有翻页 / 缩放 / 定位，比跳出应用强得多 |
| 视频 | 抽帧图 | 系统播放器 | **系统播放器**（＝双击）| 视频的"打开"就是播放；抽帧图没有"打开"的语义 |
| 目录 | 目录的脸 | 下钻 | **下钻**（＝双击）| 同上 |
| 其他文件 | 字体图标 | 系统打开 | **系统打开**（＝双击）| 同上 |

> ⚠️ **图片是唯一的例外，而且是改进不是不一致**：图片的"打开方式"就是"看"，
> 内置预览完��全能承担（还能 `← →` 翻页、滚轮缩放、定位回网格继续用方向键），
> 跳外部看图软件反而是什么都没有。**双击行为一个字不改**（既有语义不动）。

## 三、多文件 popover：键盘怎么进、怎么出

这是本方案最实的一处，也是 v1 完全漏掉的。原则：**弹层的键盘归弹层自己管，
不进网格选择器** —— 靠焦点做天然隔离，不写额外规则。

### 交互

| 键 | 行为 |
|---|---|
| `Enter`（在封面卡上）| 弹 popover，**焦点自动落在第一项** |
| `↑ ↓` | 在 popover 内上下移动高亮（**网格选择器纹丝不动**）|
| `Enter` | 打开高亮的那一项（现有 `openFile(name)`，一个字不改）|
| `Esc` / 点外面 | 关闭，焦点回到 body ⇒ 方向键立刻又能操控网格 |
| 鼠标全部照旧 | 弹层位置用鼠标坐标，条目双击打开 |

### 为什么这么切分（而不是让同一个选择器管两层）

- **状态不重叠**：网格选择器是"哪一格"，弹层高亮是"哪一部"。两个不同的问题。
  让一个 `cursorKey` 同时管两层 ⇒ 一个状态被两处写，必然出现"焦点在弹层里、选择器在弹层外"这种自相矛盾。
- **隔离是免费的**：`isGridKeyBlocked` 里的 `target !== body`（`index.vue:1386`，现有守卫）自动生效
  —— 焦点在弹层内的 `div` 上 ⇒ 网格的 keydown 收不到事件。**不需要为弹层写任何例外分支。**
- **事件不会打架**：监听挂在 popover 容器上（`@keydown`）并 `.stop`，
  根本不会冒泡到 window 被网格看见。

### 焦点怎么给出、怎么收回

- 给出：`nextTick` 后聚焦第一项（`tabindex="-1"` 让 `div` 可编程聚焦）
- 收回：关闭时 `document.activeElement.blur()` ⇒ 回到 body
- 违反这两条的后果都是"方向键失灵"，所以它们是**必做项**，不是优化项

### 右键菜单（复制文件名）

**不处理**。两个纯复制动作、纯鼠标产物，键盘用户不会开着它按方向键。
真要处理也只需一行（方向键顺手 `clickoutside` 关掉它），但不写 —— 属于"为假想场景加代码"。

## 四、行为规格：三模式 × 六输入

| 输入 | 常态浏览 | 「换封面」模式（picking）| 预览层开着 |
|---|---|---|---|
| 悬停 | 只画 hover 灰边，**不动选择器** | 同 | 预览层接管 |
| 单击卡片 | **把选择器移到这一格** | 切换选中（现有，不变）| 预览层接管 |
| 单击图片 | 选择器移到这格 + 开预览（现有，不变）| 同常态 | — |
| 双击 | 按 §二 那张表（现有，一字不改）| 现有 | — |
| `↑ ↓ ← →` | **移动选择器** | 同常态 | naive-ui 接管（←→ 翻页 / ↑↓ 缩放）|
| `Enter` | 按 §二 那张表 | **选中 / 取消**（＝单击）| 定位（现有，`index.vue:1399`）|
| `Esc` | 关预览 / 关弹层 / 关 popover | 退出 picking（现有）| naive-ui 接管 |
| 文件列表 popover 内 | `↑↓` 移高亮 · `Enter` 打开 · `Esc` 出去 | — | — |

### 三条刻意的"不统一"（防将来被当 bug 改掉）

| 不统一处 | 决定 | 理由 |
|---|---|---|
| 网格左右到头 | **停住，不环绕** | 网格是**空间**，环绕会迷失位置（第 1 项按 ← 跳到第 6 项）。预览层是**序列**，naive-ui 首尾环绕符合"上一条/下一条" |
| 悬停 vs 选择器 | 悬停**不**改选择器 | 否则鼠标随便划过就冲掉键盘选好的位置，两个输入互相打架 |
| `Enter` vs 双击（图片）| 不同 | 裁决 1，见 §二 末尾说明 |

## 五、三种"视觉身份"不许撞色

网格里同一格最多同时挂两个状态色，所以颜色必须是**三套互不重叠**的：

| 状态 | 表现 | 手法（必须与 `.located` / `.picked` 同一手法）|
|---|---|---|
| **焦点**（选择器）| 中性灰白 `#7a8da9` 边框 + `0 0 0 2px` 外发光 | 改**边框色**，不动盒模型 |
| **已选**（换封面 picked）| 绿 `#18a058` 边框（现有 `.picked`，不动）| 改边框色 |
| **定位闪烁** | 蓝 `#2080f0` 边框，1.2s 后落回焦点色 | 改边框色，**不加外发光**（会与焦点的发光叠成两圈）|

⚠️ **三条铁律**（照抄现有约束，违反就带偏 6 列网格）：

1. **只改那个本来就存在的 `border: 1px solid transparent` 的颜色 + `box-shadow`**——
   网格 6 列宽度是"margin 撑间距 + `width:100%/6−10px` 补偿"算出来的
   （`index.vue:1748-1752`），**任何新增参与布局的盒模型属性都会把它带偏**
2. **不插任何新 DOM 节点进卡片**（角标是绝对定位才敢插，见 `index.vue:187-191`）
3. 颜色**不共用**：绿=已选、蓝=定位、灰白=焦点（`index.vue:1768-1771` 已明写这条纪律）


### 6.1 `useGridCursor.ts` —— 唯一职责："选择器在哪 + 网格键盘怎么动它"

**入参**（全部只读，与 `usePreview` 同一套契约）：

```ts
useGridCursor({
  fileList,     // ComputedRef<WiredFileInfo[]>  当前这一屏
  keyOf,        // (item) => string
  imageBox,     // Ref<HTMLElement|null>  滚动容器
  picking,      // Ref<boolean>            换封面模式？
  onConfirm,    // (item) => void          Enter 干什么（index.vue 决定，见 §二）
})
```

**状态只有一个真相**：

```ts
cursorKey    // Ref<string>，'' = 未激活
```

⚠️ **不做**"切目录 / 刷新时清空选择器"这种同步代码。判据全部**派生**：

-格子不在当前 `fileList` 里 ⇒ **不画高亮**（`cursorKey` 成了野 key，视觉上自动消失）
- 野 key 状态下按方向键 ⇒ 视为"首次激活"，重新落到视口第一行

这与 `usePreview` 那套"索引算不出就自动关"（`usePreview.ts:19`）同构，也和
`fileList` 改成 computed 的理由一样（`index.vue:443-450`：**派生优于同步**）。

**行结构必须实测 DOM，不能写死列数**：`--item-width` 在 5 个断点里是
`100%/6 → 20% → 33.33% → 50% → 100%`（`index.vue:1867` + `1940-1958`）= **6 / 5 / 3 / 2 / 1 列**。
写死 6 一定在窄窗全错。

```ts
/** 把当前渲染出的格子按 top 分组成 rows[][]（有序，天然就是视觉行） */
const probeRows = (): HTMLElement[][]
```

- 判据用 **`getBoundingClientRect().top`** 而不是 `offsetTop`：`.image-box-item` 自带
  `position: relative`（`index.vue:1755`），`offsetTop` 依赖 `offsetParent` 链；
  rect 是视口坐标，一视同仁、不会因为某个祖先的定位方式变化而错位
- 高度被 `height: var(--item-height) !important`（`index.vue:1875`）钉死 ⇒
  懒加载图没到也不会改变行高 ⇒ **探测时机不需要等图片**
- 一次探测 1471 个元素的 rect ≈ 数毫秒，只在 `fileList` / `resize` 变化时重算

**缓存与失效**：`rows` 缓存闭包内，失效点只有 `fileList` 变化 与 `window.resize`。
resize 监听**必须**在 dispose 时摘掉（`usePreview.dispose` 的写法，本项目已吃两次泄漏亏）。

**首次激活落点**：`rows` 里**第一行 top < 容器可视底部**的那一行（不是 `rows[0][0]`——
`onBack` 会恢复滚动位置（`index.vue:903-906`），返回上一屏时屏幕可能在中间，
落`rows[0][0]` 会把选择器放到屏幕外看不见的地方）。

**移动**：二维下标运算 ⇒ 纯函数、可被探针断言。到边界**停住**。

**滚动跟随**：每次移动后 `scrollIntoView({ block: 'nearest' })`——
用 `nearest`不用 `center`，否则每按一次都猛跳一下。

**闪烁**：`blinkKey` + 1.2s 计时器，抄 `locateInGrid`（`usePreview.ts:233-235`）那套。

**不做的事**（防过度设计）：不写死列数、不做几何邻近搜索、不做虚拟滚动、
不做 Home/End/PageUp、不做 Shift 多选（换封面模式已经是多选，那是它的活）。

### 6.2 共用键盘守卫

```ts
// src/utils/index.ts —— 是现有 `e.target !== document.body`（index.vue:1386）的超集
export const isGridKeyBlocked = (e: KeyboardEvent) => {
  const t = e.target as HTMLElement | null
  return !!t && t !== document.body&& !!t.isContentEditable
}
```

**为什么只加这一条、原来的就够了**（v1 想加DOM 探测，核过naive-ui 源码后删掉了）：

| 担心的情况 | 真相比对|
|---|---|
| 搜索框里按方向键 | 焦点在 `<input>` ⇒ `target !== body` 已挡 ✓ |
| 弹层里按方向键 | 焦点在弹层元素上 ⇒ 已挡 ✓ |
| 弹层开着、焦点却还在 body | **不可能**：`VFocusTrap` 的 `autoFocus` 默认 true（vueuc `focus-trap/src/index.js:98-105`），打开时把焦点打进弹层 |
| `n-popover` 探测 | **必须删**：tooltip 内部就是 popover（`Tooltip.mjs:3` 直接 import `Popover_default`），而 popover 关闭后 DOM 仍在（`PopoverBody.mjs:121` 走 `v-show`）⇒ 工具条上 4 个 `n-tooltip` 悬停过一次就会**永久挡死方向键** |
| `.n-modal-mask` 探测 | 也不需要（上一行已覆盖），且它是"靠 CSS 类名猜状态"的脆弱依赖 |

**事件分工**（不互相吃掉）：

- 网格方向键 / `Enter` ⇒ **keydown**（长按连续移动必须靠 keydown 的自动重复，keyup 做不到）
- 现有 `S` / `D` / `F5` / `Backspace` ⇒ 保持 **keyup** 不动（`index.vue:1396` 已记录这条）
- 方向键处理里`e.preventDefault()`，不让浏览器滚页面

### 6.3 `usePreview.ts` 只改一处

`locateInGrid`（`usePreview.ts:225`）现在自己做"找格子 + 滚动"，那正是选择器的本职 ⇒ 搬进
`useGridCursor.focusCursor(key)`。改完它只剩"关预览 + 通知外部把焦点落过去（带闪烁）"。
`locatedKey` 从 `usePreview` 移出，**状态归一家**。

## 七、风险与自查

| 风险 | 处置 |
|---|---|
| 方向键移动会触发 `/preview` 读盘 | **结构性不可能** —— `scheduleSharpUpgrade` 只挂 `previewKey`（`usePreview.ts:238`），方向键只改 `cursorKey` |
| `cursorKey` 与 `previewKey` 不同步 | 只有 §一 那两个同步点，单向无反向。不同步的唯一合法情形是"预览关着时用方向键"，那正是预期 |
| 换封面模式下方向键与单击选中打架 | 两条路写的不是同一个状态：`cursorKey` vs `picked` Map，互不覆盖；视觉上绿框 / 灰白框分离（§五）|
| 弹层里方向键穿透到网格 | 焦点做隔离（§三），零例外分支 |
| 弹层焦点没给 / 没收回 ⇒ 方向键失灵 | §三 标为必做项，且进真机目视清单 |
| 懒加载导致行结构探测不准 | 格子高度被 `!important` 钉死，`index.vue:1875` |
| 6 列宽度被新元素带偏 | 不新增任何参与布局的节点/属性（§五 铁律 1、2）|
| 监听器泄漏 | `dispose()` 摘 resize 监听；沿用 `usePreview.dispose` 写法 |
| `offsetTop` 受 `position:relative` 影响 | 改用 `getBoundingClientRect()`（§6.1）|

**读盘清单：本方案零读盘。** 全部是内存态 + DOM 几何 + CSS，不新增任何请求。

| **封面卡上回车** | 弹文件列表、焦点在第一项、↑↓ 能走、Enter 打开、Esc 出去后方向键立刻恢复 |

| 搜索框 / 缓存记录 / 补封面弹窗开着时按方向键 | 什么都不发生 |
| 列表很长时用 ← → 横向走 | 不换行、不越界（到行尾停住）|

## 九、明确不做（防过度设计）
