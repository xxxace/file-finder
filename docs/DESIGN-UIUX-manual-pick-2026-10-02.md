## 一、⭐ 先立规矩：哪些东西**不许动**

`index.vue:69-76` 写着你批准过的工具条铁律，原文：

> 工具条 = PC 文件管理器那套：**动作常驻，忙碌时只置灰，绝不消失、绝不换形**。
> 进度和取消在网格下方的状态条（见 `.scan-bar`），工具条这一组**一个字都不随状态变**。
> ① **子元素个数仍然恒定**（4 个：更多 / 缓存记录 / 搜索 / 刷新）

⇒ 本方案因此**绝不**：
- ❌ 在工具条上加按钮 / 换文案 / 换形态（哪怕只是在"换封面状态"下）
- ❌ 搬走搜索、面包屑、历史记录（用户要在挑选时**能导航**）

⇒ **状态就放在"网格下方那条状态条"里** —— `.scan-bar` 已经有先例（扫描进度与取消就住在这儿）。

同样不许破的既有特性（`UX-DESIGN-INPUT` §四"必须保留的用户特性"）：
**双击打开**（单击不打开）、封面收敛、搜索拼音、面包屑跳转、返回恢复滚动位置。

## 二、入口：只加一项，加在「更多」里

```
工具条（一个元素都不动）
[更多 ▾] [缓存记录] [搜索] [刷新]
   │
   └─ 下拉项：… 补封面 │ **换封面** ← 只在这里多一项
```

- 命名与「补封面」对仗：「补封面」= 补那些**没有**的；「换封面」= 换掉那些**有但不好**的
- 零布局成本、零工具条改动
- ⚠️ 已知代价：藏在「更多」里，可发现性一般 —— 这是**用户明确要求**的取舍
  （"我不要搞出太多的界面和入口"），不是疏忽

## 三、叠加状态：网格"可点选"（其余一切照旧）

进入「换封面」后，**只加一层行为**，不改任何既有交互：

| 交互 | 平时 | 换封面状态 |
|---|---|---|
| **单击**格子 | 无（不打开——神圣特性） | **选中 / 取消选中** |
| **双击**格子 | 打开 | **打开**（不变 ✓） |
| 右键格子 | 现有菜单 | 现有菜单（不变 ✓） |
| 搜索 / 面包屑 / 返回 / 历史 | 正常 | **正常**（要能导航去找演员） |
| 刷新（↻） | 正常 | 正常（已选标记按盘内相对路径保留） |

### 3.1 选中态（三种）

| 对象 | 视觉 |
|---|---|
| 单个条目（封面卡 / 裸条目） | 格子外描边 2px 主色 + 右上角**勾** |
| **目录格子** | 同上，但角标显示**这一批的数量**（如 `12`）—— 因为它是"整批" |

- 角标用**绝对定位**（`position:absolute; top:2px; right:2px`），
  ⚠️ **绝不能用会影响格子几何的写法** —— 网格 6 列的宽度是
  "margin 撑间距 + `width:100%/6 − 10px` 补偿回来"算出来的（`index.vue:1444`），
  任何参与布局的新增元素都会把这套算法带偏
- 角标配色沿用项目语义色（主色实底 + 白字），不用红色（红=error 语义，这里是"已选"不是错）

### 3.2 目录格子的语义

**选中一个目录 = 选中它下面（含子目录）所有"已有封面"的条目。**

- 这是"按演员 / 按文件夹批量"的实现，**不需要任何新界面** —— 目录树本来就在主界面上
- 数量**当场算出来显示**（从缓存，零读盘）：`已选 3 处 · 共 47 张`
  ⇒ 让人在点「换封面…」之前就知道自己要处理多少
- ⚠️ 展开口径要说清：只含**已有脸**的条目；"没有封面"的那些仍归现有「补封面」管（两者互补，不重叠）

## 四、状态条（`.scan-bar` 位置）

复用网格下方那条（现有扫描进度/取消就住这里）：

```
换封面：点格子选中要换的 · 已选 3 处 · 共 47 张     [清除] [退出] [换封面…]
```

- 左：模式提示 + 实时计数（选中即跳数字，PRD §6.5 的"强反馈"）
- 右：三个动作。**主按钮 `[换封面…]` 在 0 张时 `disabled`**
- 「退出」= 清掉这一层行为（**已选标记保留**，再进来还在）；「清除」= 清空选择
- ⚠️ 不用 `n-alert`（不是告警）；一行小字 + 三个按钮，克制

## 五、处理流程（复用现有弹窗，一字不改）

点 `[换封面…]` → 打开现有 `AssistantCoverModal`，但**清单来源**变成"主界面选出来的那批"：

```
主界面（挑选）  ──►  现有弹窗（抓取 → 预览确认 → 写入）
                     · 清单 = 所选项（不再是"扫描出来的缺封面"）
                     · 进度 / 被拦 / 人工过验证 / 预览 / 写入：**全部现有分支复用**
                     · 数量可能较大 ⇒ 清单仍然只是文本行（这里不需要图：图你在主界面已经看过了）
```

**预览确认页加一列"当前"**（手选模式特有）：

```
┌──────────────────────┐
│  ┌────────┐┌────────┐│
│  │  当前   ││ 将替换  ││   ← 左：现有封面（缓存缩略图，零读盘）
│  └────────┘└────────┘│   ← 右：抓到的站点图（走现有 preview 代理）
│  TST-xxx              │
└──────────────────────┘
```

- 左标「当前」、右标「将替换」——**不用箭头、不用颜色暗示"新的更好"**
- 保留并排，因为**看得见才敢决定**（站点未必给得出更好的图）

**`n-popconfirm` 文案**：

> 将**替换** 47 张已有封面（原名不动；**原图会先备份**，可在数据目录找回）。确定吗？

## 六、naive-ui 落地清单

| 位置 | 组件 | 说明 |
|---|---|---|
| 入口 | 现有 `n-dropdown` 的 `moreOptions` **加一项** | 零结构改动 |
| 网格条目点击 | 现有 `.image-box-item` **加 `@click`**（仅状态态生效） | 不改模板结构 |
| 选中角标 | **绝对定位 div**（勾 / 数量） | ⚠️ 不参与布局，不破坏 6 列算法 |
| 状态条 | 复用现有 `.scan-bar` 的容器与样式族 | `n-button` ×3（`small`） |
| 预览确认 | 复用现有弹窗；一行变两列 | `n-image` |
| 替换确认 | `n-popconfirm` | 文案含影响面 + 备份说明 |
| 加载 / 空态 | `n-spin` / 现有 `.ffassist-hint` | 现有 |

**必须继承的避坑约定**（PRD §6 明文）：
- 动态增减的子元素**禁用 `n-space`** ⇒ 裸 flex
- 一个 update 事件**只挂一个 handler**
- 样式作用域内（`<style scoped>`），不污染全局；网格样式改动**只在状态态下生效**
- 主题：**沿用应用现状**（PRD D11：应用是浅色）

## 七、缩略图从哪来（主界面本来就有）

- 主界面网格的缩略图走**现有** `/thumb?k=`（`item.thumb` / `item.avatar`）—— **不需要任何新通道** ✓
- ⚠️ 但**弹窗的"当前"那一列**需要拿到"这些条目的缩略图"：
  它走的是 `AssistantCoverModal`，不在主界面上下文里 ⇒ 需要一个出口把条目的 `thumbData`
  登记进内存索引（`registerThumb`）后只下发 key（`/thumb?k=`）
  - `wire()` / `registerThumb` **都没 export**，`/assistant/*` 也拿不到（`server/index.ts:145/491-503/576`）
  - ⇒ 这是**唯一需要新增的后端出口**（仍是零读盘、零缓存字段）
- ⚠️ 也可以更省：**预览确认只显示"将替换"的新图**，"当前"就在主界面上（用户刚看过）。
  **若为省这一处出口，可砍掉"当前"列** —— 留作实现时的取舍（成本阶梯：一个出口 vs 一列对照图）

## 八、不做

| 不做 | 理由 |
|---|---|
| ❌ 给"糊的"加任何视觉标记（红框 / 角标 / 变暗） | 那就是判据，用户否过三次。**中性呈现** |
| ❌ 任何规则排序 / 自动预选 | 同上 |
| ❌ 新界面 / 二级视图 / 分组列表 / 新搜索框 | 与主界面重复 |
| ❌ 动工具条（加、换、隐藏） | 铁律 |
| ❌ 改双击行为 | 神圣特性 |
| ❌ 参与布局的新增 DOM（会破 6 列网格算法） | `index.vue:1444` 的算法很脆 |
| ❌ 拖拽框选 | naive-ui 无现成组件 |
| ❌ 键盘 roving（第一版） | 独立工作量，列 P1；**已知缺口** |
| ❌ 在移动硬盘上写 `.bak` | 备份落**系统盘** |

## 九、真机验收要点（无头验不了）

1. **⭐ 6 列网格有没有被角标带偏**（宽度/间距必须与改动前逐像素一致）
2. **双击仍然打开**、右键菜单仍然正常（神圣特性回归）
3. 退出状态后，主界面**完全恢复原样**（单击不再选中、角标消失）
4. 单击选中的手感：点一下有没有反馈、有没有误触打开
5. 目录格子选中后数量算得对不对（拿一个已知目录核对）
6. 刷新 / 切目录后标记还在不在
7. 40+ 张一次替换：进度、取消、部分失败的可读性
8. 写完确认系统盘备份目录里真有原图，且**盘上没多出任何文件**（除被覆盖那张）
