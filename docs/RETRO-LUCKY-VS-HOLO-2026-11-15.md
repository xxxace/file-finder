# 复盘：抽卡页 vs holo-reverse（2026-11-15）

> 对象：`D:\code\holo-reverse\src\app.js`（673 行）+ `src/styles.css`（185 行）。
> 我第一版只读了 CSS 就动手 —— 这是本次所有差距的总根因。

## 〇、一句话结论

**不是参数没调好，是驱动范式不同。**

| | 参考站 | 我 |
|---|---|---|
| 驱动 | 单个 `requestAnimationFrame` 主循环，**每帧对所有属性做弹簧子步进**（`n = ceil(dt*240)`） | CSS `transition` + `cubic-bezier` |
| 几何 | 撕口 96 段路径**逐帧重算** `clip-path`；12 片撕条各自累积 `rotateY/Z` 变换 | 一次性生成 `clip-path`，整块飞走 |
| 彩虹 | **SVG 35 条 ribbon + 行波 + 尾部渐变 + 光点**，逐帧重算 36 条边的点 | 一个 `radial-gradient` 圆环放大淡出 |
| 卡片 | 射出 → **绕屏幕螺旋 2.5 圈** → 落扇形，三轴旋转 + 透视 | 缩放 + 位移，二维 |

`transition` 只能"到得了位"，不会"活着"。它没有速度、没有过冲、没有相位差、没有"手的快慢决定撕裂声"。所以越调越像贴图。

## 二、我做错了什么（按严重度）

1. **只读 CSS 没读 JS。** `app.js` 673 行里藏着全部时间轴与物理，我拿 185 行 CSS 就判断"手法提炼完了"。这是拿静态证据代替实测，也是这次返工的全部原因。
2. **把"彩虹"当成一层叠加效果。** 它是一整个**由撕口形状驱动的 SVG 光流系统**（36 条边、行波、尾部渐变、光点、bloom）。我理解成"铺一层彩虹渐变" —— 那是两个数量级的差别。
3. **用 CSS 动画代替物理。** 观感上的"活"全部来自逐帧弹簧与子步进。我当时以"CSS compositor 更省电"为由选了 transition —— 这个理由对**静态倾斜**成立，对**一次有编排的爆开**完全不成立。
4. **卡片出场只做了"到位"。** 漏掉了"射出 → 螺旋 2.5 圈 → 落位"这整段编排，而那正是参考站让人"哇"的地方。
5. **否掉稀有度时没有补替代方案。** "不编造评级"是对的，但我因此让 5 张卡长得一模一样 —— 卡片失去了色彩层次。正确做法是：**评级不编，但色彩差异换成真实信息**（盘符/容量/最近新增/类型），让每张卡有自己的主色。
6. **包装被当成图标而不是物体。** 没有投影、没有呼吸、没有飞入、没有下落、没有侧面厚度 —— 它是一张会动的图，不是一个能拿在手里的东西。

## 三、重做方案

底层换掉：**新增一个 `rAF` 主循环 + `Spring` 引擎**，CSS transition 只保留给不参与编排的界面元素（按钮、勾选框）。

### 第 1 步：引擎 + 包装本体（决定"它是不是个实物"）
- `src/views/Lucky/spring.ts`：`Spring` 类（response/bounce 映射）+ `step(h)`；主循环按 `dt*240` 子步进
- `src/views/Lucky/stage.ts`：主循环（只有一个 `rAF`，所有对象注册进来；`prefers-reduced-motion` 时把 dt 归零，不跑物理直接落位）
- 包装：6 个弹簧 + 呼吸 + 跟鼠标 + 抓住蜷缩 + 高光随倾角 + **椭圆地面投影** + 进场飞入 + 开包后下落
- 撕条侧面：`rim` 叠片（左右各 9 条）

### 第 2 步：撕口 + 光流（决定"像不像抽卡"）
- 96 段路径生成（斜率/弓形/摆动/游走/跳变）+ 拖动跟手 + 松手飘动
- 撕条 12 片 + 每点金属宽度生成银边细带 + 撕条背面箔色
- **SVG 光流**：35 条 ribbon、36 条边、行波、尾部渐变、10 个光点、bloom + mask；撕到哪喷到哪；开包后整片冲出屏幕

### 第 3 步：卡片编排（决定"哇不哇"）
- 射出（受包壁引导）→ 螺旋 2.5 圈 → 落扇形；三轴旋转 + 透视
- 每张卡按自己相位呼吸；悬停抬升 + 深度 + 倾斜；键盘聚焦自晃
- `fan()` 三套布局（宽屏/窄屏叠手牌/竖屏 2-1-2）+ 透视补偿
- **卡片主色改为真实信息**：盘符/容量区间/最近新增 → 决定卡框与信息条的主色（不编评级）

### 第 4 步（可选）：彩带 3D + 随速度的撕裂声

## 四、不做的部分（附理由）

| 不做 | 理由 |
|---|---|
| 六种包装配色 | 我们只有一种实体：CD 盒。但可以按**盘序列号**给书脊换色 —— 有真实依据，且每次抽卡不同 |
| 角色表情（眨眼/痛苦/汗） | 没有角色，也不需要 |
| 稀有度评级（Common/Rare/Ultra） | 没有真实数据，编造评级是假信息。改用真实维度的色彩（见 §三.3） |
| 卡片 3D"立起"露出背面 | 封面是平面海报，翻面会看到空白 |
