# 导航语义升级方案 —— 「从缓存跳转」与「返回」

> 日期：2026-09-30 · 状态：**待批准，代码未动**
> 触发：用户反馈「由于我们通过缓存打开的页面是不会被识别成栈模式的，返回的体验有些怪」
> 前置硬约束（用户本轮新增）：**不允许手动输入 / 编辑路径** —— 路径只能由"点击 / 选择"产生

> 关联：`docs/DESIGN-HEADER-2026-09-30.md`（头部布局方案；本文改的是它上面那排东西**背后的状态模型**）

## 0. 结论摘要

**你的判断是对的，而且根因比"不被识别成栈模式"更精确：**

> **`openStack` 这一个数组，同时承担了两个不同的语义 ——「祖先链（我在哪）」和「访问历史（我刚在哪）」。**
> 逐层下钻时这两件事**恰好重合**，所以一直看不出问题；
> 一旦发生**跳转**（从「缓存记录」打开一行），两者**必然分叉** —— 而代码在这种情况下选择了"清空重来"。
> 结果是：**位置感丢了、返回变成死按钮、而且回不到你刚才那一屏。**

**修法（一句话）**：**把"位置"从状态里删掉**（由当前路径纯推导），让状态下只剩"历史"一个职责。

| 决策 | 定夺 | 一句话理由 |
|---|---|---|
| 面包屑的定义 | **从"相对用户选的根"改为"绝对路径链"**（`E: › 祖 › 父 › 当前`） | 这是 Apple HIG 路径控件的官方模型；且它**不需要状态** ⇒ 跳转后自动正确 |
| 「返回」 | **回上一屏（历史）**，且**跳转也可撤销** | 把"怪"变成"妙"的那一处：现在跳转不可逆，改完一次 `返回` 就能撤销 |
| 「返回」显示条件 | `dir`（**快照**：曾经选过根）→ `history.length > 1`（**事实**：此刻真有上一屏） | 这是"判据落在事实还是快照上"的同族错误（见 §3） |
| 面包屑首段（盘符） | **不可点**，只作定位 | 点它会打开盘根（通常未缓存 ⇒ 真读一次盘）。这是本轮唯一要新增的读盘路径，我选择不引入 |
| 根 chip | 保留，**升级为「回根」入口** + 显示有界化 | 解决"跳转后想回根"，且**不新增任何按钮** |
| 手动输入路径 | **不做**（你禁止） | ⇒ 连带把 `docs/DESIGN-HEADER-2026-09-30.md` 的**路线 B 降级为不做**（见 §8） |
| 左侧目录树 | 不做 | 收益已被「缓存记录」面板覆盖（上一轮已否） |

## 2. 根因：一个数组，两个语义

```
                ┌──────────────────────────────────────────────┐
                │              openStack                        │
                │  ┌────────────────┬───────────────────────┐  │
                │  │ 「祖先链」      │ 「访问历史」           │  │
                │  │ 我在哪（位置）   │ 我刚在哪（历史）        │  │
                │  └────────────────┴───────────────────────┘  │
                └──────────────────────────────────────────────┘
   逐层下钻（双击）：  祖先链 = 历史   ← 两者重合，看不出问题
   跳转（从缓存打开）：祖先链 ≠ 历史   ← 必然分叉，而代码选择"清空重来"
```

**为什么"逐层下钻"时看不出来**：双击一个子目录去，你走的正是"从父到子"的边 ⇒ 祖先链和访问历史是同一条序列。

**为什么"跳转"必然分叉**：
- **祖先链**要的是"这个目录在树上的**真实父级**"（`E: › … › 祖 › 父 › 当前`）
- **访问历史**要的是"**我上一次看的那个目录**"（可能是完全不相干的另一块盘）

这两个答案**没有任何理由相同**。而 `handleDirChange` 把跳转实现成了"清空 + 压一层"，于是：
- 祖先链 → 只剩 1 段 ⇒ **看不到自己在树的哪里**（N7）
- 访问历史 → 被销毁 ⇒ **回不到刚才那屏**，只能重开「缓存记录」再找那一行（N3）
- 「返回」按钮却还在（因为它看的是 `dir`，N5）⇒ **死按钮**（N6）

## 3. 附带发现：「返回」的条件犯了同一个错

```
     出现条件：  v-if="dir"                      →  「曾经选过根吗」  ← 快照
     执行条件：  openStack.length > 1            →  「此刻真有上一屏吗」← 事实
```

**这是"判据落在事实还是快照上"这一类错误的又一次出现**（前一次：用 `path.startsWith('#')` 判断"文件能不能打开"，见 `docs/DESIGN-CONVERGED-2026-09-24.md` 与项目记忆 §十二）。
`dir` 是**历史快照**（"我选过根"），`length > 1` 是**当下事实**（"此刻有没有上一屏"）。两者在"根层"和"跳转后"必然不一致 ⇒ 按钮可见但无效。

⇒ 修法同上一轮：**让判断依赖当场的事实**，也就是把出现条件改成 `history.length > 1`。

---

## 4. 目标（用户视角的三句话）

> ① **从缓存打开一个目录 = 一次跳转**，不是"重新开始"。
> ② 跳完之后：**我知道自己跳到了哪**（位置可见）、**一键能回到刚才那屏**（历史）、**一键能回到我的根**（书签）。
> ③ **跳转是一次可撤销的动作** —— 所以我敢到处点。

## 5. 设计

### 5.1 拆语义：位置不再存状态

| 概念 | 现在 | 改成 | 关键性质 |
|---|---|---|---|
| **位置**（我在哪） | `openStack`（从起点到当前的链） | **纯函数 `ancestorsOf(path)` 推导** | **不存状态 ⇒ 不可能与"当前路径"不一致**（这就是"用正确的方式修"：不一致在结构上消失） |
| **历史**（我刚在哪） | 混在 `openStack` 里 | `history: NavEntry[]`，每屏一个对象 | 单一职责 |
| **根**（我选的起点） | `dir` + 隐式的 `openStack[0]` | 保持 `dir`，**不再参与面包屑** | 只做"根书签" |

```ts
// 位置：无状态推导（把 levelName() 的切分逻辑收进这里，levelName 由它派生 —— 一处实现）
ancestorsOf('E:/videos/a/b')      // → E: / videos / a / b   （首段是盘符，不可点）
ancestorsOf('#CD72/videos/a')     // → 离线(CD72) / videos / a   （首段是只读锚点，不可点）
ancestorsOf('\\\\server\\share\\x')  // → \\server / share / x   （UNC 兜底：没有盘符时首段 = 第一段）

// 历史：唯一的状态（每屏一个对象，三处信息不可能错位）
type NavEntry = { path: string; searchText: string; scrollY: number }
```

> ⚠️ **两个必须写进实现的细节（自查 S-5 / S-8 补）**：
> 1. **UNC / 网络位置 / 虚拟盘兜底**：`splitDrive` 只认 `X:` 形式；这类路径**本来就存在**（用户可以通过"选择文件夹"选网络位置，缓存时按"没缓存"处理）。`ancestorsOf` 必须定义它：**没有盘符时首段就是第一段**，其余照常。
> 2. **首段标签必须与缓存面板共用同一个格式化函数**：`离线(${serial.slice(-4)})` 现在**只实现在 `HistoryTable` 的 `diskLabel()` 里**（`HistoryTable/index.vue:432`），是**本地实现**。若 `ancestorsOf` 再写一遍 ⇒ 两处各写一份同样的文案格式，以后改文案要改两处。⇒ 抽成一个共享函数（放 `src/utils/`）。

**合并 `openStack` + `searchStack` + 挂在元素上的 `scrollY`**（N10）⇒ 从"三处靠索引对齐"变成"一处一对象"。这是**顺带必须做的**，不是额外野心：因为本轮就要把"位置"从这块状态里拆走，留着平行数组只会更容易错。

### 5.2 面包屑 = 绝对路径链（Apple HIG 的官方模型）

`[引用]` Apple HIG「Path controls」原文：Standard 形态是
"**A linear list that includes the root disk, parent folders, and selected item**"；
"**If the list is too long to fit within the control, it hides names between the first and last items.**"

我们照这个模型来（它同时回答了"层级太深怎么办"）：

| 项 | 规格 |
|---|---|
| 首段 | `E:`（在线）/ `离线(CD72)`（锚点）· **不可点，只作定位** ⚠️ 见 §6 读盘清单 |
| 中间段 | 目录名 · **可点 = 跳转（压历史，不截断）** ⚠️ **这改变了现有行为**：现在是 `handleJump` 的 `slice(0, index+1)`（**截断** ⇒ 点祖先段会丢弃后面的历史，点完**回不到刚才那一层**）；改后是 `push` ⇒ 点完祖先段**还能返回**。这本身是同一个病的第二处症状，见 §12 自查 S-3 |
| 当前段 | **纯文本、不可点**（`[引用]` Fluent 2：*"Keep the current page item as text only"*）；且**可点段与不可点段必须视觉可分**（可点 = 链接色 + `cursor:pointer`，不可点 = 普通文字色 + `cursor:default`）—— 否则用户会去点一个点不动的东西（现状就犯了这错，见头部方案 F8） |
| 单段过长 | `max-width` + 省略号 + `title`/tooltip 显全名（Fluent 明文要求 tooltip） |
| 层级过多 | **显示上限 4 段：首段 + `…` + 父 + 当前**；`…` 可点开列出被折的层（**每层可点**）。⚠️ **补充约束（自查 S-2 修）：`…` 至少代表 2 段，只代表 1 段时那一段直接显示**（总长变 5 段）—— 否则 5 段路径会渲染成 `E: › … › 父 › 当前`，白白多一次点击 |
| 绝不换行 | `[引用]` Fluent 2 明文 *"Don't wrap breadcrumbs to multiple lines"*；容器 `nowrap` + `min-width: 0` |

> ⚠️ **与头部方案的一处联动**：`docs/DESIGN-HEADER-2026-09-30.md` §5.2(3) 定的阈值（≤4 层全显）是按**"相对根"的浅链**估的；面包屑改成**绝对链**后天然更深（`E: + 4 层` 就到 5 段）⇒ 该阈值按本表的"**最多 4 段：首 + `…` + 父 + 当前**"为准。阈值是可调常量，真机目视定。

**为什么"绝对链"比"相对用户选的根"更好（四条，第一条最重要）**：

1. **它不需要状态** ⇒ 跳转 / 选根 / 下钻都不可能让它不一致 —— **这就是本方案的修复核心**。
2. **与用户已有的软件一致**：Explorer 的地址栏、Finder 的路径栏都是**从卷到当前项**，不是"从你上次选的文件夹"。
3. **首段永远是同一个东西**（那块盘）⇒ 起点不会随操作变来变去。
4. `…` 折叠规则在绝对链下**正好用得上**（上一层方案里做的折叠能力，在这里才真正发挥作用）。

### 5.3 「返回」= 回上一屏，永远可用（只要真有上一屏）

| 项 | 规格 |
|---|---|
| 语义 | **回上一屏**（含滚动位置、含搜索词）＝ 浏览器的"后退" |
| 出现条件 | **`history.length > 1`**（事实）· 根层**不显示**（回哪去？） |
| 跳转 | **压历史**（不清空）⇒ 跳转可撤销 |
| 恢复 | 滚动位置（神圣，保留）+ 该屏的搜索词（神圣，保留） |
| 快捷键 | 新增 **`Backspace`**（与既有 `S` / `D` / `F5` 单键风格一致；`onKeyup` 已有 `target === body` 守卫，不会在输入框里误触发） |
| tooltip | `返回上一屏（Backspace）` —— 因为改造后它与面包屑**职责不再重叠**（面包屑 = 位置，返回 = 历史），必须说清 |

### 5.4 「返回」的妙用（这才是升级点）

> **让「跳转」从一次不可逆的动作，变成一次可以撤销的动作。**

- **现在**：从缓存打开一行 = 单向门。想回去只能重开「缓存记录」→ 找那一行 → 点开。**这就是"怪"的最痛处**。
- **改后**：`返回` 一下。⇒ 用户**敢到处跳、敢试探**，因为总有一键回退。

这一处修完，「返回」这个按钮的价值从"下钻后的回退"升级成"**万能撤销键**" —— 面包屑负责去别处，返回负责撤回。**两个控件的分工第一次变得干净。**

### 5.5 根 chip：从"回显"变成「回根」—— ⚠️ **降级为可选项（自查 S-4）**

- **可做**：点 chip 的 tag 主体 = **回到 `dir`（我选的根）** —— 现在它**没有任何点击行为**，只有那个 `×`。⇒ "跳转后想回根"有入口，且不新增按钮。
- ⚠️ **为什么降级为"可选"**：它是本方案里**唯一一处"为便利而加"**的新交互（奥卡姆要求我对它更严格），而且**它有一个副作用**：
  - **它放大了误点后果。** `×`（清空整个视图）是 `n-button size="tiny"`，与路径文字紧贴。现在误点 tag 主体**没有任何后果**（tag 不可点）；加上"点主体=回根"之后，误点会**跳转**。⇒ **必须先解决 F10**（`×` 至少加 `n-tooltip` 说明它是"清空"），再决定要不要加这个点击。
  - **替代方案已存在**：回到根 ≈ 点面包屑的中间段（如果根在路径上）+ `返回`。所以它**不是必需**的。
- **我的定夺**：**先不做**（P2）。等 F10 处理完、且你确实感到"想回根"的痛，再单独加。**不为了完整性把它塞进第一版。**
- 无论做不做，chip 的**显示有界化**（`foldPath()`）都保留 —— 那是头部方案已定的，与本条无关。

### 5.6 「加载缓存路径」的进入感

因为面包屑**由 path 推导**（不需要等数据），所以：

> **点下那一行 → 位置立刻到位 → 内容随后到。**（"位置先到、内容后到"）

- 好处：用户点了之后**马上**看到自己在新位置，而不是"面板关了、网格还是老图，不知道点没点上"。
- 配合：网格用**既有的 `loading` 状态**给一个加载态（现在 `loading` 只被用在面包屑 tag 里的那个 spinner 上 —— 而按 §5.2，那个 spinner 应该只在**当前段**显示）。
- ⚠️ **两种状态必须分开（自查 S-6 补）**：**加载中** → 网格显示加载态（不要显示旧列表，否则"位置已经到 F 盘、网格还是 E 盘的图"会误导）；**加载失败** → **保留旧列表 + 横幅**（那是刻意设计，见 `index.vue:674-675`，理由是"网络抖一下不该丢掉整个列表"）。
  现状 `fetchFolder` 失败与成功之外**完全不碰 `dataSource`** ⇒ 加载中也会显示旧列表 ⇒ 这是**新增可见行为**，要显式实现，不是顺手就有。

### 5.7 ⚠️ 必须一起改的第三处：`dir` 的职责重划（自查 S-1，这是本轮**唯一会引入回归**的坑）

`dir` 现在的消费者**只有两个**：`v-if="dir"`（返回按钮）与 `emptyTip` 的一句 early-return（`index.vue:19, 367, 737`）。
本轮把"跳转"从"选根"里拆出来之后，**跳转不再写 `dir`** ⇒ 于是：

| 情形 | 现在 | 改后（若不处理） | 后果 |
|---|---|---|---|
| 冷启动 → 直接开「缓存记录」→ 双击一行 → 落在一个**空目录** | `dir` 被设 ⇒ 显示"这个目录是空的" | `dir` 仍是 `''` ⇒ `emptyTip` 判据不成立 | **一片空白，连"空的"都不说** ⇒ 回归 |

**修法（干净且必须）**：`emptyTip` 的"是否已经进入浏览"判据从 **`dir`（快照：曾经选过根）** 改成 **`history.length > 0`（事实：此刻有一屏）**。

> ⇒ **这条自检问句在本轮出现了三次**（返回按钮条件、`emptyTip`、以及历史上的 `path.startsWith('#')`）。
> 结论：`dir` 这个变量**只应表示"用户选的根"**；凡是"是否已进入浏览 / 是否真有上一屏"的判断，**一律改用 `history`**（当下事实）。这要在实现时逐处过一遍 `dir.value` 的读取点。

### 12.3 ③ 三神技过一遍

**🔬 第一性原理**（剥到不能再剥）

1. **位置**的信息来源是"**当前路径**" ⇒ **可推导**。
2. **历史**的信息来源是"**用户的操作序列**" ⇒ **不可推导**，必须存。
3. ⇒ 结论只有一句：**一个推导、一个存储。** 本方案的**全部**就是这一句，其余都是它的后果。
4. 再剥一层：界面为什么需要"位置"？→ 因为人会**迷失**（lostness），界面的职责是降低迷失。
   ⇒ 所以位置**不必以完整字符串表达**（`[引用]` Apple 的 Pop up 形态就只显示当前项）。我们保留链条，是因为它**同时是跳转控件**——一个控件干两件事，而不是两个控件各干一件。

**🏛 苏格拉底式提问（对自己最狠的一问）**

> **Q：能不能只改"返回按钮条件"+"跳转不清栈"，完全不动状态模型？这样改动最小。**

**A：不能。** 推演：跳转若"压栈"，而面包屑**仍由 `openStack` 渲染**，那么从 `E:/videos/a` 跳到 **F 盘**的 `F:/x/y` 之后，面包屑会渲染出 `videos › a › y` —— 一条**暗示 `y` 在 `a` 之下**的链，而这条路径**物理上不存在**。
⇒ **"位置必须由路径推导"不是野心，是"不动它就会显示一条假路径"。**

**这一问的价值**：它同时（a）砍掉了"最小改动版"这条退路，（b）**证明本方案不是过度设计** —— 我砍掉了两条路线（B/C），却坚持动状态模型，原因就在这里。

**🪒 奥卡姆剃刀**（加要有理由，砍也要有理由）
