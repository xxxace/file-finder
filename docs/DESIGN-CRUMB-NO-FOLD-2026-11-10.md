# 面包屑不再按段数折叠（2026-11-10）

主人原话：「路径层级深会折叠路径中间的文件夹，这可能是之前为了省空间设计的，但是现在不需要了，
空间非常的充足，你看下要不要改回来」。

**结论：改**，但不是"关掉就算了"—— 判据本身过期了，必须一起纠正。

---

## 一、为什么它当初存在，又为什么现在不该存在

| | 当初 | 现在 |
|---|---|---|
| 地址槽宽度 | `max-width: calc(50% + 槽宽)` ⇒ **只有半条顶栏** | 11-08 已取消该预算，槽 = "吃掉全部剩余宽度" |
| 右侧动作区 | ~420px | ~137px（搜索收成图标、刷新搬去左边） |
| 折叠判据 | `foldCrumbList(crumbs, max = 4)` —— **段数常量** | 常量还在，它服务的那个预算**已经死了** |

`max = 4` ⇒ 第 5 段起就折成 `盘符 › … › 当前`。而现实路径
（`盘 :\ 分类 \ 年份 \ 演员 \ 作品 \ 子目录`）**第 5 段太常见**了 —— 等于"几乎总是折"。

⚠️ 这条属于本项目自检问句 #2 的典型形态：**判据是常量，不是用户数据的函数**。
常量过期不会报错，只会让界面越来越不懂得用空间。

## 二、改法（零测量、零新增状态）

删掉折叠这个**决策**，其余交给已经在位的 CSS：

- `.crumbs { flex-wrap: nowrap; overflow: hidden }`
- `.crumb { flex: 0 1 auto; min-width: 0 }` + `.crumb-text` 省略号 ⇒ 放不下时**历史段先让路**
- `.crumb-current { flex: 0 0 auto }` ⇒ 当前段（"我在哪"的唯一答案）**永不被压**

⇒ 空间够：全链显示；空间不够：逐段省略，**最坏形态与原来的折叠几乎同观感**
（`盘 › … › 当前`），但每一段都还能点、还带原生 title。

改动：
- `index.vue`：`crumbFold` / `crumbHidden` / `…` + 弹层 / `foldCrumbList` 导入 —— 全部删除；
  `crumbLayout = buildCrumbLayout(crumbs.value)`（fold 形参不传 ⇒ 全显）
- `styles/header.less`：`.crumb-more`（专给 `…` 的 12px padding）删除
- `utils.foldCrumbList` 与 `crumbRows.buildCrumbLayout(fold)` **保留**：纯函数、有探针
  （`docs/probes/crumbs/layout.mjs`）、零运行时开销。要恢复折叠 = 传一个参数 + 抄回弹层。

## 三、顺带变强的性质

11-08 的一条验收是「搜索展开/收起时面包屑不折叠、不整排重排」，当时靠"判据是段数、不看宽度"成立。
现在**结构完全不随宽度变** ⇒ 这条不是"仍然成立"，而是**结构性不可能违反**。

## 四、没做的事

- **按实测宽度决定折几段**（保留尽可能多的尾段）：成本高一个量级 —— 测量-决策-渲染是个回环，
  要避免"折/展"来回抖，得隐藏测量或加滞回，还要重验 11-08 的 FLIP/零位移纪律。
  ⇒ 现在的形态已经吃掉 90% 收益（常见路径全显），**不做**。真遇到"窄窗 + 极深路径"再议。

## 五、验收（30 秒目视）

1. 进到 6~8 层的目录：应看到 `盘 › 分类 › 年份 › 演员 › 作品 › 当前` **全显**，中间不再有 `…`。
2. 把窗口拖窄到 ~900px：各段开始出现省略号，**当前段仍是完整的**，没有横向溢出/换行。
3. 点开搜索框（挤压地址槽 200px）：路径段**不增减、不重排**，只是文字收窄。
